# 诊断教学：一步步把「登录失败现场」抓给我

> 本文档面向**没有学过浏览器调试**的用户。每一步都会说明：你在做什么、为什么做、做完会看到什么。
> 全程只需要 3~5 分钟。**不需要安装任何软件，不会影响你的浏览器数据。**

---

## 路线一（推荐 · 最简单）：一键导出诊断包

> 适合：你只想把现场发给我，不想自己看任何技术内容。

1. **打开 QuickLogin 管理页**
   - 点击浏览器右上角的 QuickLogin 图标 → 点「打开并行管理页」。
   - *这一步是打开扩展自己的页面（不是网站）。*
2. **先点一次「导出诊断」**（在页面右上角，「盒子」统计旁边）
   - *作用：把当前状态存档，作为「出问题之前」的对照。*
   - 会自动下载一个 `quicklogin-diag-….json` 文件，并复制到剪贴板。
3. **去复现问题**：按你遇到失败的顺序操作一遍
   （快捷登录 → 登录成功 → 页面退出账号 → 关闭页签 → 再次快捷登录 → 点登录按钮失败）。
   - *这一步期间扩展会自动记录每一个动作：打开、填表、点击、被拒、清空、驱逐……你什么都不用做。*
4. **回到管理页，再点一次「导出诊断」**
   - *作用：这次的文件里就包含了失败现场。*
5. **把第二个 json 文件发给我**（第一个也可以一起发，用于对照）。

## 路线二（进阶 · 亲眼看现场）：打开扩展的「控制台」

> 适合：你想亲眼看扩展内部发生了什么。跟着点就行，输错也不会弄坏任何东西。

### 第 1 步：打开扩展的管理界面

1. 在地址栏输入 `chrome://extensions` 回车。
   - *这是浏览器的扩展管理页。*
2. 确认右上角「**开发者模式**」开关是**打开**的（蓝色）。
   - *打开后卡片上才会显示「Service Worker」蓝字链接。*
3. 在卡片「**QuickLogin · 多账号并行**」上找到蓝色小字「**Service Worker**」，**点击它**。
   - *会弹出一个黑色/白色的开发者工具窗口——这就是扩展的「大脑」控制台。*
   - ⚠️ 这个窗口**保持打开不要关**（关了扩展会休眠，日志就停了）。

### 第 2 步：在控制台里读取「取证记录」

1. 点击 DevTools 顶部的「**Console**」（控制台）标签。
2. 把下面这行命令**整行复制**，粘贴到闪动的光标处，按回车：

```js
copy(JSON.stringify((await chrome.storage.local.get(['ql:forensics','ql:diag'])), null, 2))
```

   - *这条命令做三件事：①取出取证记录（forensics：每次打开/填表/点击/被拒/清空）；
     ②取出诊断日志（diag：规则安装的每一步）；③格式化后复制到你的剪贴板。*
   - 成功的标志：回车后下方出现 `undefined` —— 这是**正常的**，内容已经在剪贴板里了。

3. **打开记事本 → Ctrl+V 粘贴 → 保存为 txt → 发给我**。

### 第 3 步（可选）：清空记录，做一次干净的复现

1. 在同一个控制台粘贴这行并回车：

```js
chrome.storage.local.remove(['ql:forensics', 'ql:diag']).then(() => console.log('已清空'))
```

   - *作用：把之前的记录清掉，接下来的记录就只属于这一次复现，不会混入旧数据。*
2. 然后去复现问题（退出→关页→重开→点登录失败）。
3. 重复第 2 步把新记录发给我。

## 路线三（对照用）：看登录请求本身发生了什么

> 适合：想知道「点击登录后，请求发出去没有、服务器回了什么」。

1. 在登录页标签页上按 **F12**（打开网页自己的开发者工具——注意：这是**网站**的，不是扩展的）。
2. 点顶部的「**Network**」（网络）标签。
3. 勾选「**Preserve log**」（保留日志，中文界面叫「保留日志」）。
   - *作用：登录成功会跳页，不勾选的话请求记录会被清空。*
4. 在登录表单里输入账号密码，点击「登录」。
5. 在 Network 列表里找到登录请求（名称通常含 `login` 或 `Oauth/Login`），点它：
   - 看「**Status**」（状态码）：`200` = 请求本身成功；`401/403/4xx` = 被拒；`(failed)` = 根本没发出去。
   - 点「**Headers**」→「**Request Headers**」→ 找 `Cookie:` 一行 → 把整行复制发我。
   - 点「**Payload**」/「**请求负载**」→ 看发出的账号密码字段是否有值（**不要把密码发我**，只告诉我「密码字段有值/为空」）。
6. 把「Status + Cookie 行 + 密码字段有无值」这三条信息发我。

## 复现协议（配合路线一/二使用，按顺序做）

| 步骤 | 你做什么 | 扩展在记录什么 |
|---|---|---|
| 0 | 清空记录（路线二第 3 步） | —— |
| 1 | 快捷登录账号 A | `open` → `open-tab` → `token-captured` |
| 2 | 登录成功后正常操作几下 | `autoLogin: click/rejected…` |
| 3 | **页面内点「退出登录」** | `logout` |
| 4 | **关闭 A 的全部页签** | `terminate`（登录态终结） |
| 5 | **再次快捷登录 A** | `open`（注意 `staleCleared`）→ 登录页自动填表 |
| 6 | 点登录按钮，反复点到失败 | `autoLogin: click / rejected / stand-down…` |
| 7 | 回管理页「导出诊断」→ 发我 | —— |

## 名词小抄

- **Service Worker**：扩展的「后台大脑」，所有规则安装、Cookie 管理都在它里面发生。
- **`ql:forensics`**：取证记录本——逐条记下扩展做了什么动作（打开/填表/点击/被拒/清空）。
- **`ql:diag`**：诊断日志——记下规则安装的每一步（装了几条、多大、成功与否）。
- **快照**：扩展替每个账号记住的「登录时身份材料」（token + Cookie），用于本账号页签的请求回放。
- **回放**：出站请求时把该账号的身份材料装回请求头的过程。
