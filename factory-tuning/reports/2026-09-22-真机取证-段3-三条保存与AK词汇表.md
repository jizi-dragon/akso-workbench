## 2. ★★ 结论一：一次点击 → **三条**保存，而三条的差异全部可解释

| | 保存 #1 | 保存 #2 | 保存 #3 |
|---|---|---|---|
| 字节 | 9064 | 9013 | 9342 |
| `source` / `isMain` / `name` | 2 / true / 默认布局 | 同左 | 同左 |
| `sections` | 3 个（62 / 62 / 62 键） | 同左 | 同左 |
| `controls` | 7 个 | 7 个 | 7 个 |

**#1 → #2 的唯一差异**：`test_time__c`、`test_option__c` 的 `gridSpan` **2 → 1**
—— 正是演示者申报的那两处「改成半行」。⇒ **#1 带的是那次改动之前的状态**。

**#2 → #3 的唯一差异**：键的完整度（`gridSpan` / `sort` / 值全同）：

| 控件 | #2 缺哪些键（相对 #3 的 23 键） |
|---|---|
| `test_time__c` | 8 键：`defaultValue` `externalDataConfig` `hidden` `hideWhenNotData` `readOnly` `readPretty` `required` `visible` |
| `test_option__c` | 9 键：上列 + `combinationDisplayFieldId` |

⇒ **#3 是 #2 的"补全版"**。这与段 1 那一对（精简 8 键 → 完整 23 键）**是同一个现象**。

**跨段汇总（保存条数）**：段 1 = **2** 条、段 2 = **1** 条、段 3 = **3** 条。
⇒ **不要假设"一次点击 = 一条"**，也**不要**假设固定条数；平台自己的提交链会多发，
而每一条**都值得按"它带的是哪个状态"去读**，而不是当成重试。

## 3. ★★ 结论二：键数不是"新建 / 已有"，是**模型的物化程度**（F36 更正）

段 2 里我看到"新建 8 键 / 已有 23 键"，读成了「形状取决于服务端是否已认识它」。
**本轮这条被自己的数据推翻**：同一个控件在**同一次点击的三条保存**里键数不同

| 控件 | #1 | #2 | #3 |
|---|---|---|---|
| `test_file__c` | **16** | 23 | 23 |
| `test_fa__c` | **15** | 23 | 23 |
| `test_time__c` | 23 | **15** | 23 |
| `test_option__c` | 23 | **14** | 23 |
| `test_oo__c` / `test_daily_time__c` / `if_ok__c` | 23 | 23 | 23 |

缺的键**全是可空的可选键**（`visible`/`readOnly`/`readPretty`/`hidden`/`hideWhenNotData`/
`required`/`defaultValue`/`externalDataConfig`/`combinationDisplayFieldId`）。

**更正后的表述**：
> 请求体里的键集 = **客户端此刻把该组件的模型物化到了什么程度**。
> 「新建」与「精简」在段 1/段 2 里**相关**（新建的组件模型本来就少），但**不是因果**；
> 平台对**两种都接受**（三条全 `200 / code=0`）。

⇒ **对工厂的意义（比原来更好）**：不必为了"像真机"去凑那 23 个键；
**键名必须对、必需键必须在**，可选键发不发都能被接受（判据：真机自己就发过 14 键的版本）。
⇒ **但"哪些是必需键"仍然没有定论**：观测到的最小集合是段 2 新建控件的 **8 键**。

## 4. ★★ 结论三：`dataType ↔ AK*` 映射补全（7 组 / 5 个类型）

| dataType | 控件（演示者的命名） | 实测 `type` |
|---|---|---|
| **3** | 测试是否满足标准 | **`AKSelectorYesNo`** ← 本轮新增 |
| **4** | 测试选项 | **`AKSelectorSingle`** ← 本轮新增 |
| **5** | 测试时间 | **`AKDateTime`** ← 本轮新增 |
| 7 | 测试日期时间 | `AKDateTime` |
| 8 | 测试附件 | `AKAttachment` |
| 15 | 测试相关对象 | `AKSelectorObject` |
| 16 | 测试父对象 | `AKSelectorObject` |

### 4.1 ★ 它不是双射（这条会影响 D-D 的修法）

`5` 与 `7` **都**映射到 `AKDateTime`；`15` 与 `16` **都**映射到 `AKSelectorObject`。
⇒ D-D 那张表的形状应当是「**dataType → type**（允许多对一）」，
**不要**写成双向表，也不要因为"两个 dataType 共用一个 type"就以为取错了字段。

### 4.2 仍然没样本的 dataType（**继续 Fail-Closed**）

`1 文本` / `2 数字` / `13 查找` / `14 公式` / `17 长文本` / `18 富文本` / `23 对象多选`
—— **一个都没有**。D-D 的修法要求"**未知即显式失败**"，这条**不因为多认了 3 个就放松**。
