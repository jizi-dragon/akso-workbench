## 1. 术语表

### 1.1 数据与结构

- **对象（Object）** —— 平台**唯一的数据实体类型**，结构化业务数据与文档都由它承载；它不是"一张表"，而是"表结构 + 业务规则 + 界面 + 权限"的整包（`01_产品介绍/02_核心概念.md §对象`、`01_产品介绍/09_术语表.md §Object`）。⚠️ **与常见 CRM 不同**：CRM 的 Object 基本等于 schema，Gaia 的"对象"是**配置交付单位**——手册把它列为可配置组件（`01_产品介绍/03_平台架构.md §数据模型`）。
- **对象记录（Object Record）** —— 对象中的**一条具体数据**（`09_术语表.md §Object Record`；`01_快速入门/05_对象记录入门.md §什么是对象`）。业务语境说"记录/实例"，管理员语境说"对象"，**两者不同层**。
- **对象类型（Object Type / Objecttype）** —— 对象的**子分类**：同一对象下不同类型的字段集/生命周期/权限/模板可以不同；文档对象是三级：类型（Type）→ 子类型（Subtype）→ 分类（Classification）（`01_产品介绍/04_数据模型.md §对象类型、§文档对象类型（三级分类）`；`09_术语表.md §Object Type / Subtype / Classification`）。
- **字段（Field）** —— 对象的属性定义，规定数据类型与约束（`02_核心概念.md §字段`）。手册列 **16 种字段类型**：文本 / 长文本 / 数字 / 日期 / 日期时间 / 是-否 / 选项 / 父对象 / 对象 / 查找字段 / 统计字段 / 附件 / 公式 / 富文本 / 组件 / 文件（`02_核心概念.md §字段类型`，与 `04_数据模型.md §字段类型` 同表）。
- **查找字段（Lookup）** —— ⚠️ **与 CRM 的 lookup 含义不同**：手册明说它是**从父对象或引用对象同步字段值的只读字段**，示例"自动带出：产品.持有人"（`02_核心概念.md §字段类型`）。CRM 里 lookup 通常就是"可编辑的外键选择器"。Gaia 把可编辑外键叫**对象 / 父对象**，把"随外键自动带出的只读值"叫**查找字段**（`01_快速入门/01_创建对象记录.md §字段类型`：「查找/统计/公式 —— 自动计算或自动带出，这类字段通常只读」）。
- **选项集（Picklist）** —— 预定义的下拉选项集合，被"选项"类型字段引用（`09_术语表.md §Picklist`；`03_平台架构.md §数据模型` 把 Picklist 列为数据模型层可配置组件）。
- **表单布局（Form Layout）** —— **记录详情页**的字段排布（部分、列数、放哪些字段）（`03_平台架构.md §布局与界面`）。
- **列表布局（List Layout）** —— **列表页的列配置**（显示哪些字段列、列顺序）（`03_平台架构.md §布局与界面`；`02_对象管理/10_对象列表视图.md §自定义显示列`）。
- **视图（View）** —— 命名保存的**数据范围 + 筛选 + 排序 + 列**的组合。三个内置视图：`所有的{对象}` / `最近的{对象}` / `收藏夹`；另加管理员配置的**业务视图**（待我处理、待我审批）与用户**自建视图**（`10_对象列表视图.md §对象菜单通常会提供三个标准视图`；`05_搜索/03_保存视图.md`）。⚠️ **布局与视图不同层**：布局 = "长什么样"（配置态，管理员定），视图 = "看哪些记录、怎么排"（含用户自建、可共享/私有）。**不可互替**。
- **显示模式（表格视图 / 分组视图 / 树形视图）** —— 在视图之上再叠一层的组织方式：表格=按行按列；分组=按字段聚合（分组≠筛选，分组保留结果集）；树形=按层级展开，分"树形对象视图"与"相关对象树形视图"（`10_对象列表视图.md §列表显示模式`）。
- **网格视图（Grid View）** —— 类电子表格的列表模式，支持双击单元格内联编辑、多单元格批量编辑、拖拽列宽、Enter/Tab/Esc 快捷键（`02_对象管理/04_使用网格视图.md`；`05_对象记录入门.md §第五步`）。`[推断]` 它是"显示模式"的一种特例而非独立概念层。
- **暂存箱** —— 跨视图临时收集待处理记录的容器，收集完再统一发起批量动作（`10_对象列表视图.md §使用暂存箱`）。
- **编号规则（Number Rule）** —— 可配置的**编号生成规则**，属数据模型层组件；文档编号"（可自动生成）"（`03_平台架构.md §数据模型`；`04_数据模型.md §核心系统字段`）。
- **代码后缀约定** —— `__c` 自定义 / `__ak` 标准 / `__sys` 系统（`09_术语表.md §Code`）。`name__ak` 是记录主名称字段（`10_对象列表视图.md §列表中的链接字段`）。

### 1.2 文档与附件（最易混的一对）

- **文档（Document）** —— 平台中的一种**标准对象**，特殊之处是含一个**文件字段**存非结构化内容（`02_核心概念.md §文档`；`09_术语表.md §Document`）。⚠️ **与 CRM 的"文档/附件"根本不是一回事**：Gaia 的文档**不是挂在业务对象上的附件**，而是与业务对象**同级的对象**，同样有字段/生命周期/工作流/权限；业务对象只能通过**文档引用字段**指向它（`04_数据模型.md §文档对象 vs 业务对象、§文档引用字段`）。
- ⚠️ **同一物两个词**：概念章一律叫"**文档**"，界面模块与列表却叫"**文件管理 / 所有文件**"（`01_快速入门/06_文档管理入门.md §第一步`：「在顶部导航进入【文件管理】…默认进入【所有文件】列表页」）。听到"文件"时先确认是"文档对象"还是"附件字段"。
- **文件字段（File Field）** —— 文档对象专用、存 Word/PDF/Excel，**带版本控制、自动渲染、水印、全文索引**（`04_数据模型.md §字段类型 注、§核心系统字段`）。
- **附件（Attachment）** —— 直接存文件的字段类型，**无版本、无生命周期**（`02_核心概念.md §字段类型`；示例"支持性文件、图片证据"）。与文件字段是**两回事**，不可互换。
- **格式副本（Rendition）** —— 系统把源文件自动转成浏览器可查看的格式（Word/Excel/PPT→PDF，PDF/图片直接显示）（`09_术语表.md §Rendition`；`07_文档管理原理.md §文档渲染`）。
- **文档引用（Document Reference）** —— 从**任意对象**指向文档对象的特殊引用，带**版本绑定模式**：当前版本 / 最新版本 / 最新稳定版本（`04_数据模型.md §版本绑定模式`；`09_术语表.md §Document Reference`）。
- **检出/检入（Check-out / Check-in）** —— 锁定文档→本地编辑→上传解锁定；检出期间他人只读（`07_文档管理原理.md §检出检入`）。
- **版本（Version）** —— 主版本.次版本（1.0 / 0.1）；状态分**草稿版本 / 稳态版本 / 过期版本**（`07_文档管理原理.md §版本控制`）。批准时升主版本，新建次版本继续迭代。

### 1.3 关联关系

- **引用关系（Reference）** —— 非层级的对象间关联（示例"文档 → 产品"）（`04_数据模型.md §关系类型`）。
- **父子关系（Parent-Child）** —— 子记录**依赖**父记录；行为含**级联删除 / 限制删除 / 字段继承**（`04_数据模型.md §关系的行为`）。层级 ≤ 3 `[推断：来自工厂侧 kernel/semantics.py 注释所引 04_配置指南/01B_对象字段.md，本次未读]`。
- **自引用关系** —— 对象内部的层级（区域 → 子区域）（`04_数据模型.md §关系类型`）。
- ⚠️ **"引用 vs 父子"在手册里是两条不同的边，不是同一个类型的两种叫法**：`父对象` 字段建立父子关系，`对象` 字段建立引用关系；`04_数据模型.md §字段类型` 把二者分列，且"查找字段"只能从**父对象或引用对象**带值。
- **相关对象（Related Objects）** —— 详情页里的**区块**，展示与当前记录关联的对象列表；可单独做视图配置、支持表头筛选/排序/批量/导入（`02_对象管理/02_查看对象记录.md §详情页区块类型、§查看相关对象`）。⚠️ "相关对象"是**界面区块名**，不是数据模型里的关系类型——`[推断]` 它对应"父子关系里子侧的那些记录"。

### 1.4 生命周期与工作流

- **生命周期（Lifecycle）** —— 记录从创建到归档的**状态序列 + 转换规则**（`02_核心概念.md §生命周期`；`06_生命周期与工作流.md §什么是生命周期`）。七个组件：**状态、状态类型、状态转换、进入条件、进入动作、用户动作、生命周期角色**（`06_生命周期与工作流.md §生命周期组件`）。
- **状态（State）** —— 记录在某一时刻所处的阶段（草稿 / 审核中 / 已批准 / 已归档）（`09_术语表.md §State`）。
- **状态类型（State Type）** —— 状态的分类：**初始状态 / 稳态 / 终态**（`06_生命周期与工作流.md §生命周期组件`；`09_术语表.md §State Type`）。
- **阶段（Stage）/ 阶段组（Stage Group）** —— 把多个状态**组织成可视化阶段**（起草阶段 / 审批阶段 / 生效阶段 / 归档阶段）（`06_生命周期与工作流.md §生命周期阶段`；`03_平台架构.md §阶段组`）。
- **生命周期角色（Lifecycle Role）** —— 用户与文档/记录在**状态维度**上的关系（作者 / 审批人 / 查看者）（`09_术语表.md §Lifecycle Role`）。
- **工作流（Workflow）** —— 完成特定业务目标的**步骤有序集合**，用于自动化审批、任务分配、通知（`02_核心概念.md §工作流`；`09_术语表.md §Workflow`）。类型分**对象工作流**与**文档工作流**（后者经 **Envelope** 包装文档，用于多文档批量审核）（`06_生命周期与工作流.md §工作流类型`）。
- **工作流步骤（Workflow Step）** —— 手册列 **8 类**：开始 / 任务 / 判断 / 动作 / 合并 / 更新共享设置 / 通知 / 结束（`06_生命周期与工作流.md §工作流步骤类型`）。
- **动作（Action）** —— ⚠️ **同名三层，必须靠上下文区分**：
  1. **Action（术语表义）**：用户定义的**自定义操作**，可按钮触发或在工作流中调用（`09_术语表.md §Action`）。
  2. **用户动作（User Action）**：**某个生命周期状态下**用户可执行的操作，如"提交审批""批准"（`09_术语表.md §User Action`；`03_平台架构.md §用户动作`）。
  3. **进入动作（Entry Action）**：**进入某状态时自动执行**的操作（`09_术语表.md §Entry Action`；`06_生命周期与工作流.md §启动方式`）。
  另有 **事件动作（Event Action）** 与 **动作安全（Action Security）**（`03_平台架构.md §生命周期、§权限与安全`）。
  📌 **手册明说**：「更新字段」「变更状态」「发送通知」是**动作步骤内可配置的动作类型**，**不是**独立的步骤类型（`06_生命周期与工作流.md §工作流步骤类型` 的 💡 注）。
- **工作流启动方式** —— 只有两种：**手动发起**（用户在记录上点"启动工作流"）与**生命周期入口动作**（进入某状态时自动启动）。📌 手册明说：**自动触发工作流不是独立配置**，而是写成"审核中"状态的入口动作（`06_生命周期与工作流.md §启动方式`）。
- **参与人 / 参与角色** —— 发起时按角色分配（带 `*` 的通常必填）；在途可**追加**但不能删除已有参与人、不能给已完成步骤加人（`01_快速入门/07_工作流入门.md §二、分配参与人`）。
- **任务（Task）** —— 工作流产生的待办事项，分"**分配给我（我的任务）**"与"**可领取（Available Tasks）**"；领取后从可领取移入我的任务（`09_术语表.md §Task`；`01_快速入门/03_首页导航.md §各视图说明`）。
- **电子签名（E-Signature）** —— 用户对文档或操作的数字化确认；要素含用户身份、**签署时重新输入密码**、签名原因、时间戳、含义声明（`06_生命周期与工作流.md §电子签名要素`）。类型：单签名 / 双签名（操作者+复核者）/ 多级签名（`06_生命周期与工作流.md §签名类型`）。

### 1.5 权限体系

- **用户（User）** —— 独立系统账户，唯一登录凭证（`05_权限体系概述.md §用户`）。
- **用户组（Group）** —— 把用户组织在一起的容器，便于**批量授权**（`05_权限体系概述.md §用户组`；`09_术语表.md §User Group`）。
- **角色（Role）** —— 权限管理的核心单元，定义一组职责并**拥有权限集**（`05_权限体系概述.md §角色`）。分两类：**应用角色**（应用级，如系统管理员/业务管理员/普通用户）与**对象角色**（用户与**记录**的关系，供 DAC 用，如负责人/协作者）。
- **权限集（Permission Set）** —— 一组具体权限的集合，被分配给角色（`05_权限体系概述.md §权限集`；`09_术语表.md §Permission Set`）。用户可有多个权限集，**权限取并集**（`09_术语表.md §Permission Set`）。权限集覆盖**对象权限 / 字段权限 / 菜单**（`05_权限体系概述.md §权限体系架构` 图）。
- ⚠️ **角色 ≠ 权限集**：角色是"职责"，权限集是"权限包"，中间是"角色拥有权限集"（`05_权限体系概述.md §核心关系`）。把两者合成一个"角色+权限清单"的概念会丢层次。
- **功能权限 vs 数据权限** —— 功能权限由**权限集**控制（能用什么功能），数据权限由 **DAC** 控制（能看哪些数据）（`05_权限体系概述.md §功能权限 vs 数据权限`）。📌 **手册明说：功能权限是前置条件**——用户对某对象没有任何功能权限时，**即使通过 DAC 被分配了记录角色也完全无法访问**（`05_权限体系概述.md §组合效果` ⚠️ 注）。
- **DAC（动态访问控制 / Dynamic Access Control）** —— **记录级**访问控制模型：**角色 × 生命周期状态 = 记录级别的动态权限**，通过**共享规则**自动把用户分配到记录的角色（`05_权限体系概述.md §动态访问控制（DAC）`；`09_术语表.md §DAC`）。⚠️ **与一般语境里的 DAC 不同**：通用 DAC 常指"属主自行授权"，Gaia 的 DAC 特指**记录内角色分配 + 状态耦合**，且**不能突破功能权限**。
- **状态权限（State Security）** —— **细粒度**权限：按**生命周期状态 × 用户角色**再动态控制**字段 / 操作 / 关系**的访问（`05_权限体系概述.md §状态权限、§权限层次`）。手册把它单列为第三层"动态功能权限"。
- **共享（Sharing）** —— 两层，别混：
  - **共享规则（Sharing Rule）**：**配置态**，自动把用户分到记录角色（含"匹配共享规则"）（`03_平台架构.md §权限与安全`；`05_权限体系概述.md §DAC`）。
  - **权限共享**：**运行态**，在**记录详情页**手工把 用户/用户组/部门 加到这一条记录上并选角色（`02_对象管理/04_对象记录权限共享.md`）。
- **字段级安全 / 动作安全** —— 字段访问控制与动作执行权限，均属可配置组件（`03_平台架构.md §权限与安全`）。
- **业务单元（Business Unit）** —— 多业务单元的用户在登录时选择本次进入的单元（`01_快速入门/01_登录系统.md §登录时选择业务单元`）。`[推断]`：它是**数据范围**维度，与"用户组（授权容器）"不是一回事。

### 1.6 输出与合规

- **报表（Report）** —— 报表定义与展示（`03_平台架构.md §报表与输出`）。用户侧建报表要先**选报表类型**、填必填 `名称` + `Code`，再配**过滤条件 / 分组 / 展示列**（`01_快速入门/08_报表入门.md §二`）。
- **报表类型（Report Type）** —— **报表的数据源**（`03_平台架构.md §报表与输出`）。⚠️ 报名的字面像"报表的分类"，手册定义却是**数据源**。
- **运行报告（Formatted Output）** —— 手册把它注明为"**导出模板**"（`03_平台架构.md §报表与输出`）；批量打印运行报告会逐条生成并合并为一个 PDF（`02_对象管理/06_批量操作(表头).md §批量打印运行报告`）。
- **仪表盘 / 仪表板（Dashboard）** —— 数据可视化面板：**指标卡 + 图表组件**，组件**引用报表**（`03_平台架构.md §布局与界面`；`01_快速入门/09_仪表板入门.md §五`）。⚠️ 手册自身写法不统一：`06_报表/02_创建仪表盘.md` 写"仪表盘"，`01_快速入门/09_仪表板入门.md` 写"仪表板"，**指的是同一物**。
- **模板（Template）** —— ⚠️ **手册里"模板"至少是三种不同的东西**，说"模板"时必须限定：
  1. **文档模板** —— 创建文档时【选择模板】（`01_快速入门/06_文档管理入门.md §第三步`）；由**文档对象类型**决定（`04_数据模型.md §文档对象类型的作用`）。
  2. **报表 / 导出模板** —— 运行报告（导出模板）、列表导出**封面模板**（`03_平台架构.md §报表与输出`；`02_对象管理/09_列表导出.md §PDF 封面`）。
  3. **通知模板（Notification Template）** —— 通知内容模板（`03_平台架构.md §工作流与自动化`）。
- **编号规则（Number Rule）** —— 见 §1.1。
- **检查表** —— ⚠️ **在本次阅读范围内没有"检查表 / 检查清单"这个平台概念**（`01_产品介绍` 9 篇 + 快速入门 11 篇 + 对象管理 11 篇 + 搜索 3 篇全文检索无命中）。最接近的是"电子签名清单"（`08_合规架构.md §签名清单`）与导入结果日志（`02_对象管理/07_列表导入.md §结果查看`）。`[推断]`：工厂侧的 **checklist（执行清单）** 是**工厂自己造的过程产物**，不是平台术语——分析流量时不要拿它去平台里找对应接口。
- **审计追踪（Audit Trail）** —— 系统自动记录谁/何时/对什么/做了什么，含**变更前值 / 变更后值**、操作来源、IP；**不可篡改、永久保留**（`02_核心概念.md §审计追踪`；`08_合规架构.md §审计追踪`）。
- **ALCOA+** —— 数据完整性九原则（可归属/可读/同步/原始/准确/完整/一致/持久/可用）（`09_术语表.md §ALCOA+`；`08_合规架构.md §数据完整性`）。
- **GxP / 21 CFR Part 11 / EU Annex 11** —— 生命科学合规法规族；Gaia 内置对应实现（`08_合规架构.md §21 CFR Part 11 合规`）。
- **Sandbox（沙箱）** —— **开发和测试用的隔离环境**，与生产分离（`09_术语表.md §Sandbox`）。⚠️ **与"执行不可信代码的沙箱"完全无关**，本仓两处同名，说的时候要区分。
- **Sphere / ACP** —— Sphere = Dev/QA/UAT 多级环境；**ACP（Akso Configuration Package）** = 配置导出包，用于在不同 Sphere 之间搬运配置（`01_产品概述.md §部署与运维`；`03_平台架构.md §配置迁移`）。📌 这正对应配置工厂在做的事：**工厂是在用 HTTP 直接产生"ACP 里那些配置"**。
- **受控对象分类（手册口径）** —— 系统对象（不可删）/ 文档对象 / 标准业务对象（应用预置）/ 自定义对象（用户创建）（`02_核心概念.md §对象分类`；`04_数据模型.md §对象分类`）。注：两篇的示例不一致，`[推断]` 分类口径以 `02_核心概念.md` 为准。

## 2. 数据模型的关系

### 2.1 谁挂谁（手册明说的挂载关系）

```
用户 ──属于──> 用户组（多对多，便于批量授权）
用户 ──拥有──> 角色（可多个）
                └──拥有──> 权限集 ──> 对象权限 / 字段权限 / 菜单
记录 <──自动分配角色── 共享规则（DAC 的输入）
记录 ──状态──> 生命周期状态 ──×── 角色 ──> 记录级动态权限（DAC / 状态权限）

对象 ──包含──> 字段（≥1）
对象 ──子分类──> 对象类型（类型决定：可用字段 / 生命周期 / 权限规则 / 模板）
对象 ──关联──> 对象（父子 / 引用 / 自引用）
对象 ──挂载──> 生命周期（状态 + 转换）
对象 ──绑定──> 工作流（启动方式之一是"状态入口动作"）
对象 ──呈现──> 表单布局（详情页）/ 列表布局（列）→ 视图（范围）/ 菜单
对象 ──编号──> 编号规则
```
依据：`05_权限体系概述.md §核心关系 / §权限体系架构 / §权限层次`；`04_数据模型.md §对象的组成 / §对象关系`；`01_平台概述.md §配置模型层次`；`06_生命周期与工作流.md §启动方式`；`01_产品介绍/03_平台架构.md §可配置组件`。

**三个层次的官方口径**（`01_产品概述.md §配置模型层次`）：
**数据模型层**（对象、字段、关系、子类型、文件字段）→ **业务逻辑层**（生命周期、工作流、权限规则、验证规则、自动化动作）→ **界面呈现层**（菜单、列表布局、表单布局、视图、操作栏、仪表盘）。
📌 手册明说配置顺序是 **自下而上：数据模型 → 业务逻辑 → 界面呈现**（`01_产品概述.md §配置模型层次` 的 💡）。这就是"创建顺序"的权威表述。

**一条容易踩的耦合**：工作流的**自动触发不是独立开关**，而是生命周期状态的**入口动作**（`06_生命周期与工作流.md §启动方式`）。所以"要给对象配自动审批"在手册口径里等于"配一个状态 + 在该状态上挂入口动作"，不是"给对象挂一个工作流"。

### 2.2 一个"业务对象"从零到可用的最小完整集合

**手册口径的最小集**（`04_数据模型.md §对象的组成` 列了对象/对象字段/对象类型/对象关系/生命周期/权限设置六项，但"能跑起来"与"列得全"不是一回事）：

| # | 组件 | 是否最小必需 | 依据 |
|---|---|---|---|
| 1 | **对象定义**（显示名 + Code） | 必需 | `04_数据模型.md §对象的组成` |
| 2 | **≥1 个字段**（且含系统字段：ID/名称/编号/状态/创建者/创建日期…） | 必需 | `04_数据模型.md §核心系统字段` |
| 3 | **编号规则** | 需要业务编号时必需 | `03_平台架构.md §数据模型`；`04_数据模型.md §核心系统字段`（文档编号"可自动生成"） |
| 4 | **权限设置**（权限集挂到角色；必要时共享规则） | 必需（否则用户看不到对象菜单） | `05_权限体系概述.md §组合效果`：无功能权限 = 完全无法访问 |
| 5 | **菜单挂载** | 必需（否则用户进不去） | `02_核心概念.md §对象分类` 隐含；`03_平台架构.md §菜单（Menu/Tab Collection）` |
| 6 | **表单布局**（详情页读写） | 必需（无布局则字段无处呈现） | `03_平台架构.md §布局与界面` |
| 7 | **列表布局 + 至少一个视图** | 必需（列表页是默认工作页） | `10_对象列表视图.md §概述`「打开对象菜单后，系统通常先显示对象列表视图」 |
| 8 | **生命周期 + 状态** | 有状态流转时必需 | `04_数据模型.md §对象的组成` |
| 9 | **工作流 + 参与人/步骤** | 有审批时必需；自动触发要挂到状态入口动作 | `06_生命周期与工作流.md §启动方式` |
| 10 | **对象类型 / 子类型** | 同类数据要分型时必需 | `04_数据模型.md §对象类型` |
| 11 | **关系字段**（父对象 / 对象引用 / 文档引用） | 需要关联时 | `04_数据模型.md §对象关系、§文档引用字段` |
| 12 | **电子签名开关** | 关键质量决策时必需 | `06_生命周期与工作流.md §电子签名` |
| 13 | **模板**（文档模板 / 报表 / 通知） | 按需 | 见 §1.6「模板」三条 |
| 14 | **验证规则 / 公式** | 按需 | `03_平台架构.md §验证与规则` |

📌 **一句话口径**：**"对象 + 字段 + 权限集 + 菜单 + 表单布局 + 列表布局/视图"是硬最小集；生命周期/工作流/关系/类型/编号规则是"业务需要时"的增量。**
📌 **蓝图应该表达什么**：正好是上面 1、2、3、6、7、8、9、10、11、12 这十项**配置态**的东西——**不含记录，也不含第 4 项权限集**（权限在手册里是独立的权限与安全域，见 `03_平台架构.md §权限与安全`）。

## 3. 用户在界面上的典型操作路径

### 3.1 主路径：管理员配置 → 普通用户使用

**（A）管理员/配置人员侧（手册给的顺序是自下而上）**
1. 进 **管理端 → 配置管理**（`03_平台架构.md §访问路径`）。
2. **数据模型层**：建对象 → 建字段 → （对象类型）→ 建关系 → 建**编号规则** → 建**选项集** →建索引（`03_平台架构.md §数据模型`）。
3. **业务逻辑层**：建生命周期（状态 + 转换 + 进入条件/进入动作/用户动作）→ 建工作流（步骤 + 参与人 + 判断规则）→ 配权限规则（权限集、共享规则、字段级安全、动作安全）（`03_平台架构.md §生命周期、§工作流与自动化、§权限与安全`）。
4. **界面呈现层**：建页面/表单布局/列表布局/标签页 → 挂**菜单** → 配视图 → 配仪表盘/报表（`03_平台架构.md §布局与界面、§报表与输出`）。
5. 配置**即时生效**，无需重启或部署（`03_平台架构.md §即时生效`）。
6. 跨环境时导出/导入 **ACP**（`03_平台架构.md §配置迁移`）。
> 对应产品侧：**配置工厂做的就是第 2~4 步的一个子集**（见 §4）。

**（B）业务用户侧**
1. **登录**（用户名/邮箱/手机号 + 密码 [+ 验证码]；多业务单元时先选业务单元；可 LDAP / SSO）（`01_快速入门/01_登录系统.md §登录方式`）。首次登录可能被强制改密。
2. 落 **首页工作台**：待办任务（待办/已完成视图，列表/卡片模式）+ 快捷入口（收藏、最近访问）+ 质量看板（需权限）（`01_快速入门/09_首页工作台.md`）。首页标签在部分租户叫"任务"（`03_首页导航.md §首页概览`）。
3. 通过**顶部应用切换器**选应用模块（DMS/QMS/TMS/ERS…，列表取决于权限），左侧导航随之更新（`04_平台入门教程.md §第三步`）。
4. **列表页定位**：先选**视图** → 再用**筛选器** → 再**表头筛选/排序** → 打开详情（`02_界面介绍.md §使用顺序建议`；`10_对象列表视图.md §查询和定位记录`）。
5. **详情页处理**：先看**状态与生命周期阶段** → 核对关键字段 → 编辑 / 发起流程 / 维护关联（`02_界面介绍.md §进入详情后建议先做的事`）；页内用左侧目录跳区块，可"全部展开/全部折叠"（`02_查看对象记录.md §全部展开/全部折叠`）。
6. **发起工作流**：操作菜单选发起动作 → 选流程 + 填描述/参与人/必填字段 + 到期日 → 【发起】（`07_工作流入门.md §1.1`）。
7. **处理任务**：我的任务/待处理 → 打开任务看上下文 → 选批准/退回/拒绝 + 意见 → 完成（部分动作要**电子签名**：再输账号密码）（`07_工作流入门.md §三`）。
8. 全程写 **审计追踪**（`07_工作流入门.md` 合规说明）。

### 3.2 常见分支（用于把流量对齐到"用户在干什么"）

| 分支 | 触发点 | 手册依据 |
|---|---|---|
| **批量发起工作流** | 列表勾选 ≤50 条 → 【发起工作流】；只显示对全部所选记录都有效的流程 | `07_工作流入门.md §1.2` |

| **暂存箱跨视图收集** | 列表勾选 → 加入暂存箱 → 切视图/搜索继续加 → 统一发起批量操作 | `10_对象列表视图.md §使用暂存箱` |

### 3.3 对齐流量时要注意的"陷阱项"

- **同一动作有多个入口**（例：批量发起工作流在向导第 2 步、表头动作、详情页操作菜单三处都能发起）。看单个请求判断"用户在干什么"会误判。
- **批量入口的可见性由三类配置共同决定**：权限集 + 用户动作配置 + **视图配置**（表头动作要单独配到视图里，相关对象列表**不会自动继承**主列表）（`06_批量操作(表头).md §使用前提、§常见问题`）。
- **列表页的默认落点是"视图"而不是"对象"**——同一对象的不同用户可能落在完全不同的数据集上（`10_对象列表视图.md §使用建议`）。
- **列表偏好按用户自动保存**（列/列宽/行高/冻结/排序/分页/显示模式），因此"同一个 URL 不同人看到不同列"是正常的（`10_对象列表视图.md §列表偏好自动保存`）。

## 4. 与配置工厂的对应与冲突

> 工厂侧代码依据：`workbench/services/egmp/writers/blueprint.py`、`writers/spec.py`、
> `kernel/semantics.py`、`kernel/endpoints.py`、`orchestrate.PIPELINE_STEPS`。
> 本节只做**术语层**对照；接口层不在本笔记范围。

### 4.1 工厂蓝图表达了什么（对照 §2.2 最小集）

`Blueprint` 顶层：`description / objects[] / picklists[] / rules[] / permissions[] / reportTemplates[] / menu`
`ObjectDef`：`name / code / enableLifeCycle / enableSignatures / picklists[] / fields[] / formLayout / listLayout / lifecycle / workflows[]`
引擎 8 步管道：`picklists → object → fields → formLayout → listLayout → lifecycle → workflows → verify`（`orchestrate.py:29`）。

| 手册最小集 | 工厂蓝图 | 判定 |
|---|---|---|
| 对象定义 | `ObjectDef.name/code` | ✅ 对应 |
| 字段（含类型/必填/只读/默认值） | `FieldDef.*` | ✅ 对应 |
| 选项集 | `PicklistDef/OptionDef`（对象级 + 顶层共享） | ✅ 对应 |
| 表单布局 | `FormLayoutDef(sections)` | ✅ 对应 |
| 列表布局 | `ListLayoutDef(columns)` | ⚠️ **只是"列"**，没有"视图（数据范围）"这一层 |
| 生命周期状态 | `LifecycleDef.statuses/renameStatuses` | ⚠️ **只有状态，没有"转换"** |
| 工作流 | `WorkflowDef(steps/participants/rules)` | ⚠️ 步骤词表更窄（见 4.3） |
| 菜单挂载 | `MenuDef(parent/sub)` | ⚠️ 工厂自述"引擎不执行"（`spec.py:382` 注释：`execute_menu` 至今**没有任何调用方**） |
| 权限集 | `permissions[]` | ⚠️ **声明区，引擎不执行**，且结构是 `role + grants[]`（见 4.2） |
| 报表 | `reportTemplates[]` | ⚠️ 声明区，引擎不执行 |
| 编号规则 | **无** | ❌ 蓝图不表达 |
| 对象类型 / 子类型 | **无** | ❌ 蓝图不表达 |
| 对象关系（父子/引用） | 仅**字段级** `referenceObjectCode` | ⚠️ 隐含在字段里，没有独立的关系对象 |
| 共享规则 / 字段级安全 / 动作安全 | **无** | ❌ 蓝图不表达 |
| 状态权限 | **无** | ❌ 蓝图不表达 |
| 验证规则 / 公式 | `rules[]`（声明区）+ `FieldDef.formulaScript` | ⚠️ 一半声明、一半可执行 |
| 文档对象 / 文件字段 | **无**（类型码表里没有"文件"，只有 `附件` dataType=8） | ❌ 蓝图不表达文档对象 |
| 记录（数据） | **无** | ✅ 正确——工厂只造**元数据**，不造记录 |

📌 **一句话**：工厂蓝图 ≈ 手册 §2.2 最小集里"**对象 + 字段 + 选项集 + 两种布局 + 状态 + 工作流**"这六项的可执行子集，另外四项（**权限、报表、规则、菜单**）是**声明区**——`spec.py` 明确要求界面把它们标成"人工配置"，否则"确认框会替引擎做出它做不到的承诺"（`writers/spec.py:373-388`）。

### 4.2 术语层面最刺眼的 5 处「工厂用词 ≠ 平台用词」

| # | 工厂用词 | 平台用词 | 差异性质 |
|---|---|---|---|
| 1 | **`permissions[]`：`role` + `grants[]`**（`spec.py` 注解"角色名 / 授予的能力列表"） | **角色**与**权限集**是**两个实体**，中间是"角色**拥有**权限集"（`05_权限体系概述.md §核心关系`） | **塌了一层**。工厂把"角色拥有权限集 + 权限集含对象/字段/菜单权限"压成一张平表；平台侧"权限集"才是权限的载体。对流量时不要把工厂的 `role` 直接当成平台的角色，也不要指望 `grants` 能映射到某个单一权限集接口。 |
| 2 | **`listLayout`（列表布局）** | **列表布局（列配置）**与**视图（数据范围+筛选+排序+列）**是**两层**（`03_平台架构.md §布局与界面`；`10_对象列表视图.md §对象菜单通常会提供三个标准视图`） | **少一层**。工厂的 `listLayout.columns` 只对得上"列"，对不上"所有的{对象}/待我处理/收藏夹"这类视图。若真机流量里出现视图相关请求，工厂蓝图里**没有任何对应物**。 |
| 3 | **`dataType` 里 `13 = 查找`被并入 `REFERENCE_TYPES`，统一用 `referenceObjectCode`** | 手册的**查找字段**是"从父对象或引用对象**同步**字段值的**只读**字段"（`02_核心概念.md §字段类型`），是**派生值**；`对象`/`父对象`才是可编辑的关联边 | **把"派生字段"和"关联边"混成一类**。工厂的校验规则"dataType 13/15/16/23 必须提供 referenceObjectCode"（`spec.py:122`）在平台语义下要分两说：15/16 是建边，13 是声明一个跟着边走的值。另外手册的字段类型表里**没有"对象多选"**（工厂 dataType 23），这属于**手册未覆盖**，不是矛盾。 |
| 4 | **`工作流自动触发 = bindToStatusCode`（绑定状态 → 生成「提交」按钮）+ `autoEnable`** | 手册明说**自动触发不是独立配置**，而是**生命周期状态的入口动作**（`06_生命周期与工作流.md §启动方式`） | **机制名不同层**。工厂用"工作流绑状态"，平台用"状态挂入口动作"。同一个业务意图（进审批就起流程），在平台配置面上是**状态侧**的配置，不是工作流侧的配置。 |
| 5 | **`reportTemplates[]` = "报表模板"** | 手册有**报表（Report）/ 报表类型（Report Type，数据源）/ 运行报告（Formatted Output，导出模板）**三个概念，**没有"报表模板"** | **造了一个平台没有的词**。`ReportTemplateDef` 还带一个 `source` 字段（`int`）——从字面看更像手册的**报表类型（数据源）**而不是模板。要接平台接口前必须先定死它到底指哪个。 |

### 4.3 其余需要留意的错位（补充，非最刺眼五处）

- **`type: Literal["task", "decision", "action"]`（3 种步骤）vs 手册 8 类步骤 vs kernel `STEP_TYPE_NAMES` 6 种**（开始10/结束20/审批任务30/通知40/判断70/动作90）。
  `[推断]` 工厂的蓝图词表是 kernel 词表的**子集且改了名**（decision↔70 判断、action↔90 动作、task↔30 审批任务），手册的"合并步骤""更新共享设置步骤""通知步骤"在蓝图里没有对等项。手册**明说**「更新字段/变更状态/发送通知」是**动作步骤内的动作类型**——这一条与工厂用 `behaviorType` 建模 `action` 步骤的做法**一致**（`06_生命周期与工作流.md §工作流步骤类型` 注 vs `spec.py:171-172`）。
- **状态编码强制前缀 `status_...__c`**（`CODE_STATUS_RE`）。手册没有编码前缀约定；`[推断]` 这是平台实证约定（`kernel/semantics.py §CODE_PREFIXES` 把 `status_` 映射为"状态"），**不属于手册明说**。
- **系统状态只有 `init_status__c` / `complete_status__c` 两个、且只能用 `renameStatuses` 改名**（`spec.py:335-341`）。手册只说"状态类型 = 初始/稳态/终态"（`06_生命周期与工作流.md §生命周期组件`），**没给编码**。这是工厂侧的平台实证，不要当成手册结论。
- **`ObjectDef.source=3 / status=1 / objectClass=1` 全部写死**（`spec.py:99-101`）。手册的对象分类里 `source=3` 应对应**自定义对象**；`[推断]` 工厂**只能造自定义业务对象，不能造文档对象**（类型码表无"文件"、无子类型/分类）。这与"手册把文档对象当作一等对象"形成能力落差。
- **`附件`（dataType=8）≠ 手册的`文件字段`**。工厂有 `attachmentCount/attachmentSize/attachmentExtension`，对得上手册的**附件**（无版本、无生命周期）；对不上文档对象的**文件字段**（有版本、渲染、水印、全文索引）。**两者不可互替**（`02_核心概念.md §字段类型`；`04_数据模型.md §字段类型 注`）。
- **"检查表/清单"没有平台对应物**。工厂的 `generate_checklist` 产出的是「执行清单」（`writers/blueprint.py:487`），是**工厂侧的过程产物**；平台侧最接近的是审计追踪导出与导入结果日志。别在平台里找"检查表"接口。
- **`picklistCode` 与 `referenceObjectCode` 都是"编码引用"**，而手册谈的是界面行为（下拉、搜索选择），**不谈编码**。二者不冲突，但要注意工厂的校验是**跨对象引用只能给 warning**（`blueprint.py:296-297`「可能已存在于平台」）——这与手册"对象可关联"是配置态事实**不矛盾**，却意味着**蓝图自身不保证引用可解析**。

### 4.4 明确标注为「未核实」的部分

- 工厂 `rules[]`（`DeclarationRuleDef.type` 默认 `"validation"`）与手册的**验证规则（Validation Rule）**是不是同一个东西 —— **未核实**（未读 `04_配置指南/`）。
- 工厂 `MenuDef.sub.parentName`（注解"子菜单指向的**对象**"）与手册菜单模型（`Menu/Tab Collection`）的对应 —— **未核实**（`kernel/semantics.py` 里有 `MENU_ACTION_TYPE = {OBJECT_LINK:1, CONTAINER:3}`，暗示菜单项有两种动作类型，但手册未展开）。
- 工厂 `PermissionDef.grants[]` 的取值域与手册权限集里的"对象权限/字段权限/菜单"三元结构如何映射 —— **未核实**。
- 手册 `03_平台架构.md` 列的"页面（Page）/标签页（Tab）"在工厂蓝图中的对等物 —— **无**，但工厂是否有意省略 —— **未核实**。
