## 1. 配置的搬移与落地

- 三条通道职责互斥：配置包搬**组件配置**，数据迁移搬**对象实例**，配置报告只**读**不写。`07_配置迁移.md §迁移内容分类`、`16_配置报告.md §概述`、`18_数据迁移.md §与相关功能的区别`
- 配置包能搬：对象、字段、生命周期、工作流、界面、权限集（「组件配置」类别）。`07_配置迁移.md §迁移内容分类`
- 配置包**不能搬**：审批矩阵、业务模板、部分报表、业务规则基础数据等「业务配置」→ 走**数据迁移**，迁后需单独核对。`07_配置迁移.md §迁移内容分类`
- 配置包**不能搬**：第三方集成地址、业务流水号、域名、系统信息等「Sphere 参数」→ 各 Sphere 内单独维护，明说「不建议随配置包从低阶 Sphere 覆盖到生产 Sphere」。`07_配置迁移.md §迁移内容分类`
- 「配置种子数据」（角色、用户组、权限集合、翻译工作台、后台作业）当前按**全量迁移**处理，迁后核对目标 Sphere 关键数据。`07_配置迁移.md §迁移内容分类`
- **全量迁移，不支持增量迁移**：目标 Sphere 已有本地差异时，部署前必须先出配置报告判断差异是保留 / 覆盖 / 先合并。`07_配置迁移.md §全量迁移`
- 顺序（手册明说的一条链）：配置 Sphere → 验证 Sphere → UAT Sphere → 生产 Sphere；每跳都「生成配置包 → 导入 → 校验 → 部署 → 测试」。`07_配置迁移.md §配置迁移原则`
- **入站包导入 ≠ 生效**：导入只把包登记进目标 Sphere，必须再走「部署前校验 → 部署」，部署后页面/权限/工作流类变更建议重新登录或刷新。`07_配置迁移.md §导入配置包`、`§执行部署`
- 校验三态：通过 / 警告 / **阻止**；常见阻止项＝目标缺依赖组件、包版本低于当前配置版本、对象或字段依赖不完整、工作流引用的状态或角色不存在。`07_配置迁移.md §部署前校验`
- 版本号规则：4 段数字、每段 0–99999（如 `3.6.1.0`），**新包版本不得低于当前 Sphere 配置版本**；程序版本兼容性由系统设置里的程序版本参与校验。`07_配置迁移.md §版本号规则`、`03_系统设置.md §1.10 配置管理`
- **生产环境禁止访问配置管理模块**，配置变更必须在沙箱/测试环境做完再靠部署包迁到生产。`03_系统设置.md §1.10 配置管理`
- 部署期间系统进入**部署模式**，部分业务端操作受限，需避开业务高峰并提前通知。`07_配置迁移.md §执行部署`
- 部署失败按四类处置：依赖缺失（源侧补齐重生成）、版本不兼容（对齐程序版本）、目标冲突（用配置报告定夺）、无法判断（留包+日志+时间联系支持）。`07_配置迁移.md §部署失败处理`
- 出站包「保存」只创建导出记录、不产文件，必须在详情页点**生成**；生成期间不要重复创建同范围包。`07_配置迁移.md §创建配置包`、`§生成与下载`
- **配置报告不能反向导入**：明说「只导出配置清单，不修改系统配置」，且「不要把报告内容当作可导入模板修改后回传系统」。`16_配置报告.md §概述`、`§内容显示规则`
- 配置报告的「对象数据」选项当前**未实现**（`08_批量导入导出.md §创建配置报告` 标「本次暂不实现」；`16_配置报告.md §创建页字段` 措辞为「当前通常不作为主要范围」）。
- 配置报告任务**创建后不建议编辑**，范围选错只能重建；状态链路 待执行→生成中→打包中→完成/失败/取消，仅失败可重试。`16_配置报告.md §页面操作`、`§任务状态`
- 报告落地形态：纯清单 → `.xlsx`；含文档模板/页面模板/附件 → 与附件一起打 `.zip`。`16_配置报告.md §下载与通知`
- 批量导入导出的**入口不是固定菜单**，由管理员在菜单配置里开放、由权限集授权，不需要系统开关。`08_批量导入导出.md §概述`、`33_导入导出.md §访问与权限`
- 批量极限（明说数字）：导入文件 ≤ 1024 MB、单次导入 ≤ 50000 条、单次导出 ≤ 100000 条。`08_批量导入导出.md §限制说明`
- 三种导入模式的差别是「跳不跳校验」：标准导入**执行**触发器和验证规则；记录迁移模式**跳过**触发器与验证规则；文档迁移模式**保留**原始版本号和编号。`08_批量导入导出.md §标准导入模式`、`§记录迁移模式`、`§文档迁移模式`
- 记录迁移模式跳过的清单更长且带「包括但不限于」：生命周期进入动作/进入条件、对象验证规则、引用约束校验、生命周期状态控制、部分自动编号逻辑。`33_导入导出.md §迁移模式`
- 记录迁移模式**不跳过审计**——所有数据变更仍完整进审计追踪；但导入后必须人工核查关键数据。`08_批量导入导出.md §记录迁移模式`、`§常见问题`
- **无 CLI**：当前版本仅支持管理控制台界面操作，不支持独立命令行工具。`08_批量导入导出.md §常见问题`
- 列表导入的硬边界：动作类型限定为创建、隐藏迁移模式、数据限定在当前业务单元（导入其它业务单元必失败），且必须有对象创建权限 + 关系权限。`08_批量导入导出.md §功能特点`、`§权限控制`
- 生命周期可加进入动作「检查是否存在活跃的导入数据任务」：存在未完成导入任务时抛错回滚到上一状态，必填「关系」+ 提示语（500 字符）。`08_批量导入导出.md §进入动作：检查活跃导入任务`
- 数据迁移的**前置是配置迁移已完成**：目标缺对象、字段或引用关系时，数据包可能导不进去或导进去也用不了。`18_数据迁移.md §与相关功能的区别`、`§常见问题`
- 数据集容量上限（明说）：一个数据集最多 1 主对象 + 9 相关对象；一个出站数据包最多 100 个对象，超限不允许保存。`18_数据迁移.md §数据集`
- 可选对象有排除项：不包含系统对象、对象类型对象和已停用对象。`18_数据迁移.md §添加数据集`
- 标识字段默认 `name__ak`；选「创建」模式时标识字段下拉**不可用**（不在目标找已有记录）。`18_数据迁移.md §标识字段`、`§迁移模式`
- **字段范围决定包内容**：只有已选字段的值才进包；必填字段、标识字段、引用字段必须包含，否则目标侧可能导入失败或无法核对。`18_数据迁移.md §字段范围`
- 数据包生成是异步任务，生成未完成时重复点击不会重复建任务；导入失败可下载失败明细修完再导。`18_数据迁移.md §出站数据包详情`、`§入站数据包详情`
- 跨业务单元豁免只给「系统管理员角色」或内置 `admin` 账号，且**只作用于数据迁移包**；默认推荐「按原业务单元归属导入」，允许多对一（需确认）、**不允许一对多**。`18_数据迁移.md §适用身份`、`§导入`
- 作业与迁移的交集只有一句：**配置迁移后重新生成排期**，是计划作业产生新实例的五种场景之一。`12_作业管理.md §计划作业`（`[推断]` 即后台作业确随配置迁移落地，与 `07_配置迁移.md` 把「后台作业」列进配置种子数据全量迁移一致）
- 作业明说的顺序/清理规则：编辑启用中的作业会**自动转为停用**，保存后须手动重新启用才会继续排期。`12_作业管理.md §编辑作业`
- 作业异常与不可逆：同作业上一实例未结束而下一周期已到 → 新实例会生成但结果可能失败；实例连续运行超 24 小时被**强制取消**且作业**置为停用**并通知责任人。`12_作业管理.md §常见异常处理规则`
- 作业删除的边界：删定义会连带删未执行实例，已完成的**历史实例保留**；**标准作业/系统内置作业不允许删除**，也不能创建平台未开放的内置作业类型。`12_作业管理.md §删除作业`、`§系统内置作业`
- 消息作业监控的时效边界：消息记录**保留 6 个月**后自动归档，归档后管理员和用户都看不到。`31_消息作业监控.md §消息记录归档`
- 消息失败重试：系统自动重试 3 次，3 次仍失败列表才出现「重试」；手动重试前需先修渠道/收件人/错误原因。`31_消息作业监控.md §重试发送失败的消息`
- UI 设置是一批按租户生效的开关，无迁移价值也无依赖：行内功能、斑马纹、面包屑、列表行内编辑、操作列、分页位置、列表分组、相关对象详情打开方式、无数据显示方式、表单版本校验、表头筛选、树形列表视图切换器、隐藏保存并继续创建、移动端扫码统一入口、帮助中心图标。`32_UI设置.md §配置项说明`
- 改 UI 开关后页面没变化时的处置顺序（明说）：确认已保存 → 刷新或重新登录 → 检查是否被**对象级配置或权限配置覆盖**。`32_UI设置.md §常见问题`
- 有一条可影响工厂创建行为的开关：勾选「不启用表单版本校验」会**不执行表单版本校验**，手册建议设变更窗口并在完成后恢复标准校验。`32_UI设置.md §配置项说明`

## 2. 报表与运行报告

- **旧报表四层依赖链（明说）**：报表类型（数据基础）→ 报表视图（筛选/分组）→ 报表实例（分组与展示）→ 仪表板（多实例组合）。`19_报表配置.md §数据流转关系`
- 报表类型的数据来源只有两种：**对象** 或 **报表视图**；后者即多表联接。`19_报表配置.md §核心概念`
- 联接的硬约束：**线性方式**（两视图先联成新视图再与右侧联）、**左连接**、联接字段须为两视图**共有**字段。`19_报表配置.md §多表联接`
- 视图能力上限驱动了「多建视图再联接」这一手法：视图仅支持**两个**分组条件，需要更多分组就建多个分组视图再用报表类型联。`19_报表配置.md §配置示例：小组工时统计`
- 报表类型建关系时「仅支持**出站对象**」。`19_报表配置.md §步骤一：创建报表类型（工时对象）`
- 用户侧前置条件写得很直白：管理员未配可用报表类型 → 用户端**没有报表类型可选**。`06_报表/01_创建报表.md §前置条件`、`§常见问题`
- 新报表三件套是**另一套**独立模块，顺序 数据集 → QRS图表（分析图表）→ 仪表盘；「QRS图表」是管理端历史命名，实际是平台级通用分析图表对象。`37_新报表配置.md §2 配置顺序`、`06B_新报表/02_分析图表.md §开篇说明`
- 新报表**单对象内部**建议配置顺序：表单布局 → 页面链接 → 列表布局 → 动作 → 菜单。`37_新报表配置.md §2 配置顺序`
- 跨环境迁移顺序与配置顺序一致：先迁数据集，再迁图表，最后迁仪表盘；手册两次强调「数据集已完成数据迁移以后才能迁图表」「数据集和图表已完成以后才能迁仪表盘」。`37_新报表配置.md §6.2`、`§6.3`
- 新报表走的是**数据迁移包**（出站/入站数据包），不是配置包；每个对象都指定迁移模式「更新与创建」与具体标识字段（数据集/数据流组件/数据流组件字段＝**完整路径**，图表＝**组件路径**，仪表盘＝完整路径，全局筛选器＝**Id**，仪表盘分析图表＝**分析图表完整路径**）。`37_新报表配置.md §6.1–6.3`
- 数据集数据源有开关前置：只有对象配置中开启了「用于 QRS 数据源」的对象，才能作为数据集的分析数据源被选到。`06B_新报表/01_数据集.md §基础功能认识`、`01_对象配置.md §设置`
- 这个开关可反复开关、**不是不可逆项**（与同文件里「启用电子签名」「是否大容量」的不可逆形成对照）。`01_对象配置.md §4.2 不可修改或受限修改的属性`
- 数据集必须**保存 + 启用**，其输出表才能被分析图表引用；保存时会校验流程结构、节点必填项、字段有效性（缺输出节点、节点配置不完整、引用字段失效都会挡）。`06B_新报表/01_数据集.md §数据集启用与更新`
- 统计口径的坑（明说）：分组汇总的**非分组且未汇总字段会被自动剔除**；去重节点**随机保留一条**；数据排序空值升序降序**均排最后**，全空字段保持上游原序。`06B_新报表/01_数据集.md §分组汇总`、`§数据去重`、`§数据排序`
- 数据排序的保存校验是硬的：未配排序字段 → 提示「数据排序节点未配置排序规则」；启用数据截断必须先有排序且 N 为正整数。`06B_新报表/01_数据集.md §数据排序`
- **不可逆项（新报表侧）**：数据集与图表的 `Hyperlink('/web/report2/...?bid=<固定 uuid>&id=...')` 把**环境/应用实例 ID 硬编码**进了公式字段与页面链接，迁到别的环境必然指向别的实例。`37_新报表配置.md §3.3`、`§3.5.1`
- 新报表内容不会自动跟随刷新（明说）：数据集手动刷新后，引用它的**分析图表**会用最新结果，但 QRS 等**报告**以报告保存时的结果为准，需在报告详情页点「更新数据」。`06B_新报表/01_数据集.md §更新数据集`
- 新仪表盘能力边界（明说）：**不支持**在仪表盘内下钻明细，**不支持**导出图片或整板文件；移除组件只解除引用不删图表；改图表后所有引用它的仪表盘同步更新。`06B_新报表/03_仪表盘.md §创建与查看`、`§添加图表组件`
- 分析图表**唯一数据来源**是「已启用」数据集及其输出表；改 X 轴字段若不再是日期类型，已选**时间颗粒度会被清空**。`06B_新报表/02_分析图表.md §相关名词`、`§图表基础设置`
- 图表上的「剔除」是**临时移除**、可随时「恢复」，属于分析态操作而非配置变更。`06B_新报表/02_分析图表.md §图表基础设置`
- 两份「数据集」**同名不同义**，手册专门警告：新报表的数据集＝数据加工流水线；数据迁移的「数据集」＝一组待迁移的对象数据配置。`06B_新报表/01_数据集.md §开篇说明`、`18_数据迁移.md §数据集`
- 两类仪表盘**相互独立**：报表模块的仪表盘组件是「报表实例」、支持导出；新报表模块的仪表盘组件是「分析图表」、不支持整板导出。`06B_新报表/03_仪表盘.md §开篇说明`
- 报表导出可分层级（分组/次级分组/明细）与格式（EXCEL/PDF）；仪表盘导出**只有**文件名称+导出格式，不提供分层级。`06_报表/03_导出数据.md §导出报表`、`§导出仪表盘`
- 导出可见范围＝当前用户可见数据范围，受对象/字段/记录权限共同影响；改完配置**不保存就运行仍用旧配置**。`33_导入导出.md §数据处理说明`、`01_快速入门/08_报表入门.md §四、常见限制与提示`
- 报表结果有**缓存时限**，数据不一致时手动刷新；列太多会触发结果长度限制提示。`01_快速入门/08_报表入门.md §四、常见限制与提示`
- 简报订阅＝报表的定时推送，可配推送时间、时区、是否按角色推送、推送用户、邮件内是否含报表/附件；对应**简报类作业由简报订阅功能自动创建**，管理员不需手工建。`06_报表/01_创建报表.md §订阅简报`、`12_作业管理.md §1 作业的基本概念`
- **运行报告前置（明说）**：已创建目标对象、已明确数据来源对象与字段、已准备 Word 模板、**已为目标对象配置生命周期**。`24_运行报告配置.md §前提条件`
- 运行报告模板的不可逆/受限项：`所属对象`创建后**不可修改**（编辑时也不可改）；模板**在使用时不允许删除**；但删模板**不影响**此前已生成的报告。`24_运行报告配置.md §1.3 创建模板`、`§1.4 编辑与删除`
- 模板文件当前明确支持 `doc`（Word），生成结果是 `PDF`；数据源主对象与所属对象一致，**数据源层级当前支持 3 层**，相关对象报告不受层级限制。`24_运行报告配置.md §1.3`、`§2.2 数据源范围`
- 运行报告数据源只有 3 类：**相关对象**（按对象关系取数）、**审批矩阵**（引入审批配置/参与结构）、**查询列表**（按列表布局+对象组织结果集）。`24_运行报告配置.md §数据源支持的类型`
- 一条量级警告：入站关系记录数**建议不超过 500 条**，过多会导致生成耗时过长甚至失败。`24_运行报告配置.md §数据源区域`
- 版本控制是运行报告的可选项，启用后可在动作上放开「允许用户选择模板版本」；未启用或未勾选时按**当前生效版本**生成、不显示版本选择器。`24_运行报告配置.md §1.6 版本控制`、`§4.4 选择模板版本`
- 多语言的翻译链（明说顺序）：字段名先取目标语种名称 → 字段值优先取**已维护翻译值** → 翻译值为空才**调 AI 自动翻译**；模板未启用「支持翻译」时目标语言通常只有「不翻译」。`24_运行报告配置.md §4.5 多语言与语种选择`
- 运行报告的命名不在模板上，而在全局设置：`管理端 > 系统设置 > 常规设置 > 运行报告名称设置`，配「压缩包名称格式」与「运行报告名称格式」。`24_运行报告配置.md §5 运行报告名称设置`、`03_系统设置.md §1.1`
- 下载封装按**最终文件数**分流：只有 1 个文件直接下原文件、不打包；多于 1 个才走 ZIP；站内信/邮件链接同规则。`24_运行报告配置.md §6.3 单文件直下与多文件压缩包`
- 生成是异步的，完成经站内信/邮件通知并附下载链接；失败会发失败通知且错误进程序异常日志。`24_运行报告配置.md §6.4 通知方式`、`§7 常见规则`
- 静默失败点（对我们重要）：**模板变量填错不返回错误信息，对应位置显示空白**；对象为空返回空白；字段值为空返回 `N/A`。`24_运行报告配置.md §7 常见规则`
- 批量打印运行报告只支持**同一对象列表内**、不支持跨对象混合打印，且**移动端不提供该入口**。`24_运行报告配置.md §6.7 批量打印运行报告`
- 运行报告可挂三种入口：生命周期用户动作「下载运行报告」（仅配置的状态可见）、对象动作（全状态共享）、进入/用户动作「运行报告生成到附件字段」。`24_运行报告配置.md §4 配置下载运行报告动作`
- 水印是动作级开关但样式受系统约束：`显示水印` 决定该次生成是否叠加水印，内容与样式仍受系统附件水印/水印设置约束。`24_运行报告配置.md §4.6 显示水印`
- `07_配置迁移.md` 把「部分报表」归入**业务配置**（走数据迁移、迁后单独核对），而运行报告模板出现在 `08_批量导入导出.md §创建配置报告` 的「文档模板」勾选项里 —— 即报表类东西的搬移路径**不统一**，`[推断]` 报表定义偏数据迁移、模板/附件类随配置报告与配置包走。

## 3. 平台自身的 Agent 配置

- Agent 配置在管理端 **AI 配置** 中维护（AI Agent / 上下文 / 任务 / 工具相关菜单）。`Agent 配置指南.md §1.1 配置入口与层级`
- 挂载层级（明说）：业务对象（可再按**对象类型**细分）→ Agent 助手 → Agent 级上下文 → 任务 Action → 本任务上下文 / 本任务工具。`Agent 配置指南.md §1.1`
- 运行时定位方式：用户在某条业务记录详情页打开 AI 助手时，系统按**当前对象（及对象类型）**找候选 Agent，再进入对话。`Agent 配置指南.md §1.1`
- 第一条铁律是**文案二分**：描述类（Agent/Action/Context/Tool 描述）＝选型文案，回答「该不该选我」；目标/指令＝执行文案，回答「选中后怎么做」。`Agent 配置指南.md §2.1`
- 第二条铁律：**可见 ≠ 已加载**。「始终包含=是」只让该上下文一直出现在可用工具里，**没调用过就不会有真实字段值**进助手规则。`Agent 配置指南.md §2.2`
- 选型只在**会话开始看用户首句**时发生；同一会话中途改口（查询→起草）通常**不会**自动换 Agent，必须新开对话。`Agent 配置指南.md §3.1`
- 想靠改「目标」纠正选错助手是**无效**的，应改各 Agent 的**描述**对比度。`Agent 配置指南.md §3.1`、`§9 配完不对？先看这张表`
- 单/多候选改变字段作用：单候选时目标**每轮都写入**助手规则；多候选时目标不参与选型、描述参与。`Agent 配置指南.md §3.1`
- Action 数量同样改变用途：多个 Action 时描述进「可选任务」列表（展示为 `编码：描述`）；只有 1 个 Action 时描述**不进**列表（仅当备注），指令直接写入。`Agent 配置指南.md §3.2`
- 写入助手规则的固定顺序：目标 → 系统核心约束 → 补充目标 → 任务/工具说明 → 已加载的上下文数据 → 可用工具 → 输出规范。`Agent 配置指南.md §4 ②写入助手规则`
- **系统已有两类通用规则，配置侧不要重复写**：核心约束（禁止臆造数值/日期/人员/编号等）与输出规范（Markdown、对比用表格、注明来源）。`Agent 配置指南.md §5 系统已有内容：配置时不要重复写`
- 补充目标**默认留空**，只在短期试点/分期上线这类临时边界时才填。`Agent 配置指南.md §6.1`
- Tool 的**输入参数是硬的、输出参数是软的**：输入参数用于拼调用；输出参数（响应结构）只是形态说明，**系统不会按它强制校验**真实返回。`Agent 配置指南.md §6.4 工具（Tool）`
- 一条护栏：同一会话内模型可切换任务，但**受系统次数护栏限制**。`Agent 配置指南.md §3.2`
- 平台 Agent 的能力范围（明说）：智能问答、操作指引、内容辅助；`03_系统设置.md` 另有一处独立的「助手设置」（法规查询、操作指引）。两者是系统设置里的两个开关，与 AI 配置里逐对象配的 Agent 不是同一层。`03_系统设置.md §1.25 AI设置`、`§1.27 助手设置`
- **与「配置」的交集**：Agent 的挂载点是「业务对象 / 对象类型」，所以对象与对象类型属于配置包迁移的组件配置，是 Agent 的**上游依赖**；`[推断]` Agent 定义本身是否随配置包迁移，手册在本文与 `07_配置迁移.md` 中**均未说明**。
- `[推断]` Agent 配置本质是**人工文案工作**（描述对比度、指令步骤、边界措辞），无形状可推导；我们的配置工厂无法从蓝图生成它，能做的只是保证「对象 / 对象类型 / 菜单 / 权限集」这些上游组件存在且可被引用。
- `[推断]` Agent 的失败形态与工厂不同类：工厂失败＝调用报错，Agent 失败＝**静默选错人 / 静默编数据**，只能靠 2～3 条真实用户问法走查验收。`Agent 配置指南.md §8 配置检查清单`
- 手册给了行动口径：若实际产品行为与文档不符（如「始终包含」、单/多任务写入时机有变化），**以最新产品行为为准**并向平台反馈。`Agent 配置指南.md §10 行为与文档不一致时`

## 4. 签名/签署类配置

- 三类签署配置的**入口层级完全不同**，这是最容易配错的地方：契约锁关键词＝用户/业务单元维度字段；契约锁固定签署位＝**平台级策略 + 工作流节点**；文件签批手写签名＝**流程节点 + 移动端菜单 + 系统签名设置**。`34_契约锁签署配置（关键词签署位）.md §配置入口总览`、`35_契约锁签署配置（固定签署位）.md §3 平台级配置`、`36_文件签批手写电子签名配置.md §1.3 访问路径`

### 4.1 契约锁签署（关键词签署位）

- 前置四件：已具备契约锁侧联通能力（账号、接口、回调等）、已完成目标对象生命周期配置基础能力、**已确认签署文件模板中存在可命中的关键词文本**、当前操作者具备对象动作执行权限与数据访问权限。`34_…关键词签署位.md §前置条件`
- 关键词是**配置集之外**的配置：签署关键词 / 签署日期关键词在「配置端 > 用户管理 > 用户详情」逐用户维护（非必填、非多值）。`34_…关键词签署位.md §配置入口总览`、`§1 用户维度字段`
- 组织侧关键词同理：质量授权人、盖章关键词在「配置端 > 组织管理 > 业务单元详情」维护（非必填、非多值）。`34_…关键词签署位.md §2 业务单元维度字段`
- 发起前校验清单只有三条：用户签署关键词不为空、质量授权人不为空、盖章关键词不为空。`34_…关键词签署位.md §发起前校验清单`
- 动作执行逻辑（明说三步）：校验配置与数据完整性 → 执行关键词定位 → 发起契约锁流程。`34_…关键词签署位.md §1 发起契约锁签署`
- 生命周期侧的配置建议：仅在「资料已定稿/允许外发签署」状态开放动作，用**状态权限**控制可见性与可执行性，动作失败时阻断流程并返回明确错误。`34_…关键词签署位.md §1 发起契约锁签署`
- 必须成对配置 `契约锁查看`，且建议与 `发起契约锁签署` **同一可见角色范围**，否则会出现「可发起不可查看」的权限断层。`34_…关键词签署位.md §2 契约锁查看（签署进度）`
- 文档对象字段侧的对齐约束：`签署人` 应与用户关键词配置保持一致、`签署组织` 应与业务单元配置保持一致（建议字段，非强制）。`34_…关键词签署位.md §文件对象字段配置`
- `[推断]` 这类配置的不可逆项不在 Gaia 侧而在**文件内容侧**：关键词命中依赖模板文本存在，改了模板文字就等于改了签署位；手册只把它列为前置条件、未给校验手段。

### 4.2 契约锁签署（固定签署位）

- 前置：已获得契约锁服务地址与鉴权参数（`AppToken`、`AppSecret`）、已明确签署流程名称与签名时间展示策略、业务方已确认哪些文档类型启用契约锁签署。`35_…固定签署位.md §2 前提条件`
- 平台级策略五参数：服务地址、AppToken、AppSecret、流程名称、是否显示签名时间。`35_…固定签署位.md §3.1 数字签名策略`、`03_系统设置.md §9.1 第三方签名平台集成`
- AppSecret 是**凭据类配置**：手册要求妥善保管、避免泄露、建议定期更换。`03_系统设置.md §9.2 配置说明`
- 触发点在**工作流任务节点**：在「审批意见」中启用「数字签名」，用户完成任务并选择对应审批意见时触发**静默签署**。`35_…固定签署位.md §4.1`
- 三项合规性约束都配在工作流上：任务节点启用**不可代理**（保证签署人＝审批人）、工作流启用**发起后禁止变更参与人**（禁用添加参与人/重新指派/移交任务/取消任务）、文档工作流增加**预生成签批表**节点。`35_…固定签署位.md §4.2`、`§4.3`、`§4.4`
- 「强制终止电子签约（可选）」有三个**配置位**：审批不同意后的动作节点、取消工作流动作、生命周期状态进入动作。`35_…固定签署位.md §4.5 强制终止电子签约（可选）`
- 适用范围靠一个字段分流：新增布尔字段「是否启用契约锁签署」，再用字段值绑定对应工作流，实现按文档类型/场景启用。`35_…固定签署位.md §5 文档字段与适用范围配置`
- **签署人侧是外部前置**，管理员在用户信息将「是否启用数字签名」设为「是」，签署人须在个人中心完成：实名认证 → 设置数字签名 → 启用静默签署。`35_…固定签署位.md §6 签署人侧准备`
- 未完成实名认证或未设置签名时，系统提示后**跳转到设置页面**（不是静默失败）。`35_…固定签署位.md §7.2 签署任务完成`
- 签署完成后第三方流程会把**签署完成文档回传**并保存为可视格式副本。`35_…固定签署位.md §7.3 回传签署文档`
- 异常表把「不可逆」点明了一处：流程中止但第三方流程仍在进行 → 必须配「强制终止电子签约」；参与人被改动导致合规风险 → 必须启用「发起后禁止变更参与人」。`35_…固定签署位.md §8 常见异常与处理`
- 验收清单 6 条可直接当回归项：策略参数可保存并生效、任务节点可触发静默签署、不可代理与禁止变更参与人生效、预生成签批表可生成并合并、强制终止在取消/拒绝/状态变更场景生效、签署完成后文件可回传。`35_…固定签署位.md §9 验证清单`

### 4.3 文件签批手写电子签名

- 前置四件：**已启用平台电子签名基础能力**、文件签批对象或受控文档对象已配置审批流程、审批角色已具备签批动作权限、移动端已完成菜单与登录策略配置（如需移动端签批）。`36_文件签批手写电子签名配置.md §2 前提条件`
- 该前置指向一份**仓库里没有的文件** `14_电子签名配置.md`（`04_配置指南` 目录内不存在 14 号文件）——这是本轮阅读范围里唯一被引用却缺失的依赖，`[推断]` 手写签批的上游配置在本手册内无法自证。
- **能力边界（合规关键，明说）**：手写签名与签署文字属**签批展示内容**，主要用于「文件签批」流程，**不替代标准电子签名合规记录**，仍需配合电子签名记录满足审计需求。`36_…手写电子签名配置.md §1.2 能力边界`、`§5 权限与安全控制`
- 签批内容二选一：手写签名（需用户先维护签名，识别度高）/ 签署文字（输入灵活，建议限长避免覆盖版面）。`36_…手写电子签名配置.md §3.1 签批内容类型选择`
- 签署文字的参数基线：是否必填＝是、最大长度＝1000、允许编辑位置＝是、允许缩放＝是。`36_…手写电子签名配置.md §4.2 配置签署文字输入规则`
- 退回重签是一条**必须显式配置**的链路：启用「重新转档后可重新签署」、确保退回后节点仍保留签批入口、验证重签内容能覆盖新一轮审批结果。`36_…手写电子签名配置.md §4.3 配置流程退回后的重签策略`、`§7 Q3`
- 移动端是独立配置面：在我的菜单启用「手写签名」入口、支持查看/修改签名、文件签署页展示「在线签署」按钮。`36_…手写电子签名配置.md §4.4 配置移动端签批能力`
- 手写签名样式入口在全局设置：`系统设置 > 常规设置 > 签名设置`；GxP/高审计场景建议开启「签名人 + 签名时间 + 签名含义」。`36_…手写电子签名配置.md §4.5 配置手写签名样式`
- 移动端三条提示逻辑可当验收用例：非当前用户签署位置提示无权限、当前用户未设签名提示先去设置、未做任何签批动作直接提交提示先添加签名或文字。`36_…手写电子签名配置.md §4.4`、`§7 Q2`
- `[推断]` 三类签署的**共同不可逆点**是「已发出的签署单据与已完成的签署动作」：手册给的都是事前配置位（状态权限、动作可见性、参与人冻结、强制终止），没有一处描述如何撤销已完成的签署；因此签署类配置只适合在低阶 Sphere 配好、验完再随配置包上生产。
