## 1. 工作流结构语义

### 1.1 节点类型全集（一行一类）

- **开始**：系统自动生成，**每个工作流有且仅有一个**，可编辑但**不可删除**。`05 §1.2 NOTE`
- **结束**：系统自动生成，同样有且仅有一个、可编辑不可删除。`05 §1.2 NOTE`
- **工作流任务**：需要用户执行的步骤（评估、调查、审核）。`05 §1.2`
- **判断**：根据条件进行分支。`05 §1.2`
- **合并**：汇聚多个分支到同一路径。`05 §1.2`
- **动作**：由系统自动执行的动作。`05 §1.2`
- **更新共享设置**：向共享设置中的角色添加或移除参与者。`05 §1.2`
- **通知**：发送消息通知。`05 §1.2`
- **可手动添加的只有后 6 类**，开始/结束不可手动添加。`05 §1.2 NOTE`
- 节点一词在工作流组成表里与"路径/参与者/变量"并列，节点本身不含流程控制语义。`05 §1.1`

### 1.2 节点连接与顺序规则

- 每个节点都有"下一个/下一步"字段（步骤列表里是一列），动作节点的下一步**可配置一个或多个候选节点**。`05 §工作流步骤` `05D §1.1`
- **判断节点按规则列表从上到下依次匹配，命中第一条即进入该分支**，不再看后面的规则。`05C §1.3`
- 判断节点建议同时配置**默认分支**，供所有规则都未命中时继续执行，避免流程中断。`05C §1.3`
- 判断规则内部由条件组构成（并且/或者、条件组加减、条件顺序），**与生命周期中的逻辑条件配置方式一致**。`05C §1.2`
- 合并节点的用法是把两条或多条路径汇聚到同一路径，典型例：判断的不同分支在审批通过/拒绝后都要发通知，先合并再统一进通知步骤。`05E`
- 开始节点**未配置任何控件**时，流程发起后直接进入后续节点，不停留在发起页。`05A §开始设置`
- 步骤列表可维护字段：名称 / Code / 类型 / 描述 / 下一个 / 操作。`05 §工作流步骤`
- `[推断]` 手册**没有**给步数上限、环检测、连线必填、孤立节点检测这类结构约束；工厂侧 `backfill_connections` 在 `nextStepCode` 解析不到已建步骤时是**静默跳过**（不计入 `connections`）。`writers\workflows.py:185-210`

### 1.3 启用与停用（版本机制）

- 新建保存后处于**未启用**：不能被动作选中，也不能在业务端发起和使用。`05 §2.1 创建页字段表` `§2.2 版本与状态 1`
- 点 **启用** 后当前版本成为正式生效版本，满足条件的新流程按该版本运行。`05 §2.2 版本与状态 2`
- 已启用要调整**不能原地改**：必须点 **编辑** 升版，新版本状态变 `编辑中`，**旧版本仍保持原有启用状态**。`05 §2.2 版本与状态 3`
- **旧实例不随版本切换**：旧版本已有未关闭的流程实例继续按旧版本执行，不会因后续编辑自动切换到新版本。`05 §2.2 版本与状态 4`
- 只有编辑中的新版本再次点 **启用** 后，后续新发起的流程才使用新版本。`05 §2.2 版本与状态 5`
- 版本列表三态：`编辑中`（草稿）/ `启用`（业务端生效）/ `禁用`（历史版本，保留追溯）。`05 §2.3`
- `禁用` 的成因被明说是"新版本启用后，旧启用版本转为历史版本"——即版本只增不改。`05 §2.3`
- 详情页字段里 `状态` 的取值写作"例如 编辑中、启用、未启用"，`版本`字段记录当前流程定义版本号。`05 §详情区域字段`
- `[推断]` 手册未给"停用/下架一个已启用工作流"的路径（只有列表页出现"未启用"这一显示值），也未给删除入口；工厂侧端点表里有 `WORKFLOW_DELETE` / `WORKFLOW_CHANGE_STATUS` / `WORKFLOW_UPDATE`，但**只有 ChangeStatus 有调用方**。`kernel\endpoints.py:60-62`

### 1.4 绑定到状态或事件的方式

- **启动方式只有两种**：手动启动（配置位置 = `生命周期 > 用户动作`）、自动启动（配置位置 = `生命周期 > 进入动作/事件动作`）。`05 §4.1`
- 手动启动的可发起范围由生命周期 **用户动作** 权限按角色控制：执行=允许发起 / 查看=按钮可见但不可点 / 隐藏=按钮不可见。`05 §4.3`
- 权限判断逻辑：未启用 DAC 时按生命周期用户动作权限过滤；启用 DAC 时还会叠加共享设置角色权限。`05 §4.3`
- **自动启动 5 个必要条件**（需同时满足）：① 勾选"允许从进入动作和事件动作自动启动"；② 勾选"对单个对象记录使用工作流"；③ 开始节点参与者控件使用系统可自动解析的模式；④ 开始节点不依赖必须由发起人手工填写的控件；⑤ 不要求"工作流发起人"作为必选参与者。`05 §4.2`
- **启动状态**字段：标识该工作流可在哪个生命周期状态下启动；**不设置则不受指定状态限制**，设置了才只有该状态可发起。`05 §2.1 创建页字段表` `§2.2 详情区域字段`
- **生命周期**字段（必填）决定工作流的绑定范围，"仅满足该生命周期条件的记录可发起流程"。`05 §列表页说明` `§2.1`
- 工作流类型创建时二选一、页面只读：**对象工作流**（除文件对象外全部对象）/ **文档工作流**（仅文件对象）。`05 §2.1` `§2.2`
- **表单布局**为可选绑定：配置后发起人与参与人在流程中看到的表单展示方式以该布局为准，并能结合该布局中的表单规则控制字段显示、可编辑范围与交互。`05 §2.1` `§2.2`
- 开始节点控件里放"变量"控件 + 工作流详情页 `变量` 区域，是运行时参数进入流程的通道；变量可用在判断节点条件与通知内容、动作参数。`05 §2.1 步骤 6` `§变量`
- 取消动作挂在工作流层（不绑状态），由"规则 + 动作"两列构成，`暂无数据`时表示只执行系统默认取消行为。`05 §取消动作` `§2.2 取消动作配置页`
- `[推断]` 工厂的 `bindToStatusCode` 与手册的"启动状态"**不是同一个概念**：手册的启动状态是"可在哪个状态发起"，工厂实现是"在该状态上生成一个提交按钮"（`writers\lifecycle.py:92-138` 写 UserAction/Create），对应的是 §4.1 的**手动启动**入口。

## 2. 各节点类型的关键配置项

### 2.1 开始节点 `05A`

- 页面三区块：`详情` / `开始设置` / `开始步骤规则`。`05A §页面结构`
- 可添加控件 **6 类**：说明、参与者、日期、字段、变量、电子签名。`05A §可添加的控件类型`
- 参与者添加方式 **5 种**：工作流发起人选择参与者 / 使用角色作为参与者 / 使用自定义动作定义参与者 / 使用字段作为参与者 / **使用审批矩阵作为参与者**。`05A §参与者添加方式`
- 参与者控件配置项 **12 项**：控件类型、Code、参与者名称、添加参与者、允许参与的角色、不允许参与的角色、选择角色后再选用户、支持按用户组选参与人、排除工作流发起人、业务单元字段、列表布局、过滤条件。`05A §参与者控件常见配置项`
- 开始步骤规则：`执行方式`（总是执行 / 有条件地执行）+ `动作类型`（显示 / 隐藏）+ `操作名称`（目标控件）+ 添加动作；一条规则可同时控制多个控件。`05A §新建规则常见配置项`
- 规则条件**基于当前对象字段**；批量工作流下按记录集合整体判断——所选记录**全部命中**才生效，任一未命中即不生效。`05A §开始步骤规则`
- 开始节点没控件就不停在发起页（见 §1.2），所以"控件为空"本身是一种配置决策。`05A §开始设置`

### 2.2 工作流任务节点 `05B`

- 常规设置 **17 项**：任务名称、将任务分配给（工作流发起人 | 参与者组）、任务类型（并行|串行）、任务分配模式（系统指派|任务领取）、任务说明、任务要求（必须|可选）、不允许工作流发起人接收此任务、在不查看详情的情况下完成任务、不需要手动完成（仅提醒）、不允许移交任务、不允许代理、完成按钮显示名称、关联记录打开模式、显示有关以前任务的信息、到期日期、预警日期、更新对象日期字段时更新活动任务的截止时间。`05B §1.1`
- **到期日期 6 种来源**：工作流开始日期 / 任务创建日期 / 日期控件 / 对象字段 / **到期策略** / **公式**。`05B §1.1`
- **预警日期只 2 种**：任务到期前 / 公式。`05B §1.1`
- 参与者组在**开始节点**中定义（将任务分配给"参与者组"时的来源）。`05B §1.1`
- 会签/或签：手册用的是"任务类型 并行/串行"+"任务分配模式 系统指派/任务领取"两组字段，另在常见模式表出现"会签审批（多人同时审批，全部通过）""或签审批（多人中任一通过即可）"。`05B §1.1` `05 §6.2`
- `[推断]` 工厂的 `dispatchMode`（10=会签 / 20=或签）在手册里**没有可直接对应的二值选项**；最接近的语义锚点是"并行指派（全部参与人须完成）"与"或签（任一通过）"。
- **审批矩阵**只作为"参与者的一种来源"出现，没有独立的节点级配置面；批量发起时校验所选记录的审批矩阵规则是否一致。`05A §参与者添加方式` `05H §7.5`
- 指派方式：并行指派（默认，一次为所有参与人生成任务）/ 串行指派（按参与人选择顺序逐个生成，上一人完成才生成下一人）。`05B §1.6`
- 串行指派约束：参与人选择顺序即分配顺序；添加参与人时**不能选择前面节点已选过的用户**。`05B §1.6`
- **串行提前结束条件**：条件类型=任一断言包含于、逻辑值=任务上设置的审批意见（必填）；`所有断言等于`/`没有断言等于`→不满足则不再生成并**进入判断节点 else 分支**；`至少一个断言等于`→命中即停止生成并进入下一节点。`05B §1.6`
- 取消任务**不影响**串行指派逻辑；重新指派**不影响**指派顺序。`05B §1.6 NOTE`
- 提示用户填写 **4 个开关**：要求填写任务备注（可命名、可设必填）、要求填写字段（逐个配必填）、需要电子签名（可配是否必须填用户名、是否启用数字身份认证）、要求用户填写审批意见（可命名、可开启"展示为按钮"）。`05B §1.3`
- 审批意见项逐条可控 **7 项**：取消带指定标签的任务 / 要求填写字段 / 允许填写备注（含名称与必填）/ 电子签名与签名备注 / 允许添加附件（含数量·大小·格式限制）/ 填写签名含义（含名称·可选值·必填）/ 选择职位。`05B §1.3`
- **任务提醒 3 模式**：不提醒 / 使用提醒策略 / 自定义提醒。`05B §1.4`
- 自定义提醒每条 = 通知模板（必填）+ 收件人（必填）+ 发送日期（任务创建日期 / 任务到期日期 / 到期日期控件 / 公式）。`05B §1.4`
- 节点内 **`更新共享设置`**（与 `05F` 的独立节点不是一回事）= 对象（当前对象|相关对象）+ 事件（任务指派 / 任务完成 / 任务取消 / 任务重新指派 / 任务移交 / 任务领取 / 撤销领取 / 任务代理）+ 动作（添加|删除）+ 角色，四者全必填，可加多条规则。`05B §1.2`
- 到期/提醒可用**全局策略**：`业务逻辑 > 工作流设置` 维护"工作流任务到期日期策略"与"工作流提醒策略"，节点选"到期策略"/"使用提醒策略"即继承。`05B §1.4`
- 通知区：可设通知模板 + 收件人（常见"任务所有者"），勾"包括以前任务的审批意见和注释"后可选择以前的任务一并发送。`05B §1.4`
- 外部协作区：可设签名人信息来源（示例 `人员(person__ak)`）。`05B §1.4`
- 全局界面参数（`管理端 > 系统设置 > 常规设置 > 工作流`）**13 项**，影响业务端展示而不改流程定义本身，例如：审批意见显示为下拉选择、工作流任务操作按钮尺寸（适中|较大）、在详情页显示责任人、通过按钮展示任务、生成任务时立即替换变量、催办时间间隔等。`05B §工作流设置：界面与交互选项`

### 2.3 判断节点 `05C`

- **条件类型 3 类**：字段（来源 = **当前对象字段** 或 **出站对象字段**）、流程任务断言、流程变量。`05C §条件类型`
- 流程任务断言比较方式 **3 种**：所有断言等于 / 至少一个断言等于 / 没有断言等于。`05C §流程任务断言配置`
- 用流程任务断言前，须先确认对应任务节点**已配置断言项**。`05C §使用建议`
- 复杂场景通过**条件组**组合多个条件类型；逻辑条件（并且/或者、条件组加减、条件顺序）与生命周期一致。`05C §条件类型`
- 文档工作流的判断条件类型写作"任务、字段、变量、**状态**"（比对象工作流多一个"状态"）。`05I §8.2`
- 从上到下依次匹配、命中第一条即进入该分支；建议配默认分支。`05C §1.3`

### 2.4 动作节点 `05D` —— 动作类型尽量枚举全

- 执行方式 **2 种**：总是执行 / 有条件地执行。`05D §执行方式`
- 动作条目配置项：动作类型、状态（动作类型=`修改状态`时指定目标生命周期状态）、当前对象字段、值（如固定值、指定为空）、添加动作、删除动作；**同一节点多个动作条目按配置顺序依次执行**。`05D §动作条目配置项`
- 下一步"**可配置一个或多个候选节点**"。`05D §1.1`
- 配置示例（两条动作顺序执行）：`动作类型=修改状态, 状态=暂时关闭` → `动作类型=修改记录字段, 当前对象字段=DW, 值=指定为空`。`05D §1.3`

**动作类型全集 = 30 项，分 3 组** `05D §1.4.1`~`§1.4.3`

| 组 | 动作类型 |
|---|---|
| 基础记录动作（16） | 修改附件字段 / 修改相关对象附件字段 / 修改状态 / 设置字段为空 / 创建相关对象记录 / 根据相关对象创建记录 / 修改状态为工作流启动时状态 / 修改相关对象记录 / 修改相关对象生命周期状态（废弃） / 修改相关对象生命周期状态 / 修改记录字段 / 修改记录字段(多字段) / 修改相关对象记录字段（废弃） / 修改相关对象记录字段 / 修改相关对象记录字段（多字段）(废弃) / 修改相关对象记录字段（多字段） `05D §1.4.1` |
| 批量与辅助（7） | 批量修改相关对象生命周期状态 / 批量修改相关对象记录字段 / 批量生成相关对象编号 / 文件打印替换最新版本 / 检查是否存在活跃的导入数据任务 / 使电子签名记录作废 / 移除任务电子签名记录 `05D §1.4.2` |
| 模块专用（7） | [DMS]文件委托 / [DMS]计算培训完成率 / [DMS]批量计算平衡表 / [DMS]批量生成下载附件 / [TMS]发布测验 / [TMS]执行影响决策 / [TMS]角色的学员生成至直接分配请求-学员 `05D §1.4.3` |

- 名称带 **`废弃`** 的 3 项：旧能力仍可见，**仅用于兼容历史流程**，新建/改造时应替换为非废弃对应项。`05D §1.4.1` `§1.5`
- 带 **`[DMS]` / `[TMS]` 模块前缀**的动作：只在对应模块已启用且当前租户具备能力时**才出现在下拉框**，不属于所有工作流都会看到的通用动作。`05D §1.4.3`
- 多记录工作流下动作节点额外有"**自动移除匹配的项**"（执行过程中移除不满足条件的记录）能力。`05H §7.2 动作节点配置`

### 2.5 通知节点 `05G` / 更新共享设置节点 `05F` / 合并节点 `05E`

- 通知节点每条通知 = **消息模板（必填）+ 收件人（必填）**；可"添加通知"多条，可逐条删除；保存前须确认两项均已选，避免执行时漏发。`05G §1.3`
- 更新共享设置节点每条规则 = **工作流参与者组（必填）+ 动作（添加|删除，必填）+ 角色（必填）**；可"添加规则"多条。`05F`
- 该节点与任务节点内的"更新共享设置"**明确不是一回事**：前者是独立步骤节点，后者是任务内基于事件触发的共享更新规则。`05F §说明`
- 合并节点：手册全文只有 2 句语义（汇聚两条或多条路径到同一路径），**没有任何配置项、字段、规则**。`05E`

### 2.6 取消动作（工作流级）`05 §2.2 取消动作配置页`

- 控件：执行方式（总是执行 / 有条件地执行）、动作类型、添加动作、删除图标。
- 常见动作类型 **3 种**：发送通知 / 修改记录字段 / 修改记录字段（多字段）。`05 §常见动作类型`
- 默认取消行为（无需配置即生效）：取消未完成任务、通知相关参与者、将流程上下文恢复到取消前状态。`05 §4.4`

### 2.7 两类工作流的差异

- 文档工作流特点：生命周期 = 单个文档生命周期或所有文档生命周期；**创建草稿时保持在当前版本**；**签批表显示电子签名**；所有文档生命周期支持通过**状态类型**控制流程。`05I §8.1`
- 对比表：开始节点字段控件——文档工作流支持当前文档的文档类型下所有字段，对象工作流支持当前对象所有字段（**排除 lookup**）；任务分配模式——文档工作流**无**（默认系统指派），对象工作流有系统指派/任务领取。`05I §8.2`
- 多记录工作流：生命周期 = 单个对象生命周期或所有文档生命周期；启动状态**取交集**（所有记录同时满足才可选）；任务分配模式**仅系统指派（默认）**；审批意见支持"每个记录一个"或"所有记录共用一个"；**自动创建信封对象记录**。`05H §7.1`
- 多记录开始节点：**字段控件不支持多对象工作流**（多文档工作流支持基础文档字段或文档类型字段）；变量控件支持文本、选项、布尔、附件；参与人控件仅支持"工作流发起人选择参与者"与"使用角色作为参与者"；**支持审批矩阵控件**。`05H §7.2`
- 多记录批量发起上限：手册写"一次建议不超过系统上限，常见为 **50～100 条**，以当前环境提示为准"。`05H §通用操作步骤 1`
- 多记录任务处理：被移除的记录不再参与后续任务，**已完成的任务不受影响**；移除可恢复（**仅限本人在当前任务节点移除的项**）。`05H §7.4`

## 3. 公式配置（工厂**完全未验证**的能力面）

### 3.1 定位与作用域

- 公式字段**只读**，用户不能手工编辑；值由表达式**实时计算**。`06 §1` `§1.3`
- **每个对象最多可配置 10 个公式字段**；公式字段**不用于**对象搜索字段索引配置。`06 §1.3`
- 公式是平台内的**通用能力**，同一套语法与编辑器在 **8 类场景**复用：公式字段、验证规则、设置字段默认值、字段图标/字体样式、**工作流动作**、自动计算日期、条件分支计算、图标与字体展示、文本拼接与格式化。`06 §1.2`
- 公式字段创建 4 步：字段类型选 `公式` → **选择返回类型** → 编辑器写表达式并执行 **`语法检查`** → 保存。`06 §2`
- 访问路径：`配置环境 > 配置管理 > 对象管理 > 对象 > {目标对象} > 字段 > 创建/编辑`。`06 §1.1`

### 3.2 返回类型（`returnType` 的语义依据——只到这里为止）

- 手册给的返回类型清单原文是"**文本、数字、日期、日期时间、布尔等**"——**没有穷举**，"等"之后手册未列。`06 §2 步骤 3`
- 由函数返回类型反推，平台至少还存在这些返回类型：**长文本**（`Concat`/`Lower`/`Upper`/`Trim`）、**选项**（`Case` 的 result 可为选项）、**图标**（`Icon`）、**字体样式**（`Font`）、**链接**（`Hyperlink`）、**对象实例**（`RecordByLabel`）。`06 §4.3` `§4.4` `§4.6`
- `If()` 的返回类型栏写作"文本、数字、日期/日期时间、布尔、长文本"。`06 §4.3`
- `Case()` 的返回类型写作"与 `result` 类型一致"，而 `result` 可为"文本、数字、日期/日期时间、布尔、长文本、**选项**"（比 `If` 多一项）。`06 §4.3`
- **存在按入参决定返回类型的函数**：`DateAdd()` 的返回类型 = "**与 `date` 类型一致**"（传日期得日期、传日期时间得日期时间）。`06 §4.1`
- `[推断]` `returnType` 在工厂侧是 `int`，而手册**完全不给码值、不给枚举表**——码值只能来自平台读侧 schema 或界面真实请求体，**不能从手册推**。
- `[推断]` 手册也没有写"返回类型与目标字段类型必须一致"的硬规则，只在配置建议里把类型匹配写成人的责任（见 §3.6）。

### 3.3 函数库大类（6 类，手册逐函数给了用法/描述/参数类型/返回类型/示例）

- **时间函数（15）**：`Year` `Month` `Day` `Hour` `Minute` `Second` `Now` `Today` `Date` `DateTime` `StartOfDay` `DateAdd` `DateDiff` `CalcWorkDay` `IsWorkday`。`06 §4.1`
  - 其中 `CalcWorkDay(DateTime, NumOfDay[, Calendar])` 剔除所有节假日、`NumOfDay` 可为负；`IsWorkday(DateTime[, Calendar])` 返回布尔，不传日历则用系统默认工作日历。`06 §4.1`
  - `StartOfDay(Date, Format, TimeZone)`：`Format` 取 `minute/mi` 或 `second/ss`，`TimeZone` 取 `system` 或 `user`。`06 §4.1`
  - `DateAdd`/`DateDiff` 的 `format` 取值：`year/yy`、`quarter/qq`、`month/mm`、`day/dd`、`week/wk`、`hour/hh`、`minute/mi`、`second/ss`；`DateDiff` 要求两端类型一致。`06 §4.1`
- **数学函数（8）**：`Abs` `Average` `Ceiling` `Floor` `Max` `Min` `Round` `Sum`。`06 §4.2`
- **逻辑函数（7）**：`And` `Or` `Not` `If` `Case` `Includes` `IsBlank`。`06 §4.3`
  - `Includes(field,value)` 对多选字段判包含、对单选字段判匹配；选项字段的 `value` 填**选项 code**。`06 §4.3`
  - `Case(expression,case1,result1,…,else_result)` 的 `expression` 限"数字或选项字段"，`case` 限"数字或选项 code"。`06 §4.3`
- **文本函数（11）**：`Concat` `Length` `Lower` `Upper` `Trim` `Hyperlink` `Left` `Right` `Mid` `Icon` `Font`。`06 §4.4`
  - `Concat` 参数可为文本/长文本/数字（数字隐式转文本），**超过 1500 字符时保留前 1500 位**。`06 §4.4`
  - `Left`/`Right` 的 `num` 为负数时从对侧裁剪。`06 §4.4`
  - `Hyperlink(href,label[,target])` 的 `target` 取 `_blank` 或 `_self`（默认 `_self`）。`06 §4.4`
  - `Icon(name,color[,width][,text])`：`width` 为 12~100、默认 12，**图标库由系统维护**。`06 §4.4`
  - `Font(Color[,Weight])`：`Weight` 取 `normal` / `bold` / `bolder`。`06 §4.4`
- **转换函数（2）**：`Num(value)`（文本/文本字段/选项字段→数字，**转换失败返回 `null`**）、`Text(Value)`（数字/数字字段/选项字段/**对象/父对象字段**→文本）。`06 §4.5`
- **对象函数（2）**：`RecordByLabel(Label)`（返回**对象实例**）、`RelatedRecordTextConcat(RelatedObjectCode,FieldCode,Separator)`（按**相关对象的关系编码 + 字段编码**取值并用分隔符拼接，返回长文本）。`06 §4.6`
- 函数名**不区分大小写**。`06 §4`

### 3.4 公式能引用什么

- **当前记录字段**：直接按字段 code 写 `field_code__c`。`06 §3.2`
- **常量**：文本 `"文本"` 或 `'文本'`；数字 `100`/`3.14`；布尔 `true`/`false`（**不区分大小写**）。`06 §3.2`
- **选项常量**：`{!$picklist.pickcode.[opcode1,opcode2]}` —— 返回选项字段的一个或多个选项值。`06 §3.2`
- **系统变量**（经变量面板插入）：当前用户、当前用户 Id、当前用户姓名、当前用户登录账号、**当前用户所属部门**、**当前公司**。`06 §3.2`
- 编辑器有 **7 个面板**：编辑区 / 语法检查 / **字段面板**（插入当前对象可用字段）/ 变量面板 / 函数面板（按分类插入函数模板）/ 运算符面板 / 图标面板。`06 §3.1`
- **跨对象引用**：手册的字段面板措辞是"插入**当前对象**可用字段"，**没有**给通用的跨对象字段遍历语法。`06 §3.1`
- 跨对象读有两条**明确**的路：① `Text(对象/父对象字段)` 直接解引用到该记录的 `name__ak`——手册示例 `Text(对象)` → `"张三"`，对象为空 → `"空值"`；② `RelatedRecordTextConcat(关系编码, 字段编码, 分隔符)` 取**相关对象**记录字段并拼接。`06 §4.5` `§4.6`
- **父子关系**的表达：靠"对象/父对象字段"（`Text()` 的参数类型明写"对象/父对象字段"）与"相关对象的关系编码"（`RelatedRecordTextConcat` 的第一个参数）。`06 §4.5` `§4.6`
- 工作流动作场景的示例里出现过 `today__c`（系统日期字段）与 `current_due_date__c`。`06 §1.2` `§6.1`
- `[推断]` **没有多级遍历（`a.b.c`）的任何证据**；能确认的跨对象深度是"一层引用解引用到 `name__ak`"与"一层关系取任意字段"。
- `[推断]` 手册未提及全局变量/流程变量是否可在公式中引用（流程变量只在判断节点与通知/动作参数里被点名）。`06 §1.2` 全文检索无

### 3.5 运算符与运行期异常语义（工厂建模必读）

- 运算符四类：数学 `+ - * / % ()`；比较 `= != > >= < <=`（**相等是单等号**，不是 `==`）；逻辑 `&&` `||`；文本拼接 `&`。`06 §5.1`
- **除数为 0（`/`）→ 返回 0，不报错**；**取余分母为 0（`%`）→ 返回 0，不报错**。`06 §5.2`
- **数字溢出 → 按系统可计算范围截断处理**。`06 §5.2`
- **文本长度超过 1500 → 自动保留前 1500 个字符**（`Concat` 同口径）。`06 §5.2` `§4.4`
- **计算过程出现 NULL → 返回 NULL**。`06 §5.2`
- `Num(value)` 转换失败返回 `null`。`06 §4.5`
- 配置建议：日期计算统一用 `DateAdd()`/`DateDiff()`，**避免直接对日期做加减**。`06 §7`
- 条件分支多时优先 `Case()` 而非多层嵌套 `If()`（可读性）。`06 §7`
- `[推断]` 手册**未涉及**批量/多记录场景下公式如何计算。

### 3.6 保存时平台会校验什么

- 手册中**唯一显式**的公式校验是编辑器的 **`语法检查`**——"校验表达式语法是否可执行"。`06 §3.1` `§2 步骤 4`
- 手册**没有**写保存时校验：返回类型与字段类型是否匹配、引用的字段是否存在、权限、循环引用、公式长度/复杂度上限。`06 §2` `§7` 全文检索无
- 反而把类型匹配写成**人的责任**："先确认目标字段返回类型，再编写公式，避免类型不匹配"；"公式保存前先执行 `语法检查`，再使用典型数据做结果验证"。`06 §7`
- `[推断]` 类型不匹配在手册口径下**不是保存期硬门禁**；`[推断]` 公式没有自定义函数、复用、注释能力（检索不到相关条文）。
- **工厂侧现状（代码事实，非手册）**：`dataType=14` 时 `returnType` / `formulaScript` **原样透传**（值可为 `None` 也照发），`validate_blueprint` 的字段校验分支里**完全没有 `dataType==14` 的分支**——即两个键既不校验也不补默认。`writers\fields.py:80-82` `writers\blueprint.py:276-301`

### 3.7 公式与工作流/其他配置的接口

## 4. 不可逆与强制项

### 4.1 工作流结构层

- **开始步骤与结束步骤不可删除**，只能编辑；每个工作流**有且仅有一个**。`05 §1.2 NOTE`
- **未启用**状态下工作流不能被动作选中、不能在业务端发起和使用。`05 §2.1` `§2.2`
- 已启用工作流**不能原地修改**：必须 **编辑 → 升版**，新版本进 `编辑中`，**旧版本保持启用**。`05 §2.2 版本与状态 3`
- **旧实例不跟随新版本**：旧版本已有未关闭实例继续按旧版本执行。`05 §2.2 版本与状态 4`
- 🔴 **节点删除"仅在可编辑版本中可用"**（任务节点与动作节点的页面操作都这么写）——启用版本里的节点**删不掉**，必须先升版。`05B §页面右上角` `05D §页面右上角`
- `未启用` 与 `编辑中` 都**不能直接用于发起流程**；只有 `启用` 版本被业务端实际使用。`05 §2.2 详情区域字段` `§2.3`
- `禁用` = 历史版本，保留用于追溯，不再作为当前生效版本。`05 §2.3`
- 工作流 Code 手册只给"建议长期保持稳定""建议使用稳定、可读的英文或缩写"，**不给字符正则**。`05 §列表页说明` `§2.1`
- 🔴 **文档工作流「创建草稿时保持在当前版本」：仅在工作流未启用时可修改；工作流启用后不可再更改（不能反复打开和关闭）**。`05I §8.3`
- 同名选项勾选/未勾选的行为差异是**语义反转**的：勾选 → 文档升版后活跃工作流关联的文档自动变成最新版本；未勾选 → 停留发起时的版本。`05I §8.3`
- 取消动作的**系统默认行为不可关闭**：取消未完成任务 / 通知相关参与者 / 将流程上下文恢复到取消前状态；额外行为靠追加配置。`05 §4.4`
- 系统设置开启「取消工作流时输入电子签名」后，业务端取消会先弹签名框，**签名通过后才执行取消动作**。`05 §4.4`
- 带 **`废弃`** 标记的动作类型仍可见但仅用于兼容历史配置，不建议新建使用，改造时应逐步替换。`05D §1.4.1` `§1.5`
- 模块专用动作（`[DMS]`/`[TMS]`）**依赖模块能力**，不是所有租户都会看到。`05D §1.4.3`
- 动作节点与取消动作的条件化只有"总是执行 / 有条件地执行"两档。`05D §执行方式` `05 §取消动作配置页`
- **文档工作流「签批表显示电子签名」的作用域**：写在审批意见**内**只对该条审批意见生效；写在审批意见**外**表示所有审批意见都需电子签名。`05I §8.3`
- 多记录工作流：任务分配模式**仅系统指派**（无任务领取）；启动状态**取所有记录交集**；批量发起基于审批矩阵时**规则必须一致**，否则直接提示"所选记录的审批矩阵规则条件不相同，无法发起此工作流"。`05H §7.1` `§7.5`
- 审批矩阵成员写入实例是**完全覆盖**（不是合并）。`05H §7.5`
- 多记录任务中被移除的记录不再参与后续任务，**已完成任务不受影响**；移除可恢复，但**仅限本人在当前任务节点移除的项**。`05H §7.4`

### 4.2 自动化簇（22 / 22A / 26 / 27 / 28 / 29 / 33）

- **联动规则的结构性字段保存后不可改**：对象 / 相关对象 / 联动字段 / 联动对象（`26 §2.3` 说"保存后不可修改"，`§3.2` 说编辑页保持只读）；`Code` 在编辑页只读。`26 §2.3` `§3.2`
- 联动规则删除后规则不再可用；若用户**先手工加了相关对象记录、后设联动字段并保存**，系统按规则**重建**联动结果，**已有手工记录可能被替换**。`26 §1` `§8.3`
- 启用联动规则的相关对象部分**通常按只读策略展示**，避免手工编辑与自动联动冲突。`26 §5.3`

- 创建相关记录：**单个配置最多 30 条字段映射**；不支持附件、公式、查找、统计等字段类型映射；选项字段仅支持单选映射。`27 §4.1` `§4.2`
- 创建相关记录映射冲突规则：多个源字段映射到同一目标字段时**以第一条有效映射为准**；映射值**覆盖**目标字段自身默认值。`27 §4.4`
- 创建相关记录的系统字段处理是**固定**的：状态用目标对象初始状态、记录状态默认启用、更新时间=创建时间、更新人=创建人、创建人无映射时取源记录创建人。`27 §6`
- **Web 动作**：`Code` **不可编辑**；删除前做依赖校验，**已被生命周期用户动作引用则阻断删除并提示引用位置**。`28 §4.2` `§5`
- 页面链接：**`对象 + 页面模式` 联合唯一**，冲突提示"此对象的XX模式已存在"；**标准内置页面链接不可删除**，只能改名称与描述；`复制`模式当前为**预留能力、暂未开放**。`29 §2.2 保存校验规则` `§4` `§概述 NOTE`
- 页面链接字段长度是硬约束：名称 1-200、Code 1-200、描述 0-500、URL 1-2000。`29 §2 关键字段说明`
- **对象动作**：`动作`/`名称`/`Code` 必填；`Code` 建议上线前一次性确定（改名会牵动权限、流程、自动化引用）；`状态` 停用后**动作实例保留**但不再作为可执行入口。`22 §2.2` `§2.3`
- 对象动作**不绑定到某一个生命周期状态**（如"下载运行报告"在**所有**生命周期状态下均可执行）。`22 §概述` `§2.4`
- 对象动作的执行权限是**系统级上下文**：即使用户对目标对象没有显式创建权限，只要被授予该动作的执行权限，**仍可能通过该动作完成数据创建或更新**。`22 §4`
- 匿名创建二维码：`Code` 必填且**在当前对象范围内唯一**；关系切换后若原布局不在新范围内，**系统会清空已选布局**；匿名创建的记录**创建人恒为 `系统 system`**（不记录扫码人账号）。`22A §3.1` `§2.3` `§3.3`
- 记录动作的三种实例类型权限面不同：无实例动作（权限集）/ 单实例动作（权限集 + 生命周期/状态安全）/ 多实例动作（批量操作权限 + 动态动作计算）。`33 §2`
