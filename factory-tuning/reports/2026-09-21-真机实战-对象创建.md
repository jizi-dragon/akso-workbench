## 2. 工厂实际发出的请求（抓包自 `client.post`，不是读代码推断）

`POST /api/platform/BasicObject/SaveBasicObject`，**8 个键**：

```json
{"name": "测试09-03", "code": "test_0903__c", "source": 3, "status": 1,
 "objectClass": 1, "enableLifeCycle": true, "enableSignatures": false,
 "summaryFields": []}
```

`SaveBasicObject` 的响应是 `{code:0, data:true, ...}` —— **不回 id**。
本次的 `objectId` 是**回读**来的（`created_id` → `_refetch_object`），
返回值 `id=id-fd4376ea`。

> **这是 `docs/PITFALLS.md` #62 修复后的第一次真机验证。**
> 修复前 `data:true` 这个布尔会被当成 id，`objectId` 会变成字符串 `"True"`。

## 4. 本次实战判定掉的两个悬而未决问题

### D2′：工厂比界面"多发"的键 —— **不需要改**

平台对象记录的读回证明：**「整键不发」与「显式发 `false`」在平台侧等价**。

| | 界面发出的 | 平台存下的 |
|---|---|---|
| 测试09-01（两个开关都开） | `enableLifeCycle:true, enableSignatures:true` | `true / true` |
| 测试09-02（两个开关都关） | **两个键都不发** | **`false / false`** |
| 测试09-03（本次，工厂发） | `enableLifeCycle:true, enableSignatures:false` | `true / false` |

也就是说：平台的缺省就是 `false`，所以"工厂发显式 `false`"与"界面省略"落到的终态**完全相同**。
这是一处**形状差异，不是结果差异**。

同理，`isRequired` 是**平台真实存在的字段**（读回记录 93 个键里有它，22/22、12/12、13/13 全带），
工厂发它是正确的。

### D5′：工厂"少发"的键 —— **不需要改**

**`objectRelation` 不是"要发的键"，是平台自己生成的。**
界面给两个引用字段只发了 `{"controlField": null}` 和 `{}`（近乎空），
平台却把整条关系记录填全了——`id` / `name` / `code` / `objectId` / `objectCode` /
`type` / `referenceObjectId` / `referenceFieldCode` / `delRule` / `sort` …（20+ 个键）。

**真正决定关系的是 `referenceObjectId`，而工厂是发的。** 所以不补 `objectRelation` 无害。

**`__observed` 不是平台字段**：三个对象的字段读回里出现 **0 次**（0/22、0/12、0/13）。
它是界面自己的东西（每字段一个唯一 GUID，与任何 id 都不相交）。不发它是安全的。

### 顺带更正一条"看起来像缺陷"的东西

平台字段记录里有 **93 个键**，但其中**没有 `statisticsArrange`、也没有 `disabled`**
（出现 0 次）——而**界面和工厂都在发这两个键**。
它们是**写了但平台不存**的键。这不是工厂的缺陷（界面同样发），但值得记一笔：
**别拿这两个键去判断"平台发了什么"**。

## 5. 已知限制（本次没做成的部分）

1. **蓝图路径表达不出"裸对象"**：`ObjectDef.fields` 是 `min_length=1`，
   所以 `/api/factory/run` 那条路**必须至少带 1 个字段**。
   本次为了做出与 09-01/09-02 同形的裸对象，走的是写入口 `create_object`，
   **没有经过蓝图/orchestrate 的 8 步管道**。要端到端验那条路，得接受多 1 个字段。
2. **监视器录不到本次执行**：Monitor 绑在浏览器页面上（`page.on(...)`），
   而工厂走 Python httpx。**这两条通道互不可见**——所以本文的请求体是**包 `client.post` 抓的**，
   不是 Monitor 录的。想让 Monitor 录到工厂，需要另接一层。
3. **`isRequired` 疑似有第二条写入路径**：`test_fa__c` 平台上是 `isRequired: true`，
   但采集到的它那条 `SaveField` 请求里**根本没有 `isRequired` 这个键**。
   说明"必填"多半是由**另一个请求**设置的，而那个请求被 Monitor 丢掉了
   （该场采集 130 条里 **110 条被 DROP**）。
   **推论**：工厂目前只在 `SaveField` 里发 `isRequired`，**能不能真的建出"必填"字段，未验证。**
