# 模块契约

> 本文件是 Akso Workbench 的模块间契约定稿。任何模块接入都必须遵守。

## 1. Router 规范

- 每个领域一个 `api/routes_*.py`，导出 `router = APIRouter(prefix="/api/...", tags=[...])`。
- **数据校验（pydantic 约定）**：
  - 请求体必须声明 pydantic BaseModel（FastAPI 自动校验，非法入参自动 422），禁止裸 `dict` 收参；
  - 响应：新代码必须声明 `response_model`（含嵌套结构）；存量路由渐进补齐，改动即补；
  - 服务层入参若来自不可信源（文件/外部命令输出），在服务层边界再过一次 pydantic 校验。
- 响应统一 JSON；长任务（子进程/浏览器）用 SSE（`text/event-stream`）回传日志流。
- 错误返回 `{"detail": "<人话>"}`；HTTP 状态码：400 参数、404 不存在、409 冲突、502 子进程失败。
- 新路由必须在 `api/__init__.py::create_app()` 注册。

## 2. 子进程描述 schema（services/proc.py）

```python
@dataclass
class ProcSpec:
    argv: list[str]            # 完整命令行（argv[0] 为可执行文件）
    cwd: str | None = None     # 工作目录（默认适配器 repoPath）
    env: dict[str, str] | None = None   # 追加环境变量
    timeout_s: float = 1800    # 超时（秒），超时杀进程
    on_log: Callable[[str], None] | None = None  # 行级日志回调（SSE 用）
```

`ProcResult`：`code`（退出码）、`duration_s`、`stdout_tail`、`stderr_tail`、`timed_out`。
约定：stdout/stderr 逐行解码（utf-8，容错 replace）；超时/启动失败抛 `ProcError`（附诊断：可执行文件是否存在、cwd 是否存在）。

## 3. adapters/*.json 格式

```jsonc
{
  "id": "akso-cc",                 // 模块唯一 id
  "title": "...",                  // 展示名
  "repoPath": "D:\\...",           // 原仓库绝对路径（只读）
  "repoPathEnv": "AKSO_CC_REPO",   // 环境变量覆盖名
  "entry": "dist/main.js",         // 入口（相对 repoPath）
  "runtime": "node",
  "nodeVersion": ">=18",
  "commands": { "<name>": { "args": [...], "description": "...", "artifacts": "..." } }
}
```

- 适配器是**只读引用声明**：绝不复制原项目代码，绝不写原仓库。
- `repoPath` 解析顺序：环境变量 > JSON 值；不存在时模块标记 `missing`。

## 4. 模块注册表（services/modules.py）

- 模块 id：`workbench`（自身）、`akso-cc`、`akso-auto`、`quick-login(知识已迁)`。
- `GET /api/modules` 返回每个模块：`status ∈ {ok, degraded, missing}`、依赖体检项（Node 可用性、入口存在性、repoPath 存在性、Python 依赖、Playwright 浏览器）。
- `POST /api/modules/{id}/check` 触发即时复检。

## 5. 前端页接入规范

- 页面文件：`static/pages/<name>.html`（由 `index.html` 的 Tab 导航 iframe/跳转接入）。
- 资源：`static/js/<name>.js` + `static/css/<name>.css`，复用 `tokens/base/app` 设计系统。
- JS 与后端交互统一走 `static/js/api.js` 封装；SSE 用 `EventSource`。

## 6. 统一账号库契约

- 表（DB 迁移 7）：`platform_env(id, name, base_url, note)`；`account(id, env_id, username, password_enc, role, tags, created_at, updated_at)`。
- `password_enc` = Fernet(密钥存 settings 表，seed 机制沿用 mogul)。明文只在内存与内联参数中出现，绝不入库、绝不写原项目 env 文件。
- 导出给子进程的 env 文件写到工作区临时目录（如 `resources/env/workbench.json`），任务结束后立即删除。

## 7. 托管浏览器契约

- 一账号 = 一个 Playwright BrowserContext（原生隔离；DNR/Cookie 袋/命名空间隔离**不迁**）。
- 自动登录引擎注入节奏：齐备门槛 → 提交前回读 → MutationObserver 即时填充 → 用户点击接管 → 失败让位。
- token 捕获：`context.on("response")` 拦截；捕获结果随账号状态回传前端。

## 8. Agent 层契约（阶段 3）

- 工具名与 mogul harness 一致风格：`login_platform` / `read_config` / `write_config` / `search_knowledge` / `run_insight` / `run_factory`。
- 所有工具调用记入 `agent_audit` 审计表；写路径必须先经蓝图校验。
