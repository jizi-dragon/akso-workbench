## 1. 系统定位与总体架构

Akso Workbench 是**四项目融合**的本地工作台：

```
                    ┌─────────────────────────────────────────────────┐
                    │                Akso Workbench                    │
                    │        (Python 3.12+ / FastAPI / SQLite)         │
                    │                                                  │
  ┌───────────┐     │  ┌────────────┐  ┌────────────┐  ┌───────────┐  │
  │ 浏览器 UI  │◄────┼──┤ 静态前端    │  │ REST/SSE   │  │ pywebview │  │
  │ (用户)     │     │  │ static/    │◄─┤ api/       │  │ 桌面壳     │  │
  └───────────┘     │  └────────────┘  └─────┬──────┘  └─────┬─────┘  │
                    │                        │               │        │
                    │  ┌─────────────────────▼───────────────▼─────┐  │
                    │  │              services/ 服务层              │  │
                    │  │  fork 存量(mogul) + 聚合层 + 账号/浏览器    │  │
                    │  └───┬──────────┬──────────┬─────────┬───────┘  │
                    └──────┼──────────┼──────────┼─────────┼──────────┘
                           │          │          │         │
                    ┌──────▼───┐ ┌────▼─────┐ ┌──▼──────┐ ┌▼────────────┐
                    │ SQLite   │ │ Node 子  │ │ Playwright│ │ DeepSeek/  │
                    │ mogul.db │ │ 进程     │ │ chromium │ │ 千问 Embed │
                    │ (兼容接管)│ │ (封装)   │ │ (托管池) │ │ (HTTP API) │
                    └──────────┘ └────┬─────┘ └─────────┘ └─────────────┘
                                      │ 只读引用（adapters/*.json 声明路径，
                                      │  绝不写入）
                        ┌─────────────┴──────────────┐
                        │ D:\ai_assistant\akso-cc    │  平台配置洞察（冻结）
                        │ D:\ai_assistant\akso-auto  │  配置自动化（冻结）
                        └────────────────────────────┘
```

**四条设计底线**（改代码前必读）：

1. **四原项目冻结**：akso-cc / akso-auto / quick-login / mogul_simulator 只读。跨边界只有两种合法通道——adapters JSON 声明 + Node 子进程调用；统一账号库读原 env 文件导入（只读）。
2. **fork 边界**：`workbench/` 内 fork 自 mogul 的文件（见 §3 标注「fork」）改动最小化；新建模块不往 fork 文件里塞逻辑，fork 文件只做「接线」（注册路由、追加迁移）。
3. **凭证只进内存**：明文密码的生命周期 = 从 Fernet 解密到注入子进程参数/浏览器表单为止。不入库、不落盘、不进日志。
4. **DB 只进不退**：schema 变更一律追加 `MIGRATIONS` 新版本号，永不修改历史迁移（兼容旧 mogul.db 的 `_sqlx_migrations` 机制）。

## 2. 技术栈与依赖关系

| 层 | 技术 | 用途 | 关键约束 |
|---|---|---|---|
| 运行时 | Python ≥3.12 + uv（uv.lock 锁定） | 唯一包管理入口 | 依赖变更走 `uv lock && uv sync` |
| Web 框架 | FastAPI + uvicorn[standard] | REST + SSE + 静态托管 | 入参必须 pydantic BaseModel |
| 数据校验 | pydantic v2 | 请求体/服务层边界 | 响应模型渐进补齐（契约 §1） |
| 存储 | SQLite（WAL，单连接+线程锁） | 全部业务数据 | 迁移机制兼容旧 Tauri/sqlx 库 |
| 子进程 | subprocess + Node ≥18 | 封装 akso-cc/akso-auto | stdin 管道喂 confirmEnv |
| 浏览器 | Playwright(Python) chromium | 托管会话 + 自动登录 | 一账号一 context |
| 加密 | cryptography(Fernet) | 账号密码加密 | 密钥存 settings 表 |
| LLM | DeepSeek API + 千问 Embedding | 对话 + 向量检索 | Key 存本机 SQLite |
| 桌面壳 | pywebview（可选） | 窗口化 | 缺失自动降级浏览器模式 |
| 质量 | pytest 33 项 + ruff (E4/E7/E9/F/I/B) | 门禁 | 提交前全绿 |

## 4. 数据流与关键机制

### 4.1 一次「对象理解报告」的完整链路

```
浏览器 insight.html
  → POST /api/insight/run-sse {command:understand, account_id, objects}
    → routes_insight._build_argv
        ├─ accounts.get_account     （env_base_url + username）
        ├─ accounts.reveal_password （Fernet 解密，仅内存）
        └─ [node, dist/main.js, understand, --objects=…, --url=…, --user=…, --pass=…, --output=<runtime/insight/<job>/understand>]
    → proc.run_proc（cwd=akso-cc 仓库，stdout/stderr 逐行 → SSE 帧）
    → 结束帧 {status, workdir} → 前端 GET /api/insight/artifacts/{job} 列产物
    → GET /api/insight/artifacts/{job}/file?name=… 预览 md / 下载 drawio
```

### 4.2 一次「一键登录」的完整链路

```
浏览器 browser.html
  → POST /api/browser/open {account_id}
    → browser_pool.open_account
        ├─ accounts.get_account / reveal_password
        ├─ chromium.new_context()          ← 一账号一 context（原生隔离）
        ├─ TokenCapture.attach(context)    ← context.on("response") 抓 Bearer JWT
        ├─ autologin.install(page)         ← add_init_script 注入 MAIN world 引擎
        ├─ URL 决策：有 token 快照 → baseUrl；否则 → baseUrl + /login
        └─ autologin.start(page, u, p)     ← 启动五重门控状态机
    → 前端 2s 轮询 GET /api/browser/sessions/{id}
        （引擎状态聚合进 snapshot：phase/attempts/errors/reason；success → status=online）
```

## 5. 测试手册（怎么测）

### 5.1 三层测试策略

```
第 1 层  纯单测（秒级，无外部依赖）     test_proc / test_accounts / 部分 test_app
第 2 层  机器验收（本地模拟外部系统）   test_autologin（模拟 antd 平台）/ test_encapsulation（argv 构建）
第 3 层  真机验收（真实 eGMP 测试环境） 手动：akso-cc login / orchestrate / browser open
```

### 5.2 常用命令

```powershell
uv run pytest                          # 全套（33 项，约 1-2 分钟，含 chromium 用例）
uv run pytest tests/test_autologin.py -v   # 只跑自动登录 9 断言

uvx ruff check .                           # lint 门禁（提交前必过）

```

### 5.4 真机验收 SOP（只对测试环境账号执行）

1. 确认 `tools/setup.ps1` 全绿；
2. `POST /api/accounts/import/preview` → `/api/accounts/import`（或 CLI 干跑 `tools/import_accounts.py --dry-run`）；
3. 顺序：insight `login` → factory `orchestrate`（离线）→ browser `open`（看自动登录到「我的待办-首页」）；
4. **禁止**对生产环境跑 factory `create`（真实写配置）；`create` 只允许出现在明确声明测试环境的会话。

## 6. 维护手册（怎么维护）

### 6.1 常见排障速查

| 症状 | 先查 | 处方 |
|---|---|---|
| insight/factory 503「原仓库不存在/入口缺失」 | `tools/setup.ps1` 适配器行 | 原仓库挪位 → 设 `AKSO_CC_REPO`/`AKSO_AUTO_REPO` 环境变量；入口缺失 → 原仓库内 `npm run build`（akso-cc） |
| 洞察命令非零退出但看不出原因 | 任务 `proc.log`（runtime/insight/<job>/） | akso-cc 顶层异常 exit 1；understand/spider 单对象失败不阻断（exit 0），看末行「N/M 个对象成功」 |
| factory 卡住无输出 | confirmEnv stdin 约定 | 确认走的是 routes_factory（已喂 `\n\n`）；自写驱动脚本时必须管道喂换行 |
| 自动登录失败 | sessions 接口的 `autologin.reason` | user_*：用户接管（正常）；deadline：页面太慢/选择器失配；attempts_limit：连点 4 次被拒——先查账号密码；errors_limit：服务端连续 401——查凭据/验证码 |
| browser 503「chromium 启动失败」 | `playwright install chromium` | 环境迁移后必做；CI 里加 `--with-deps`（Linux） |
| 账号解密失败 AccountError | settings 表 `account_fernet_key` | 密钥随库走；换库需重新导入账号（密钥丢了凭据不可恢复，这是设计使然） |
| 前端页白屏 / 接口 404 | 路由是否注册 | `test_app::test_routes_registered` 直接指认缺失前缀 |
| uv sync 拉包超时 | 镜像配置 | `[[tool.uv.index]]` 已配清华源；仍超时查本机代理 |
| mogul.db 被接管/未接管 | config.bootstrap_database | 旧 Python 版 `%APPDATA%/MogulWorkbench/mogul.db` 优先；指定 `WORKBENCH_DB` 可完全隔离 |

### 6.2 各模块维护场景与红线

**fork 存量（§3.2）**
- 场景：bugfix、UI 微调 → 直接改，CHANGELOG 记录。
- 红线：不重构、不改公开接口；`harness/` 是阶段 3E 扩展基座，动它需在台账立项。
- DB：fork 表结构冻结（迁移 1-6 不动），新需求一律追加迁移 10+。

**聚合层（§3.3 proc/modules）**
- 场景：新子进程命令 → 只加 adapters JSON + 对应 routes_*，proc.py 不动；
- 红线：proc 的 stdin/超时/日志泵语义已被 insight+factory 共同依赖，改动必须全量回归 test_proc + 两条路由的真机冒烟。

**洞察/工厂（§3.4/3.5）**
- 场景：akso-cc/akso-auto 上游命令参数变化 → 只改 `adapters/*.json` 与 `_build_argv`；上游发现缺陷 → 台账记「上游缺陷」，不改原仓库；
- 红线：凭证注入永远内联（不落盘、不写原项目 env.json）；`confirmed` 守卫不可绕过。

**账号库（§3.6）**
- 场景：加字段 → 迁移 10（ALTER TABLE account ADD …）+ `_sanitize` 白名单同步；
- 红线：任何新接口不得回传 `password_enc`；`reveal_password` 只允许服务层内部调用（自动登录/内联注入），路由层永不暴露。

**托管浏览器（§3.7）**
- 场景：新平台登录页适配 → 优先调引擎选择器常量（`请输入用户名` placeholder、antd 错误类名），参数节奏（30s/4 次/2 次）不动——它们是上游实证值；
- 红线：改引擎 JS 后必跑 test_autologin 9 断言；「不迁清单」（DNR/Cookie 袋/命名空间隔离）不要因"看起来有用"迁回来——context 已原生隔离。

**egmp 内核（§3.9）**
- 场景：触发某 writers/insight 文件 → 按台账流程：立项 → 迁移 → TS 版标维护模式 → CHANGELOG；
- 红线：`UNRESOLVED_ACTION_READ_NOTE`（进入动作无公开读接口）是 6 轮 48+ 路径探测的实证结论，不要盲目重试已证 404 的路由。

**前端（§3.10）**
- 场景：新模块页 → pages/<name>.html + js/<name>.js + 复用 modules.css/modules-common.js + index.html 导航加一项；
- 红线：设计令牌只用 tokens.css 变量；SSE 解析统一走 modules-common.postSSE，不重复造轮子。

### 6.3 新增一个业务模块的标准动作（checklist）

1. 契约：`docs/模块契约.md` 加一节（路由前缀/数据契约/凭证来源）；
2. DB：需要存状态 → `db.py` 追加迁移 N；
3. 服务层：`services/<name>.py`（领域错误类型 + 完整类型注解 + 模块头文档串）；
4. 路由：`api/routes_<name>.py`（请求体 BaseModel；新代码带 response_model）；在 `api/__init__.py` 注册；
5. 前端：`static/pages/<name>.html` + js + index.html 导航；
6. 测试：conftest 风格临时库 → 单测 + （涉及外部系统）机器验收台架；`uvx ruff check .` + `uv run pytest` 全绿；
7. 台账：`docs/迁移台账.md` 加行；`CHANGELOG.md` Unreleased 记录。

## 7. 已知边界（不做的事，写下来防止争论）

- 无鉴权/多租户：本机单用户定位（127.0.0.1 绑定）；如需局域网部署再议 token 鉴权。
- 单进程内子进程任务串行：长任务（inventory 全量）建议分对象多次调用；任务队列是过度设计。
- 前端无构建链/无框架：原生 ES Module + 设计令牌，够用且零工具链负担；引入框架需全队评审。
- 扩展形态能力（DNR 回放/Cookie 袋/命名空间隔离/轮盘 UI）**永不迁移**，留在 quick-login 仓库演化。
