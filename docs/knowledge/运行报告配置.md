# 运行报告配置：逻辑与流程（变更样例）

> 适用：akso-workbench「运行报告」板块的页面模板（DTE 报告模板）。
> 样例：`RC-BQ290-01 变更申请与审批表`、`RC-BQ290-02 变更实施与审批表`（用户现用表单）、
> `变更-默认布局 (5).docx`（系统导出的字段映射）、`变更运行报告（新）.docx`（用户手工改好的报告）。
> 语法细节以 `模板参数配置.md` 为准；本文只讲「怎么把一份用户表单配成能出数的运行报告」。

## 1. 三份材料各管什么

| 材料 | 作用 | 不能拿它做什么 |
|------|------|----------------|
| 用户现用表单（Word/纸质） | 版式、章节顺序、中英文标签、合并单元格、页眉；决定报告「长什么样」 | 里面没有字段 code，不能直接上线 |
| 系统「默认布局」导出 | 字段字典：每个布局分区的「标签 → `<<[code]>>`」，含循环表关系码、日期格式、附件、电子签名 7 列 | 它是**字段全集**，不是报告版式；直接打印会得到一张字段清单 |
| 配置报告 Excel（`对象` / `对象.字段`） | 核对字段 code、数据类型、`__cr` 是否成立（`[统计]关系编号`） | 不含版式，也不含布局分区 |
| 手工改好的运行报告 | 合并后的目标形态：表单骨架 + 占位符 | 单份样例，不代表全部场景 |

**一句话**：报告 = 用户表单的壳 + 系统字段的占位；默认布局导出是「字典」，不是「模板」。

## 2. 配置逻辑（六条）

1. **版式跟用户表单，字段跟系统导出。** 保留用户表单的章节、标签、表头、页眉、分页；
   只把「人等填」的空白换成占位符。不要为了省事把默认布局整份导出当报告。
2. **报告是子集。** 默认布局 21 个分区、近 200 个字段，一份报告通常只取其中 15–30 个；
   取舍标准：这张表/这一栏在纸质流程里是否要签字/归档。不取的整段删掉，不要让读者看空表。
3. **标签不能反推 code。** 中文标签在系统里大量重名/近义（「变更类型」vs「变更时限」、「状态」vs「是否完成」）。
   code 只从默认布局导出或配置报告里抄；关系码（`__cr`/`__sysr`）只从导出的 `<<foreach [in …]>>` 里抄。
4. **子表用一行 foreach。** 导出的循环表往往是「表头 + 一行数据」，多出来的空行要删到只剩一行；
   表头保留中文，一行里按列放 `<<[字段]>>`，整行外面套 `<<foreach [in 关系码]>>…<</foreach>>`。
5. **人填控件改成系统值。** 勾选框（□永久/□临时、□是/□否）在报告里不保留控件，直接输出字段值；
   多部门勾选表通常整段删掉——系统里对应的是「字段 + 电子签名」，不是九宫格。
6. **日期、空值、附件用固定写法。** 日期 `:"yyyy-MM-dd"`、日期时间 `:"yyyy-MM-dd HH:mm:ss"`；
   允许空的关系用 `?.`，日期可能 N/A 时按 `模板参数配置.md` §5.2 处理；
   附件列用 `<<foreach [in 附件字段]>><<if [IndexOf()>0]>>、<</if>><<[FileName]>><</foreach>>`。

## 3. 变更样例：报告字段从哪来

`变更运行报告（新）.docx` 把 01（申请）与 02（实施）两份表单合并成一张报告：
保留 01 的标题/CR 编号/申请/评审/关闭，插入 02 的实施计划表；删除所有勾选格与部门签字格。共 27 个占位。

**关系码怎么来的**：`change_action_change_number__cr` 来自「变更行动措施」分区的一行 foreach——
子对象 `change_action__c` 通过父字段 `change_number__c` 指向变更；这是父对象关系，`__cr` 成立。
电子签名是 `change_plan_esignature_parent_id__sysr`（`_sysr` 系统关系），7 列固定：
`user_account__sys`、`signature_position_name__sys`、`signature_time__sys`、`signature_meaning_name__sys`、
`opinion_name__ak`、`signature_reson__sys`、`signature_user__sys`。

## 4. 配置流程（可直接照做）

1. **收材料**：用户现用表单 + 系统「默认布局」导出 + 配置报告 Excel。缺默认布局时，用对象分析拿到字段表再手拼关系码，
   但 `__cr` 仍要去配置报告 `[统计]关系编号` 核对，不能猜。
2. **拆章节**：把表单章节与默认布局的分区对齐，列一张「取 / 不取」表；决定报告要覆盖到申请、实施、关闭中的哪几段。
3. **建字典**：从默认布局导出里抽 `标签 → code`（按分区归类）；同一 code 出现在多处时以分区上下文确认。
4. **就地改模板**：在用户 docx 上改，不重排版式：
   - 空白/下划线 → 占位符；同一行多个字段就按原文顺序插入；
   - 表格数据行 → 只留一行，套 foreach；表头保留中文；
   - 勾选框/多部门签字格 → 删掉，换字段或签名表；
   - 日期字段补 `:"yyyy-MM-dd"`。
5. **处理签名与附件**：需要签字就加 7 列签名 foreach（表头中文），不要用单列打包；
   附件区用 `FileName` 列表，多个附件用 `IndexOf()>0 → 、` 分隔。
6. **校验与试渲染**：用 `validate_filled.py` 检查 foreach 配对、空值列、code 是否在配置报告里；
   再用一条真实 CR 渲染一份，和用户表单逐段对照（尤其打印分页、表头、签字区）。
7. **交付与维护**：模板文件 + 字段映射说明 + 改动记录。字段改名/新增/停用后，重新导出默认布局、更新字典、
   再跑一次校验；不要把旧模板直接复制给下一个对象。

## 5. 变更样例里需要确认的点

1. **「变更类型」用的是 `change_time_scope__c`（变更时限）。** 表单里的「永久/临时」确实是时限，语义对；
   但字段中文名是「变更时限」，报告标签写「变更类型」。建议要么保留双关，要么把标签改成「变更时限」。
2. **评审区只取了各问题的「内容」字段，丢了 `is_*` 的「是/否」。** 例如「是否需要修订文件」后面直接输出
   `security_risk_content__c`；如果答案是「否」，内容为空，报告上就是空白，读者无法区分「否」和「没填」。
   建议二选一：加 `<<if [is_security_risk__c=="true"]>>是…<<else>>否<</if>>`，或把 `is_*` 与内容一起输出。
3. **「是否完成」用 `status_id__sys`（流程状态）。** 它输出的是「进行中/已完成」这类状态名，不是「是/否」；
   如果报告要的是勾选语义，需要条件判断或换字段。
4. **「变更配套措施」这一栏丢了 `change_supporting_measures__c`。** 样例写成「变更配套措施：仓储物料：…」，
   伞标题下面是仓储物料的值；如果要保留「配套措施」本身的文字，应在冒号后补该字段，或删掉伞标题只留分项。
5. **02 表里有系统没有的栏位**：「需要修订文件/记录编号」「验证方案编号」「下发部门」「确认/复核部门」在默认布局里
   都没有对应字段。它们只能手写，或改成备注字段；不要在报告里留一个永远空的占位。
6. **关闭区少了 `change_close_remarks__c`（变更关闭备注），也没有审批签名。** 如果报告要归档关闭结论，
   需要补字段；如果要签字，按签名 7 列加 `change_plan_esignature_parent_id__sysr`。
7. **实施表只取了 10 列中的 4 列**（业务编号/部门/实施事项/完成）。若报告要体现截止日期、完成总结、实际完成日期，
   从 `due_date__c`、`complete_summary__c`、`actual_completion_date__c` 增列即可，foreach 结构不变。
8. **评审小组的九部门勾选格与管理者代表签字被整段删除。** 这是对的——系统里对应「评审任务 + 电子签名」；
   若要显示评审意见，应改用签名 foreach，而不是恢复勾选表。

## 6. 变更默认布局的分区清单（21 个）

| 类型 | 分区 |
|------|------|
| 字段型 | 全局变量、隐藏内容、变更业务类型、基础信息、通用变更-变更类型与目的、变更风险评估、变更关闭、有效性评估结果、变更终止 |
| 循环表 | 相关变更、风险评估任务、制定项目里程碑计划、变更涉及部门、变更行动措施、阶段性实施、计划调整、变更延期申请、证据补充 |
| 附件型 | 输出验证报告、设计修改报告、变更终止（终止相关附件）、证据补充（补充材料） |
| 签名 | 电子签名（7 列 foreach） |

字段型分区是「标签 + 单个占位」，循环表分区是「表头 + 一行 foreach」，附件型是「FileName 列表」，
签名是固定 7 列。配置时按这四类各自套写法即可，不要混用。

## 7. 工具注意

- **系统导出的默认布局是 ISO 29500 Strict 包**（`purl.oclc.org/ooxml/...` 命名空间），
  `python-docx` 与技能里的 `inspect_template.py` 会报
  `KeyError: no relationship of type .../officeDocument`。要么在 Word 里「另存为」一次转成常规 docx，
  要么按 XML 直接解析（本地名 `w:p`/`w:tbl`/`w:tc` 不变）。后续做「上传默认布局自动建字典」时必须兼容 Strict。
- 校验脚本：`validate_filled.py` 需要「原模板 + 已填充 + 配置报告」三件套；模板阶段至少做一次
  `foreach` 配对与 code 存在性检查。
- 本机没有 `py` 启动器，用 `python`（`D:\software\conda\python.exe`，python-docx 1.2.0 / openpyxl 3.1.5）。

## 8. 维护规则

- 字段 code 变了：重导默认布局 → 更新「标签 → code」字典 → 模板全文替换 → 重跑校验。
- 新增分区（例如新增「变更终止」表）：先确认默认布局里有对应 foreach，再决定报告是否加章节。
- 报告模板与映射说明同版本入库；模板文件名带对象与版本，例如 `变更运行报告-v3.docx`。
- 上线前必须用真实数据渲染一次，检查：空值、否/未填、日期格式、打印分页、附件名、签名行。
