# 模板参数配置

> 适用范围：eGMP / Akso 平台运行报告、Word 模板中的参数占位、条件判断、数组循环、关联对象取值、日期与数字格式。  
> 整理日期：2026-11-11。  
> 来源：业务侧提供的语法要点，以及《运行报告》实践材料（含 seq 日志排查、Word 域、单元格合并等场景）。  
> 标注「待验证」的写法尚未在全部模板类型上逐条回归，正式模板请先在测试环境预览确认。

## 0. 一分钟速查

| 需求 | 写法 | 示例 |
|---|---|---|
| 输出字段 | `<<[字段Code]>>` | `<<[Controlled_number__c]>>` |
| 条件 | `<<if [条件]>>…<</if>>` | `<<if [Flag=="true"]>>是<</if>>` |
| 多分支 | `<<elseif [条件]>>` / `<<else>>` | 见 §2.1 |
| 数组循环 | `<<foreach [in 关系Code]>>…<</foreach>>` | 见 §3.1 |
| 循环分隔符 | `<<[IndexOf() != 0 ? "," : ""]>>` | 逗号分隔 |
| 循环加序号 | `foreach` + Word 自动编号 | 见 §3.6 |
| 包含判断 | `字段.Contains("内容")` | 见 §2.2 |
| 不包含 | `!字段.Contains("内容")` | 见 §2.2 |
| 多个条件 | `&&` | 见 §2.6 |
| 关系为空 | `关系Code.Count()>0` | 见 §2.5 |
| 空值安全 | `关系Code?.字段Code` | 见 §4.4 |
| 布尔转换 | `Convert.ToBoolean(字段)` | 见 §2.3 |
| 日期格式 | `<<[字段]:"yyyy-MM-dd">>` | 见 §1.2、§5 |
| 日期为 N/A | 先判断，再 `Convert.ToDateTime(...)` | 见 §5.2 |
| 数字保留两位 | `<<[字段]:"0.00">>` | 见 §1.4 |
| 去重 | `.Select(...).Distinct()` | 见 §3.7 |
| 合并单元格 | `<<cellMerge>>` | 见 §3.8 |
| 导出/打印时间 | Word 域，不用模板语法 | 见 §6.5 |
| 关联对象出站取值 | `关系Code.字段Code` | 见 §4.2 |

## 1. 基本占位符

### 1.1 输出一个字段

```text
<<[字段Code]>>
```

- `字段Code` 从对象字段里复制，保留大小写、下划线和 `__c` / `__sys` 后缀。
- 参数必须用 `<<[` 开头、`]>>` 结尾；中间不要随意加空格。
- 普通文字直接写，不需要包在 `<< >>` 里。

### 1.2 输出日期并指定格式

```text
<<[BirthDate]:"yyyy-MM-dd HH:mm:ss">>
```

冒号后面的格式串决定输出样式，常用格式：

| 格式 | 输出 |
|---|---|
| `yyyy-MM-dd` | `2026-11-11` |
| `yyyy-MM-dd HH:mm:ss` | `2026-11-11 14:30:00` |
| `yyyy年MM月dd日` | `2026年11月11日` |
| `dd/MMM/yyyy` | `30/Dec/2025`（英文月份缩写） |

说明：材料里英文日期写作 `dd/mmm/yyyy`，但 .NET 自定义格式中月份缩写是 `MMM`；按 `MMM` 使用，若平台不识别再以预览结果为准（见 §9）。

### 1.3 输出布尔值

布尔字段可以直接输出，也可以先转换再参与判断：

```text
<<[Flag]>>
<<[Convert.ToBoolean(Flag)]>>
```

### 1.4 数字保留小数位

```text
<<[Training_hours__c]:"0.00">>
```

- `0.00` 表示固定两位小数，例如 `0.0444444` 输出 `0.04`。
- 材料原样写的是 `"\0.00"`（带反斜杠）；如果 `"0.00"` 不生效，再按原材料试 `"\0.00"`，两种写法**待验证**（见 §9）。

### 1.5 原始材料中的特殊写法

材料里出现过一个用书名号包裹的关联字段：

```text
«dms_document_Superior_department__cr___department_name_en__c»
```

这更像排版符号，不一定是模板语法。若预览时原样输出，改用常规占位符：

```text
<<[dms_document_Superior_department__cr___department_name_en__c]>>
```

## 2. 条件判断

### 2.1 if / elseif / else

```text
<<if [Flag=="true"]>>AAA<<elseif [Flag=="false"]>>BBB<<else>>CCC<</if>>
```

展开写更易读：

```text
<<if [Flag=="true"]>>
  AAA
<<elseif [Flag=="false"]>>
  BBB
<<else>>
  CCC
<</if>>
```

规则：

- 等于用 `==`，不要写成单个 `=`。
- 不等于用 `!=`。
- 字符串值放英文双引号里，例如 `"true"`、`"异常（偏差）审核同意"`。
- 每个 `<<if>>` 必须有对应的 `<</if>>`；`elseif` / `else` 不单独闭合。
- 条件成立输出 if 分支，否则继续看 `elseif`，全部不成立才走 `else`。

### 2.2 包含判断

```text
字段.Contains("指定内容")
```

示例：字段值包含指定文字时输出「符合要求」，否则输出 `--`：

```text
<<if [QC0001__c.Contains("成品取样-执行批准的取样规程")]>>符合要求<<else>>--<</if>>
```

不包含：在字段 Code 前加 `!`。

```text
<<if [!system_audit__c.Contains("是")]>><<[Reporting_party__c]>><</if>>
```

注意：

- 当前按 `.Contains("...")` 整理；材料中也出现过 `Contain`，两种拼写是否都支持**待验证**，优先用示例里的 `.Contains`。
- 包含判断是否区分大小写，材料未说明；重要模板请用真实数据预览。
- 内容里的中文括号、空格会参与匹配，必须与平台数据完全一致。

### 2.3 布尔条件

字段本身是布尔值时，可以先转成布尔再判断：

```text
<<if [Convert.ToBoolean(Controlled_number__c)]>>控制号：<<[Controlled_number__c]>><</if>>
```

适合「有值才显示」的场景：字段为空或 false 时整段不输出。

也可以直接比较字符串：

```text
<<if [Whether_change_termination__c=="是"]>>1<<else>>2<</if>>
```

### 2.4 空值与 N/A

运行报告在 seq 日志里可能出现 `null`，它不是 `N/A`，直接取值会报错。先判空再输出：

```text
<<if [Expiration_deviation__c!=null&&Expiration_deviation__c!="N/A"]>>超期的偏差编号：<<[Expiration_deviation__c]>><</if>>
```

规则：

- `null` 用 `!=null` 判断。
- `N/A` 用 `!="N/A"` 判断。
- 两个都要判时用 `&&` 连接，中间不要加多余空格或中文符号。

### 2.5 关系可能还没有数据

入站关系在业务上可能一条都没有，例如变更开启状态下没有风险任务。先判断关系条数：

```text
<<if [risk_assessment_matrix_change__cr.Count()>0]>>
  有风险任务
<</if>>
```

关系不存在或为空时，`Count()>0` 为 false，整段不输出。

### 2.6 多个条件

`Where` 与 `if` 都用 `&&` 连接多个条件：

```text
<<if [条件1 && 条件2]>>…<</if>>
<<foreach [in 关系Code.Where(p=>p.字段A=="值A" && p.字段B=="值B")]>>…<</foreach>>
```

示例：

```text
<<foreach [in change_esignature_parent_id__sysr.Where(p=>p.signature_meaning_name__sys=="变更关闭审核" && p.opinion_name__ak=="同意")]>>…<</foreach>>
```

## 3. 数组循环

### 3.1 基本循环

```text
<<foreach [in 关系Code]>><<[数组内字段Code]>><</foreach>>
```

- `关系Code` 是当前对象指向子表 / 多值关系的 code，例如 `deviation_esignature_parent_id__sysr`。
- 循环体里直接写数组元素的字段 code，不需要再写关系 code 前缀。
- 每个 `foreach` 必须有 `<</foreach>>`。

### 3.2 用分隔符拼接数组元素

逗号分隔：

```text
<<foreach [in 关系Code]>><<[IndexOf() != 0 ? "," : ""]>><<[数组内字段Code]>><</foreach>>
```

原理：`IndexOf()` 为 `0` 时输出空串，其余项输出逗号，于是结果形如 `A,B,C`，末尾不会多一个逗号。

空格分隔：

```text
<<foreach [in c4256_C6515__cr.c4256_C5723__cr]>><<[IndexOf() != 0 ? "   " : ""]>><<[name__ak]>><</foreach>>
```

如果分隔符是顿号、分号或换行，把三元表达式里的 `","` 换掉即可：

```text
<<[IndexOf() != 0 ? "、" : ""]>>
```

### 3.3 循环内过滤与排序

材料示例：只取签署意见包含「异常（偏差）审核同意」的记录，并按签署时间排序：

```text
<<foreach [in deviation_esignature_parent_id__sysr.Where(p=>p.signature_meaning_name__sys.Contains("异常（偏差）审核同意")).OrderBy(p=>p.signature_time__sys)]>>
  <<[user_account__sys]>><<[user_id__sys]>>  <<[signature_position_name__sys]>>  <<[signature_time__sys]:"yyyy-MM-dd">>
<</foreach>>
```

说明：

- `Where(p=>...)` 过滤，`p` 是循环项的别名，可换成其他字母。
- `p.signature_meaning_name__sys` 是循环项上的字段。
- `OrderBy(p=>p.字段)` 升序；`OrderByDescending(p=>p.字段)` 降序。
- 排序字段可以是时间、数字或文本；文本按 A-Z 排序。
- 这段示例会输出**所有匹配项**；如果只要第一条，在循环体里加 `<<if [IndexOf()==0]>>…<</if>>`。

### 3.4 只输出排序后的第一条

```text
<<foreach [in deviation_esignature_parent_id__sysr.Where(p=>p.signature_meaning_name__sys.Contains("异常（偏差）审核同意")).OrderBy(p=>p.signature_time__sys)]>><<if [IndexOf()==0]>><<[user_account__sys]>><<[user_id__sys]>>  <<[signature_position_name__sys]>>  <<[signature_time__sys]:"yyyy-MM-dd">><</if>><</foreach>>
```

这里的 `IndexOf()==0` 表示只渲染排序后的第一项，不是「所有项都加分隔符」。

### 3.5 降序排序

```text
<<foreach [in persons.OrderByDescending(p=>p.Age)]>>…<</foreach>>
```

升序用 `OrderBy`，降序用 `OrderByDescending`：

```text
<<foreach [in persons.OrderBy(p=>p.Age)]>>…<</foreach>>
```

### 3.6 循环列表加序号

在 Word 表格里给循环结果加「序号」列，不要用 `IndexOf()` 手写数字，直接用 Word 的自动编号：

1. 在「序号」单元格里先写 `<<foreach [in 关系Code]>>`。
2. 再插入 Word 的「编号」或「项目符号和编号」中的数字编号。
3. 同一行其他单元格放字段占位符，行末用 `<</foreach>>` 闭合。

示意：

```text
| 序号 | 审批人部门科室 | 审批时间 |
| <<foreach [in annual_training_plan_esignature_parent_id__sysr]>> | <<[signature_dept_name__sys]>> | <<[signature_time__sys]:"yyyy-MM-dd HH:mm:ss">><</foreach>> |
```

注意：`foreach` 放在序号单元格里，编号由 Word 维护；复制模板后如果序号不连续，检查编号是否被拆成了普通文本。

### 3.7 列表去重

场景：变更下的风险评估矩阵，除业务编号外其他字段都一样，导出时只想显示一条。

`<<cellMerge>>` 只能合并**相邻**的相同单元格；如果相同数据不相邻（例如第 2 条和第 4 条相同），用 `Distinct()`：

```text
<<foreach [in 关系Code.Select(p=>new{新数组字段1=p.关系字段1,新数组字段2=p.关系字段2}).Distinct()]>><<[新数组字段1]>><<[新数组字段2]>><</foreach>>
```

原理：

- 平台数据每条都有不同的 id、业务编号，直接 `Distinct()` 不会去重。
- 先用 `Select(p=>new{...})` 只投影「要显示的字段」，把这些字段组成匿名对象，再 `Distinct()`。
- 单个字段也适用：

```text
<<foreach [in audit_materials_audit_management__cr.Select(p=>new{Manufacturer=p.audit_materials_material_supplier_list__cr.manufacturer_name__c}).Distinct()]>><<[Manufacturer]>><</foreach>>
```

注意：

- `new{...}` 里的属性名自己起，右侧写 `p.关系字段`。
- 投影字段越少，去重越彻底；不要把 id、编号带进去。
- 匿名对象 `Distinct()` 在当前模板引擎中的支持情况**待验证**（见 §9）。

### 3.8 相同单元格合并

在需要合并的单元格内容前加 `<<cellMerge>>`，通常紧跟在 `foreach` 之后：

```text
<<foreach [in 关系Code]>><<cellMerge>><<[字段Code]>><</foreach>>
```

说明：

- 只合并**相邻**的相同单元格；不相邻的重复数据用 §3.7 的 `Distinct()`。
- 多个列都要合并时，在对应单元格的语句前分别加。
- `<<cellMerge>>` 的准确放置位置（foreach 后 / 字段前 / 字段后）在不同模板里可能不同，**待验证**；先按「foreach 后、字段前」试。

### 3.9 数组里还有数组（嵌套循环）

关系返回值本身还是数组时，可以嵌套 `foreach`：

```text
<<foreach [in c4256_C6515__cr]>><<[c4256_C5723__cr.department__ak]>><</foreach>>
```

检查表 / 调查表 / 考卷的运行报告是典型的三层结构：章节 → 回答 → 可用回答 / 依赖。示意：

```text
<<foreach [in section.OrderBy(p=>p.sort_number__ak)]>>
  <<cellMerge>><<[name__ak]>>
  <<foreach [in response.OrderBy(p=>p.sort_number__ak)]>>
    <<cellMerge>> | <<[name__ak]>> |
    <<if [response_type__ak=="单选"]>>
      <<foreach [in answer.Where(o=>o.is_check__ak=="是")]>><<[name__ak]>><</foreach>>
    <<elseif [response_type__ak=="日期"]>>
      <<[Convert.ToDateTime(response_content_date__ak).ToString("yyyy-MM-dd")]>>
    <<elseif [response_type__ak=="多选"]>>
      <<foreach [in answer.Where(o=>o.is_check__ak=="是")]>><<[name__ak]>><</foreach>>
    <<else>>
      <<[response_content__ak]>>
    <</if>>
  <</foreach>>
<</foreach>>
```

材料里的实际关系 code 为 `reason_questionnaire_section_parent__akr`、`reason_questionnaire_response_section__akr`、`reason_questionnaire_answer_parent__akr`，使用时替换示意里的 `section` / `response` / `answer`。

### 3.10 附件字段按列表显示

附件字段在表单里是分段显示，导出时可以用 `foreach` 遍历附件字段本身：

```text
<<foreach [in Customer_opinion_proof__c]>><<[FileName]>> | <<[FileSize]>> | <<[CreatedTime]>><</foreach>>
```

表格写法：

```text
| 文件名 | 文件大小 | 创建时间 |
| <<foreach [in Customer_opinion_proof__c]>><<[FileName]>> | <<[FileSize]>> | <<[CreatedTime]>><</foreach>> |
```

## 4. 关联对象取值

### 4.1 入站关系：用数组循环

当前对象被多条子记录引用时（一对多 / 多对多），用 `foreach` 遍历关系 code：

```text
<<foreach [in 关系Code]>><<[字段Code]>><</foreach>>
```

示例：遍历偏差的电子签名记录。

### 4.2 出站关系：关系 Code + 字段 Code

当前对象指向一个关联对象时（多对一），取关联对象上的字段：

```text
关系Code.字段Code
```

例如取关联部门对象上的英文名称：

```text
<<[dms_document_Superior_department__cr.department_name_en__c]>>
```

材料里也出现过把关系 code 与字段 code 拼成一个长参数名的写法：

```text
<<[dms_document_Superior_department__cr___department_name_en__c]>>
```

两种写法以目标环境实际解析为准，**待验证**；先试点号形式，不解析再用材料里的长 code。

### 4.3 name_ak

关联对象的 `name_ak` 也按字段处理：

```text
<<[关系Code.name_ak]>>
```

用于取关联对象的显示名称，而不是内部 id。

### 4.4 关联对象可能为空：`?.`

关联对象为空时，直接取 `关系Code.字段Code` 会报「对象引用未设置为对象的实例」。在关系后加 `?`：

```text
<<[revise_action_measures_Revised_executor__cr?.account__ak]>>
```

材料中的报错原文：

```text
An error has been encountered while evaluating the expression or statement
'revise_action_measures_Revised_executor__cr.account__ak]'.
Object reference not set to an instance of an object.
```

处理：关系后加 `?.`，字段仍按原名写；如果整段都可能为空，再套一层 `<<if [关系Code!=null]>>…<</if>>`。

### 4.5 只显示部门的最小一级

部门字段值可能是 `公司>部门>科室` 这样的层级字符串，用 `Split('>').Last()` 取最后一级：

```text
<<[grant_dep__c.Split('>').Last()]>>
```

输出只保留最小部门，例如 `质量部>QA>现场QA` 输出 `现场QA`。

## 5. 日期、空值与格式

### 5.1 常规日期格式化

```text
<<[BirthDate]:"yyyy-MM-dd">>
```

### 5.2 日期字段可能是 N/A

直接格式化 `N/A` 会报错或输出异常，先判断再转换：

```text
<<if [BirthDate!="N/A"]>><<[Convert.ToDateTime(BirthDate).ToString("yyyy-MM-dd")]>><</if>>
```

更稳的写法：`Convert.ToString(...)` 判断后再转换，else 分支原样输出：

```text
<<if [Convert.ToString(Task_completion_time__c)!="N/A"]>><<[Convert.ToDateTime(Task_completion_time__c).ToString("yyyy-MM-dd")]>><<else>><<[Task_completion_time__c]>><</if>>
```

说明：

- `Convert.ToDateTime(...)` 把字符串转成日期，`.ToString("yyyy-MM-dd")` 再格式化。
- 适用「N/A 和实际日期混在一起」的字段；比直接在字段后加格式更稳。
- 空字符串、`null` 见 §2.4。

### 5.3 时间精确到秒

```text
<<[created_time__sys]:"yyyy-MM-dd HH:mm:ss">>
```

### 5.4 英文日期格式

```text
<<[字段]:"dd/MMM/yyyy">>
```

输出 `30/Dec/2025`：日 / 英文月份缩写 / 年。

材料里写作 `dd/mmm/yyyy`；.NET 的月份缩写是 `MMM`，若 `MMM` 不生效再按原材料试小写（见 §9）。

### 5.5 数字限制小数位

见 §1.4：`<<[Training_hours__c]:"0.00">>`。

## 6. 完整示例

### 6.1 签署意见（只取第一条匹配记录）

```text
<<foreach [in deviation_esignature_parent_id__sysr.Where(p=>p.signature_meaning_name__sys.Contains("异常（偏差）审核同意")).OrderBy(p=>p.signature_time__sys)]>><<if [IndexOf()==0]>><<[user_account__sys]>><<[user_id__sys]>>  <<[signature_position_name__sys]>>  <<[signature_time__sys]:"yyyy-MM-dd">><</if>><</foreach>>
```

输出效果类似：

```text
zhangsan 张三  质量负责人  2026-11-11
```

### 6.2 有控制号才显示

```text
<<if [Convert.ToBoolean(Controlled_number__c)]>>控制号：<<[Controlled_number__c]>><</if>>
```

### 6.3 生日为 N/A 时不显示

```text
<<if [BirthDate!="N/A"]>>出生日期：<<[Convert.ToDateTime(BirthDate).ToString("yyyy-MM-dd")]>><</if>>
```

### 6.4 关联部门英文名

```text
<<[dms_document_Superior_department__cr.department_name_en__c]>>
```

### 6.5 导出/下载时间、打印时间

这类“生成文件时才知道”的时间**不要用模板参数**，直接用 Word 域：

1. Word 菜单：插入 → 文档部件 → 域。
2. 选择 `Date`（日期）或 `Print Date` / `PRINTDATE`（打印时间，Word 版本不同名称略有差异）。
3. 勾选「自动更新」，否则导出后会保留上次的旧时间。

材料截图里的关键点就是：**一定要勾选自动更新**。

运行报告数据里还可以直接取以下字段（3.2.4 版本以后）：

```json
"current_user_name": "变更管理员BG01",
"current_user_account": "BG01",
"current_download_date": "2024-12-03 14:05:43",
"current_company": "四川科伦药业股份有限公司"
```

对应占位符可写 `<<[current_user_name]>>`、`<<[current_user_account]>>`、`<<[current_download_date]>>`、`<<[current_company]>>`；这些字段的可用版本与准确写法**待验证**（见 §9）。

### 6.6 只显示最小部门

```text
<<[grant_dep__c.Split('>').Last()]>>
```

### 6.7 富文本里有表格时宽度异常

富文本字段导出的表格默认可能是 `width: auto`，在运行报告里显示不全。用 `Replace` 把宽度改成 `100%`：

```text
<<html [Content_for_change__c.Replace("width: auto;","width: 100%;")]>>
```

注意：

- `<<html ...>>` 是富文本专用写法，普通字段不要加。
- `Replace` 的两个参数都要英文双引号，且空格、分号要与原样式一致。
- 若字段值里没有 `width: auto;`，这段不会产生副作用。

### 6.8 检查表 / 调查表 / 考卷（章节 → 回答 → 可用回答）

完整结构见 §3.9。关键点：

- 章节、回答、可用回答分别是三层关系，逐层 `foreach`。
- 章节和回答按 `sort_number__ak` 升序。
- 单选、多选只取 `is_check__ak=="是"` 的选项。
- 日期型回答先 `Convert.ToDateTime` 再格式化。
- 其他类型走 `else`，直接输出 `response_content__ak`。

### 6.9 列表去重（只显示一条）

```text
<<foreach [in 关系Code.Select(p=>new{字段1=p.关系字段1,字段2=p.关系字段2}).Distinct()]>><<[字段1]>><<[字段2]>><</foreach>>
```

实际例子（供应商列表按制造商去重）：

```text
<<foreach [in audit_materials_audit_management__cr.Select(p=>new{Manufacturer=p.audit_materials_material_supplier_list__cr.manufacturer_name__c}).Distinct()]>><<[Manufacturer]>><</foreach>>
```

### 6.10 条件输出 1 / 2

```text
<<if [Whether_change_termination__c=="是"]>>1<<else>>2<</if>>
```

## 7. 常见错误

| 现象 | 常见原因 | 处理 |
|---|---|---|
| 参数原样输出 `<<[...]>>` | 闭合符号写错，或参数 code 不存在 | 检查是否为 `<<[` + code + `]>>` |
| 多出一个 `>` | 手敲时写成 `<<[字段]>>>` | 只保留两个 `>` |
| 条件不生效 | 用了 `=` 而不是 `==` | 改成 `==` / `!=` |
| 条件块把后面内容全吞了 | 少了 `<</if>>` 或 `foreach` 未闭合 | 从内到外逐个配对 |
| 包含判断不生效 | `.Contain` / `.Contains` 拼写不一致 | 先按 `.Contains("...")` |
| `IndexOf()` 报错 | 写在了 `foreach` 外面 | 移到循环体内 |
| 日期报错 | 字段值是 `N/A` / 空 / `null` | 先判断，再 `Convert.ToDateTime` |
| 过滤条件不匹配 | 中文括号、空格、大小写不一致 | 用平台里的原值复制，不要手打 |
| 引号变成中文引号 | 从 Word 复制进了 `“ ”` | 表达式内统一用英文 `"` |
| 关联字段取不到 | 点号写法与长 code 写法混用 | 两种分别预览，确认平台认哪一种 |
| 对象引用未设置为对象的实例 | 关联对象为空，仍直接取子字段 | 关系后加 `?.`，或先 `!=null` 判断 |
| 序号不连续 | 序号列没插入 Word 自动编号，或 `foreach` 位置不对 | 在序号单元格写 `foreach`，再插入 Word 编号 |
| 相同数据没合并 | `<<cellMerge>>` 只合并相邻单元格 | 不相邻的重复数据改用 `Distinct()` |
| `cellMerge` 不生效 | 放置位置不对（foreach 后 / 字段前 / 字段后） | 三种位置各预览一次 |
| 去重不生效 | `Select` 里带进了 id 或业务编号 | 只投影要显示的字段 |
| 富文本表格显示不全 | 表格宽度是 `width: auto` | 用 `Replace("width: auto;","width: 100%;")` |
| 导出时间不更新 | Word 域没勾选「自动更新」 | 重新插入域并勾选自动更新 |

## 8. 上线前检查清单

- [ ] 每个 `<<if>>` 都有 `<</if>>`，每个 `<<foreach>>` 都有 `<</foreach>>`。
- [ ] 条件里的字符串用英文双引号，运算符是 `==` / `!=`，多条件用 `&&`。
- [ ] `IndexOf()` 只出现在 `foreach` 内。
- [ ] 数组为空、关系不存在（`Count()==0`）时，整段不报错、不留多余分隔符。
- [ ] 日期字段用 `N/A`、`null`、正常日期各预览一次。
- [ ] 关联对象分别用「有值 / 无值」的数据预览；空值场景加 `?.` 或 `!=null`。
- [ ] 需要合并的单元格确认数据相邻，并预览 `<<cellMerge>>` 效果。
- [ ] 需要去重的列表确认 `Select` 投影字段里没有 id、业务编号。
- [ ] 循环序号用 Word 自动编号，复制模板后检查序号是否连续。
- [ ] 导出/打印时间用 Word 域，并勾选「自动更新」。
- [ ] 附件字段按列表预览，确认文件名、大小、时间都输出。
- [ ] 富文本字段预览表格宽度，需要时加 `Replace`。
- [ ] 长文本、中文括号、特殊字符不会被截断或转义。
- [ ] 模板预览结果与平台页面显示一致，再发布。

## 9. 待验证清单

以下写法来自材料，但存在两种口径或尚未在真实模板上回归，正式使用前请先在测试环境确认：

1. **`Contain` 还是 `Contains`**：材料文字写「包含 Contain」，示例用 `.Contains(...)`。
2. **`«...»` 写法**：材料中的关联字段用书名号包裹，可能是排版符号，不一定是模板语法。
3. **出站关联取值**：材料说 `关系Code.字段Code`，示例却是拼成一个长 code（`...__cr___department_name_en__c`）。
4. **`IndexOf()` 的下标口径**：经过 `Where` / `OrderBy` 后，下标是按过滤后的序列算，还是按原始序列算；材料示例按过滤后序列取第一条。
5. **布尔字符串**：`Flag=="true"` 与 `Convert.ToBoolean(Flag)` 在不同字段类型上的表现。
6. **`Contains` 大小写**：是否区分大小写，材料未说明。
7. **`null` 的覆盖范围**：`!=null` 在文本、日期、关联字段上是否都成立。
8. **数字格式 `"\0.00"`**：材料原样带反斜杠；`"0.00"` 是否等价，需预览确认。
9. **`<<cellMerge>>` 的位置**：foreach 后、字段前、字段后三种写法是否都支持。
10. **`Distinct()` + 匿名对象**：`Select(p=>new{...}).Distinct()` 在当前模板引擎中的支持范围。
11. **`<<html ...>>`**：是否只对富文本字段生效，`Replace` 的大小写与空格是否必须完全一致。
12. **`current_*` 变量**：`current_user_name` / `current_user_account` / `current_download_date` / `current_company` 的可用版本与占位符写法。
13. **英文日期 `MMM` 与 `mmm`**：材料写 `dd/mmm/yyyy`，.NET 月份缩写为 `MMM`，以预览为准。
14. **`GroupBy`**：材料提到在模板里写 `GroupBy` 后转档空白，尚未定位原因；使用前先做最小模板验证。
