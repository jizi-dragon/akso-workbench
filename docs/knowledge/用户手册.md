# akso-workbench 用户手册

> 适用版本：0.1.x  
> 适用对象：用 akso-workbench 管理 eGMP 配置、做对象分析的业务/实施同学  
> 阅读方式：第一次使用先看「快速开始」，之后按功能查对应章节即可。

## 1. 它能帮你做什么

akso-workbench 是 DSH 里的一个配置工作台。它不是另一个 eGMP 页面，而是把“读配置、改配置、做分析、留审核记录”串起来：

| 能力 | 你可以做什么 |
|---|---|
| 账号中心 | 管理站点、账号、盒子（分组）；把账号放进配置池，供底部账号条和 agent 使用 |
| 配置工具 | 查对象/字段/选项集、表单/列表布局、生命周期、审批矩阵、工作流、菜单与通知 |
| 对象分析 | 输入 1–3 个对象，读生命周期、字段、动作、工作流、审批矩阵，生成 md/drawio/png 报告 |
| 运行日志 | 查看最近事件，下载 7 天/30 天日志，排查“点了什么、报了什么错” |
| Agent 对话 | 用自然语言让 agent 调上面的工具；写操作必须经过审批窗 |
| 运行报告 | 填目标对象和原始表单路径，复制生成指令；中间态、字段映射和最终模板由 agent 在工作区完成 |

一句话原则：**读可以放心读；写必须走“计划 → 审核文档 → 审批窗 → 执行”。**

## 2. 快速开始

1. 在 DSH 左侧栏打开 **akso-workbench**。
2. 如果提示未连接云端，先登录 akso-cloud 账号（与 akso-cloud 同一账号库）。
3. 在 **账号中心 → 站点管理** 添加一个站点（例如 `https://tonbridge-config.aksoegmp.com`）。
4. 在 **添加账号** 里填站点、账号、密码；需要给 agent 用时，勾选“放入配置池”。
5. 在输入框下方的 **账号条** 选择当前账号。状态栏应显示账号和环境；没有当前账号时，agent 会提示 `needs-account`。
6. 直接对 agent 说你要做什么，例如：
   - “分析对象 `change_plan__c`”
   - “给对象 `product_impact_v2__c` 加一个文本字段”
   - “检查 `变更申请审核工作流` 的参与者和审批矩阵”

> 当前账号是唯一环境入口。不要在对话里手填环境地址；agent 会按底部账号条的账号换票。

## 3. 界面总览

左侧栏固定五个模块：

| 模块 | 用途 |
|---|---|
| 账号中心 | 账号、站点、盒子、配置池、同步 |
| 配置工具 | 六类配置能力的查询/写入入口与标准方案 |
| 运行报告 | 入口页：填对象/模板、复制指令、索引运行报告指南 |
| 对象分析 | 单对象/多对象分析、历史、报告下载 |
| 运行日志 | 事件概览、7/30 天日志下载 |

输入框下方是 **账号条**：显示当前账号、环境、连接状态；点它可以切换账号。只有“配置池”里的账号会出现在这里。

## 4. 账号中心

### 4.1 站点管理

站点代表一个 eGMP 环境，账号必须属于某个站点。

- 新增：填名称、Base URL、备注。
- 编辑/删除：在站点行操作。
- 一个站点可以有多个账号；一个账号只属于一个站点。

### 4.2 添加账号

需要填：

- 站点
- 页签名（可选，用于区分同一账号的不同用途）
- 账号、密码
- 盒子（分组，可选）
- 是否放入配置池

“放入配置池”表示允许 agent/底部账号条使用这个账号。**不放池的账号不会出现在账号条里。**

### 4.3 并行账号

按盒子筛选、搜索账号；可以查看账号状态、打开账号、编辑、移入/移出配置池、设置当前账号。  
账号多时建议先用盒子分组，再按盒子筛选。

### 4.4 盒子管理

盒子是账号分组，也可以绑定站点。

- 新建、改名、启用/停用、绑定/解除站点。
- 删除盒子时，可以勾选“同时删除盒内账号”：
  - 勾选：先删账号，再删盒子；账号和盒子都不保留。
  - 不勾选：只删盒子，盒内账号移到默认盒子。
- 默认盒子不能删除，只显示“固定”。

### 4.5 同步

账号中心右上角有「同步」按钮：

- 页面打开时自动同步；页面可见时每 60 秒同步一次。
- 状态缓存 30 秒；超过 30 秒会重新取云端状态。
- 手动点「同步」会立即拉取；同步中按钮会显示「同步中…」。
- 如果长时间不更新，先点一次同步；仍然不动时看「运行日志」里的 `state.sync` 事件。

## 5. 配置工具

配置工具分六个区：

| 分区 | 能做什么 | 典型顺序 |
|---|---|---|
| 对象建模 | 对象、字段、选项集的查询与写入 | 建对象 → 建选项集 → 建字段 |
| 布局 | 表单布局、列表布局 | 先读全量 → 改 → 全量写回 |
| 生命周期 | 状态、状态上的用户动作/进入动作 | 先建状态 → 再挂动作 |
| 审批矩阵 | 矩阵类型、匹配字段、规则 | 建矩阵 → 匹配字段 → 加规则 → 回读 |
| 工作流 | 审批流的开始/任务/判断/动作/结束 | 参与者 → 节点 → 收口关系 → 发布 |
| 菜单 / 通知 | 菜单树、通知模板 | 先查父菜单 → 再建子菜单 |

### 5.1 查接口

每个能力卡片会显示：

- 能力名、方法、路径
- 风险等级（低/中/高）
- 是否不可逆
- 参数说明、示例请求
- 标准方案（如果有）

点「详情」看完整参数。不要直接照抄示例里的 id；用你当前环境的真实 id。

### 5.2 写配置

写操作不要在页面上直接“点一下就写”。推荐流程：

1. 先让 agent 读当前配置，说明要改什么。
2. agent 生成计划；计划会列出每一步的对象、字段、接口和参数。
3. 生成审核文档（见第 8 节），你先看文档和 checklist。
4. 审批窗弹出后，确认无误再点「同意」。
5. 执行完成后回读，确认平台真的写成功。

> 新建对象必须同时开启生命周期和电子签名。参与者控件只允许“字段”或“审批矩阵”两种来源。

### 5.3 工作流配置的推荐顺序

1. 先列参与者：哪些节点需要谁审批；参与者控件只能是字段或审批矩阵。
2. 再列节点：开始、状态、任务、判断、动作、结束。
3. 再列关系：每个节点的 `nextStepId`、判断分支、拒绝回退。
4. 建节点时可以先放临时 `nextStepId` 占位；全部建完后必须 update 收口并回读。
5. 发布前检查：开始节点有参与者/签名、任务有参与者、判断有 else、拒绝有回退、流程有结束。

## 6. 对象分析

### 6.1 能分析什么

输入对象 id 或 code，一次最多 3 个对象。分析结果包括：

- 对象概览：名称、code、生命周期、启用状态数、字段数、工作流数、矩阵数
- 启用状态清单（停用状态不展开）
- 每个状态的用户动作/进入动作
- 字段表（报告最后一段）
- 工作流解析：触发、步骤、判断分支、动作效果、拒绝回退
- 审批矩阵表：矩阵、状态、关联工作流、参与者控件、应用节点、菜单、业务数据、异常
- 自动观察与读取告警

### 6.2 怎么用

1. 打开 **对象分析**。
2. 输入一个或多个对象；多个用换行、逗号或空格分隔，最多 3 个。
3. 点「开始分析」。
4. 看「对比总览」和每个对象的明细；单对象默认展开，多对象默认收起。
5. 需要留档时点「下载分析包（.zip）」。

### 6.3 报告和下载

- 页面下载：一个 zip 包，包内根路径是 `akso-workbench-data/analysis/<对象名>-时间戳/`，解压后是：
  - `code-analysis-YYYY-MM-DD.md`
  - `code-analysis-YYYY-MM-DD.drawio`
  - `code-analysis-YYYY-MM-DD.png`
- agent 分析：不生成 zip，直接把同样三件套写到 `<工作区>/akso-workbench-data/analysis/<对象名>-时间戳/`。
- Markdown 适合评审；drawio 适合继续编辑；PNG 适合直接贴到文档/群里。

### 6.4 结果怎么读

- **生命周期总览**：只列启用状态；已知的状态变更画实线；触发源读不到的工作流放在右侧“待确认触发源”清单，不猜箭头。
- **工作流页**：一条工作流一页，画任务、判断、动作、分支；`behaviorType=46` 改的是关联对象，不是本对象。
- **矩阵表**：看“有没有菜单、有没有业务数据、应用在哪个任务节点”；没有菜单/没有数据会写在异常列。
- **告警**：不要跳过。常见的“未反查到直接触发点”“菜单已找到但业务数据读取失败”都需要人工确认。

### 6.5 边界

- 只读，不写平台。
- 只分析启用状态；停用状态上的动作不分析。
- 工作流只分析挂到启用状态的流程。
- 页面和 agent 都走同一个分析入口；不要手工写临时 JSON 冒充报告。
- 分析历史会保留；失败也会留痕。

## 7. 运行日志

「运行日志」用于排查问题和给支持同学提供证据：

- 顶部显示事件数、占用空间、保留期、日志文件数、日志目录。
- 「下载 7 天日志」「下载 30 天日志」生成一个文件；超过 12 MB 会从最旧的记录裁掉。
- 「复制日志目录」方便你直接打开目录。
- 日志里不会记录口令/令牌；请求体会打码。

遇到“同步不动、审批不弹、分析没产物”时，先下载 7 天日志，再描述操作时间点，排查会快很多。

### 7.1 检查更新

「运行日志」页头部有版本号与「检查更新」按钮，进页面时也会自动查一次（10 分钟内不重复请求网络）。

- 只在**正式版**更新时提醒：版本号中间那段变大（`0.2.28 → 0.3.0`）。`0.2.28 → 0.2.29` 这种日常提交只在运行日志区给一句轻提示，不催你换。
- 有正式版时，页面顶部与运行日志区各出一条横幅：显示新版本号、发布日期，给「下载更新包」「打开发布页」「复制安装步骤」。
- 点「下载更新包」会把 zip 下到 `$DSH_HOME/akso-workbench/updates/<版本>/` 并校验 sha256；下载完照着步骤替换即可。
- **换插件要完全退出 DSH 再打开**（关窗口不算）。插件在启动时加载，刷新页面不会生效。
- 检查更新失败不影响使用：页面只显示「没查到」和原因，不会挡住任何操作。

发布方要发新版本时，改 akso-cloud 的 `web/downloads/workbench/latest.json`：`version` 填新版本号，
把插件包 zip 传到 GitHub Release 资产后填 `zipUrl` / `zipSha256` / `zipBytes`。


## 8. 审核文档与审批

### 8.1 两类审核文档

| 类型 | 用在什么时候 | 内容 |
|---|---|---|
| 创建审核 | 新建对象/字段/布局/工作流等较大改动 | 问题、执行计划、预期结果 checklist、执行明细 |
| 更新审核 | 已执行任务的小范围调整/优化 | 任务概述、调整计划、预期 checklist、关联已执行文档 |

规则：

- 文件放在 `<工作区>/akso-workbench-data/reviews/`。
- 文件名是“任务名 + 时间戳”。
- 创建文档是任务的第一目标；checklist 没完成前不要重复发起同一任务。
- 任务执行成功后，文档标记“已结束/审核文件作废”，只作历史记录。
- 已执行的文档禁止修改；后续调整必须新建“更新审核”文档，并注明调整原因。

### 8.2 审批窗怎么用

审批窗会显示：

- 环境、目标、账号
- 这次会改什么（按创建/更新和类型分组）
- 审核文档卡片和「在右侧打开」
- 调整内容输入框
- 拒绝 / 提交调整 / 同意

- 点「同意」：执行计划，平台开始写入。
- 点「拒绝」：不执行，平台零写入。
- 在输入框写调整意见后点「提交调整」：不执行，agent 会按意见重新出计划。
- 内容过多时：默认只显示前 4 组，点「查看全部」展开；中间内容可滚动，标题和底部按钮固定。
- 点「折叠」：审批窗缩成一条，方便继续看对话；点「展开」恢复。

> 审批窗和对话输出应同时出现。agent 在弹窗前应先给你一段“目标 / 执行方案 / 预期结果 + 审核文档链接”。

## 9. Agent 对话示例

### 9.1 读配置

```text
帮我分析对象 change_plan__c。
只分析启用状态，工作流要写步骤名称；矩阵用列表呈现。
```

```text
查一下 supplier__c 的字段和生命周期，先不要改。
```

### 9.2 写配置

```text
给对象 product_impact_v2__c 加一个单选字段“物料状态”，
选项：已售、在库、在制原材料、在途；非必填。
先出计划和审核文档，不要直接写。
```

```text
把“基础信息”分区加到表单布局，放在“工作流时间线”后面；
字段顺序按我给的清单。先读现有布局再改。
```

### 9.3 工作流/矩阵

```text
检查变更申请审核工作流的参与者：
开始节点用了哪些矩阵？每个矩阵被应用到哪个任务节点？
矩阵有没有管理菜单？菜单下有没有业务数据？
```

```text
新建一个审批矩阵，匹配字段是“变更类型”，
规则用应用角色约束，先出计划给我审。
```

### 9.4 对话时的注意事项

- 先选底部账号条的账号；没有账号时 agent 无法读平台。
- 不要贴密码、token、Cookie；账号由账号中心管理。
- 写操作不要催 agent “直接写”；让它先出计划和审核文档。
- 对结果有疑问时，先看审核文档和运行日志，再让它重跑。

## 10. 数据放在哪里

| 内容 | 位置 | 是否进 Git |
|---|---|---|
| 审批/审核文档 | `<工作区>/akso-workbench-data/reviews/` | 否 |
| 对象分析产物 | `<工作区>/akso-workbench-data/analysis/<对象名>-时间戳/` | 否 |
| 分析历史 | `<dshHome>/akso-workbench/analysis-history/` | 否 |
| 配置计划/任务 | `<工作区>/akso-workbench-data/config-plans/`、`config-tasks/` | 否 |
| 运行报告 | `<工作区>/akso-workbench-data/reports/` | 否 |
| 运行日志/审计/审批记录 | DSH profile 下的 `.dsh/akso-workbench/`（页面可复制） | 否 |
| 账号/会话状态 | DSH profile 下的 `.dsh/akso-workbench/cloud.json` 等 | 否 |
| 能力目录/规范 | 仓库 `plugin/src/config/capabilities.ts`、`docs/knowledge/` | 是 |

`<工作区>` 是当前 DSH 会话的工作区（例如 `D:\DDUP\Akso_AI`），不是仓库目录，也不是 DSH profile。

## 11. 常见问题

### 11.1 左侧栏看不到 akso-workbench

- 检查插件是否启用：DSH 插件管理里看 `akso-workbench-dsh-ui`。
- 改过插件构建产物后，刷新 DSH 页面；host 侧改动要重启 DSH 或开新会话。
- 如果 profile 的 link 指向旧目录，重新指向 `akso-workbench/plugin`。

### 11.2 底部账号条没有账号

- 账号没有放进“配置池”；到账号中心勾选“放入配置池”。
- 账号条没有当前账号；选一个。
- 账号登录失效；到账号中心重新登录/同步。

### 11.3 分析结果没有产物

- 页面分析：看是否下载了 zip；zip 解压后才有目录。
- agent 分析：看返回的 `artifacts` 是否为 null；null 表示没定位到工作区。
- 旧会话可能仍加载旧插件 revision；重启 DSH 或开新会话再试。

### 11.4 审批窗不弹 / 审核文档打不开

- 没有工作区根时，审核文档不会生成，工具会返回 `review-unavailable`，不弹审批。
- 审核文档在 `akso-workbench-data/reviews/`；确认文件存在。
- 「在右侧打开」依赖当前 DSH 会话；点不开时用文件路径手动打开，或刷新页面重试。

### 11.5 矩阵表为空

- 当前对象的工作流没有挂到启用状态 → 不进入分析。
- 工作流开始节点没有矩阵参与者（只有字段参与者）→ 不会产生矩阵行。
- 矩阵表为空不等于对象没有矩阵；先看工作流开始节点和对象矩阵列表。

### 11.6 运行报告页复制了指令，但没有产物

「运行报告」页是入口，不是生成器：它只负责收集目标对象/原始表单路径、生成并复制 agent 指令，不直接产出 docx。

- 先把页面里的「复制生成指令」粘贴到对话，确认 agent 读到 `docs/knowledge/运行报告生成.md` 和 `模板参数配置.md`。
- 中间态和字段映射应落在工作区 `akso-workbench-data/reports/`；没有文件时，让 agent 返回实际路径，不要只看聊天里的说明。
- 中间态未审核前，agent 不应把 `<<字段名称>>` 换成 `<<[code]>>`；如果已经换了，要求它退回中间态重做。

## 12. 安全与边界

- 账号密码只存在 akso-cloud 账号库；插件不落明文密码。
- agent 只能使用底部账号条当前账号，不能自己切环境。
- 写操作必须经过审批窗；拒绝就是零写入。
- 审核文档、分析产物、日志都不进 Git；不要把它们提交到仓库。
- 发现异常先留日志和审核文档，再让 agent 重跑；不要手工改平台数据“绕过”审批。
