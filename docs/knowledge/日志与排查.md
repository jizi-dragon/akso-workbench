# 日志与排查

> 目的：让**用插件的人**把使用现场带回来，而不是只给一句「刚才不行」。
> 运行日志是使用记录（JSONL，本机落盘、页面一键下载）；它与写入审计、审批决策、
> HTTP access 日志是**四类不同的记录**，不要混着看（区别见文末）。

## 1. 日志在哪、怎么拿到

| 项 | 值 |
|---|---|
| 目录 | `$DSH_HOME/akso-workbench/journal/`（`DSH_HOME` 缺省是 `~/.dsh`） |
| 文件 | 按天切：`YYYY-MM-DD.jsonl`；单文件超 4 MB 换 `YYYY-MM-DD.2.jsonl`…（每天最多 5 个） |
| 保留 | 30 天；按总大小 96 MB 再兜底删最旧的 |
| 页面入口 | 左栏 **akso-workbench → 运行日志**：看事件数 / 体积 / 起止时间 / 目录，下载 7 天或 30 天 |
| 下载格式 | `application/x-ndjson`；响应头 `X-Journal-Events`、`X-Journal-Truncated` 给出条数与是否截断 |

**让用户带回日志的步骤**：打开「运行日志」→ 点「下载 7 天」（问题久远就 30 天）→ 把
`akso-workbench-journal-*.jsonl` 发回来。单次导出上限 12 MB，超出会从最旧的事件丢，
`journal.meta` 里 `truncated: true`、`dropped` 是丢弃条数。

不需要登录平台就能下载；日志只在本机，插件不会上传任何内容。

## 2. 一行是什么

```json
{"at":"2026-11-17T06:30:12.345Z","ts":1763351412345,"kind":"tool.done","tool":"akso_workbench_accounts","uid":"AKW-TOOL-ACCOUNTS-V1","ms":12,"ok":true,"result":{"ok":true,"counts":{"accounts":3,"sites":2,"boxes":1}}}
```

- `kind`：事件名（见 §3），前缀就是模块。
- `at` / `ts`：UTC 时间与毫秒时间戳，按本地时区切天。
- 其余字段由事件决定，**写盘前统一打码**：敏感 key（password/token/secret/authorization/…）
  变 `[redacted]`，JWT 与 `Bearer …` 变占位符，字符串截 600 字，深层对象/数组有上限。
- 单行超过 16 KB 会被替换成 `{"truncated":true,"bytes":N}` —— 正常事件不会到这一步。

## 3. 事件目录

| 前缀 | 事件 | 看什么 |
|---|---|---|
| `app` | `app.start` | 插件加载：node/DSH 版本、路由数、`dshHome` |
| `tool` | `tool.invoke` / `tool.done` / `tool.fail` | 哪个工具（含 UID）、参数形状、耗时、`ok`、失败原因 |
| `http` | `http` | `METHOD path → status ms`；403 围栏、401 会话过期都在这里 |
| `cloud` | `cloud.login` / `cloud.login.failed` / `cloud.logout` / `cloud.sync` / `cloud.device.start` / `cloud.device.approved` | akso-cloud 登录、设备流、快照同步（`revision` 或 error） |
| `account` / `pool` / `site` / `box` | `account.create` / `account.select` / `pool.toggle` / `site.create` / `box.rename` / `box.bind` | 账号条与基础数据变更（账号打码、**没有口令**） |
| `egmp` | `egmp.token.mint` / `egmp.logout` / `egmp.needs-account` | 换票（只在真的换了时记）、断开、账号门拒绝 |
| `config` | `config.prefs` / `config.invoke` | 审批开关变更、HTTP 直调能力（有 `write` 标记） |
| `plan` / `apply` | `plan.created` / `apply.run` | 计划几步入库；执行结果、失败步、verified 数 |
| `approval` | `approval.wait` / `approval.decide` / `approval.timeout` / `approval.cancelled` / `approval.busy` | 弹窗等了多久、用户点了什么、是否超时/中断 |
| `analysis` | `analysis.run` | 对象分析：查询、对象、字段/状态/流程数、耗时、失败原因 |
| `error` | `error.api` / `error.tools` | 未落入业务分支的异常（带 status、traceId、path） |
| `client` / `ui` | `client.api` / `client.api.error` / `ui.logs.open` / `ui.journal.download` / `ui.error` | 浏览器侧：谁调了哪个接口、前端未捕获异常（消息 + 栈前 6 行） |
| `journal` | `journal.meta`（导出第一行） | 导出元信息：format/version/days/events/app/dshHome/node/platform |

## 4. 常见问题怎么查

**「工具报 needs-account / 让我去登录」**
1. 搜 `egmp.needs-account`，看 `needsAccountAt` 那段时间；再搜 `account.select` 确认账号条是否为空。
2. 写入路径还要求账号在**配置池**里：搜 `pool.toggle`，没有 `inPool: true` 就是没进池。

**「平台 401 / 令牌过期」**
- 搜 `"status":401` 或 `egmp.token.mint`；`http` 事件里看是哪个 path 先 401。
- `cloud.sync` 失败会带 error；快照会标 stale，但界面不会清空。

**「点了同意却没写」**
- 搜同一次 `planId`：`plan.created` → `approval.wait` → `approval.decide`（verdict=approve？）
  → `apply.run`。缺 `approval.decide` 说明弹窗没结算（超时/中断/关页面）。
- `apply.run` 里 `failed` 给出卡住的步；`verified` 是回读确认过的步数。
- 引擎内部 code（`APPROVAL_MISMATCH`、`TARGET_CHANGED`…）**不会**随工具返回，
  但在 host 日志与 `error.api` 里能看到；计划文件里还有完整 steps 可回查。

**「页面白屏 / 某个按钮没反应」**
- 搜 `ui.error` 与 `client.api.error`：前者是前端异常（含栈），后者是请求非 2xx。
- `client.api` 记录的是写请求成功路径，读请求失败才记 `client.api.error`。

**「对象分析结果不对」**
- 搜 `analysis.run` 的 `query` / `object` / `fields` / `statuses` / `workflows` / `warnings`；
  局部接口失败进的是 `warnings`，不是整体失败。

**按 UID 对齐 agent 与 host**
- 工具返回对象带 `_uid`，`tool.invoke/done` 里也有同一个 UID；把 `_uid` 与
  `docs/knowledge/agent调用时序.md` 的图对上，就知道是哪条链路。

## 5. 与审计的区别（别拿日志当审计）

| 记录 | 位置 | 用途 | 是否可改 |
|---|---|---|---|
| 运行日志 journal | `$DSH_HOME/akso-workbench/journal/` | 用户带回现场、排查 | 30 天后自动删；可下载 |
| 写入审计 | `$DSH_HOME/akso-workbench/config-audit/<YYYY-MM>.jsonl` | 谁对哪版计划做了什么（**不记 params**） | 长期保留 |
| 审批决策 | `config-audit/approvals-<YYYY-MM>.jsonl` | 同意/拒绝/补充/超时留痕 | 长期保留 |
| HTTP access | DSH 宿主日志（ctx.logger） | 请求级看板 | 随宿主日志滚动 |

## 6. 新增事件时

1. host 侧用 `recordEvent(kind, data)`（`plugin/src/index.ts` 的 `apply()` 里），**只传摘要**：
   不传 token、口令、请求体原文、完整账号表；账号用 `maskEmail`。
2. 浏览器侧用 `track('client.*' | 'ui.*', data)`（`plugin/src/client/api.ts`），只允许这两个前缀。
3. 新事件同步更新本文件 §3 的表、`docs/knowledge/agent调用时序.md` §7 的图 8，以及 `AGENTS.md`
   的「日志与审计」条目；`plugin/test/journal.test.ts` 补一条打码/边界用例。
4. 加完跑 `npm --prefix plugin test`（journal + host 两条链路都会验证）。
