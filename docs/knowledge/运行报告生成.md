# 运行报告生成指南

> 适用范围：akso-workbench「运行报告」页面模板 / DTE 报告模板。
> 本文是流程与规则的汇总；完整语法查 `模板参数配置.md`，变更对象样例查 `运行报告配置.md`。
> 最近更新：2026-11-24（CAPA 原始表单中间态实践）。

## 1. 一句话定义

**运行报告 = 用户表单的版式 + 系统字段的变量。**

- 用户表单决定章节、表头、合并单元格、分页、签字位置；
- 系统字段提供数据，不把系统「默认布局导出」整份打印成报告；
- 中间态先用 `<<字段名称>>` 给用户审核，确认后再替换成 `<<[code]>>` 和 `if` / `foreach`。

## 2. 四份输入材料

| 材料 | 作用 | 不能做什么 |
|---|---|---|
| 用户现用表单（Word/纸质） | 版式、章节、双语标签、表格、页眉页脚 | 没有字段 code，不能直接上线 |
| 系统默认布局导出 | 字段字典、分区、循环关系码、签名 7 列 | 是字段全集，不是报告版式 |
| 配置报告 Excel（`对象` / `对象.字段`） | 核对 code、数据类型、`__cr` 关系编号 | 不含版式 |
| 已经改好的同类报告 | 参考结构、foreach/if 写法 | 不能直接套到别的对象 |

没有默认布局导出时，用对象分析拿到字段表，再从 `LayoutDetail` 确认相关对象分区和关系；**关系码必须核实，不能猜**。

## 3. 生成流程

### 3.1 收材料与体检

1. 原始 `.doc` 先转 `.docx`；保留原件，不覆盖。
2. 统计页数、外层表格、嵌套表格、签字行、复选框、黄色填写提示。
3. 找出所有空白格、勾选项、签字/日期位置；这些是后面要替换的地方。
4. 数占位时注意：**合并单元格会重复计数**，以唯一标签和实际表格结构为准。

### 3.2 先做中间态

中间态是给用户审核的“可读版”，不是最终模板：

- 保留原始章节、表格、双语标签、页眉页脚、分页；
- 删除黄色“填写提示”、`□` 复选框、下划线空白；
- 把空白换成 `<<字段名称>>`，一个单元格只放一个字段；
- 相关对象表严格 **两行**：第一行表头，第二行 `<<foreach [in 关系码]>>` + 字段名称 + `<</foreach>>`；
- 签字位置用电子签名表，不写“见文末”之类提示；
- 没有可靠字段的格子留空，不编造占位（例如“序号”“重启原因”）。

### 3.3 用户审核

审核重点：

- 章节是否齐全、有没有整段漏掉；
- 字段标签是否和纸质表单一致；
- 相关对象表是不是“表头 + 一行数据”；
- 签字位置、签字含义、签名时间是否合理；
- 哪些格子是故意留空，哪些是字段没找到。

### 3.4 替换成最终模板

用户确认后再做：

1. `<<字段名称>>` → `<<[code]>>`；
2. 相关对象行加 `foreach`，关系码来自布局导出或配置报告；
3. 条件段落加 `if/elseif/else`；
4. 日期加格式，附件加 `FileName` 循环，签名用固定字段；
5. 跑校验，真实数据渲染一次。

## 4. 语法速查

| 需求 | 写法 |
|---|---|
| 字段 | `<<[name__ak]>>` |
| 条件 | `<<if [Flag=="true"]>>是<<else>>否<</if>>` |
| 多分支 | `<<elseif [条件]>>` |
| 循环 | `<<foreach [in 关系码]>>…<</foreach>>` |
| 日期 | `<<[initiated_date__c]:"yyyy-MM-dd">>` |
| 日期时间 | `<<[signature_time__sys]:"yyyy-MM-dd HH:mm:ss">>` |
| 关联取值 | `<<[关系码.字段Code]>>` |
| 空值安全 | `<<[关系码?.字段Code]>>` |
| 关系非空 | `<<if [关系码.Count()>0]>>` |
| 附件 | `<<foreach [in 附件字段]>><<if [IndexOf()>0]>>、<</if>><<[FileName]>><</foreach>>` |
| 合并单元格 | `<<cellMerge>>` |

完整规则以 `模板参数配置.md` 为准；布尔值不要依赖原样输出，正式模板用 `=="true"` 判断。

## 5. 相关对象表：只留两行

推荐结构：

```text
| 责任部门 | 责任人 | 措施计划 | 措施类别 | 是否引入新风险 | 新风险说明 |
| <<foreach [in action_capa_plan__cr]>><<责任部门>> | <<责任人>> | <<措施计划>> | <<措施类别>> | <<是否引入新风险>> | <<新风险说明>><</foreach>> |
```

规则：

- 表头行保留中文/双语，不写 code；
- 第二行每格只放一个字段，不能把“整改部门 + 责任人”塞进一格；
- `foreach` 可以放在第一格，`<</foreach>>` 放最后一格；
- 没有字段的列（如“序号”）留空，不造 `<<序号>>`；
- 数据行只留一行，多余的空白行删掉。

## 6. 电子签名表

签名不是普通文本，不能写 `<<签字/日期>>`。使用签名关系（CAPA 为 `capa_plan_esignature_parent_id__sysr`）：

```text
| 签名人账号 | 签名人岗位 | 签名时间 | 签名含义 |
| <<foreach [in capa_plan_esignature_parent_id__sysr]>><<user_account__sys>> | <<signature_position_name__sys>> | <<signature_time__sys>> | <<signature_meaning_name__sys>><</foreach>> |
```

- 常见 7 列：`user_account__sys`、`signature_position_name__sys`、`signature_time__sys`、`signature_meaning_name__sys`、`opinion_name__ak`、`signature_reson__sys`、`signature_user__sys`；
- 需要按签字位置过滤时，在 foreach 内加 `if [signature_meaning_name__sys=="..."]`；
- 签名表可以逐位置放，也可以统一收口到文末；无论哪种，都必须“表头 + 一行 foreach”且不跨页。CAPA 中间态采用文末统一表，避免页底拆表。

## 7. CAPA 实例（2026-11-24）

- 父对象：`capa_plan__c`，对象 id `3a19df9c-485b-088a-ba92-c707490b4e43`；
- CAPA 行动措施关系：`action_capa_plan__cr`（子对象 `action__c`，父字段 `capa_plan__c`）；
- 签名关系：`capa_plan_esignature_parent_id__sysr`；
- 父字段：`name__ak`、`initiated_date__c`、`source__c`、`defect_description__c`、`incident_investigation__c`、`risk_assessment__c`、`defect_root_cause__c`、`is_capa_effective__c`、`video_off_in_suspend__c`（标签“是否关闭”，code 语义异常）等；
- 行动措施字段：`responsible_department__c`、`owner__c`、`description__c`、`measure_type__c`、`whether_new_risks_are_introduced__c`、`new_risk_content__c`、`whether_design_process_change_is_caused__c`、`completed_summary__c`、`does_the_implementation_of_measures_introd__c`、`risks_introduced_during_implementation_of_measures__c`；
- 中间态产物：`akso-workbench-data/reports/CAPA-运行报告-中间态.docx`，字段映射：`CAPA-中间态-字段映射.md`。

### CAPA 已知差异

1. 原始“问题来源”是多选，`source__c` 是单选；报告只取主来源，或改成拼接。
2. `video_off_in_suspend__c` 标签是“是否关闭”，code 语义不符，上线前让产品确认。
3. “重启 CAPA 原因”没有完全对应的独立字段；暂用 `closure_conclusion__c`，或留空。
4. 无法映射的格子（序号、重启原因等）必须留空，不编造。
5. 页底签名表容易被拆成表头/数据两页；要么提前分页，要么统一放文末。

## 8. 校验清单

- [ ] `foreach` 与 `<</foreach>>` 成对，`if/elseif/else` 与 `<</if>>` 成对；
- [ ] 每个 code 都能在字段字典里找到，大小写、`__c` / `__sys` 一致；
- [ ] `__cr` / `__sysr` 关系码来自布局导出或配置报告，不是按标签猜的；
- [ ] 相关对象表只有表头 + 一行数据，第二行每格一个字段；
- [ ] 没有“填写提示”、`□`、下划线空白、多余空行；
- [ ] 日期都有格式串，签名用签名关系而不是普通占位；
- [ ] 真实数据渲染一次，检查空值、否/未填、附件名、打印分页、签字区；
- [ ] 中间态与字段映射说明同版本交付。

## 9. 常见坑

- **把默认布局导出当报告**：那只是字段字典，版式和字段子集要自己定。
- **按中文标签猜 code**：标签会重名，必须查字典。
- **合并单元格重复计数**：唯一标签数比占位总数可靠。
- **相关对象表留多行**：只留一行数据 + foreach，否则会打印空行。
- **一格放两个字段**：第二行每格只放一个字段，签字和不签字都适用。
- **签字写普通占位**：必须用 `capa_plan_esignature_parent_id__sysr` 一类签名关系。
- **无字段硬编占位**：留空并写进待确认，不要造 `<<序号>>`。
- **页底签名表**：Word/LibreOffice 都可能拆行，提前分页或统一放文末。
