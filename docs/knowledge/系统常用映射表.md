# 系统常用映射表

> 平台把「做什么动作」写成数字：动作节点里是 `behaviorType`，状态按钮里是 `actions[]` 里的类型，菜单里是 `menuActionType`。填错数字通常**不报错**、只是行为不对，所以集中记在这里。
>
> 每组标题下面写 `作用域：workflow / lifecycle / menu …`，卡片详情里的「系统常用映射表」只显示与当前接口域相关的那几组。改完刷新页面即生效。

## 工作流步骤类型（stepType）

作用域：workflow

| 值 | 含义 | 备注 |
| --- | --- | --- |
| 10 | 开始节点 | 系统节点，删不掉；发起人表单控件挂在这里 |
| 20 | 结束节点 | 系统节点，删不掉 |
| 30 | 任务节点（审批） | 参与者、会签/或签、审批按钮都在这里配 |
| 70 | 判断节点 | 按条件分支，每条规则一个 nextStepId，另给 else |
| 90 | 动作节点 | 自动执行：改状态、触发另一条流程 |

## 工作流状态（ChangeWorkflowBasicStatus 的 status）

作用域：workflow

| 值 | 含义 | 备注 |
| --- | --- | --- |
| 10 | 草稿 | 新建出来的初始态 |
| 20 | 启用 | 发布后可用 |
| 30 | 禁用 | 停用 |
| 40 | 编辑中 | 加步骤 / 改节点前必须切到这里 |

## 行为类型（动作节点 / 状态按钮 / 进入动作的 behaviorType）

作用域：workflow / lifecycle

| 值 | 含义 | 备注 |
| --- | --- | --- |
| 7 | 发起工作流 | `behaviorValue.workflowId` 填 workflowBasicId；动作节点、状态按钮、进入动作都用它拉流程 |
| 9 | 修改生命周期状态 | `behaviorValue.statusId` 填目标状态 id |
| 5 | 修改记录字段 | `behaviorValue.fieldId` + `behaviorValue.value`（可填 `formula`/常量/字段值） |
| 10 | 启动检查表（异步） | `behaviorValue.checklistTypeCode` 填检查表类型 code；进入动作常用 |
| 48 | 启动检查表 | 与 10 同类，用户动作常用；配置键可能大小写不同（`BehaviorType`/`ChecklistTypeCode`） |
| 17 | 创建相关对象记录 | `behaviorValue.recordIds` 填目标对象/记录相关配置 id |
| 46 | 修改相关对象生命周期状态 | 常配 `relatedObjectId`、`targetStatusId` |
| 68 | 运行报告生成到附件字段 | 运行报告类动作 |
| 89 | 权限共享复制到 | 进入 / 事件动作可用 |
| 576 | 修改相关文档的文件 | 文档类动作 |
| 600 | 使电子签名记录作废 | 签名类动作 |
| 800 | 活跃工作流 | 用户动作常用 |
| 811 | 催办 | 用户动作常用 |

> 这张表只列常用值。前端枚举的完整 221 项（含 `[DMS]` / `[TMS]` / `[QRS]` 专用动作）见 [`../analysis/lifecycle-action-types.md`](../analysis/lifecycle-action-types.md)。
>
> 注意：`GetListByStatusId` 只返回动作壳；进入动作的 `configs[]`（含 `behaviorType`）要再调 `GET /api/config/lifecycle/EnterAction/GetById?id=<actionId>`。用户动作的 `configs[]` 通常在 `UserAction/GetById` 的 `actions[]` 里。`configs: []` 表示未配置具体动作，不能从名称反推类型。

## 待补：动作库内部编码（actions[] / actionCode）

作用域：workflow / lifecycle

> `behaviorType` 已按前端枚举补齐（见上表与完整表）；这里待补的是动作库条目的内部编码（如“发起工作流”在 `actions[]` 里的 `actionCode`）。没确认前，配置动作先按 `behaviorType` + `behaviorValue` 组装，不要猜内部编码。

## 组件实例保存的操作类型（component_instance_save.operationType）

作用域：object / field / picklist / layout / listlayout / lifecycle

| 值 | 含义 | 备注 |
| --- | --- | --- |
| 10 | 新增 | 不存在才插入（Insert） |
| 20 | 更新 | 已存在才修改（Update） |
| 30 | 覆盖 | 默认值：没有就建、有就覆盖（Cover） |

> 来源：egmp_gws_mcp v1.0.0 的 `component_instance_save` 工具说明，以及二进制里的报错文案
> `Invalid operation_type: %d, allowed values: 10(Insert)/20(Update)/30(Cover)`。配组件（对象/字段/布局/选项集/生命周期）批量落库时，用它决定插入、更新还是覆盖。

## 用户任务的人员字段类型（user_task_create.persionFieldType）

作用域：workflow / notice

| 值 | 含义 | 备注 |
| --- | --- | --- |
| UserId | 平台用户 Id | 默认；`person_code` 里填的就是用户 Id |
| Account | 登录账号 | 填登录名 |
| JobNumber | 工号 | 填工号 |

> 来源：egmp_gws_mcp v1.0.0 的 `user_task_create`。我们能力目录暂未收录 `user_task_*`，这一组先作为
> 「给某人派任务」时的取值参考；真要用还得先补对应接口能力。
