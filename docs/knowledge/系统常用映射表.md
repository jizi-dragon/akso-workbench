# 系统常用映射表

> 平台把「做什么动作」写成数字：动作节点里是 `behaviorType`，状态按钮里是 `actions[]` 里的类型，菜单里是 `menuActionType`。填错数字通常**不报错**、只是行为不对，所以集中记在这里。
>
> 每组标题下面写 `作用域：workflow / lifecycle / menu / layout …`，卡片详情里的「系统常用映射表」只显示与当前接口域相关的那几组。改完刷新页面即生效。

作用域：workflow

| 值 | 含义 | 备注 |
| --- | --- | --- |

| 20 | 结束节点 | 系统节点，删不掉；`workflow.create` 自动建好（code `…_End__c`、sort 10000） |

## 表单布局联动规则 · 效果属性（rules[].effectSuccess[].value 的键）

作用域：layout

| 值 | 含义 | 备注 |
| --- | --- | --- |
| visible | 显示 | 控件常用；与 `hidden` 反向 |
| hidden | 隐藏 | 分区 / 控件 |
| readOnly | 只读 | 分区 / 控件；`false` 表示解锁 |
| readPretty | 阅读 | 控件 |
| required | 必填 | 控件；字段本身必填时 `false` 会被平台忽略 |
| expansion | 展开 | 分区 |
| activePageCode | 活动页 | 效果目标是「表单布局」时改 |
| activeSectionCode | 活动分区 | 同上 |
| formEditStatus | 表单编辑状态 | 同上 |

> 来源：前端包 `akso-script-entry-index-*.js` 的 `ls`（条件目标）/ `cs`（效果目标）/ `Oa`（运算符）/ `Fa`（组连接），2026-11-23 从线上包读出并核对过一条真实规则；2026-11-24 又用两条「取消场景」规则核对过字段条件与控件效果。
> 规则存在表单布局的 `rules[]` 里，跟着 `SaveLayoutDetail` 整份回写，不是「关系联动规则」`LinkageRule` 那套实体。
> 多条规则命中同一目标同一属性时，以**最后触发**的规则为准；停用（`enable:false`）的规则不参与。
> 条件 `targetType:1`（当前对象字段）的 `targetId` 填字段 id，选项类字段的 `logicValue` 填选项 id；效果 `targetType:5` 的 `targetId` 填控件 id，两者不能混。
> 效果 `value` 只覆盖写出来的属性；控件在布局里 `hidden/visible` 为 `null`（默认显示）时，写 `{ hidden:false }` 是空操作，要做二选一需成对写 `{ hidden:true }` 或把默认改成隐藏。

## 待补：动作库内部编码（actions[] / actionCode）

作用域：workflow / lifecycle

> `behaviorType` 已按前端枚举补齐（见上表与完整表）；这里待补的是动作库条目的内部编码（如“发起工作流”在 `actions[]` 里的 `actionCode`）。没确认前，配置动作先按 `behaviorType` + `behaviorValue` 组装，不要猜内部编码。
