## 为何保留而不是删除

本目录里的文档记录了大量**只在真机复现过的教训**（架构分析 §8 的 10 条排障条目、SESSION-DIGEST 的
20 条环境坑），其中多条无法从当前代码反推出来。内容已全部搬入常驻文档，但保留原文是为了：
1. 溯源——某条结论当初是在哪次事故里得出的；
2. 校验——搬移过程中若发生失真，可对照原文；
3. 反面教材——它们证明了「一份自述版本的架构文档」会在 1 个 MINOR 版本内失效，
   所以现行体系把内容按**变更频率**拆开（ADR 记不变的决策、CONFIG/SCHEMA/API 记随代码走的事实）。
