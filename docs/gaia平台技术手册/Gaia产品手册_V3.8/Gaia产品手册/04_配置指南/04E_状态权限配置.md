# 状态权限配置
> 本指南说明如何在 Gaia 平台中配置生命周期状态权限。 
状态权限用于控制记录在不同生命周期状态下的可见范围和可执行行为。   

---

## 概述

状态权限用于控制“记录处于某个生命周期状态时，用户可以看到什么、可以执行什么”。

它是生命周期状态下的细粒度授权机制，常用于：
- 在“审核中”让关键字段只读
- 在“已批准”限制手动动作
- 在“归档”将多数动作收敛为隐藏或查看，仅对少数必要动作保留执行

---

## 核心概念

| 概念 | 说明 |
|------|------|
| **状态权限** | 按生命周期状态控制字段、动作和相关能力域的可见性与可执行性 |
| **默认状态行为** | 当前状态下的默认权限基线，未单独配置角色覆盖时按此生效 |
| **角色覆盖** | 对指定生命周期角色单独设置权限行为，用于在默认状态行为基础上做差异化控制 |

---

## 权限评估规则

状态权限最终生效结果，建议按以下顺序理解：
1. **权限集对象权限**：先决定用户对对象是否有基础访问能力（读/编/删上限）
2. **生命周期角色**：确定用户在该生命周期中的角色身份
3. **状态默认行为**：应用当前状态的默认状态行为
4. **角色覆盖**：若为某角色配置了覆盖，按覆盖值计算
5. **多角色冲突合并**：同一用户命中多个角色覆盖时，按更宽松的行为生效
> \[!NOTE\]
状态权限不能突破权限集对象权限上限。 
例如：用户对象权限只有“只读”，即使状态权限配置为“编辑”，最终也不能编辑。   

---

## 行为类型说明

### 字段类行为

| 行为 | 含义 |
|------|------|
| **隐藏（Hidden）** | 字段不可见，不可编辑 |
| **查看（Read-only）** | 字段可见，不可编辑 |
| **编辑（Edit）** | 字段可见，可编辑 |

### 动作类行为

| 行为 | 含义 |
|------|------|
| **隐藏** | 动作不显示，用户无法看到也无法执行 |
| **查看** | 动作可见，但不可执行 |
| **执行** | 动作可见，用户可执行 |

动作类行为通常适用于对象动作、用户动作、工作流动作、关系动作、审批矩阵动作等能力域。

---

## 前提条件
- 已在对象上启用生命周期并由系统自动创建生命周期，且已配置状态
- 已配置生命周期角色
- 已明确不同状态下的权限边界（字段可编辑范围、动作开放范围）
- 如需配置关系类状态权限，已在对应关系上启用关系安全设置

---

## 访问路径
1. 进入 **管理端** → **配置管理**
2. 进入 **业务逻辑** → **生命周期**
3. 打开目标生命周期，进入目标状态详情页
4. 在页面中找到 **状态权限** 相关分组并点击【编辑】

---

## 启用关系安全

关系类状态权限用于控制哪些用户可以将对象记录或文档与当前对象建立入站关系。 
只有先启用关系安全，管理员才能在生命周期状态的 **状态权限：关系** 分组中对该关系设置权限行为。

### 启用前确认
- 关系安全控制的是对象的入站关系，因此通常需要在子对象或引用对象一侧进行设置
- 配置前需确认当前对象或父对象是否已启用生命周期
- 如果关系未启用关系安全，即使对象已经配置生命周期，在状态权限中也不会出现该关系

### 启用方法
1. 进入目标对象配置页
2. 打开对象字段或父对象字段配置
3. 勾选 **启用关系安全设置**
4. 保存配置

### 启用后效果
- 在 **对象 → 关系** 页面的入站关系列表中，**是否启用关系安全** 列会显示为“是”
- 未启用时，该列显示为“否”
- 启用后，对应关系会出现在对象生命周期状态详情页的 **状态权限：关系** 分组中
- 管理员可在该分组内继续为关系配置 `隐藏`、`查看` 或 `执行` 等权限行为

### 使用建议
- 仅对确实需要按生命周期状态控制的关系启用关系安全，避免无关关系进入状态权限配置范围
- 如果关系权限没有按预期显示，优先检查关系是否已启用关系安全，以及对象或父对象是否已启用生命周期

## 配置状态权限

### 1\. 配置默认状态行为

先配置默认状态行为，作为所有角色的基线。

常见分组包括：
- **状态权限：字段**
- **状态权限：对象动作**
- **状态权限：附件**
- **状态权限：用户动作**
- **状态权限：工作流**
- **状态权限：关系**
- **状态权限：审批矩阵**

建议先完成“字段”和“动作”两类核心分组，再补充其他分组。

### 2\. 配置角色覆盖

在默认状态行为基础上，对指定角色做差异化控制：
1. 进入目标分组点击【编辑】
2. 选择目标条目（字段或动作）
3. 为目标生命周期角色设置覆盖行为
4. 保存并验证

适用场景示例：
- 默认字段行为为“查看”，仅“编辑者”覆盖为“编辑”
- 默认动作行为为“查看”，仅“拥有者”覆盖为“执行”

### 3\. 按状态分层配置

建议按状态分层收敛权限：
- **起草类状态**：关键字段允许编辑，动作相对开放
- **审核类状态**：字段偏只读，限制手工修改动作
- **批准/归档状态**：动作最小化，优先只读与追溯

---

## 验证清单
1. 同一状态下，不同角色看到的字段和按钮是否符合预期
2. 用户命中多个角色时，最终行为是否符合“更宽松合并”规则
3. 状态切换后，权限是否随状态实时变化
4. 权限集对象权限较低的用户，是否无法越权执行状态权限中的高权限动作
5. 审计日志是否记录关键权限行为与状态变更

---

## 常见问题

**Q1：状态权限配置为“编辑”，用户仍不能编辑，为什么？**   A：先检查权限集对象权限。状态权限不能突破对象权限上限。

**Q2：一个用户属于两个生命周期角色，行为不一致时怎么处理？**   A：同一条目命中多个角色覆盖时，按更宽松行为生效。

**Q3：为什么推荐先配默认状态行为，再配角色覆盖？**   A：先确定基线，再做差异化，能降低遗漏和冲突，后续维护也更清晰。

**Q4：为什么在“状态权限：关系”里看不到目标关系？**   A：先检查该关系是否已启用 **启用关系安全设置**，并确认当前对象或父对象已启用生命周期。未满足前提时，关系不会出现在状态权限中。
