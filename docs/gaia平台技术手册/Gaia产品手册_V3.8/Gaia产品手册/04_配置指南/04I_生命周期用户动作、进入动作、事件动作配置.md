\# 生命周期用户动作、进入动作、事件动作配置
> 本文是生命周期动作配置手册，面向配置管理员。重点说明三类动作如何选、如何配、配完如何验证。   

---

## 文档定位

本文用于指导以下配置工作：
- 在生命周期状态中配置自动动作（进入动作）
- 在生命周期状态中配置用户触发动作（用户动作）
- 在生命周期中配置事件触发动作（事件动作）
- 统一排查动作未触发、触发重复等常见问题

条件表达式明细（进入条件、动作执行条件、用户动作校验、`已变更` 等）已拆分到专题文档：[生命周期状态条件配置](04H_%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F%E7%8A%B6%E6%80%81%E6%9D%A1%E4%BB%B6%E9%85%8D%E7%BD%AE.md)。

---

## 访问路径

### 状态页动作入口

`配置端 > 配置管理 > 业务逻辑 > 生命周期 > 选择目标生命周期 > 选择目标状态`

在状态页可配置：
- 进入动作
- 用户动作

### 事件动作入口

`配置端 > 配置管理 > 业务逻辑 > 生命周期 > 选择目标生命周期 > 事件动作`

---

## 快速决策：三类动作怎么选

| 业务诉求 | 推荐动作类型 | 触发方式 | 用户是否可见 |
|------------|------------------|------------|------------------|
| 记录进入某状态后自动执行 | 进入动作 | 状态变更后自动触发 | 不可见 |
| 用户在页面点击按钮后执行 | 用户动作 | 用户手动触发 | 可见 |
| 创建/修改/复制等事件发生时执行 | 事件动作 | 事件触发自动执行 | 不可见 |

| 判断维度 | 进入动作 | 用户动作 | 事件动作 |
|------------|------------|------------|------------|
| 与状态绑定 | 绑定目标状态 | 绑定当前状态 | 不绑定状态 |
| 典型用途 | 自动更新、联动、发起流程 | 提交审批、人工发起流程 | 初始化、改动后同步 |
| 常见误用 | 用于人工确认场景 | 用于纯系统自动场景 | 与进入动作重复执行同一逻辑 |

## 一、配置进入动作

进入动作在记录进入目标状态时由系统自动执行，常用于状态推进后的自动处理。

### 何时使用
- 进入状态后要自动更新字段或相关记录。
- 进入状态后要自动发起工作流、发送通知或生成编号。
- 进入状态后要执行批量联动，不希望依赖用户手动点击。

### 配置步骤
1. 打开目标生命周期状态。
2. 进入 **进入动作** 页签。
3. 点击 **创建进入动作**。
4. 选择动作类型，填写动作参数。
5. 按需配置执行条件。
6. 调整动作排序。
7. 保存并用测试数据验证。

### 配置用户动作执行前校验规则

执行前校验用于在用户点击动作按钮后、系统正式执行动作前做拦截。校验未通过时，用户动作不会继续执行，系统按配置显示错误消息。

进入用户动作配置后，在执行前校验或条件校验区域新增校验规则，并填写以下参数：

| 参数 | 说明 |
|------|------|
| 名称 | 校验规则显示名称。建议写清校验目的，例如 `提交前必填项校验`。 |
| Code | 校验规则编码，页面保存时按平台规则显示 `&#95;&#95;c` 后缀。 |
| 来源 | 系统显示为 `自定义`，表示该规则由管理员配置。 |
| 验证方式 | 选择校验结果的处理方式。常用选项为 `规则验证未通过视为错误`，表示规则不满足时阻断用户动作。 |
| 规则 | 配置判断条件。默认以 `并且` 组合条件；点击 `+` 可继续新增条件。 |
| 错误消息 | 校验未通过时展示给用户的提示文案。文案应说明用户需要补充或修正的内容。 |
| 消息显示位置 | 选择错误消息在页面上的显示位置。 |
| 消息显示部分Code | 当错误消息需要显示在指定页面区域时，填写对应区域 Code。 |
| 状态 | `启用` 后规则生效；`停用` 后规则不参与用户动作校验。 |
| 描述 | 记录规则用途、适用场景或维护说明。 |

配置完成后保存用户动作，并用满足和不满足条件的记录各测试一次。重点确认两件事：校验未通过时动作被阻断，错误消息能让用户知道下一步怎么处理。

### 关键配置点

| 配置点 | 说明 | 常见问题 |
|---------|------|------------|
| 显示条件 | 控制按钮是否展示 | 误以为“看不到按钮”是规则未命中 |
| 执行前校验 | 点击后正式执行前拦截 | 按钮可见但点击失败 |
| 执行工作 | 动作触发后的系统执行逻辑 | 配置了动作但没有后续处理 |
| 排序与分组 | 控制前端展示顺序 | 同状态按钮太多，用户误点 |

#### 根据表单创建相关对象：创建后的交互

动作类型为「根据表单创建相关对象」时，在「创建方式」旁新增配置项「创建后的交互」，与创建方式独立组合：

| 选项 | 说明 |
|------|------|
| 关闭窗口 | 默认值。创建成功后关闭创建界面，回到主对象详情页，相关对象列表刷新 |
| 弹出层显示详情 | 创建成功后以弹出层打开新记录详情 |
| 抽屉展示详情 | 创建成功后以抽屉打开新记录详情 |
| 新开页面展示详情 | 创建成功后在新标签页（或创建页原地跳转）打开新记录详情 |

仅创建保存成功后触发；表单校验失败或保存失败时不触发。存量动作升级后默认为「关闭窗口」。批量创建时，非关闭窗口选项仅展示最后一条创建成功记录的详情。

运行报告类用户动作（下载运行报告、运行报告生成到附件字段）的参数说明见 [24\_运行报告配置.md](24_%E8%BF%90%E8%A1%8C%E6%8A%A5%E5%91%8A%E9%85%8D%E7%BD%AE.md)。
> \[!NOTE\]
一个用户动作只能维护一组条件校验。需要按不同条件执行不同分支时，建议通过中间状态拆分流程。

## 三、配置事件动作

事件动作在创建、修改、复制等事件发生时自动触发，不依赖用户点击，也不直接依赖当前状态。

### 何时使用
- 记录创建后自动初始化字段或启动流程。
- 记录修改后自动执行同步或补偿逻辑。
- 需要在事件层统一处理规则，而不是挂到某个状态。

### 配置步骤
1. 打开目标生命周期。
2. 进入 **事件动作** 页签。

4. 点击 **创建事件动作**。

6. 按需配置执行条件。
7. 保存并触发对应事件验证结果。

## 条件配置说明（入口导航）

本文只保留动作配置所需的条件入口说明，条件表达式细节统一参见 [生命周期状态条件配置](04H_%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F%E7%8A%B6%E6%80%81%E6%9D%A1%E4%BB%B6%E9%85%8D%E7%BD%AE.md)。

| 条件能力 | 配置位置 | 作用 |
|------------|------------|------|
| 进入条件 | 状态 \> 进入条件 | 控制记录能否进入状态 |
| 进入动作执行条件 | 状态 \> 进入动作 | 控制自动动作是否执行 |
| 用户动作显示条件 | 状态 \> 用户动作 | 控制按钮显示 |
| 用户动作执行前校验 | 状态 \> 用户动作 \> 条件校验 | 控制点击后是否允许运行 |
| 事件动作执行条件 | 生命周期 \> 事件动作 | 控制事件触发后是否执行动作 |

## 推荐配置顺序
1. 先完成状态与流转配置。
2. 配置进入动作，打通自动化主链路。
3. 配置用户动作，补齐人工触发入口。
4. 配置事件动作，补充初始化和事件同步。
5. 统一补充条件规则和提示文案。
6. 做端到端回归验证后再发布。

## 上线前验证清单

| 验证项 | 验证方式 |
|---------|------------|
| 进入动作是否按顺序执行 | 准备命中条件样本，检查动作执行顺序与结果 |
| 用户动作是否按配置展示 | 使用命中/不命中显示条件的样本验证按钮可见性 |
| 用户动作校验提示是否可理解 | 人工触发不满足条件路径，检查提示文案 |
| 事件动作是否重复触发 | 连续创建/修改记录，检查日志和结果记录 |
| 联动范围是否受条件限制 | 构造相关对象多样本，确认不会全量误更新 |

## 常见问题

**Q1：为什么新建记录时没有执行初始状态进入动作？**   A：这是系统默认行为。新建记录进入初始状态时不执行进入动作；从其他状态回到初始状态时才执行。

**Q2：为什么用户能看到按钮但点击失败？**   A：优先检查用户动作的执行前校验规则和提示文案，再检查执行工作和动作参数。

**Q3：为什么动作没有触发？**   A：按顺序检查触发入口（状态/事件是否正确）、执行条件是否命中、动作排序是否被前序动作影响。

**Q4：为什么同一业务逻辑执行了两次？**   A：通常是进入动作和事件动作同时配置了同类逻辑。建议保留一个主触发入口，另一个只做补偿或移除。
