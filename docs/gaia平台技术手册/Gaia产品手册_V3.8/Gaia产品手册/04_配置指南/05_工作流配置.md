\# 工作流配置
> 本文介绍如何在 Gaia 平台配置和管理工作流，包括工作流定义、任务节点、决策分支与自动化规则。   

---

## 概述

Gaia 平台的工作流引擎支持灵活的业务流程自动化，可用于文档审批、变更控制、纠正预防措施（CAPA）等场景。

### 访问路径

**配置端** \> **业务逻辑** \> **工作流**

### 列表页说明

工作流列表页用于查看当前租户下已创建的工作流，并从列表进入对应工作流详情页。

页面左侧导航中：
- `业务逻辑 > 工作流`：工作流定义入口
- `业务逻辑 > 工作流设置`：工作流全局参数入口

列表常见字段如下：

| 字段 | 说明 |
|------|------|
| **名称** | 工作流显示名称。用于配置端识别流程，也会在业务端发起流程时显示。 |
| **Code** | 工作流系统编码，用于区分不同流程定义。建议长期保持稳定。 |
| **工作流类型** | 标识流程属于对象工作流或文档工作流。文档工作流仅适用于文件对象。 |
| **生命周期** | 工作流绑定的生命周期。仅满足该生命周期条件的记录可发起流程。 |
| **状态** | 工作流状态（如编辑中、启用、未启用）。仅启用状态可在业务端发起。 |
| **操作** | 行级入口，可进入查看、编辑等操作。 |

使用建议：先通过搜索、筛选和分页定位目标工作流，再进入详情页维护节点、分支、通知和自动化规则。

## 1\. 工作流基础概念

### 1.1 工作流组成

| 组件 | 说明 |
|------|------|
| **工作流定义** | 整个流程的配置，包含节点、路径和规则。 |
| **节点** | 流程步骤，如工作流任务、判断、合并、动作、更新共享设置、通知。 |
| **路径** | 节点之间的连接关系与流转条件。 |
| **参与者** | 执行任务的用户或角色。 |
| **变量** | 流程运行中传递与复用的数据。 |

### 1.2 节点类型

| 类型 | 说明 |
|------|------|
| **工作流任务** | 需要用户执行的步骤（如评估、审核）。 |
| **判断** | 根据条件进行分支。 |
| **合并** | 汇聚多个分支到同一路径。 |
| **动作** | 由系统自动执行的动作。 |
| **更新共享设置** | 向共享设置中的角色添加或移除参与者。 |
| **通知** | 发送消息通知。 |
> \[!NOTE\]
当前可手动添加的节点类型为：工作流任务、判断、合并、动作、更新共享设置、通知。工作流创建后，系统会自动生成开始步骤和结束步骤；每个工作流有且仅有一个开始步骤和一个结束步骤。开始步骤与结束步骤可编辑但不可删除。

## 2\. 创建与维护工作流

### 2.1 创建工作流
1. 进入 **配置端** \> **业务逻辑** \> **工作流**。
2. 点击页面右上角 **创建**。
3. 在“选择类型”窗口中选择工作流类型并确认。
4. 在创建页填写基础信息并保存。

工作流类型说明：

| 类型 | 说明 | 适用场景 |
|------|------|------------|
| **对象工作流** | 用于对象记录的审批与任务流转。除文件对象外，其余对象均使用对象工作流。 | 偏差、变更、CAPA、培训、申请单等业务对象。 |
| **文档工作流** | 用于文件对象的审批、审阅、发放与签名。 | 仅适用于文件对象。 |

创建页 `详情` 区域常见字段：

| 字段/控件 | 说明 | 是否必填 |
|-------------|------|------------|
| **名称** | 工作流显示名称。 | 是 |
| **Code** | 工作流系统编码，建议使用稳定、可读的英文或缩写。 | 是 |
| **工作流类型** | 创建时确定的类型，在当前页面只读显示。其中文档工作流仅适用于文件对象；除文件对象外，其余对象均使用对象工作流。 | 是 |
| **生命周期** | 绑定生命周期，决定可发起范围。 | 是 |
| **状态** | 当前工作流定义状态。创建页通常默认显示为`未启用`；未启用状态下，工作流不能被动作选中，也不能在业务端发起和使用，需通过**启用**操作后才会成为可用版本。 | 否 |
| **启动状态** | 标识该工作流可以在哪个生命周期状态下启动。如果设置了启动状态，则只有在指定的生命周期状态下才可以发起该工作流。 | 否 |
| **描述** | 说明用途、范围和维护约束。 | 否 |
| **表单布局** | 为该工作流选择表单布局。配置后，发起人或参与人在流程中看到的表单展示方式会以所选布局为准；同时还可以结合该表单布局中的表单规则，进一步控制字段显示、可编辑范围或页面交互效果。 | 否 |

创建页常见复选项：

| 复选项 | 作用 |
|---------|------|
| **允许从进入动作和事件动作自动启动** | 允许由生命周期进入动作或事件动作自动发起流程。 |
| **工作流取消时必须填写注释** | 取消流程时要求填写原因，便于审计。 |
| **对单个对象记录使用工作流** | 流程按单条记录运行；取消勾选通常用于多记录流程。 |
| **只允许用户完成单个任务** | 同一用户在同一流程中仅可完成一个任务。 |
| **工作流发起后禁止变更参与者** | 流程发起后冻结参与者范围。 |
5. 完成必填项后点击 **保存**。保存后，系统会保留当前工作流，并继续在同一页面或后续详情页中维护变量、步骤和取消动作等配置。

新建并保存后的工作流通常先处于**未启用**状态，此时仅表示流程定义已经创建成功，并不代表已经可以投入业务使用。只有后续点击**启用**后，当前工作流定义才会以正式版本生效，满足条件的新流程才能选中并使用该版本。
6. 如需在流程中使用运行时参数，可继续在页面下方的 `变量` 区域点击 **添加变量** 创建变量。变量通常用于：
- 让发起人在开始节点填写额外参数。
- 在判断节点中作为分支条件。
- 在后续步骤中复用流程运行时输入的信息。
7. 如当前暂时不需要变量或取消动作，可以先只保存基础信息，后续再回到工作流详情页继续补充。

### 2.2 工作流详情页

从工作流列表点击流程名称或操作入口，可进入工作流详情页。

**典型面包屑路径**：`工作流 > {工作流名称}`

#### 页面顶部操作

| 操作 | 说明 |
|------|------|
| **返回** | 返回工作流列表页，不保存未提交修改。 |
| **启用** | 将当前工作流切换为可发起状态。只有启用状态的工作流版本才能在业务端被选中和使用；启用后，后续新发起的流程会按当前启用版本运行。 |
| **查看版本** | 查看当前工作流的历史版本，用于核对不同版本之间的配置差异，并确认当前哪一个版本处于启用状态。 |
| **编辑** | 基于当前工作流创建一个新的可编辑版本。点击后，工作流会升版，新版本状态变为`编辑中`，可继续维护详情、步骤、变量和取消动作。 |

#### 详情区域字段

| 字段 | 说明 |
|------|------|
| **名称** | 当前工作流显示名称。 |
| **Code** | 当前工作流系统编码。 |
| **工作流类型** | 当前流程属于对象工作流还是文档工作流。其中文档工作流仅适用于文件对象；除文件对象外，其余对象均使用对象工作流。 |
| **生命周期** | 当前流程绑定生命周期。 |
| **状态** | 当前流程状态，例如编辑中、启用、未启用。只有`启用`状态的版本才可被业务端实际使用；`未启用`和`编辑中`都不能直接用于发起流程。 |
| **启动状态** | 标识该工作流可以在哪个生命周期状态下启动。如果设置了启动状态，则只有在指定的生命周期状态下才可以发起该工作流。 |
| **描述** | 流程用途补充说明。 |
| **表单布局** | 当前流程关联的表单布局。配置表单布局后，还可以结合该布局中的表单规则，进一步控制流程中的字段显示和交互行为。 |
| **版本** | 当前流程定义的版本号。工作流启用后会固定一个正式版本；后续点击**编辑**时会在此基础上升版，新版本进入`编辑中`状态，启用后才会替代旧版本供新流程使用。 |

版本与状态说明：
1. 创建并保存后，工作流先处于**未启用**状态，此时不能被动作选中，也不能在业务端发起。
2. 点击 **启用** 后，当前版本成为正式生效版本，满足条件的新流程会按该版本运行。
3. 已启用的工作流如果需要调整，应点击 **编辑** 进入新版本维护；此时新版本状态为**编辑中**，旧版本仍保持原有启用状态。
4. 如果旧版本已经有未关闭的流程实例，这些实例会继续按旧版本执行，不会因为后续编辑而自动切换到新版本。
5. 只有当编辑中的新版本再次点击 **启用** 后，后续新发起的流程才会使用新版本。

#### 工作流步骤

`工作流步骤` 区域用于维护流程中的开始、任务、动作、判断、合并、结束等步骤。

步骤列表常见字段：

| 字段 | 说明 |
|------|------|
| **名称** | 步骤显示名称。 |
| **Code** | 步骤系统编码。 |
| **类型** | 步骤类型。 |
| **描述** | 步骤用途说明。 |
| **下一个** | 当前步骤完成后流转到的下一个步骤。 |
| **操作** | 进入步骤详情继续配置。 |

#### 变量

`变量` 区域用于维护流程运行时变量。变量可在开始节点填写，也可在判断节点、通知内容和动作参数中复用。

#### 取消动作

`取消动作` 区域用于定义流程取消时需追加执行的规则和动作。

常见字段：

| 字段 | 说明 |
|------|------|
| **规则** | 触发取消动作的条件。 |
| **动作** | 条件满足后执行的系统动作。 |

当该区域显示“暂无数据”时，表示取消流程仅执行系统默认取消行为。

#### 取消动作配置页

在工作流详情页 `取消动作` 区域点击 **新建** 可进入配置页。

**典型面包屑路径**：`{工作流名称} > 取消动作`

主要控件：

| 控件 | 说明 |
|------|------|
| **执行方式** | 控制动作在何种条件下执行。 |
| **总是执行** | 流程一旦取消即执行。 |
| **有条件地执行** | 仅满足条件时执行。 |
| **动作类型** | 取消时要执行的具体动作。 |
| **添加动作** | 新增一条取消动作。 |
| **删除图标** | 删除当前动作行。 |

常见动作类型：

| 动作类型 | 说明 |
|------------|------|
| **发送通知** | 向指定对象发送取消通知。 |
| **修改记录字段** | 更新单个字段值。 |
| **修改记录字段（多字段）** | 一次更新多个字段值。 |

建议将取消动作用于“流程取消后必须补偿处理”的场景，例如通知相关人员、回写业务状态、清理临时数据。

### 2.3 查看版本

在工作流详情页点击 **查看版本** 可进入版本列表页。

**典型面包屑路径**：`对象工作流 > {工作流名称} > 工作流版本`

版本列表常见字段：

| 字段 | 说明 |
|------|------|
| **名称** | 工作流名称。 |
| **版本** | 版本号。 |
| **描述** | 版本说明。 |
| **状态** | 版本状态（编辑中/启用/禁用）。 |
| **创建时间** | 版本创建时间。 |

状态含义：

| 状态 | 说明 |
|------|------|
| **编辑中** | 草稿版本，可继续维护，尚未生效。 |
| **启用** | 当前对业务端生效的正式版本。满足发起条件的新记录会按此版本运行工作流；如果旧版本已有未关闭的流程实例，这些实例仍继续按各自发起时所使用的版本执行。 |
| **禁用** | 历史版本，保留用于追溯，不再作为当前生效版本使用。常见于新版本启用后，旧启用版本转为历史版本。 |

使用版本列表时，通常可以按以下顺序判断：
1. 先看哪一个版本处于**启用**状态，确认业务端当前实际运行的是哪一版。
2. 再看是否存在更高版本号但状态为**编辑中**的版本，确认是否还有尚未发布的草稿调整。
3. 最后通过**创建时间**核对版本演进顺序，辅助排查某次配置变更大致发生在什么时间。
4. 如果业务端同时存在新旧流程实例，应优先确认这些实例分别是在什么版本启用期间发起，再判断它们为什么会使用不同的流程定义。

## 4\. 工作流启动

### 4.1 启动方式

| 方式 | 说明 | 配置位置 |
|------|------|------------|
| **手动启动** | 用户通过动作按钮发起流程。 | 生命周期 \> 用户动作 |
| **自动启动** | 满足条件后由系统自动发起。 | 生命周期 \> 进入动作/事件动作 |

### 4.2 自动启动必要条件

工作流通常需同时满足以下条件才可自动启动：

| 序号 | 条件 | 说明 |
|------|------|------|
| 1 | 允许自动启动 | 在工作流定义中勾选“允许从进入动作和事件动作自动启动”。 |
| 2 | 单记录流程 | 勾选“对单个对象记录使用工作流”。 |
| 3 | 参与者模式兼容 | 开始节点参与者控件应使用系统可自动解析的模式。 |
| 4 | 开始节点控件受限 | 开始节点不应依赖必须由发起人手工填写的控件。 |
| 5 | 不依赖发起人任务 | 自动启动场景下不应要求“工作流发起人”作为必选参与者。 |

### 4.3 控制用户可发起的工作流

通过生命周期 **用户动作** 权限控制不同角色在不同状态下可发起的工作流。

配置建议：
1. 在生命周期状态中创建“发起工作流”类型的用户动作。
2. 在权限配置中按角色设置： 
    - **执行**：允许发起
    - **查看**：按钮可见但不可点击
    - **隐藏**：按钮不可见

权限判断逻辑：
- 未启用 DAC：按生命周期用户动作权限过滤可发起流程。
- 启用 DAC：还会结合共享设置角色权限进一步过滤。

### 4.4 取消动作默认行为

默认情况下，用户取消工作流时，系统会：
- 取消未完成任务
- 通知相关参与者
- 将流程上下文恢复到取消前状态

如需增加额外行为，可在工作流详情页 `取消动作` 区域配置。
> 若管理员在 **系统设置 → 常规设置 → 工作流** 中开启了「取消工作流时输入电子签名」，业务端取消工作流时会先弹出电子签名框，签名通过后再执行取消动作。详见 [03\_系统设置.md](../03_%E7%AE%A1%E7%90%86%E5%91%98%E6%8C%87%E5%8D%97/03_%E7%B3%BB%E7%BB%9F%E8%AE%BE%E7%BD%AE.md)。

## 5\. 工作流监控

### 5.1 实例状态

| 状态 | 说明 |
|------|------|
| **进行中** | 工作流正在执行。 |
| **已完成** | 工作流正常结束。 |
| **已取消** | 工作流被手动取消。 |
| **已失败** | 工作流执行异常失败。 |
| **已暂停** | 工作流被暂停等待。 |

### 5.2 作业重试机制

工作流中的异步任务（如接口调用、脚本执行）失败时，系统采用指数退避重试策略：
- 随重试次数增加，间隔逐步延长
- 减少瞬时故障对系统的冲击
- 提高任务最终成功率

### 5.3 管理权限

管理员通常可以：
- 查看工作流实例状态
- 重新分配任务
- 取消进行中的工作流
- 处理失败的工作流

## 6\. 最佳实践

### 6.1 设计原则
- **简洁清晰**：避免过于复杂的流程设计。
- **职责明确**：每个节点的参与者职责清晰。
- **容错处理**：设置合理的超时和异常处理。
- **可追溯**：关键节点记录审计信息。

### 6.2 常见模式

| 模式 | 场景 |
|------|------|
| **简单审批** | 单一审批人审批。 |
| **层级审批** | 逐级上报审批。 |
| **会签审批** | 多人同时审批，全部通过。 |
| **或签审批** | 多人中任一通过即可。 |
| **条件分支** | 基于金额/风险等级走不同分支。 |
