# 运行报告配置
> 本文介绍如何在 Gaia 平台中配置运行报告模板，并为业务对象提供“下载运行报告”能力。

## 概述

运行报告用于基于 Word 模板生成对象记录的格式化报告。

当前已确认的能力包括：
- 配置运行报告模板
- 定义运行报告的数据源
- 为相关对象生成独立报告
- 启用运行报告模板版本控制
- 在启用版本控制后支持选择模板版本
- 支持按目标语言生成运行报告
- 在生命周期状态中配置“下载运行报告”用户动作
- 配置运行报告名称与压缩包名称
- 异步生成报告并通过通知提供下载链接

### 适用场景

| 场景 | 说明 |
|------|------|
| 记录导出为正式报告 | 将对象记录字段按模板生成 PDF 报告 |
| 记录附带附件下载 | 在下载报告时一并打包记录上的附件源文件 |
| 相关对象资料汇总 | 为相关对象生成独立报告并放入压缩包 |

---

## 前提条件

在配置运行报告前，请先确认：
- 已创建目标对象
- 已明确报告对应的数据来源对象和字段
- 已准备 Word 模板文件
- 已为目标对象配置生命周期

## 1\. 运行报告模板管理

### 1.1 访问路径

运行报告模板位于：

`业务管理 > 模板 > 运行报告模板`

### 1.2 模板列表

模板列表展示系统中的运行报告模板。

| 字段 | 说明 |
|------|------|
| 名称 | 运行报告模板名称 |
| Code | 运行报告模板的 code |
| 模板文件 | 已上传的运行报告模板文件 |
| 所属质量组织 | 模板所属的质量组织；未隔离时可为空 |
| 创建时间 | 模板创建时间 |
| 是否启用版本控制 | 标识当前模板是否启用了版本控制 |
| 版本 | 启用版本控制时显示当前模板版本 |
| 生效时间 | 启用版本控制时显示模板生效时间 |
| 所属对象 | 模板关联的对象 |
| 状态 | 模板当前状态，包含启用和停用 |
| 操作 | 通过操作菜单执行编辑、启用、停用、删除等操作 |

说明：
- 启用版本控制的模板，会在列表中显示`版本`和`生效时间`
- 未启用版本控制的模板，`版本`通常为空

### 1.3 创建模板

在模板列表中点击`创建`，填写以下信息：

| 属性 | 说明 |
|------|------|
| 名称 | 必填，1-200 字符，唯一 |
| Code | 必填，模板 code |
| 所属对象 | 必填，支持标准对象和自定义对象；创建后不可修改 |
| 运行报告模板 | 上传 Word 模板文件；当前方案明确支持 `doc` 格式 |
| 状态 | 启用或停用，默认启用 |
| 描述 | 选填 |
| 数据源 | 定义生成运行报告时使用的数据来源；主对象与所属对象一致，当前支持 3 层 |
| 相关对象报告 | 可为相关对象生成独立报告；当前方案中该部分无层级限制 |

### 1.4 编辑与删除
- 编辑模板时，`所属对象`不可修改
- 运行报告模板在使用时不允许删除
- 删除模板后，该模板不能再在业务端使用
- 删除模板不会影响之前已经生成的运行报告

### 1.5 模板详情页

运行报告模板详情页用于查看模板基础信息、模板文件和数据源设计。

#### 基础信息参数

| 参数 | 含义 |
|------|------|
| 所属质量组织 | 当前模板所属的质量组织。未启用质量组织隔离或未设置时，可显示为空或 `N/A` |
| 名称 | 运行报告模板名称，用于在列表、动作配置和业务端识别该模板 |
| Code | 运行报告模板的唯一标识，用于配置和字段引用识别 |
| 所属对象 | 模板绑定的主对象。运行报告的数据源主对象与此对象保持一致 |
| 状态 | 当前模板是否可用。处于启用状态的模板才可在业务端使用 |
| 字段和部分无数据时显示为 N/A | 控制模板渲染时的空值表现。启用后，字段值为空或模板中的对应部分无数据时显示 `N/A`；未启用时显示为空白 |
| 启用版本控制 | 控制当前模板是否按版本维护。启用后，可按不同模板版本匹配历史或指定版本的数据生成报告 |
| 运行报告模板 | 当前上传的 Word 模板文件，可在详情页直接下载查看原模板 |
| 描述 | 对模板用途或适用范围的补充说明 |
| 运行报告名称 | 用于设置或展示该模板生成运行报告时的名称规则；生成结果命名会结合运行报告名称设置生效 |

#### 页面按钮

| 按钮 | 说明 |
|------|------|
| 返回 | 返回运行报告模板列表页 |
| 编辑 | 进入当前模板的编辑状态 |
| 打开变量生成器 | 打开变量生成器，查看模板可用变量。该能力与叠加层模板中的变量生成器保持一致 |

#### 数据源区域

详情页下方展示数据源设计区域，用于查看当前模板的数据源配置和相关对象报告设计。

| 项目 | 说明 |
|------|------|
| 数据源 | 定义运行报告主数据的来源关系和字段范围 |
| 相关对象报告 | 为相关对象单独设计报告输出结构 |
| 放大显示 | 数据源和相关对象报告设计器支持放大窗口查看与编辑，便于处理复杂关系配置 |
| 入站关系记录数量提示 | 页面提示入站关系中的记录数量建议不要超过 500 条；记录过多时，可能导致生成运行报告耗时过长，甚至失败 |

#### 数据源支持的类型

在数据源设计区域中，当前支持添加以下类型：

| 类型 | 含义 | 适用场景 |
|------|------|------------|
| 相关对象 | 基于主对象与其他对象之间已配置的对象关系取数。通常用于按对象关系向下展开关联记录或字段 | 需要在报告中展示主对象关联的业务对象数据，如子记录、关联单据、关联版本等 |
| 审批矩阵 | 基于审批矩阵配置取数。用于将与当前业务记录匹配到的审批矩阵信息作为报告数据来源之一 | 需要在报告中展示审批角色、审批链路、矩阵匹配结果等审批配置数据 |
| 查询列表 | 基于查询列表取数。页面上通常需要选择列表布局和对象，用于按列表定义的结果集组织输出数据 | 需要按既定列表规则汇总一组记录，而不是仅按单一对象关系直接取数 |

说明：
- `相关对象`更偏向按对象关系直接取数
- `审批矩阵`更偏向引入审批配置或审批参与结构
- `查询列表`更偏向基于列表定义组织一组查询结果

#### 查询列表配置说明

从当前页面表现看，查询列表通常包含以下配置项：

| 参数 | 含义 |
|------|------|
| 列表布局 | 指定查询结果采用哪一个列表布局进行组织或展示 |
| 对象 | 指定该查询列表面向的对象类型 |

#### 相关对象与相关对象报告的区别

| 项目 | 含义 |
|------|------|
| 数据源中的相关对象 | 将相关对象作为主报告的一部分数据来源，数据会参与主报告渲染 |
| 相关对象报告中的关系 | 为相关对象单独生成独立报告，不直接并入主报告正文结构 |

### 1.6 版本控制

运行报告支持版本控制。

适用场景：
- 运行报告模板配置发生变化后，历史业务数据仍需要匹配之前版本的模板
- 新旧流程并存时，需要避免历史记录直接使用最新模板生成报告

配置建议：
- 当运行报告模板会随业务流程或字段结构调整而变化时，建议启用版本控制
- 启用后，应按版本维护对应的运行报告模板，避免历史记录与模板不匹配

## 2\. Word 模板要求

---

运行报告基于 Word 模板生成。

### 2.1 模板文件
- 使用 Word 模板文件
- 模板中可插入对象字段和相关对象字段
- 模板中的字段名称应与对象字段的 `code` 保持一致

### 2.2 数据源范围

| 配置项 | 说明 |
|---------|------|
| 主对象 | 与所属对象一致 |
| 数据源层级 | 当前支持 3 层 |
| 相关对象报告 | 可单独生成，不受层级限制 |

---

## 3\. 模板语法

运行报告模板语法基于 Aspose.Words 的 LINQ Reporting Engine。详细语法可参考官方文档： [https://docs.aspose.com/words/net/template-syntax/](https://docs.aspose.com/words/net/template-syntax/)

### 3.1 基本写法

模板标签使用 `<< >>` 包裹，最常见的写法是：
```text
<<[表达式]>>
```

其中，`表达式` 用于读取当前数据源中的字段、变量或计算结果。

### 3.2 输出字段值

可直接在模板中输出当前对象或当前循环项的字段值。例如：
```text
运行报告名称：<<[name__ak]>>
运行报告编码：<<[code__ak]>>
状态：<<[status__ak]>>
```

如果在循环中输出相关记录，可使用当前项变量：
```text
<<foreach [item in RelatedItems]>>
- <<[item.name__ak]>>
<</foreach>>
```

### 3.3 格式化输出

字段输出时可追加格式说明，用于日期、时间或文本格式化。例如：
```text
创建时间：<<[create_time__sys]:"yyyy-MM-dd HH:mm:ss">>
生效日期：<<[effective_time__sys]:"yyyy-MM-dd">>
```

### 3.4 循环输出列表

当数据源返回的是多条记录时，可使用 `foreach` 输出列表内容。

基本语法：
```text
<<foreach [item in 集合表达式]>>
  模板内容
<</foreach>>
```

示例：
```text
缺陷列表：
<<foreach [item in Defects]>>
- 缺陷名称：<<[item.name__ak]>>
  缺陷编号：<<[item.code__ak]>>
<</foreach>>
```

### 3.5 条件判断

当需要根据字段值决定是否显示某段内容时，可使用条件语法。

基本语法：
```text
<<if [条件表达式]>>
  条件成立时输出
<<elseif [条件表达式]>>
  其他条件成立时输出
<<else>>
  默认输出
<</if>>
```

示例：
```text
<<if [status__ak == "启用"]>>
当前模板状态：启用
<<else>>
当前模板状态：未启用
<</if>>
```

### 3.6 变量

可先定义变量，再在后续内容中复用。

基本语法：
```text
<<var [reportTitle = name__ak + "运行报告"]>>
标题：<<[reportTitle]>>
```

### 3.7 HTML 输出

如果数据内容本身包含 HTML，可使用 `-html` 让模板按 HTML 渲染。

示例：
```text
<<[description__ak] -html>>
```

### 3.8 示例组合

下面是一个简化示例，演示字段输出、循环和条件的组合写法：
```text
运行报告：<<[name__ak]>>
生成时间：<<[create_time__sys]:"yyyy-MM-dd HH:mm:ss">>

<<if [status__ak == "启用"]>>
模板状态：当前模板已启用
<<else>>
模板状态：当前模板未启用
<</if>>

相关缺陷：
<<foreach [item in Defects]>>
- 名称：<<[item.name__ak]>>
  编码：<<[item.code__ak]>>
<</foreach>>
```

### 3.9 使用建议
- 模板语法应尽量保持简洁，优先使用清晰的字段输出和简单判断。
- 循环和条件可以嵌套，但不建议层级过深，以免维护困难。
- 模板发布前，建议使用真实或接近真实的数据进行测试，确认字段、格式和循环结果正确。
- 字段名、变量名和数据源命名应保持一致，便于后续排查和维护。

## 4\. 配置下载运行报告动作

运行报告可通过以下入口提供给业务端用户：
- **生命周期用户动作**：`对象配置 > 目标对象 > 生命周期 > 目标状态 > 用户动作`，动作类型为「下载运行报告」（仅配置的状态可见）
- **对象动作**：`对象配置 > 目标对象 > 动作`，分配「下载运行报告」后，所有生命周期状态共享该配置（详见 [22\_对象动作配置.md](22_%E5%AF%B9%E8%B1%A1%E5%8A%A8%E4%BD%9C%E9%85%8D%E7%BD%AE.md)）
- **进入动作 / 用户动作「运行报告生成到附件字段」**：将报告写入附件字段，参数见下文水印与语种说明；动作清单见 [04I\_生命周期用户动作、进入动作、事件动作配置.md](04I_%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F%E7%94%A8%E6%88%B7%E5%8A%A8%E4%BD%9C%E3%80%81%E8%BF%9B%E5%85%A5%E5%8A%A8%E4%BD%9C%E3%80%81%E4%BA%8B%E4%BB%B6%E5%8A%A8%E4%BD%9C%E9%85%8D%E7%BD%AE.md)

### 4.1 动作类型

新增动作类型：

`下载运行报告`

### 4.2 配置位置

用户动作路径：`对象配置 > 目标对象 > 生命周期 > 目标状态 > 用户动作`

对象动作路径：`对象配置 > 目标对象 > 动作`

在新增或编辑时，页面会先配置通用动作信息，再配置“下载运行报告”专属参数。对象动作与用户动作的专属参数保持一致。

### 4.3 动作参数

#### 通用动作信息

| 参数 | 控件 | 说明 |
|------|------|------|
| 动作名称 | 输入框 | 用户动作的显示名称；为必填项 |
| Code | 输入框 | 用户动作的唯一编码；为必填项 |
| 图标 | 下拉框 | 配置动作按钮显示的图标 |
| 分组 | 下拉框 | 配置该用户动作所属分组 |
| 动作类型 | 下拉框 | 选择为 `下载运行报告` |

#### 下载运行报告专属参数

| 参数 | 控件 | 说明 |
|------|------|------|
| 模板 | 下拉框 | 选择该对象上已配置的运行报告模板；基于所选模板生成运行报告 PDF 文件 |
| 下载格式 | 下拉框 | 当前页面支持配置下载格式；运行报告当前生成结果为 `PDF` |
| 目标语言 | 选择项 | 必选；首项为「不翻译（原始语言）」，其后为模板支持的具体语种 |
| 启用预览 | 复选框 | 控制用户执行该动作时是否支持预览运行报告 |
| 包含附件 | 复选框 | 选中后会将附件内容一并纳入下载结果 |
| 主对象包含相关对象附件 | 复选框 | 控制主对象生成结果中是否同时包含相关对象附件 |
| 合并附件到报告 | 复选框 | 控制附件内容是否合并到运行报告结果中 |
| 当运行报告启用版本控制后允许用户选择模板版本 | 复选框 | 仅在模板启用版本控制时生效；允许用户在下载时选择模板版本 |
| 显示水印 | 复选框 | 控制生成结果是否显示水印；同时适用于「下载运行报告」与「运行报告生成到附件字段」（含生成到相关对象附件字段） |
| 是否常用动作 | 复选框 | 控制该动作是否作为常用动作使用 |
| 不显示在操作栏 | 复选框 | 控制该动作是否在操作栏中隐藏 |

### 4.4 选择模板版本

当运行报告模板已启用版本控制时，可进一步支持在生成报告时选择模板版本。

适用说明：
- 该能力建立在“运行报告支持版本控制”基础上
- 对应用户动作 / 对象动作中的 `当运行报告启用版本控制后允许用户选择模板版本`
- 用于在同一模板存在多个版本时，按需要选择具体模板版本生成报告
- 该能力应与未启用版本控制的模板区分使用

适用动作：

| 动作 | 说明 |
|------|------|
| 下载运行报告 | 用户执行下载前可选择模板版本 |
| 运行报告生成到附件字段 / 生成到相关对象附件字段 | 生成写入附件前可选择模板版本（开关开启且模板已启用版本控制时） |

未开启版本控制，或动作未勾选「允许用户选择模板版本」时，系统按当前生效模板版本生成，不展示版本选择器。

### 4.5 多语言与语种选择

运行报告支持按目标语言生成报告，也支持显式选择不翻译。

适用方式：
- 在用户动作 / 对象动作中指定`目标语言`
- 在表单布局支持的下载入口中，由用户选择语种后下载
- 在运行报告预览的语种切换器中切换语种

目标语言选项：

| 选项 | 说明 |
|------|------|
| 不翻译（原始语言） | 跳过全部翻译逻辑（含已维护翻译值与 AI 翻译），以模板原始语言生成报告；新建动作时默认选中 |
| 具体语种（如 English） | 按该语种翻译生成报告 |

翻译规则（选择具体语种时）：
- 字段名称显示为目标语种对应的名称
- 字段值优先使用该语种下已维护的翻译值
- 若对应语种的翻译值为空，则调用 AI 自动翻译

说明：
- 模板未启用「支持翻译」时，目标语言通常仅显示「不翻译」且不可选其他语种
- 表单布局启用「允许用户选择语种」后，用户侧下拉首项同样为「不翻译（原始语言）」
- 用户在表单中手动切换语种（含切回不翻译）后，以用户选择为准生成报告
- 历史数据中目标语言为空时，行为等同于「不翻译」

### 4.6 显示水印

`显示水印` 控制运行报告 PDF 是否叠加水印，覆盖以下场景：

| 动作 | 生效说明 |
|------|------------|
| 下载运行报告（用户动作 / 对象动作） | 勾选后下载的 PDF 显示水印；未勾选则不显示 |
| 运行报告生成到附件字段 | 勾选后写入附件字段的报告 PDF 显示水印 |
| 运行报告生成到相关对象附件字段 | 与生成到附件字段相同，按动作上的水印开关生效 |

水印内容与样式仍受系统附件水印/水印设置约束；本开关决定该次生成是否应用水印。

### 4.7 预览弹出层

当用户动作勾选 `启用预览` 后，用户执行“下载运行报告”时，可先在弹出层中预览报告内容。

#### 预览弹出层组成

| 区域 | 说明 |
|------|------|
| 顶部标题区 | 显示当前预览记录名称 |
| 模板选择区 | 支持在弹出层顶部选择运行报告模板 |
| 语种选择区 | 支持切换预览使用的语种；首项为「不翻译（原始语言）」 |
| 附件显示开关 | 支持通过 `显示附件` 控制是否在预览中显示附件相关内容；显示后可查看附件列表 |
| 操作按钮区 | 支持 `下载`、`打印` 和关闭弹层 |
| 左侧记录列表 | 显示可切换的记录列表，便于在同一弹层中查看不同记录的预览结果 |
| 中间预览区 | 显示运行报告正文内容 |
| 预览工具栏 | 支持页码切换、缩放、全屏等查看操作 |

#### 预览页中的典型操作
- 选择运行报告模板后预览对应模板生成的内容
- 切换语种（含「不翻译」）后查看对应语言的预览结果
- 勾选 `显示附件` 后查看附件相关预览内容
- 在预览界面中对附件进行预览
- 在预览界面中下载附件
- 通过 `下载` 直接下载当前运行报告
- 通过 `打印` 输出当前预览内容

#### 预览中的下载方式

在预览弹出层中点击 `下载` 时，支持以下两种下载方式：
- `下载原格式`
- `下载PDF格式`

#### 说明
- 预览弹出层用于下载前核对内容，不替代最终下载结果。
- 预览页面中的展示内容会受模板、语种及附件显示开关影响。
- 开启 `显示附件` 后，附件除可显示外，还支持在预览界面中直接预览和下载。
- 预览弹出层中的下载菜单可按需要选择原格式或 PDF 格式。

`管理端 > 系统设置 > 常规设置 > 运行报告名称设置`

可配置以下内容：

## 6\. 生成与下载

### 6.1 生成方式

用户点击已配置的`下载运行报告`动作后，系统会异步生成运行报告。

### 6.2 生成结果
- 运行报告生成为 `PDF` 文件
- 可按目标语言生成对应语种的报告
- 如勾选`包含附件`，系统会将附件源文件一并打包

### 6.3 单文件直下与多文件压缩包

下载结果按最终文件数量分流：

| 场景 | 下载结果 |
|------|------------|
| 最终仅 1 个文件（例如仅报告 PDF，未附带其他附件） | **直接下载原文件**，不打包为 ZIP |
| 最终文件数大于 1（报告 \+ 附件，或多份相关报告等） | 维持 **ZIP 压缩包**下载 |

说明：
- 单文件直下时，文件名仍按「运行报告名称格式」规则生成。
- 站内信 / 邮件中的下载链接遵循同一分流规则。
- 异步生成、通知与权限模型不变，仅下载封装方式按文件数量区分。

### 6.4 通知方式

处理完成后，系统通过以下渠道通知用户：
- 站内信
- 邮件

通知消息中附带报告下载链接。

### 6.5 用户提示

触发下载后，页面提示：

`运行报告生成中，系统将在处理完成后向您发送通知。`

### 6.6 下载结果结构（多文件）

多文件场景下，压缩包通常包含：
- 运行报告 PDF 文件
- 主记录上的附件源文件
- 相关对象的报告或文件夹

### 6.7 批量打印运行报告

在对象列表页，可对多条记录一次性生成运行报告并合并为单个 PDF，再进入打印预览。

| 项 | 说明 |
|---|------|
| 入口 | 对象列表页动作区 **批量打印运行报告**（需对象已配置可用运行报告模板，且用户具备对应权限） |
| 前置条件 | 至少勾选一条记录；未勾选时动作禁用 |
| 确认内容 | 通常包含对象、已选数量、运行报告模板、模板版本、目标语言、是否包含附件等 |
| 执行方式 | 通过后台任务执行；可留在当前页查看进度，也可关闭浮层后从任务中心 / 通知打开结果 |
| 结果 | 多条报告合并为一个 PDF；确认预览后调用浏览器打印；打印动作可记入审计 |

注意：
- 仅支持同一对象列表内批量，不支持跨对象混合打印。
- 记录多、含附件或单份 PDF 较大时，耗时可能较长。
- 移动端不提供该批量入口。
- 单条记录的「下载运行报告」逻辑不变；批量打印是列表侧增强能力。

## 7\. 常见规则

运行报告生成过程中，按以下规则处理数据：

| 场景 | 结果 |
|------|------|
| 对象本身为空 | 返回空白 |
| 对象存在，但字段值为空 | 返回 `N/A` |
| 附件为空 | 返回空白 |
| 模板变量填写错误 | 不返回错误信息，对应位置显示空白 |

如果生成过程失败，系统会发送失败通知，错误信息会记录到程序异常日志中。
