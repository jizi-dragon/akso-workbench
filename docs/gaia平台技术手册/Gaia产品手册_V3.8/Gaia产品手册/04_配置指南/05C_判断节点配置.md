# 判断节点配置

判断节点用于根据条件决定流程进入哪个后续分支。系统会按规则顺序依次判断，命中后进入对应分支。

---

## 判断节点配置

### 1.1 详情区配置

`详情` 区用于维护判断节点的基础信息（如节点名称、说明等）。

该区域主要用于识别和管理节点本身，不直接定义分支命中逻辑；分支命中逻辑在 `规则区` 配置。

### 1.2 规则区配置

`规则区` 用于配置“如果…则…”条件，决定命中后进入哪个分支。

#### 条件类型

判断节点支持以下条件类型：

| 条件类型 | 用途 | 说明 |
|------------|------|------|
| **字段** | 按对象字段值判断分支 | 字段来源支持**当前对象字段**和**出站对象字段**。 |
| **流程任务断言** | 按前置任务节点断言结果判断分支 | 适合“任务执行结果是否满足要求”的分支判断。 |
| **流程变量** | 按流程变量值判断分支 | 适合按发起页输入或上游节点产出变量做分流。 |

说明：
- 判断节点中的逻辑条件（`并且` / `或者`、条件组加减、条件顺序）与生命周期中的逻辑条件配置方式一致。
- 复杂场景可通过条件组组合多个条件类型，实现多维度分支判断。

#### 流程任务断言配置

选择条件类型为 `流程任务断言` 后，通常需要依次选择：
1. 任务节点（例如：`审核中`）
2. 断言比较方式（下拉选项）

断言比较方式包括：

| 比较方式 | 命中条件 |
|------------|------------|
| **所有断言等于** | 该任务节点下全部断言都等于目标值时命中。 |
| **至少一个断言等于** | 该任务节点下至少一个断言等于目标值时命中。 |
| **没有断言等于** | 该任务节点下没有任何断言等于目标值时命中。 |

使用建议：
- 使用 `流程任务断言` 前，先确认对应任务节点已配置断言项。
- 多条规则同时引用同一任务节点时，建议在描述中写清判断意图，便于后续维护。

### 1.3 默认分支与执行顺序

判断节点按规则列表从上到下依次执行匹配。系统命中第一条满足条件的规则后，即进入该规则指定分支。

建议同时配置默认分支：当所有规则都未命中时，流程可进入默认分支继续执行，避免流程中断或走向不明确。
