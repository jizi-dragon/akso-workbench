\# 通知节点配置

通知节点用于在指定流程阶段向目标对象发送通知消息，推动协作信息同步。

---

## 通知节点配置

通知节点用于在流程运行到当前步骤时，向指定收件人发送系统通知。常见场景是：流程通过审批后通知提交人，或在分支判断后通知下一处理人。

### 1.1 页面路径与顶部操作

**典型面包屑路径**：

`工作流 > {工作流名称} > 新建节点`

页面右上角常见操作如下：

| 操作 | 说明 |
|------|------|
| **返回** | 放弃当前未保存修改并返回上一页。 |
| **保存** | 保存当前通知节点配置。保存成功后，节点可在流程中按配置发送通知。 |

### 1.2 详情区配置

`详情` 区用于维护通知节点的基础信息。

| 字段 | 说明 |
|------|------|
| **名称** | 节点显示名称。 |
| **Code** | 节点系统编码，建议使用稳定英文标识。 |
| **类型** | 固定为`通知`。 |
| **描述** | 说明该通知节点的用途。 |
| **下一步** | 当前通知节点执行后流转到的下一节点。 |

### 1.3 通知区配置

`通知` 区用于配置具体通知条目（如“通知1”）。

| 配置项 | 是否必填 | 说明 |
|---------|------------|------|
| **消息模板** | 是 | 选择要发送的通知模板。 |
| **收件人** | 是 | 选择该条通知的接收对象。 |

页面操作：
- 点击`添加通知`可继续新增通知条目。
- 每条通知右上角的`×`可删除该条通知。
- 点击右上角`保存`后，节点按当前通知配置生效。

使用建议：
- 需要给不同人群发送不同内容时，建议拆分为多条通知分别配置。
- 保存前确认每条通知的`消息模板`与`收件人`均已选择，避免节点执行时漏发通知。
