# 对象动作配置
> 本文说明如何为对象定义并管理“对象动作”，包括动作分配、动作级安全（ALS）和权限配置。对象动作是记录动作（Record Action）在具体对象上的可执行实例。   

---

## 概述

对象动作用于在对象记录上提供可执行入口。配置完成后，用户可在记录详情页的“动作”菜单中看到并执行对应动作。

核心特征如下：
- 对象动作来源于记录动作定义。
- 对象动作可按对象和对象类型进行配置。
- 对象动作不绑定到某一个生命周期状态。
- 动作是否可见、可点击，取决于权限与动作安全配置。

---

## 1\. 管理入口

### 1.1 查看记录动作定义

路径：`配置端 > 配置管理 > 记录动作`   用途：查看平台可分配的记录动作定义。

### 1.2 管理对象动作实例

路径：`配置端 > 对象配置 > 对象 > {对象} > 动作`   用途：将记录动作分配到指定对象，并维护该对象下的动作实例。

---

## 2\. 为对象分配动作

### 2.1 操作步骤（创建动作页）
1. 进入 `对象 > {对象} > 动作` 页签。
2. 点击 **创建**，进入“创建动作”页面。
3. 在 **动作** 下拉框中选择要分配的记录动作。
4. 填写 **名称** 与 **Code**。
5. 按需设置 **状态**、**动作分组**、**描述**，并根据页面是否显示相关开关，设置 **设置为常用动作**、**用于生命周期用户动作类型**。
6. 点击 **保存**。若对象已关联生命周期，系统会提示为各生命周期状态设置 Atomic Security 默认值。

### 2.2 字段说明（创建动作页）

| 字段 | 必填 | 说明 |
|------|------|------|
| 动作 | 是 | 选择要分配到当前对象的记录动作。选择后，系统会自动带出 `sourceCode`、`来源`、`用途` 等只读信息。 |
| 名称 | 是 | 对象动作在配置端和业务端的显示名称，建议使用“动词 \+ 业务对象/结果”的命名方式（如“提交审批”）。 |
| Code | 是 | 对象动作的技术标识，建议使用英文小写和下划线，发布后保持稳定，避免影响权限、流程或自动化引用。 |
| sourceCode | 否（只读） | 记录动作定义的源编码。未选择动作时显示 `N/A`。 |
| 来源 | 否（只读） | 记录动作来源（如系统内置或自定义）。未选择动作时显示 `N/A`。 |
| 用途 | 否（只读） | 记录动作用途类型（如用户对象动作、批量操作等）。未选择动作时显示 `N/A`。 |
| 状态 | 否 | 默认 `启用`。停用后，动作实例保留但不再作为可执行入口提供给业务端用户。 |
| 动作分组 | 否 | 用于对动作进行分类管理，便于在动作较多时按分组维护和展示。 |
| 描述 | 否 | 配置备注信息，仅用于管理员理解配置意图，不在业务端直接展示。 |
| 用于生命周期用户动作类型 | 否（部分动作显示） | 勾选后，该动作可在 `生命周期 &gt; 状态 &gt; 用户动作` 的动作类型中被选择使用；不勾选时，该动作仅作为对象动作入口使用。 |
| 设置为常用动作 | 否 | 勾选后，动作通常会在业务端优先展示；不勾选时通常进入“更多动作”区域。最终展示位置受页面布局和权限配置影响。 |

### 2.3 创建页面的校验与生效说明
1. `动作`、`名称`、`Code` 为必填，未填写时无法保存。
2. `Code` 建议在上线前一次性确定，避免后续改名带来权限与脚本引用调整成本。
3. 保存后仅表示“对象动作实例”创建成功，业务端是否可见、可点击，仍取决于后续 ALS 与权限配置。
4. 对于需要在生命周期中复用的动作，需勾选 **用于生命周期用户动作类型**，否则在生命周期用户动作配置中不可选。
5. 建议创建后立即联动检查：`权限集/执行`、`状态权限/角色`、业务端实际展示位置。

### 2.4 可分配「下载运行报告」

对象可分配的记录动作中包含「下载运行报告」。配置后：
- 该对象所有生命周期状态下均可执行（不绑定单一状态）
- 可在详情页工具栏（记录操作）或列表批量操作中使用（取决于用途配置）
- 专属参数（模板、包含附件、目标语言、显示水印等）与用户动作「下载运行报告」一致

详细参数、语种「不翻译」、水印生效范围与生成结果说明见 [24\_运行报告配置.md](24_%E8%BF%90%E8%A1%8C%E6%8A%A5%E5%91%8A%E9%85%8D%E7%BD%AE.md)；生命周期用户动作入口见 [04I\_生命周期用户动作、进入动作、事件动作配置.md](04I_%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F%E7%94%A8%E6%88%B7%E5%8A%A8%E4%BD%9C%E3%80%81%E8%BF%9B%E5%85%A5%E5%8A%A8%E4%BD%9C%E3%80%81%E4%BA%8B%E4%BB%B6%E5%8A%A8%E4%BD%9C%E9%85%8D%E7%BD%AE.md)。

## 3\. 配置动作安全

动作级安全建议分两层配置：权限集 层和 状态权限 层。

### 3.1 权限集 层

用于在权限集级别控制动作的基础权限：
- `查看`：用户可看到动作。
- `执行`：用户可执行动作。

配置路径：`用户与组 > 权限集 > {权限集} > 对象 > {对象}`   在“对象动作权限”中编辑并保存。

说明：
- 可按“全部对象动作”授权，也可按具体动作逐个授权。
- 若使用“全部对象动作”授权，后续新增动作通常会自动纳入该授权范围。

### 3.2 状态权限 层

用于在生命周期状态和角色维度控制动作表现：
- 隐藏（不可见）
- 查看（置灰）
- 执行

状态权限 层用于精细化控制“在哪个状态、哪些角色可执行哪些动作”。

### 3.3 推荐配置顺序
1. 先分配对象动作实例。
2. 再配置权限集的 `查看/执行`。
3. 最后配置 状态权限 的状态与角色策略。

---

## 4\. 执行权限说明

对象动作通常以系统级权限上下文执行。 
这意味着：即使用户对目标对象没有显式创建权限，只要被授予了该动作的执行权限，仍可能通过该动作完成相关数据创建或更新。

上线前建议检查：
1. 动作是否涉及跨对象写入。
2. 执行结果是否超出用户日常对象权限预期。
3. 是否已配置必要的前置校验、确认提示与审计追踪。

---

## 5\. 常见问题

### 5.1 动作未显示

可按以下顺序排查：
1. 动作实例是否已分配到该对象。
2. 权限集是否授予该动作 `查看`。
3. 状态权限 是否将动作设置为隐藏。

### 5.2 动作显示但不可点击

可按以下顺序排查：
1. 权限集是否授予该动作 `执行`。
2. 状态权限 是否将动作设置为“可见但不可执行”。
3. 当前记录状态和角色是否命中执行策略。
