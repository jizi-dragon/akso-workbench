## 概述

Gaia 通知体系由三层组成：
1. 触发层：生命周期事件、工作流节点、系统任务触发通知。
2. 模板层：消息模板（含适用对象范围）决定通知内容与渠道展示。
3. 投递层：企业微信、钉钉、邮件、站内信、短信、平台消息、外部协作专用邮件、WeLink、飞书等渠道发送并记录状态。

### 功能支持范围

| 功能 | 说明 |
|------|------|
| 模板适用对象 | 在模板中选择“所有对象”或“单个对象（特定对象）” |
| 消息模板管理 | 统一维护通用模板和渠道专属模板 |
| 模板变量替换 | 支持对象字段、任务字段、全局变量 |
| 通知触发规则 | 生命周期进入动作、工作流节点、系统通知 |
| 渠道接入 | 企业微信、钉钉、邮件、站内信、短信、平台消息、外部协作专用邮件、WeLink、飞书 |
| 发送监控与重试 | 发送日志、失败重试、手动重试、CSV 导出 |

---

## 前提条件

在开始配置前，请确认：
- 账号具备通知相关菜单的访问权限。
- SMTP 已完成连通性配置（需要邮件通知时）。
- 如果消息渠道使用企业微信、钉钉或飞书，需先在`系统设置 > 第三方设置`完成对应第三方应用基础设置。
- 如果消息渠道使用短信，需先在短信供应商完成短信模板备案，并在`系统设置 > 第三方设置`完成短信服务商基础配置。
- 生命周期或工作流中已有可触发通知的业务动作。
- 模板将引用的字段在目标对象中真实存在。

---

## 配置总流程
1. 在消息模板中选择适用对象（所有对象或单个对象），明确模板生效范围。
2. 创建消息模板，先完成通用模板，再按渠道覆写。
3. 在生命周期或工作流中引用对应的消息模板。
4. 配置第三方渠道参数（如邮件、协作平台、短信）。
5. 在测试环境联调并验证变量、链接和投递结果。
6. 发布后在消息作业监控中持续观察失败率和重试情况。

## 1\. 消息模板配置

### 1.1 访问路径

`管理端 > 配置管理 > 通知模板 > 消息模板`

### 1.2 模板结构

消息模板采用“通用模板 \+ 渠道专属模板”：
- 通用模板：统一维护主题、跳转链接、正文基线。
- 渠道专属模板：在单个渠道覆盖通用模板内容。
- 勾选“覆盖通用模板”后，该渠道发送时优先使用专属模板。

### 1.3 创建模板

点击“创建”后，先在基础信息区完成以下字段（与创建界面一致）：

| 字段 | 必填 | 说明 |
|------|------|------|
| 名称 | 是 | 建议格式：`&#91;业务域]&#95;&#91;对象]&#95;&#91;场景]` |
| Code | 是 | 系统唯一编码，建议语义化且稳定 |
| 来源 | 是 | 默认“自定义”，通常保持默认值 |
| 对象 | 是 | 模板适用对象；可选择“所有对象”或“单个对象（特定对象）” |
| 状态 | 是 | 启用/停用 |
| 通知渠道类型 | 是 | 勾选可发送渠道（企业微信、钉钉、邮件、站内信、短信、平台消息、外部协作专用邮件、WeLink、飞书） |
| 描述 | 否 | 说明模板用途、触发来源和维护边界 |

“对象（适用对象）”选择建议：

| 选项 | 含义 | 典型场景 |
|------|------|------------|
| 所有对象 | 模板可被不同对象复用，变量以通用变量为主 | 平台级通用提醒、系统类通知 |
| 单个对象（特定对象） | 模板仅用于选定对象，变量生成器按该对象字段提供 | 偏差、培训、文档等业务对象通知 |
1. 跨对象复用通知时，优先选“所有对象”。
2. 需要引用对象字段（如记录名称、状态、负责人）时，选“单个对象（特定对象）”。
3. 绑定流程前，确认触发对象与模板适用对象一致，避免变量为空或模板不可选。

### 1.4 配置通用模板

| 控件 | 作用 | 配置要点 |
|------|------|------------|
| 主题 | 定义通知标题 | 可插入变量，不建议过长 |
| 跳转链接 | 定义点击后进入页面 | 建议使用记录 URL 变量，避免硬编码 |
| 模板内容 | 定义正文 | 支持变量、富文本、超链接 |
| 变量生成器 | 快速插入变量 | 按对象范围筛选，避免插入无效字段 |

### 1.5 配置渠道与渠道专属模板

在“通知渠道类型”字段中勾选渠道后，系统生成对应渠道页签。可按渠道覆写。

当前页面可选渠道（与界面一致）：
- 企业微信
- 钉钉
- 邮件
- 站内信
- 短信
- 平台消息
- 外部协作专用邮件
- WeLink
- 飞书

| 渠道 | 建议写法 |
|------|------------|
| 企业微信 | 标题简洁，首句写清任务动作和截止时间 |
| 钉钉 | 先写结论，再给处理入口链接，避免长段落 |
| 邮件 | 标题完整、正文结构化、保留处理链接 |
| 站内信 | 短句提醒，突出“要做什么” |
| 短信 | 内容最短化，避免复杂变量和富文本 |
| 平台消息 | 用统一格式输出，便于批量处理 |
| 外部协作专用邮件 | 内容以对外沟通口径为准，避免内部术语和内部链接 |
| WeLink | 重点信息前置，正文控制长度，保留可点击处理入口 |
| 飞书 | 建议使用短段落和清晰动作词，减少复杂排版 |

### 1.6 渠道专项配置

#### 邮件渠道

| 配置项 | 说明 |
|---------|------|
| 附件设置 | 支持从对象附件字段、文档字段引用附件；最多 10 个 |
| 日程信息 | 可配置地点、开始时间、结束时间（接入 Exchange 后生效） |

#### 短信渠道

| 配置项 | 说明 |
|---------|------|
| 签名名称 | 短信展示的发送方签名 |
| 通道号 | 运营商/平台分配通道 |
| 短信模板 ID | 外部短信平台模板标识 |
| 模板内容 | 建议短句，避免超长被截断 |

### 1.7 模板状态管理

| 操作 | 结果 |
|------|------|
| 启用 | 模板可被触发规则引用并发送 |
| 停用 | 新触发不再使用该模板 |
| 删除 | 模板移除；删除前需确认无流程依赖 |

编辑时通常不允许修改 `Code` 和 `来源`。

### 1.8 消息变量说明

消息模板中可以设置变量。在发送消息前，消息解析引擎会根据触发上下文将变量替换成实际内容，再按所选渠道投递。

消息变量的写法、变量生成器分类和排查方法详见： [消息变量配置](12A_%E6%B6%88%E6%81%AF%E5%8F%98%E9%87%8F%E9%85%8D%E7%BD%AE.md)

## 2\. 通知触发规则

### 2.1 生命周期触发

在目标状态的“进入动作”中添加“发送通知”。

典型路径： `生命周期配置 > 目标生命周期 > 目标状态 > 进入动作 > 创建进入动作`

关键参数：通知模板、接收人、执行条件。

### 2.2 工作流触发

在任务节点、审批节点或通知节点中配置通知行为。

典型路径： `配置端 > 业务逻辑 > 工作流 > 选择工作流 > 节点配置`

可配置内容：
- 指派人是否默认接收通知。
- 是否抄送角色或指定用户。
- 完成节点后是否发送结果通知。
- 是否使用发送日期公式控制提醒时间。

### 2.3 系统触发

系统预置场景会自动触发系统通知，例如：密码到期提醒、批量任务完成、异常告警等。

## 3\. 第三方设置

消息发送依赖第三方设置。使用企业微信、钉钉、邮件、短信、平台消息、外部协作专用邮件、WeLink、飞书等渠道前，请先完成对应第三方参数配置，具体设置请参考[第三方设置](12B_%E7%AC%AC%E4%B8%89%E6%96%B9%E8%AE%BE%E7%BD%AE.md)。

## 4\. 发送监控与排错

### 4.1 消息作业监控

访问路径： `管理端 > 运维管理 > 消息作业 > 消息作业监控`

可执行操作：
- 按标题、渠道、状态、时间、收件人筛选。
- 查看单条发送日志。
- 对失败记录手动重试。
- 导出 CSV。

### 4.2 常见发送状态

| 状态 | 含义 | 处理建议 |
|------|------|------------|
| 已发送 | 投递成功 | 无需处理 |
| 发送失败 | 渠道返回错误 | 查日志并修复配置后重试 |
| 待重试 | 系统自动重试中 | 关注最终状态 |
| 已取消 | 超过重试次数或人工取消 | 排查后重新触发业务动作 |
| 仅站内 | 邮件未启用或配置无效 | 检查模板是否勾选邮件渠道，并确认 SMTP 配置可用 |

### 4.3 失败排查顺序
1. 查触发是否命中：流程动作是否执行、条件是否满足。
2. 查模板是否可用：模板是否启用、变量是否有效。
3. 查渠道是否连通：SMTP、协作平台、短信参数是否正确。
4. 查收件目标：收件人地址/账号是否有效。

---

## 5\. 验证清单

建议在沙箱环境完成以下验证后再发布：
1. 创建测试记录并触发业务动作。
2. 验证站内信是否到达。
3. 验证邮件/协作平台/短信是否按预期到达。
4. 检查模板变量、跳转链接、附件和日程信息。
5. 在消息作业监控中确认状态为“已发送”或“可接受重试完成”。

---

## 6\. 最佳实践
1. 先确定模板适用对象，再配置模板内容，最后绑定触发规则。
2. 关键业务通知优先按“单个对象”建模板，减少无效变量。
3. 模板名称保持稳定，避免流程引用后频繁改名。
4. 渠道专属模板只用于确有差异的渠道，减少维护成本。
5. 每次模板变更后至少跑一轮端到端联调并留档。

---

## 7\. 常见问题

### Q1：用户只收到站内通知，未收到邮件，先查什么？

先检查三项：模板是否勾选邮件渠道、收件人邮箱是否有效、SMTP 是否可用。

### Q2：变量显示为空白或原样文本，怎么处理？

核对变量 API 名称和对象范围；用有真实值的测试记录重新渲染。

### Q3：什么时候需要渠道专属模板？

当同一通知在不同渠道的长度、语气、链接策略明显不同，就应启用专属模板覆写。

### Q4：模板可以直接删除吗？

可以，但必须先确认生命周期、工作流、计划任务中不再引用该模板。

### Q5：批注中 @ 用户是否能触发通知？

当前不支持。需要通过工作流、生命周期动作或通知规则实现定向通知。
