# 生成匿名创建二维码配置
> 本文说明如何在对象动作中配置“生成匿名创建二维码”动作，使业务用户可以生成匿名填写入口，并让外部人员扫码创建相关对象记录。   

---

## 概述

“生成匿名创建二维码”是对象动作中的一种创建类动作。配置完成并启用后，业务端会出现生成二维码入口。外部人员扫码后进入匿名填写页，按指定表单布局提交数据。

该能力适用于以下场景：
- 需要向外部协作方收集信息，但不希望为其创建平台账号。
- 需要基于当前记录创建一条相关对象记录。
- 需要为匿名填写页指定固定的创建关系和表单布局。

匿名创建不会绕过平台配置。扫码创建时仍会执行字段校验、表单规则、关系安全和审计记录。匿名创建生成的记录默认创建人为 `系统 system`，不会记录为扫码填写人的个人账号。

---

## 1 配置入口与前提

### 1.1 管理入口

路径：`配置端 > 配置管理 > 对象管理 > 对象 > {对象} > 动作`

在目标对象的 `动作` 页签中点击 `创建`，进入创建动作页面。该页面用于为当前对象新增对象动作实例。

### 1.2 配置前检查

| 检查项 | 说明 |
|---------|------|
| 对象关系 | 当前对象需已配置可用于匿名创建目标记录的关系。关系决定二维码创建的数据落点。 |
| 表单布局 | 目标相关对象需有可用于匿名填写的表单布局。选择关系后，表单布局列表会按关系过滤。 |
| 动作权限 | 生成二维码的业务用户需具备该对象动作的查看和执行权限。 |
| 关系安全 | 待创建相关对象不能仅允许查看。若关系安全不允许创建，扫码页会阻断提交。 |

---

## 2 创建匿名二维码动作

### 2.1 创建步骤
1. 进入 `对象 > {对象} > 动作` 页签。
2. 点击 `创建`。
3. 在 `动作` 下拉框中选择 `生成匿名创建二维码`。
4. 填写动作的 `名称`、`Code`、`状态`、`动作分组` 和 `描述`。
5. 在匿名创建配置区选择 `关系`。
6. 选择 `表单布局`。未选择关系前，表单布局不可选。
7. 点击 `保存`。保存成功后，业务端可按权限显示生成二维码入口。

### 2.2 通用字段

| 字段 | 是否必填 | 说明 |
|------|------------|------|
| 动作 | 是 | 选择动作类型。选择 `生成匿名创建二维码` 后，页面显示关系和表单布局配置项。 |
| 名称 | 是 | 动作在配置端和业务端的显示名称。可使用默认名称，也可按业务场景改为“生成供应商反馈二维码”等名称。 |
| Code | 是 | 动作编码，用于权限、迁移和排错。建议使用英文小写和下划线，后缀保持为 `&#95;&#95;c`。 |
| sourceCode | 否 | 系统自动生成或带出的源编码，只读展示。 |
| 来源 | 否 | 通常显示为 `自定义`，用于区分系统内置动作和自定义动作。 |
| 用途 | 否 | 通常显示为 `用户对象动作`，表示该动作可作为对象记录上的用户动作入口。 |
| 状态 | 否 | 控制动作是否启用。停用后，业务端不再提供该动作入口。 |
| 动作分组 | 否 | 用于对动作进行分类展示和维护。动作较多时，建议按业务目的分组。 |
| 描述 | 否 | 记录配置目的、适用场景或注意事项，供管理员后续维护时查看。 |

### 2.3 匿名创建配置字段

| 字段 | 是否必填 | 说明 |
|------|------------|------|
| 关系 | 是 | 选择匿名扫码后要创建记录所依赖的对象关系。该关系会决定目标对象、关系安全和可选表单布局范围。 |
| 表单布局 | 是 | 选择匿名填写页使用的表单布局。可选项受 `关系` 联动过滤；切换关系后，若原布局不在新范围内，系统会清空已选布局。 |

## 3 校验、权限与审计

### 3.1 保存校验

点击 `保存` 时，系统会执行以下校验：

| 校验项 | 规则 | 处理方式 |
|---------|------|------------|
| 动作 | 必须选择动作类型 | 未选择时禁止保存 |
| 名称 | 必填 | 未填写时禁止保存 |
| Code | 必填且在当前对象范围内唯一 | 为空或重复时禁止保存 |
| 关系 | 选择 `生成匿名创建二维码` 后必填 | 未选择时禁止保存 |
| 表单布局 | 必须来自所选关系的可用布局范围 | 未选择或布局不匹配时禁止保存 |

### 3.2 权限控制

| 能力 | 权限说明 |
|------|------------|
| 创建或编辑动作配置 | 需要具备管理端对象动作配置的创建或编辑权限。 |
| 查看动作配置 | 需要具备对象动作配置查看权限。 |
| 业务端生成二维码 | 业务用户需要具备该对象动作的查看和执行权限。 |
| 匿名扫码提交 | 匿名页面不要求外部人员登录，但创建过程仍受关系安全、字段校验和表单规则约束。 |

### 3.3 记录归属

匿名填写页提交成功后，系统创建的目标记录默认创建人为 `系统 system`。该值用于表示记录由匿名入口创建，而不是由某个已登录平台用户手工创建。

如果业务需要识别实际提交人、提交单位或来源渠道，应在匿名填写表单中配置对应字段，并要求外部人员填写；也可以结合业务编号、来源字段或审计记录进行后续追溯。

### 3.4 审计记录

平台会记录该动作的配置变更，包括创建、编辑、启用和停用。建议上线后重点关注以下审计信息：
- 操作者、操作时间和所属对象
- 关系和表单布局的变更前后值
- 匿名创建记录的创建人为 `系统 system`
- 匿名扫码创建时的关系安全校验结果
- 被拒绝创建的原因

## 4 业务端效果

动作配置完成并启用后，具备权限的业务用户可在对应记录的动作入口中生成二维码。外部人员扫码后的流程如下：
1. 打开匿名填写页。
2. 页面按配置的表单布局展示字段。
3. 外部人员填写并提交表单。
4. 系统创建相关对象记录，并建立与当前记录的关系。新记录的创建人为 `系统 system`。
5. 创建成功后显示成功页，页面仅提供关闭入口。

创建成功页不提供跳转业务列表页或继续创建入口。如需再次填写，外部人员需要重新扫码进入匿名填写页。

若关系安全仅允许查看或不允许创建，扫码页会提示当前关系无法创建数据，并终止提交。

---

## 5 上线前检查

| 检查项 | 建议 |
|---------|------|
| 动作状态 | 确认动作已启用，并在业务端可见。 |
| 动作权限 | 使用典型业务角色验证二维码生成入口是否可见、可点击。 |
| 关系安全 | 使用测试二维码验证匿名创建是否能通过关系安全校验。 |
| 表单布局 | 检查匿名填写页是否只展示外部人员需要填写的字段。 |
| 必填字段 | 确认布局中的必填字段均可由外部人员填写，或已通过默认值自动带入。 |
| 提交人识别 | 如需识别实际填写人或单位，应在表单中配置对应字段；不要依赖系统字段 `创建人` 区分外部填写人。 |
| 成功页 | 验证创建成功后仅能关闭页面，不会跳转到业务列表页。 |
| 审计记录 | 检查动作配置变更和扫码创建结果是否可追溯。 |

## 常见问题

### Q1：为什么选择关系后看不到预期表单布局？

表单布局会按所选关系过滤。请确认目标对象已有启用状态的表单布局，并且该布局适用于当前匿名创建场景。

### Q2：为什么扫码后提示无法创建数据？

通常是关系安全不允许创建，或动作已停用、权限配置不完整。先检查关系安全，再检查对象动作状态和业务端动作权限。
