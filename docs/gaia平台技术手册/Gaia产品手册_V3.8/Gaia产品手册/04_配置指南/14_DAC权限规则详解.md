# DAC 权限规则详解
> 本文面向管理员，说明 Gaia 平台动态访问控制（Dynamic Access Control，DAC）的规则类型、配置前提、权限计算方式和常见排查方法。配置共享规则的字段、页面和按钮说明，参见 [共享规则](../04_%E9%85%8D%E7%BD%AE%E6%8C%87%E5%8D%97/01F_%E5%85%B1%E4%BA%AB%E8%A7%84%E5%88%99.md)。   

---

## 概述

DAC 用于控制用户能访问哪些具体记录。它会和权限集、对象权限、生命周期角色和状态权限一起生效。

可以按以下顺序理解权限结果：
1. 权限集决定用户具备哪些基础能力，例如能否进入对象、查看字段、执行动作。
2. DAC 和共享规则决定用户能访问哪些记录。
3. 生命周期角色决定用户在记录生命周期中的默认查看、编辑和删除边界。
4. 状态权限继续按当前状态收紧字段、动作、附件、关系和审批矩阵等能力。
> \[!NOTE\]
DAC 不能突破权限集上限。即使用户通过共享规则获得某条记录的编辑者角色，如果权限集没有授予对象编辑或字段编辑权限，用户仍不能编辑对应内容。   

---

## 规则类型

Gaia 中与 DAC 相关的记录级授权主要有两类：匹配共享规则和手动共享。匹配共享规则适合长期、可复用的自动授权；手动共享适合少量临时例外。

| 类型 | 适合场景 | 授权结果 | 维护位置 |
|------|------------|------------|------------|
| 匹配共享规则 | 按国家、部门、站点、产品线、文件夹等字段自动分配记录权限 | 记录字段值与用户角色设置记录匹配时，系统自动生成权限共享（主体为用户，**不支持用户组**） | 生命周期角色、用户角色设置对象 |
| 手动共享 / 人工分配 | 临时协作、少量例外授权、自动规则暂时覆盖不到的记录 | 有权限的用户在记录详情中手动把用户、用户组或部门加入记录角色 | 业务端记录详情页的权限共享区域 |

### 选择建议

| 场景 | 建议 |
|------|------|
| 多个对象都按相同维度授权，例如偏差、CAPA、变更都按部门和产品线划分权限 | 优先使用匹配共享规则，减少重复配置 |
| 只有一条或少量记录需要临时开放 | 使用手动共享 |
| 权限逻辑依赖组织树、部门树或文件夹树 | 使用匹配共享规则，并选择合适的层级匹配方式 |
| 规则复杂且会影响大量历史数据 | 先评估刷新范围和验证方式，再启用或调整规则 |

## 配置前提

配置 DAC 前，先确认以下事项：

| 前提 | 说明 |
|------|------|
| 目标对象支持 DAC | 系统类对象、基础运维对象或不适合记录级共享的对象可能不支持启用 DAC。 |
| 对象已启用生命周期 | DAC 依赖生命周期角色来承载记录级角色，例如拥有者、编辑者、查看者或自定义角色。 |
| 生命周期角色已配置权限 | 至少确认查看、编辑、删除等角色权限符合预期。 |
| 权限集已授予基础能力 | 管理员和业务用户需要具备对象、字段、动作和菜单等基础权限。 |
| 共享字段稳定 | 匹配字段应尽量选择业务含义稳定、不会频繁批量变更的字段。 |
| 已准备验证账号 | 配置后用不同角色账号验证列表可见性、详情访问、字段编辑和动作按钮。 |

共享规则的常见配置路径：

`管理端 > 配置管理 > 生命周期 > 目标对象生命周期 > 角色 > 目标角色`

在生命周期角色详情页的“基本信息”区域，使用“动态权限控制”下的两个开关控制共享规则能力：
- `启用自定义共享规则`：开启后，可在当前生命周期角色下维护自定义规则。
- `启用匹配共享规则`：开启后，可在当前生命周期角色下维护权限匹配规则。

业务端查看权限共享的常见位置：

`业务端 > 目标对象 > 记录详情 > 权限共享`

## 匹配共享规则

匹配共享规则通过字段值匹配来自动分配记录角色。管理员先维护“谁在什么范围内拥有什么角色”，系统再把这些设置应用到符合条件的记录上。

典型逻辑如下：
```text
用户角色设置记录
用户：张三
角色：编辑者
匹配字段：国家 = 中国，产品线 = Quality Suite

业务记录
国家 = 中国，产品线 = Quality Suite

结果
系统为该业务记录生成权限共享，张三获得编辑者角色。
```

### 适用场景
- 按部门、业务单元、国家、站点、产品线等维度划分数据范围。
- 多个业务对象使用相同的授权模型，例如偏差、CAPA、变更都按同一套组织维度授权。
- 需要随着记录新增或字段变化自动更新权限。
- 需要通过部门树或文件夹树实现本级、下级、子级等层级授权。

### 配置步骤
1. 创建用户角色设置对象。

在 `管理端 > 配置管理 > 对象` 中创建对象，对象类别选择 `用户角色设置`。该对象用于保存用户、角色和匹配字段值。匹配共享规则的授权主体为**用户**，**不支持用户组**。
2\. 在生命周期角色中启用共享规则能力。

进入目标对象对应的生命周期，在需要被规则授予的角色详情页中开启 `启用匹配共享规则`。如果还需要人工维护条件型授权，也可以同时开启 `启用自定义共享规则`。共享规则入口跟随生命周期角色显示，不在对象配置页维护。
3\. 创建匹配共享规则。

在当前生命周期角色的 `权限匹配规则` 区域创建匹配规则，填写名称、Code、状态和匹配字段。单条匹配规则最多配置 5 个规则字段。
4\. 维护用户角色设置记录。

在业务端或管理端进入用户角色设置对象，创建具体记录，例如“张三 \+ 编辑者 \+ 部门 = 质量部”。保存后，系统会用这些记录参与匹配计算。
5\. 验证共享结果。

创建或打开一条满足条件的业务记录，在权限共享区域查看系统生成的权限共享，并用对应用户账号验证访问结果。

### 用户角色设置记录

用户角色设置记录包含以下信息：

| 字段 | 说明 |
|------|------|
| 用户 | 获得权限的主体。匹配共享规则仅支持选择用户，**不支持用户组**。若需按组授权，请改用手动共享，或为组内成员分别维护用户角色设置记录。 |
| 角色 | 用户在命中记录上获得的生命周期角色，例如查看者、编辑者、拥有者或自定义角色。 |
| 匹配字段值 | 用于和业务记录字段比对的值，例如部门、国家、产品线、站点。 |
| 状态 | 停用后不再参与新的权限计算；已生成的权限共享需要按系统刷新机制更新。 |
> \[!IMPORTANT\]
用户角色设置记录不是普通备注数据。字段值写错、角色选错或记录停用，都会直接影响用户是否能看到记录。   

### 支持的匹配字段

| 字段类型 | 匹配方式 |
|------------|------------|
| 选项字段 | 匹配同一选项集或可被系统识别为同源的选项值。 |
| 对象字段 | 匹配引用同一对象的字段，包括对象字段、父对象字段，以及来源字段为对象或父对象的 Lookup 字段。 |
| Lookup 字段 | 当 Lookup 的源字段类型和目标匹配字段兼容时，可参与匹配。 |
| `name&amp;#95;&amp;#95;ak` | 当用户角色设置中的对象字段引用对象与共享规则所属对象一致时，可按记录 ID 匹配 `name&amp;#95;&amp;#95;ak`。 |

如果字段 Code 一致，系统可以自动识别匹配关系；Code 不一致时，需要管理员在页面中明确选择。

### 树形字段匹配

当匹配字段引用树形对象，例如部门、组织、文件夹，可以按层级关系控制授权范围。

| 匹配方式 | 命中范围 | 示例 |
|------------|------------|------|
| 相等 | 只匹配当前节点 | 用户角色设置为“质量部”，只命中部门等于“质量部”的记录。 |
| 相等且包含下级 | 匹配当前节点及所有子孙节点 | 用户角色设置为“质量部”，命中“质量部”及其所有下级部门记录。 |
| 相等且包含子级 | 匹配当前节点及直接子节点 | 用户角色设置为“质量部”，命中“质量部”和直属下级部门记录。 |

示例：
```text
部门树：质量部 > QC 组 > 微生物实验室

用户角色设置：部门 = 质量部

相等：命中质量部记录
相等且包含子级：命中质量部、QC 组记录
相等且包含下级：命中质量部、QC 组、微生物实验室记录
```

### 权限刷新

以下变化会触发匹配共享规则重新计算：

| 变化 | 影响 |
|------|------|
| 新增业务记录 | 系统检查记录字段值是否命中规则，并生成权限共享。 |
| 修改匹配字段 | 系统重新判断记录是否应增加、调整或移除权限共享。 |
| 删除业务记录 | 系统删除对应权限共享。 |
| 匹配规则变更 | 新增、修改、停用或删除规则后，相关记录需要重新计算。 |
| 用户角色设置记录变更 | 新增、修改、停用或删除记录后，相关权限共享需要刷新。 |
| 配置迁移 | 迁移后需要执行或等待权限初始化计算，确认共享结果已更新。 |

权限刷新由后台异步完成。数据量较大、规则较多或字段批量变更时，结果可能不会立即出现在业务端。

## 手动共享 / 人工分配

手动共享用于处理少量例外授权。拥有记录相应权限的用户可以在记录详情页的权限共享区域，把其他用户、用户组或部门加入某个记录角色。需要按组临时或例外授权时，应使用手动共享（匹配共享规则不支持用户组）。

### 页面行为

启用 DAC 后，业务记录详情页会显示 `权限共享` 区域。管理员可以在这里查看当前记录的共享来源。

| 列 | 说明 |
|---|------|
| 用户类型 | 显示共享对象是用户、用户组、部门或其他可共享主体。 |
| 名称 | 显示被授权对象的名称。 |
| 角色 | 显示该对象在当前记录上的生命周期角色。 |
| 方式 | 显示共享来源，例如匹配共享规则或人工分配。 |
| 操作 | 对可手动维护的权限共享显示编辑或移除操作。系统自动生成的权限共享由规则维护。 |

### 添加权限共享
1. 打开目标记录详情页。
2. 进入 `权限共享` 区域。
3. 点击 `添加`。
4. 选择用户、用户组或部门。
5. 选择角色并保存。

保存后，授权一般立即生效。若用户仍无法访问记录，继续检查权限集、对象权限、生命周期角色权限和状态权限。

### 分配限制

手动共享应遵循当前用户的权限边界。一般情况下，用户不能把高于自己权限等级的角色分配给他人。

| 当前用户在记录上的角色 | 通常可分配的标准角色 |
|---------------------------------|------------------------------|
| 拥有者 | 拥有者、编辑者、查看者 |
| 编辑者 | 编辑者、查看者 |
| 查看者 | 不可继续分配 |

自定义角色的可分配范围以生命周期角色配置和页面实际校验为准。

### 使用建议
- 用于临时协作、紧急处理或少量例外，不建议作为长期批量授权方式。
- 临时授权结束后应及时移除。
- 调整高权限角色前，应确认该用户是否真的需要编辑、删除或发起动作。
- 如果同类例外不断出现，应考虑改用匹配共享规则（按用户），或确认是否应改为对用户组的手动共享并定期清理。

## 权限计算

系统会收集记录上的权限共享，并结合用户身份、角色、生命周期和状态权限计算最终结果。
```text
1. 收集权限共享
   包括匹配共享规则、手动共享等来源
2. 匹配用户身份
   判断用户本人、所属用户组、部门或其他共享主体是否命中
3. 确定记录角色
   同一用户命中多个角色时，按权限更高的角色结果生效
4. 结合生命周期角色权限
   判断该角色在当前生命周期中是否允许查看、编辑或删除
5. 结合状态权限
   按当前状态继续控制字段、动作、附件、关系和审批矩阵
6. 得到最终权限
   用户在业务端看到可访问记录、字段和动作
```

### 计算原则

| 原则 | 说明 |
|------|------|
| 权限集是上限 | DAC 只能让用户获得记录访问范围，不能授予权限集中没有的能力。 |
| 多来源可叠加 | 同一用户可同时通过匹配规则和手动共享获得角色。 |
| 手动共享不被自动规则改写 | 自动刷新不会直接修改人工分配记录；如需撤销，应手动移除。 |
| 状态权限继续收紧 | 用户能打开记录，不代表能编辑字段或执行当前状态下的动作。 |
| 后台刷新可能延迟 | 大量记录或规则变化后，应等待刷新完成再判断配置是否失败。 |

## 排查顺序

当用户反馈“看不到记录”“打开后不能编辑”“权限共享没有生效”时，建议按以下顺序排查：
1. 检查用户状态。

确认用户未停用，所属部门、职位和用户组正确。
2\. 检查权限集。

确认用户具备对象查看、字段查看、动作执行等基础权限。
3\. 检查目标对象 DAC 开关。

确认目标对象已启用动态访问控制，并绑定正确的用户角色设置对象。
4\. 检查生命周期角色。

确认共享规则中使用的角色存在，并且该角色在生命周期中具备对应查看或编辑权限。
5\. 检查匹配字段。

对比业务记录字段值与用户角色设置记录字段值。树形字段还要确认匹配方式是否符合预期。
6\. 检查权限共享记录。

在业务记录详情页查看权限共享来源，确认是规则未命中、规则未刷新，还是用户命中后被其他权限收紧。
7\. 检查状态权限。

如果用户能打开记录但不能编辑字段或点击按钮，重点检查当前状态下的字段权限、动作权限和附件权限。
8\. 检查后台刷新。

批量导入、规则变更、配置迁移后，等待后台计算完成。必要时查看作业、日志或重新触发权限初始化。

## 日常维护建议

### 规则设计
- 匹配共享规则按用户维护主体；需要按用户组授权时，使用手动共享，或把组员拆成用户角色设置记录。
- 匹配字段选择稳定维度，例如部门、业务单元、站点、国家、产品线。
- 单条规则字段不要过多。字段越多，命中条件越严格，也越难排查。
- 同一对象存在多条规则时，记录规则用途和适用范围。
- 对树形字段，先确认业务需要“本级”“直属下级”还是“所有下级”。

### 变更管理
- 修改共享规则前，先确认会影响新记录还是历史记录。
- 对生产环境的大范围权限变更，先在测试环境验证。
- 配置迁移后检查权限初始化结果。
- 定期清理停用用户、过期用户组和无效用户角色设置记录。
- 对拥有者、编辑者、系统管理员等高权限角色定期复核。

### 验证方式

建议至少准备以下验证用例：

| 验证项 | 检查内容 |
|---------|------------|
| 命中规则的用户 | 能看到目标记录，并获得预期角色能力。 |
| 不命中规则的用户 | 看不到目标记录，或只能看到其本应访问的数据。 |
| 字段变更 | 修改匹配字段后，权限按新字段值刷新。 |
| 状态变更 | 记录进入不同生命周期状态后，按钮和字段权限符合状态权限配置。 |
| 手动共享 | 添加后能访问，移除后权限回收。 |

## 常见问题

### 匹配共享规则配置后，为什么权限没有立即生效？

匹配共享规则由后台异步计算。先检查规则是否启用、用户角色设置记录是否正确、匹配字段值是否一致；如果刚完成批量导入、规则修改或配置迁移，等待刷新完成后再验证。

### 用户能看到对象菜单，但看不到记录，应该查哪里？

对象菜单可见说明用户可能已经具备对象或菜单权限，但记录级权限仍可能不满足。检查 DAC 规则、权限共享、手动共享和记录所有者，再检查生命周期角色权限。

### 用户能打开记录，但不能编辑字段或按钮不可用，是什么原因？

记录级访问已经满足，但权限集、生命周期角色权限、字段权限、表单布局权限或状态权限可能继续收紧了操作范围。优先检查权限集和当前状态下的状态权限。

### 手动共享会覆盖自动规则吗？

不会。手动共享是单独的共享来源，不会被自动规则刷新改写。用户最终权限会综合所有共享来源计算；如果要撤销手动授权，需要在权限共享中手动移除。

### 修改匹配字段后，权限会自动更新吗？

会。系统会根据匹配字段变化重新计算权限共享。大量记录批量变更时，刷新可能需要时间。

### 什么时候不建议使用手动共享？

当同类授权会长期存在、涉及大量记录或频繁重复发生时，不建议逐条手动共享，应优先配置匹配共享规则（按用户维护）。若必须按用户组授权，只能使用手动共享，并定期复核，避免例外授权堆积。

### 匹配共享规则为什么选不到用户组？

匹配共享规则的用户角色设置主体仅支持用户，不支持用户组。需要把权限授给某个用户组时，请在记录详情的权限共享中手动添加该用户组。

### 树形字段应该选择哪种匹配方式？

只授权当前节点时选“相等”；需要包含所有下级时选“相等且包含下级”；只包含直接下级时选“相等且包含子级”。配置后用本级、直接下级和更深层级数据分别验证。

### 如何导出权限报告？

在角色对象中配置“导出权限报告”动作后，可在角色列表或详情页导出权限报告。相关说明参见 [权限配置](./02_%E6%9D%83%E9%99%90%E9%85%8D%E7%BD%AE.md)。
