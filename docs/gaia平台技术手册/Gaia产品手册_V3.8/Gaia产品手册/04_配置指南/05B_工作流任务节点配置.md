\# 工作流任务节点配置

工作流任务节点用于承载人工处理步骤，定义任务分配、填写要求、提醒通知和协作约束。

---

## 工作流任务节点配置

工作流任务节点用于设定需要用户手动执行的步骤，一般为评估、调查、审核等。

任务节点详情页通常包含：`详情`、`工作流任务设置`、`更新共享设置`、`提示用户填写`、`通知`、`任务提醒`、`外部协作`。

**典型面包屑路径**：

`工作流 > {工作流名称} > 节点: {任务节点名称}`

页面右上角常见操作如下：

| 操作 | 说明 |
|------|------|
| **返回** | 返回当前工作流页面。 |
| **删除** | 删除当前任务节点（仅在可编辑版本中可用）。 |
| **编辑** | 进入任务节点编辑态，修改节点配置。 |

`详情`区域常见字段如下：

| 字段 | 说明 |
|------|------|
| **名称** | 任务节点显示名称。 |
| **Code** | 任务节点系统编码。 |
| **类型** | 当前节点类型，任务节点通常显示为`工作流任务`。 |
| **描述** | 节点说明；未填写时通常显示 `N/A`。 |
| **下一步** | 当前任务完成后流转到的下一节点。 |
| **标签** | 节点标签信息；未配置时通常显示 `N/A`。 |

### 1.1 常规设置

| 设置 | 说明 |
|------|------|
| **任务名称** | 业务端待办中显示的任务标题。 |
| **将任务分配给** | 可选择"工作流发起人"或"参与者组"；参与者组在工作流开始节点中定义 |
| **任务类型** | 可配置`并行`或`串行`，决定多人参与时任务生成顺序。 |
| **任务分配模式** | 可配置`系统指派`或`任务领取`。系统指派会按规则直接分配给参与人；任务领取由候选人自行领取。 |
| **任务说明（i）** | 展示给任务处理人的补充说明。 |
| **任务要求** | 必须：参与人必填；可选：参与人可为空。 |
| **不允许工作流发起人接收此任务** | 勾选后，该任务节点的参与人将排除工作流发起人。 |
| **在不查看详情的情况下完成任务** | 勾选后，任务参与者可直接从首页任务视图完成任务，无需进入详情 |
| **不需要手动完成（仅提醒）** | 勾选后该任务更偏向提醒型节点，不要求用户执行标准“完成任务”动作。 |
| **不允许移交任务** | 勾选后任务处理人不能把任务移交给其他人。 |
| **不允许代理** | 勾选后任务不允许通过代理机制处理。 |
| **完成按钮显示名称** | 自定义业务端“完成”按钮文案；未配置时通常显示 `N/A`。 |
| **关联记录打开模式** | 控制从任务进入关联记录时的打开方式（如`编辑`）。 |
| **显示有关以前任务的信息** | 控制是否在当前任务页展示历史任务信息。 |
| **到期日期** | 设置任务截止时间来源。可选类型包括：`工作流开始日期`、`任务创建日期`、`日期控件`、`对象字段`、`到期策略`、`公式`。 |
| **预警日期** | 仅支持两种类型：`任务到期前`、`公式`。 |
| **更新对象日期字段时更新活动任务的截止时间** | 勾选后，当对象日期字段变更时，活动任务截止时间同步更新。 |

到期日期设置：
- 当到期日期类型选择`公式`时，可使用 `CalcWorkDay(StartData,Hour,WorkCalendarCode)`，实现仅按工作日计算截止时间。

预警日期设置：
- **任务到期前**：按“任务到期前 N 小时”触发预警提醒。
- **公式**：通过公式计算预警时间。可使用 `CalcWorkDay(StartData,Hour,WorkCalendarCode)`，实现仅在工作日触发提醒。

### 1.2 更新共享设置

可在**更新共享设置**中定义规则，根据任务中触发的事件（任务指派/完成/取消/重新指派），将角色中的用户添加或删除到共享设置中。

在任务节点中展开`更新共享设置`后，可按“对象 \+ 事件 \+ 动作 \+ 角色”的组合配置规则，左下角`添加规则`用于继续新增规则行。

| 配置项 | 是否必填 | 说明 |
|---------|------------|------|
| **对象** | 是 | 规则作用范围。可选 `当前对象`、`相关对象`。 |
| **事件** | 是 | 触发规则的任务事件。可见选项包括：`任务指派`、`任务完成`、`任务取消`、`任务重新指派`、`任务移交`、`任务领取`、`撤销领取`、`任务代理`。 |
| **动作** | 是 | 对共享设置执行的操作。可选 `添加`、`删除`。 |
| **角色** | 是 | 选择要加入或移出的目标角色。 |

配置生效逻辑：
- 当所选`事件`在当前任务上发生时，系统会对所选`对象`的共享设置执行`动作`。
- `动作 = 添加`时，将所选角色加入共享设置；`动作 = 删除`时，将所选角色从共享设置中移除。
- 一条规则只描述一组“对象-事件-动作-角色”关系；需要覆盖多个场景时，可通过`添加规则`维护多条规则。

### 1.3 提示用户填写

| 类型 | 说明 | 使用场景 |
|------|------|------------|
| v1.2 | 2026-04-24 | 调整文档首段写法，改为直接说明任务节点作用。 |
| **字段** | 配置任务所有者在完成任务时需要填写的字段 | 如评估专员完成评估任务时填写一系列信息 |
| **审批意见** | 配置任务所有者在完成任务时需要选择的审批意见 | 如部门负责人审批时选择同意/拒绝 |

在该任务节点中，`提示用户填写`区域通常由以下开关组合而成：

| 配置项 | 作用 | 说明 |
|---------|------|------|
| **要求填写任务备注** | 要求处理人填写备注 | 可配置备注名称，并可进一步设置是否必填。 |
| **要求填写字段** | 要求处理人填写指定字段 | 在字段列表中逐个配置“是否必填”。 |
| **需要电子签名** | 要求处理人进行电子签名 | 可继续配置是否必须填写用户名、是否启用数字身份认证等选项。 |
| **要求用户填写审批意见** | 要求处理人选择审批意见 | 可配置审批意见名称；也可开启“审批意见展示为按钮”。 |

审批意见项支持逐条展开维护。每条意见可单独控制以下能力：
- 是否取消带指定标签的任务
- 是否要求填写字段
- 是否允许填写备注（含备注名称与必填设置）
- 是否需要电子签名与签名备注
- 是否允许添加附件（含数量、大小、格式限制）
- 是否需要填写签名含义（含含义名称、可选值、是否必填）
- 是否需要选择职位

### 1.4 通知与任务提醒

可设定向任务所有者发送自动通知时使用的通知模板。勾选"包括以前任务的审批意见和注释"后，可选择以前的任务，系统会将所选任务的审批意见和注释与通知一并发送给任务所有者。可配置任务提醒。

除任务节点自身的通知与提醒设置外，系统还支持通过`业务逻辑 > 工作流设置`统一维护任务到期策略和任务提醒策略。任务节点在配置时可以直接引用这些全局策略，减少在多个任务节点中重复维护相同规则。

#### 任务提醒（节点内配置）

任务节点中的`任务提醒方式`支持三种模式：

| 模式 | 说明 |
|------|------|
| **不提醒** | 当前任务节点不发送任务提醒。 |
| **使用提醒策略** | 复用工作流设置中预先维护的提醒策略。 |
| **自定义提醒** | 在当前任务节点直接配置提醒规则。 |

当选择`自定义提醒`时，页面会出现提醒规则块（如“任务提醒1”）。每条提醒规则常见字段如下：

| 字段 | 是否必填 | 说明 |
|------|------------|------|
| **通知模板** | 是 | 选择该条提醒使用的消息模板。 |
| **收件人** | 是 | 选择提醒接收对象。 |
| **发送日期** | 否 | 配置该条提醒的触发时间。支持类型：`任务创建日期`、`任务到期日期`、`到期日期控件`、`公式`。 |

发送日期补充说明：
- 当发送日期类型选择`公式`时，可使用 `CalcWorkDay(StartData,Hour,WorkCalendarCode)`，用于仅在工作日发送提醒。

页面操作：
- 点击`添加任务提醒`可继续新增提醒规则块，用于同一任务配置多次提醒或不同收件对象。
- 每条提醒规则块右上角的`×`可删除该条提醒规则。

#### 工作流设置：统一任务到期与提醒策略

进入`配置端 > 业务逻辑 > 工作流设置`后，可以统一维护以下两类配置：

| 设置项 | 作用 | 对任务节点的影响 |
|---------|------|------------------------|
| **工作流任务到期日期策略** | 预先定义任务到期时间的计算方式，例如“任务创建日期 \+ 12 小时”。 | 任务节点的**到期日期**可直接选择“到期策略”，引用这里定义的全局规则。 |
| **工作流提醒策略** | 预先定义提醒名称、通知模板、收件人和发送日期。 | 任务节点的**任务提醒方式**选择“使用提醒策略”时，会继承这里维护的提醒规则。 |

工作流提醒策略列表中常见字段含义如下：

| 字段 | 说明 |
|------|------|
| **名称** | 当前提醒策略的名称，用于在任务节点中选择对应策略。 |
| **通知模板** | 发送提醒时使用的消息模板。模板内容决定提醒消息的标题和正文。 |
| **收件人** | 提醒接收对象，例如任务所有者、未完成任务所有者、工作流发起人。 |
| **发送日期** | 提醒的触发时间，例如“任务创建日期 \+ 3 小时”。 |
| **操作** | 可对现有提醒策略执行编辑或删除。 |

任务节点中与全局策略相关的常见配置关系如下：

| 任务节点配置 | 可选方式 | 说明 |
|------------------|------------|------|
| **到期日期** | 工作流开始日期、任务创建日期、日期控件、对象字段、到期策略、公式 | 选择**到期策略**时，节点直接复用工作流设置中的统一到期规则；选择其他方式时，以节点当前配置为准。 |
| **任务提醒方式** | 不提醒、使用提醒策略、自定义提醒 | 选择**使用提醒策略**时，节点复用工作流设置中的提醒策略；选择**自定义提醒**时，仅当前节点使用自己的提醒配置。 |

建议将多个任务节点共用的时限规则和提醒规则放在工作流设置中统一维护；只有当单个任务节点存在特殊时限或特殊提醒对象时，再在节点内改为自定义配置。

在任务节点详情页中，常见配置结果如下：

| 区域 | 常见配置 |
|------|------------|
| **通知** | 可设置通知模板；收件人常见为`任务所有者`。 |
| **任务提醒** | 可选不提醒、使用提醒策略或自定义提醒；示例为`自定义提醒`。 |
| **外部协作** | 可设置签名人信息来源（如`人员(person&#95;&#95;ak)`），用于电子签名相关协同。 |

#### 工作流设置：界面与交互选项

除到期策略和提醒策略外，`管理端 > 系统设置 > 常规设置 > 工作流` 还提供一组会直接影响业务端工作流展示和交互方式的全局参数。这些设置通常不改变流程定义本身，但会影响发起、待办处理、详情页查看和批量工作流的操作体验。

| 设置项 | 启用后的表现 | 关闭后的表现或默认行为 |
|---------|------------------|---------------------------------|
| **选择加入工作流发起者以分配可选任务角色** | 在分配可选任务角色时，可将工作流发起人纳入候选范围。适合发起人也可能承担后续任务的场景。 | 候选范围不自动包含工作流发起人，避免发起人与后续处理人混用。 |
| **工作流角色高级配置** | 工作流角色配置页会提供更细的高级配置能力，用于处理复杂的角色范围或分配规则。 | 仅使用基础角色配置，适合普通审批链路。 |
| **审批意见显示为下拉选择** | 审批意见以单一下拉框呈现，适合意见选项较多或希望收纳显示的场景。 | 审批意见按默认单选按钮方式展示，选项会直接铺开显示。 |
| **工作流任务操作按钮尺寸** | 控制业务端任务操作按钮尺寸。当前可选值包含 `适中` 和 `较大`；`较大` 适合需要更明显点击区域的场景。 | 未单独调整时按默认尺寸显示，默认值为 `适中`。 |
| **文档批量工作流支持切换视图** | 文档批量工作流任务页左侧记录面板支持在列表视图和主附件文件视图之间切换；系统会记住用户上次选择。 | 仅使用默认列表视图，不提供额外视图切换入口。 |
| **在详情页显示责任人** | 详情页显示当前任务责任人。默认最多展示 2 个，点击“更多”可展开查看完整责任人列表，姓名支持悬浮信息。 | 详情页不额外展示责任人信息，需要通过任务面板或其他入口查看。 |
| **通过按钮展示任务** | 活跃任务以按钮方式展示，便于在同一详情页中快速切换不同任务。 | 使用系统默认的任务展示方式，不额外提供按钮式切换。 |
| **在详情页标题行显示活跃工作流提示** | 详情页标题行显示活跃工作流提示入口，方便直接确认当前记录是否存在进行中的工作流。 | 标题行不显示活跃工作流提示，需要进入任务或流程相关区域再查看。 |
| **多记录工作流启动后进入信封详情** | 发起多记录工作流后，系统直接进入对应信封详情页，便于继续查看批量任务和参与记录。 | 发起后保持默认跳转逻辑，不直接进入信封详情。 |
| **变更流程责任人和任务责任人添加备注** | 变更流程责任人或任务责任人时，可同时填写备注，便于说明调整原因并保留审计线索。 | 仅完成责任人变更，不额外记录备注说明。 |
| **以角色作为参与人不使用用户默认列表布局的过滤条件** | 以角色作为参与人时，不再套用用户默认列表布局中的过滤条件，适合跨组织或跨业务单元选人。需要过滤时，可在参与人控件上单独配置过滤条件。 | 默认沿用用户默认列表布局中的过滤条件，用于常规基础筛选或组织隔离。 |
| **生成任务时立即替换变量** | 创建任务时立即把变量替换为当时的实际值；后续即使变量再变化，已生成任务中的值也不会自动更新。适合任务名称、任务备注等需要锁定快照的场景。 | 任务中的变量按默认机制处理，不在任务创建瞬间固定为快照值。 |
| **催办时间间隔** | 控制同一任务两次催办之间的最短间隔，避免短时间内重复催办。可根据租户需要设置具体时长，例如 `60 分钟`。 | 若不调整该值，则按当前租户已配置的催办节奏执行。 |

使用这些全局参数时，建议先在测试环境验证以下影响：
- 详情页展示类设置会直接改变业务端页面呈现，适合先让关键用户试用后再推广。
- 发起与参与人相关设置会影响候选人范围和批量工作流体验，修改前应确认现有流程是否依赖原有筛选逻辑。
- 变量替换、催办间隔等运行时设置会影响任务生成和催办节奏，建议与流程管理员统一口径后再调整。

### 1.5 任务分配模式

| 模式 | 说明 | 业务端操作 |
|------|------|---------------|
| **系统指派** | 参与者为组时，发起人可将任务分配给组中每个用户 | "将任务分配给以下所有参与人"；组中所有用户都需完成此任务 |
| **任务领取** | 参与者为组时，任务对组中每个用户可用 | "可用于所有用户"；组中用户可领取任务，并非所有人都必须完成 |
> \[!NOTE\]
若同一参与者控件用于多个任务且使用不同的任务分配模式，发起人在业务端开始工作流的对话框中可能看不到"将任务分配给以下所有参与人"或"可用于所有用户"操作。若发起人属于参与者组但被限制接收任务，则不会接收任务。   

### 1.6 任务指派方式：并行指派与串行指派

在任务分配模式为"系统指派"时，可配置任务的指派方式：

| 指派方式 | 说明 | 适用场景 |
|------------|------|------------|
| **并行指派**（默认） | 一次性为所有参与人生成任务，所有参与人可同时处理 | 需要多人同时审批的场景 |
| **串行指派** | 按顺序依次为参与人生成任务，上一个参与人完成任务后才为下一个参与人生成任务 | 需要按顺序逐级审批的场景 |

**串行指派配置要点**：
- 参与人选择顺序即为任务分配顺序
- 添加参与人时，不能选择前面节点已经选择的用户
- 系统生成任务时，依次为每一个用户生成任务
- 当上一个参与人完成任务后才会为下一个参与人生成任务

**串行任务提前结束条件**：

当任务类型为串行时，可配置提前结束条件。当多人按顺序参与审核时，满足条件后提前结束任务节点：
- **条件类型**：任一断言包含于
- **逻辑值**：任务上设置的审批意见（必填）
- **判断逻辑**： 
    - 如果选择"所有断言等于"或"没有断言等于"：当已完成的任务都满足此断言，将继续依次生成后续任务，直至完成全部串行的任务；否则不再继续生成任务，并进入判断节点 else 分支
    - 如果选择"至少一个断言等于"：当任务中出现一个断言满足条件时，则停止后续任务生成，并进入下一个节点；否则继续依次生成后续任务，直至完成
> \[!NOTE\]
取消任务不影响串行指派逻辑。重新指派任务不影响任务的指派顺序。   

### 1.7 审批意见展示为按钮

在工作流任务节点中勾选【审批意见展示为按钮】，在下方审批意见上选择按钮样式，审批意见将以按钮形式展示，便于用户快速选择。
