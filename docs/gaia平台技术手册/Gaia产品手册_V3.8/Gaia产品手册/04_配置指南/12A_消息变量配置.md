## 1\. 变量机制

消息变量用于在模板中引用运行时数据，例如记录名称、状态、链接、任务描述和接收人信息。

### 1.1 变量解析时机

通知触发后，系统会按以下顺序处理变量：
1. 获取触发上下文（对象记录、任务、流程节点、接收人等）。
2. 调用消息解析引擎识别模板中的变量表达式。
3. 将变量替换成实际值后，再按渠道发送消息。

### 1.2 变量写法

变量通常使用占位表达式写法，例如：
- `{!Record.Name}`
- `{!Record.Status}`
- `{!Record.Url}`
- `{!Task.Description}`
- `{!Recipient.Name}`
- `{!CurrentUser.Name}`

建议通过“变量生成器”插入变量，避免手工输入导致 API 名称错误。

## 2\. 变量生成器

### 2.1 页面位置

`管理端 > 配置管理 > 通知模板 > 消息模板 > 创建/编辑`

变量生成器位于模板编辑区右侧，可点击变量名称插入到主题、跳转链接或模板内容。

### 2.2 常见变量来源

| 变量来源 | 说明 | 使用前提 |
|------------|------|------------|
| 对象字段（Record） | 通用对象字段 \+ 指定对象的业务字段变量 | 已选择模板“对象”，并且字段存在真实值 |
| 任务（Task） | 当前任务标题、描述、截止时间等 | 通知由任务或流程任务节点触发 |
| 接收人（Recipient） | 接收人姓名、账号等 | 已配置接收人 |
| 当前用户（CurrentUser） | 当前操作用户信息 | 通知由用户动作或系统上下文触发 |
| 全局变量 | 系统级通用变量 | 变量在当前版本开放可用 |
| 工作流/安全/常用地址 | 流程上下文、安全相关和通用地址变量 | 与当前触发场景匹配 |

说明：不同版本与对象下可见的变量项可能不同，请以当前页面“变量生成器”实际显示为准。

### 2.3 通用对象字段变量

在变量生成器中，通用对象字段可见项通常包括以下变量：

| 分组 | 变量名称 | 说明 |
|------|------------|------|
| 通用对象字段 | Id | 记录唯一标识 |
| 通用对象字段 | 名称 | 记录名称 |
| 通用对象字段 | 版本号 | 记录版本信息 |
| 通用对象字段 | 创建人 | 记录创建人 |
| 通用对象字段 | 创建时间 | 记录创建时间 |
| 通用对象字段 | 更新人 | 最近更新人 |
| 通用对象字段 | 更新时间 | 最近更新时间 |
| 通用对象字段 | 是否删除 | 记录删除标记 |
| 所属对象 | 对象类型 | 当前记录所属对象类型 |
| 所属对象 | 记录状态 | 当前记录状态 |

当消息模板“对象”选择“单个对象（特定对象）”时，变量生成器会额外显示该对象的业务字段（对象字段），可直接作为变量插入主题、跳转链接或模板内容。

| 对象设置 | 可选字段范围 | 说明 |
|------------|------------------|------|
| 所有对象 | 仅通用对象字段 \+ 所属对象字段 | 不显示某个具体对象的专属业务字段 |
| 单个对象（特定对象） | 通用对象字段 \+ 所属对象字段 \+ 该对象业务字段 | 可直接选择该对象的标准字段与自定义字段作为变量 |

使用方式：
1. 在消息模板中将“对象”选择为目标业务对象。
2. 在变量生成器中展开对象字段分组并点击字段名称插入。
3. 保存前用真实数据触发一次通知，验证变量替换结果。

使用建议：直接通过变量生成器点击插入，不手工拼写变量表达式，避免字段名与实际 API 不一致。

在变量生成器中，常用地址可见项通常包括以下变量：

| 分组 | 变量名称 | 说明 |
|------|------------|------|
| 常用地址 | 对象详情 | 当前对象记录详情页地址 |

### 2.9 变量作用范围与发送场景

变量可用范围与消息发送场景直接相关。不是所有变量都能在所有场景下使用。

| 发送场景 | 可用变量范围（常见） | 说明 |
|------------|------------------------------|------|
| 工作流节点发送（任务/通知节点） | 对象字段、任务变量、工作流变量、接收人、当前用户、全局变量、常用地址 | 只有在工作流场景发送时，才可使用工作流变量和任务变量 |
| 生命周期动作发送 | 对象字段、接收人、当前用户、全局变量、常用地址 | 通常不提供工作流变量和任务变量 |
| 系统类通知（如验证码） | 安全变量、全局变量（按场景） | 以对应系统通知能力为准 |

示例：
- 在工作流中发消息，可使用`工作流名称`、`任务名称`、`任务截止日期`等变量。
- 在非工作流场景发送消息时，上述工作流/任务变量通常不可用或替换为空。

最终以当前模板编辑页右侧“变量生成器”实际显示项为准。

## 3\. 使用建议
1. 标题优先放核心变量，如记录名称、状态，便于接收人快速判断。
2. 跳转链接优先使用记录 URL 变量，避免硬编码地址。
3. 短信渠道控制长度，避免放入过多变量导致正文截断。
4. 对关键通知先在测试环境跑通一次，确认变量都能正常替换。

## 4\. 常见问题排查

### Q1：变量显示为空白，怎么处理？

检查模板“对象”是否与触发对象一致，并确认字段在测试数据中有实际值。

### Q2：变量原样显示为文本，没有被替换，怎么处理？

检查变量写法是否正确（建议从变量生成器重新插入），并确认流程确实命中该模板。

### Q3：为什么同一模板在不同渠道效果不同？

不同渠道有长度和格式限制。建议为企业微信、钉钉、飞书、短信等渠道单独维护专属模板。
