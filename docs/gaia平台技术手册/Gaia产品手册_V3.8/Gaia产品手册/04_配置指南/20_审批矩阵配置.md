# 审批矩阵配置

审批矩阵用于根据业务对象上的不同条件，自动装配不同的审批参与人和审批顺序。它适合处理“同一类流程，但不同场景下审批人、审批层级、审批方式不同”的配置场景。

配置完成后，审批矩阵可以在业务表单中展示，也可以在工作流开始节点作为参与人来源使用。系统会根据对象实例数据匹配对应规则，并带出相应的矩阵角色和参与人。

当业务记录命中具体审批矩阵后，系统还可以带出该矩阵对应的说明提示，用来提醒发起人当前条件下的选人要求、适用范围或注意事项。

---

## 适用范围

| 项目 | 说明 |
|------|------|
| 适用对象 | 文档对象、业务对象 |
| 适用角色 | 实施顾问、配置管理员 |
| 典型用途 | 按基地、文件类型、对象分类、组织范围等条件区分审批路径 |

---

## 进入方式

在管理端进入 `配置管理 > 业务逻辑 > 审批矩阵`，打开审批矩阵配置页面。

该页面用于统一维护审批矩阵配置。配置生效后，系统会自动生成相应的审批矩阵管理对象、审批矩阵角色对象，以及业务侧使用的审批矩阵成员数据结构。

---

## 功能概览

审批矩阵主要解决以下几类差异化审批需求：
- 同一流程在不同条件下，参与人数不同。
- 同一流程在不同条件下，参与人群不同。
- 同一流程在不同条件下，审批方式不同，例如串行或并行。

审批矩阵能力与工作流联动后，通常会带来以下效果：
- 工作流任务支持串行审批，串行任务可设置提前结束条件。
- 工作流开始节点支持“使用审批矩阵作为参与者”。
- 业务页面可根据对象实例自动展示匹配到的审批矩阵。
- 发起流程时可按规则带出矩阵成员，并按顺序分配任务。
- 命中的审批矩阵可额外显示说明提示，帮助发起人在不同条件下理解当前矩阵的适用规则。
- 审批矩阵可按用户组限制候选参与人范围，也可以直接带出默认用户，减少发起时的手工选人。

---

## 配置模型

一个审批矩阵配置，通常包含以下几部分：

| 组成 | 作用 |
|------|------|
| 审批矩阵配置 | 定义基础信息、适用对象、生命周期和锁定状态。 |
| 匹配字段 | 定义系统用哪些对象字段去匹配审批矩阵。 |
| 矩阵角色规则 | 定义不同规则下可出现的角色、任务类型和参与人约束。 |
| 审批矩阵管理对象 | 系统自动生成，用于管理实际矩阵数据。 |
| 审批矩阵角色对象 | 系统自动生成，作为审批矩阵管理对象的子对象。 |
| 审批矩阵成员对象 | 系统自动生成，用于保存业务侧实际参与成员。 |
| 审批矩阵默认职位管理 | 可选对象。启用默认职位管理后自动生成。 |

## 列表页

审批矩阵列表页用于查看系统中的全部审批矩阵配置。

### 列表字段

| 字段 | 说明 |
|------|------|
| 名称 | 审批矩阵配置名称。 |
| Code | 审批矩阵配置编码。 |
| 状态 | 当前配置是否启用。 |
| 对象 | 该审批矩阵所作用的对象。 |
| 描述 | 该审批矩阵的描述。 |
| 操作 | 对当前配置进行编辑、启用或停用。 |

### 页面行为
- 列表默认按创建时间倒序显示。
- 顶部支持按名称关键字搜索。
- 只有启用状态的审批矩阵配置才会参与业务侧的矩阵匹配。

### 列表操作

| 操作 | 说明 |
|------|------|
| 编辑 | 打开审批矩阵配置并进入编辑模式。 |
| 启用 | 将停用的配置切换为启用。启用后该配置可参与匹配。 |
| 停用 | 将启用的配置切换为停用。停用后业务侧不再展示对应审批矩阵部分。 |

## 新建审批矩阵配置

在列表页右上角点击 `创建`，进入审批矩阵配置创建页。

创建时需要先填写审批矩阵基础信息。保存成功后进入详情页，后续再继续补充匹配字段和矩阵角色规则。

如果配置创建后状态为启用，系统会自动生成对应的审批矩阵管理对象；同时还会生成审批矩阵角色对象，以及审批矩阵角色规则对应的选项集。

### 基础信息字段

| 字段 | 说明 |
|------|------|
| 名称 | 审批矩阵配置名称，建议直接体现业务场景。 |
| Code | 审批矩阵配置编码，通常以 `&#95;&#95;c` 结尾。 |
| 状态 | 可选 `启用` 或 `停用`。启用后该配置才会参与匹配。 |
| 对象 | 审批矩阵所适用的业务对象。 |
| 对象类型 | 基于所选对象的对象类型，可按需选择。 |
| 生命周期 | 基于所选对象的生命周期。非文档对象默认取对象生命周期；文档对象默认基础生命周期。 |
| 锁定状态 | 选填。对象实例处于这些生命周期状态时，业务侧不能维护审批矩阵成员。 |
| 启用默认职位管理 | 选填。启用后，系统额外生成“审批矩阵默认职位管理”对象，用于维护默认职位。 |

### 创建后的自动生成内容

保存审批矩阵配置后，系统会自动创建以下依赖结构：
- `审批矩阵管理` 对象：用于维护实际矩阵数据。
- `审批矩阵角色` 子对象：用于维护矩阵中的角色。
- 对应选项集：用于保存角色规则项。
- 勾选 `启用默认职位管理` 时，额外创建 `审批矩阵默认职位管理` 对象。

如果名称或 Code 与系统内已有对象或选项集重复，保存会失败，并提示重新编辑。

---

## 查看与编辑配置

审批矩阵详情页通常分为三块：
- 详情部分：展示基础信息。
- 匹配字段部分：展示当前用于矩阵匹配的字段。
- 矩阵角色规则部分：展示当前定义的角色规则。

进入编辑后，修改基础信息会同步影响系统自动生成的审批矩阵管理对象及相关依赖项。尤其是名称、Code、匹配字段和角色规则变更，会进一步影响业务侧展示和匹配结果。

---

## 匹配字段

匹配字段决定系统根据对象实例上的哪些值去命中审批矩阵。

### 支持的字段类型

匹配字段可从当前对象上已启用的字段中选择，支持以下类型：
- 对象
- 父对象
- 选项
- 公式（可选；返回类型为 `链接`、`图标` 的公式字段除外）

其中，公式字段在匹配字段选择时有以下限制：
- 返回类型为 `链接` 的公式字段不可选。
- 返回类型为 `图标` 的公式字段不可选。

### 匹配方式

| 匹配方式 | 说明 |
|------------|------|
| 相等 | 仅当字段值完全相同才命中。 |
| 相等且包含下级 | 树形对象专用。命中当前值及其下级。 |
| 相等且包含子级 | 树形对象专用。命中当前值及其子级。 |

### 空值匹配方式

审批矩阵配置的匹配字段支持单独设置空值匹配方式，可选值如下：

| 空值匹配方式 | 说明 |
|------------------|------|
| 匹配空值 | 字段值为空时，按空值进行匹配。 |
| 不匹配空值 | 字段值为空时，忽略该字段进行匹配。 |

### 操作说明

| 操作 | 说明 |
|------|------|
| 添加 | 在匹配字段区域点击 `添加`，选择字段、匹配方式和空值匹配方式后保存。 |
| 编辑 | 修改已有匹配字段的匹配方式、空值匹配方式或其他配置。 |
| 删除 | 删除当前匹配字段。系统会二次确认。 |

### 配置规则
- 不能添加重复字段。创建或编辑时如果出现重复，系统会提示该字段已存在。
- 每个匹配字段可单独设置空值匹配方式。
- 空值匹配方式为 `匹配空值` 时，字段值为空会作为有效匹配条件参与命中判断。
- 空值匹配方式为 `不匹配空值` 时，字段值为空会被忽略，不参与命中判断。
- 新增匹配字段后，系统会在对应的审批矩阵管理对象上同步新增字段。
- 当新增的匹配字段为公式字段时，系统会自动创建与该公式字段“返回类型”一致的字段类型，而不是创建公式类型字段本身。
- 修改匹配字段后，系统会在审批矩阵管理对象上生成新的对应字段，并将修改前字段设为停用。
- 删除匹配字段后，审批矩阵管理对象上的关联字段会同步停用。

## 矩阵角色规则

矩阵角色规则用于定义在什么条件下，出现哪些角色，以及这些角色在流程中的任务形式和参与人范围。

### 规则字段

| 字段 | 说明 |
|------|------|
| 名称 | 规则名称。保存后会同步生成对应选项。 |
| Code | 规则编码。保存后会同步生成对应选项编码。 |
| 状态 | 启用或停用。停用后业务侧不再显示该规则。 |
| 应用角色 | 选择系统中已启用的应用角色。 |
| 应用角色约束 | 用于进一步限制可选参与人的角色范围。 |
| 任务类型 | 可选 `串行` 或 `并行`，默认 `串行`。并行时，同一角色内部可并行生成任务。 |
| 锁定状态 | 选填。对象实例处于这些状态时，不可编辑参与人。 |
| 条件 | 用于限制该规则的适用范围。 |
| 帮助内容 | 展示在业务侧参与人控件上，提示用户该角色的填写要求。 |

这里的 `帮助内容` 是角色级提示，用于说明某个矩阵角色应该如何选人。它和审批矩阵管理记录上的 `提示说明` 不是同一个字段。`提示说明` 是矩阵级提示，用于在当前业务记录命中某个审批矩阵后，整体说明这套矩阵为什么会生效，或者提醒发起人当前场景下的审批要求。

### 规则操作

| 操作 | 说明 |
|------|------|
| 创建 | 在矩阵角色规则区域点击 `创建`，填写规则表单后保存。 |
| 编辑 | 修改已有规则。 |
| 启用 | 让当前规则重新参与业务侧展示与匹配。 |
| 停用 | 让当前规则在业务侧不再可用。 |

### 规则保存后的系统行为
- 规则保存成功后，系统会在对应选项集上自动创建一个选项。
- 选项名称等于规则名称。
- 选项 Code 等于规则 Code。
- 修改规则名称时，对应选项名称会同步更新。
- 修改规则状态时，对应选项状态会同步更新。

## 审批矩阵管理对象

审批矩阵配置启用后，系统会自动生成 `审批矩阵管理` 对象，用于维护实际矩阵数据。

### 关键字段

| 字段 | 说明 |
|------|------|
| 名称 | 审批矩阵名称。 |
| 权重 | 用于作为匹配优先级。权重越大，优先级越高。 |
| 是否默认规则 | 当其他规则均未命中时，自动匹配该矩阵。默认值为 `否`。 |
| 参与人类型 | 选填。用于定义当前审批矩阵中的参与人按 `角色` 还是按 `用户组` 维护。默认按 `角色` 处理；切换为 `用户组` 后，业务侧会按用户组成员范围提供候选人。 |
| 允许用户添加角色 | 选中后，发起流程时允许用户在矩阵中新增参与角色。 |
| 提示说明 | 选填。维护当前审批矩阵的说明提示。命中该矩阵后，系统会在发起工作流时显示这段提示，并在业务表单的审批矩阵部分于创建、编辑模式下展示；详情模式不显示。 |
| 描述 | 记录矩阵用途或补充说明。 |

### 使用建议
- 如果存在多个可能同时命中的矩阵，优先用 `权重` 控制命中顺序。
- `是否默认规则` 建议谨慎使用，通常保留一个兜底矩阵即可。
- `参与人类型` 会影响业务侧的选人方式。只有确实需要按用户组统一限制候选人时，再切换为 `用户组`。
- `允许用户添加角色` 适合需要业务人员在发起时补充审批人的场景。

### 提示说明的显示规则
- 当业务记录命中某一条审批矩阵管理记录，且该记录已维护 `提示说明` 时，系统会优先显示这条矩阵级提示。
- 在业务表单中展示审批矩阵时，`提示说明` 只在创建模式和编辑模式下显示，方便用户边看提示边维护参与人。
- 业务表单详情模式不显示 `提示说明`，避免在只读场景重复占用页面空间。
- 移动端当前以查看模式为主，且不支持发起工作流，因此移动端表单中不显示这类提示。
- 如果对象已启用实例多语言，`提示说明` 作为审批矩阵管理记录上的实例数据，可配合对象实例多语言能力维护不同语言的显示内容。相关说明可参见 [01\_对象配置.md](01_%E5%AF%B9%E8%B1%A1%E9%85%8D%E7%BD%AE.md)。

## 审批矩阵角色对象

系统会自动生成 `审批矩阵角色` 子对象，用于维护矩阵中的具体角色定义。

### 默认字段

| 字段 | 说明 |
|------|------|
| 名称 | 角色名称。 |
| 审批矩阵管理对象 | 指向所属审批矩阵管理记录。 |
| 规则 | 指向审批矩阵自动生成的规则选项集。 |
| 是否专属成员 | 标识该角色是否为专属成员。 |
| 最小成员数 | 该角色至少需要选择的人数。 |
| 最大成员数 | 该角色最多允许选择的人数。 |
| 用户组 | 选填。参与人类型为 `用户组` 时，用来指定当前角色对应的用户组。发起流程时，可选参与人范围来自该用户组中的成员。 |
| 默认用户 | 选填，可多选。用于为当前角色预先带出默认参与人。发起流程时，系统会先填入这里维护的用户。 |
| 是否允许修改参与人 | 布尔字段，默认 `是`。为 `否` 时，发起流程页中的当前角色参与人控件只读，发起人不能改动系统带出的人员。 |
| 是否以用户组的用户作为默认值 | 布尔字段，默认 `否`。为 `是` 时，系统会自动把当前用户组中的成员作为默认参与人带出。 |
| 排序 | 角色顺序。业务侧按此顺序排列角色。 |

### 用户组与默认用户的使用方式
- 当审批矩阵的 `参与人类型` 为 `角色` 时，业务侧仍按原有角色选人方式处理。
- 当审批矩阵的 `参与人类型` 为 `用户组` 时，当前角色应维护 `用户组` 字段；发起流程时，候选用户范围来自该用户组成员。
- 如果维护了 `默认用户`，系统会在发起流程时优先带出这些用户，适合固定审批人的场景。
- 如果勾选 `是否以用户组的用户作为默认值`，系统会把用户组中的成员整体带出，适合整组人员同时参与的场景。
- 如果同时维护了默认用户并开启“以用户组的用户作为默认值”，建议先在测试环境确认最终带出的名单是否符合预期，再用于正式流程。
- `是否允许修改参与人` 用于控制发起人能否调整系统带出的名单。需要强约束的审批场景，可将其设为 `否`。

## 审批矩阵成员对象

系统会自动生成 `审批矩阵成员` 对象，用于保存业务侧实例上的实际矩阵成员。

### 默认字段

| 字段 | 说明 |
|------|------|
| 名称 | 成员记录名称。 |
| 对象 | 所属业务对象。 |
| 对象实例 | 关联的业务记录。 |
| 审批矩阵 | 当前审批矩阵。 |
| 审批矩阵管理 | 关联的审批矩阵管理记录。 |
| 审批矩阵角色 | 当前成员所属角色。 |
| 审批矩阵角色顺序 | 角色在矩阵中的顺序，任务会按此顺序分配。 |
| 用户 | 实际参与用户。 |
| 顺序 | 用户在角色内部的顺序，串行任务按此顺序分配。 |

---

## 默认职位管理

勾选 `启用默认职位管理` 后，系统会额外生成 `审批矩阵默认职位管理` 对象，并在审批矩阵管理页面中增加默认职位维护区域。

### 默认职位管理字段

| 字段 | 说明 |
|------|------|
| 名称 | 默认职位记录名称。 |
| 审批矩阵管理 | 关联父级审批矩阵管理记录。 |
| 用户 | 选择用户。 |
| 职位 | 该用户可选职位范围内的职位。 |
| 审批矩阵角色 | 可选范围为当前审批矩阵已创建的角色。 |

### 适用场景
- 同一用户在不同审批角色下有固定默认职位时，可以提前维护。
- 需要在业务侧快速带出默认角色和职位关系时，建议启用。

## 表单布局中的审批矩阵部分

对象表单布局支持新增 `审批矩阵` 类型的部分。

### 作用
- 将审批矩阵显示到对象详情表单中。
- 根据对象实例数据和审批矩阵管理数据的匹配结果，展示对应矩阵。
- 一个矩阵角色对应一个参与人控件，参与人可多选，并可设置顺序。
- 如果命中的审批矩阵管理记录维护了 `提示说明`，系统会在创建和编辑模式下先显示这段提示，再显示矩阵角色与参与人控件。
- 当矩阵按 `用户组` 选人时，角色控件中的候选用户范围会按对应用户组成员收窄。
- 当角色维护了 `默认用户`，或开启“以用户组的用户作为默认值”时，系统会先带出默认名单，再决定用户是否还能继续调整。

### 变化规则
- 创建审批矩阵配置后，系统会自动生成对应名称的审批矩阵部分。
- 停用或删除审批矩阵配置后，该部分会从业务侧消失。
- 配置人员可将该部分加入对象表单布局中使用。

### 提示说明显示规则
- 创建模式：显示命中矩阵的 `提示说明`，便于用户首次填写时理解当前矩阵的适用条件。
- 编辑模式：继续显示 `提示说明`，便于用户调整参与人时核对规则。
- 详情模式：不显示 `提示说明`，仅展示已保存的矩阵结果。
- 移动端查看模式：不显示 `提示说明`。

## 在工作流中的使用

审批矩阵最常见的使用方式，是在工作流开始节点中作为参与人来源。

### 开始节点配置

在工作流开始节点的参与人控件中，`添加参与者` 可选择 `使用审批矩阵作为参与者`。

选择该方式后：
- 需要选择一个审批矩阵配置。
- 可选范围为当前工作流关联对象上已配置的审批矩阵。
- 如果该对象没有配置审批矩阵，则这里无法选择审批矩阵。

### 发起流程时的行为

在发起工作流的弹窗中：
- 系统会显示审批矩阵。
- 系统会根据对象实例数据自动匹配规则，并展示命中的矩阵角色。
- 如果命中的审批矩阵管理记录维护了 `提示说明`，系统会同步显示该提示，提醒用户当前条件下应如何理解和使用这套矩阵。
- 当审批矩阵的 `参与人类型` 为 `用户组` 时，发起人只能从角色对应的用户组成员中选择参与人。
- 当角色维护了 `默认用户` 时，系统会自动带出这些用户，发起人无需重复选择。
- 当角色开启 `是否以用户组的用户作为默认值` 时，系统会自动把该用户组成员带入当前角色。
- 当角色的 `是否允许修改参与人` 为 `否` 时，当前角色参与人控件为只读；系统带出的默认名单可以查看，但不能手工改动。
- 如果矩阵规则允许用户添加参与人，则界面会出现 `添加参与人` 按钮。
- 用户新增角色后，需要继续选择对应人员。

### 任务分配规则
- 角色之间的顺序，按审批矩阵角色顺序分配。
- 角色内部用户顺序，按成员顺序分配。
- 任务类型为 `串行` 时，系统按顺序逐个分配任务。
- 任务类型为 `并行` 时，同一角色内部可同时生成并行任务。

### 相关说明

与工作流步骤和参与人配置相关的详细说明，可参见 [05\_工作流配置.md](05_%E5%B7%A5%E4%BD%9C%E6%B5%81%E9%85%8D%E7%BD%AE.md)。

## 配置注意事项
- 只有启用状态的审批矩阵配置才会参与匹配。
- 停用状态的矩阵角色规则不会在业务侧显示。
- 锁定状态会影响业务侧是否允许编辑矩阵成员。
- 匹配字段、角色规则变更，会同步影响自动生成的管理对象、字段或选项集。
- 名称或 Code 与系统已有对象、字段、选项集冲突时，保存会失败。
- 发起工作流时，如启用了“允许用户添加角色”，新增角色后的参与人选择会变为必填。
- 当 `参与人类型` 为 `用户组` 时，未维护用户组的角色无法正确收敛候选范围，建议在启用前逐项检查。
- `默认用户` 和“以用户组的用户作为默认值”都会影响发起流程时的初始名单。正式启用前，建议准备一条测试记录验证带出结果。
- 如果 `是否允许修改参与人` 设为 `否`，发起人无法在发起页纠正默认名单，因此更应提前核对用户组成员和默认用户配置。
- `提示说明` 维护在审批矩阵管理记录上，适合说明“当前命中的整套矩阵为什么生效”；`帮助内容` 维护在矩阵角色规则上，适合说明“这个角色应该怎么选人”。
- 如果对象未启用实例多语言，`提示说明` 只能按当前记录值显示，不会自动出现多语言版本。
- 匹配字段可按业务需要设置空值匹配方式。若需将“未填写”作为可识别条件，请使用 `匹配空值`；若空值不应影响规则命中，请使用 `不匹配空值`。

## 常见配置顺序

建议按以下顺序完成审批矩阵配置：
1. 创建审批矩阵配置，先确定对象、生命周期和基础状态。
2. 添加匹配字段，明确系统按哪些条件匹配矩阵。
3. 配置矩阵角色规则，定义角色范围、任务类型和约束条件。
4. 在审批矩阵管理对象中维护实际矩阵数据，按需填写矩阵级 `提示说明`，并确认 `参与人类型`。
5. 在审批矩阵角色对象中补充用户组、默认用户和参与人可编辑性设置。
6. 按需启用默认职位管理。
7. 将审批矩阵部分加入业务对象表单布局。
8. 在工作流开始节点中选择“使用审批矩阵作为参与者”。
