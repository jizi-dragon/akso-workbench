\# 对象生命周期配置
> 本指南说明如何在 Gaia 平台中配置和管理对象生命周期。
如需查看文档多生命周期配置，请参考 [文档生命周期配置](04B_%E6%96%87%E6%A1%A3%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F%E9%85%8D%E7%BD%AE.md)。   

---

## 概述

生命周期定义文档或对象记录可以处于的状态，以及状态之间的转换规则。合理的生命周期设计是实现业务流程自动化和合规控制的基础。

### 对象生命周期组件结构图
```text
对象生命周期
├─ 详情
├─ 状态
│  ├─ 详情
│  ├─ 进入条件
│  ├─ 进入动作
│  ├─ 用户动作
│  ├─ 状态权限：字段
│  ├─ 状态权限：对象动作
│  ├─ 状态权限：附件
│  ├─ 状态权限：用户动作
│  ├─ 状态权限：工作流
│  ├─ 状态权限：关系
│  └─ 状态权限：审批矩阵
├─ 状态类型
├─ 角色
└─ 事件动作
```

### State 与 Status

Gaia 平台中的对象记录具有两种状态概念：

| 概念 | 说明 | 适用范围 |
|------|------|------------|
| **State（记录状态）** | 对象记录的基础状态，所有对象记录都拥有 | 所有对象（无论是否启用生命周期） |
| **Status（生命周期状态）** | 对象记录在生命周期中所处的状态 | 仅启用生命周期的对象 |

#### State（记录状态）

State 是对象记录的内置字段（`state__ak`），包含以下可选值：
- **启用**：记录正常可用
- **停用**：记录已禁用

**State 控制规则**：
- 未启用生命周期的对象：State 可通过编辑字段手动修改，可选值为"启用"、"停用"
- 启用生命周期的对象：State 由生命周期状态控制，不支持手动编辑。在生命周期状态配置中，可设置"处于此状态的记录置为停用"选项来控制 State

#### Status（生命周期状态）

Status 对应生命周期中的状态，只有启用生命周期的对象记录才拥有 Status。

**Status 与 State 的关联**：
- 在生命周期状态配置中，可勾选"处于此状态的记录置为停用"
- 勾选后，对象记录处于该生命周期状态时，State 自动置为"停用"
- 未勾选时，对象记录处于该生命周期状态时，State 自动置为"启用"

## 前提条件
- 您具有系统管理员或业务管理员权限
- 您已规划好状态和转换逻辑
- 已在目标对象上勾选“启用生命周期”选项，系统已自动创建该对象对应生命周期（该选项一旦创建后不可修改）
- 建议先完成[对象配置](01_%E5%AF%B9%E8%B1%A1%E9%85%8D%E7%BD%AE.md)与[工作流配置](05_%E5%B7%A5%E4%BD%9C%E6%B5%81%E9%85%8D%E7%BD%AE.md)，避免后续反复调整生命周期

---

## 配置流程总览（推荐步骤）
1. 在对象上启用生命周期，确认系统自动创建生命周期。
2. 进入生命周期列表并定位目标生命周期。
3. 在生命周期中完成状态、状态类型和状态流转等核心配置。
4. 按需配置进入条件、进入动作、用户动作、事件动作与状态权限。
5. 配置生命周期角色并完成验证后发布。

## 配置介绍

### 访问生命周期配置
1. 进入 **管理端** → **配置管理**
2. 在左侧导航进入 **业务逻辑** → **生命周期**
3. 查看现有生命周期列表

### 查看生命周期列表

以下说明对应“对象生命周期”列表页面，用于快速检索和进入生命周期配置。

#### 页面结构

| 区域 | 位置 | 作用 |
|------|------|------|
| 左侧导航 | 配置管理左侧菜单 | 从 **业务逻辑 → 生命周期** 进入对象生命周期列表 |
| 查询区 | 列表上方右侧 | 输入关键词后检索生命周期 |
| 分页区 | 查询区右侧 | 查看“当前第 N 页 / 共 X 条”，并切换页码 |
| 列表区 | 页面主体 | 查看生命周期基础信息并进入操作 |

#### 列表字段说明

| 字段 | 说明 | 常见用法 |
|------|------|------------|
| **名称** | 生命周期显示名称 | 点击名称进入该生命周期详情页 |
| **Code** | 生命周期系统标识符 | 用于接口、脚本和跨 Sphere 迁移识别 |
| **对象** | 该生命周期绑定的对象 | 确认生命周期作用范围 |
| **状态** | 生命周期配置本身是否可用（如“启用”） | 排查为什么对象未按预期流转时先看此列 |
| **生命周期状态** | 该生命周期下已配置的状态标签（如“开启/关闭/待处理/完成/取消”） | 快速核对状态集是否完整 |
| **操作** | 行级操作入口（齿轮按钮） | 进入该条生命周期的配置操作 |

#### 查询与分页
1. 在查询框输入关键词（可按名称、Code 或对象名检索）
2. 点击查询图标后刷新列表结果
3. 通过页码或上一页/下一页切换结果页
4. 可切换每页条数（如 `20条/页`），并通过“跳至”快速定位页码

#### 使用建议
1. 优先通过 **Code** 做精确检索，避免名称近似导致误改
2. 批量排查时先看 **状态** 和 **生命周期状态** 两列，再进入详情
3. 上线前按对象逐一核对是否都绑定到正确生命周期

### 对象生命周期

在对象生命周期列表中点击生命周期名称后，进入详情页。该页面用于查看生命周期基础信息、维护状态、映射状态类型、配置角色权限和查看事件动作。

#### 页面定位与顶部操作

| 控件 | 说明 | 使用时机 |
|------|------|------------|
| **面包屑：所有的生命周期 \> \{生命周期名称\}** | 显示当前所在生命周期，并可返回上级列表 | 需要切换到其他生命周期时 |
| **返回** | 返回生命周期列表页，不修改当前配置 | 仅查看后返回 |
| **编辑** | 进入当前生命周期编辑模式 | 需要修改详情、角色权限或状态配置时 |

#### 详情

详情部分展示生命周期基础属性，常见字段包括：
- **名称**：生命周期显示名称
- **Code**：系统唯一标识（用于接口和迁移）
- **对象**：绑定对象名称
- **状态**：生命周期可用状态（如启用）
- **来源**：生命周期来源（如自定义）
- **描述**：用途说明
- **阶段组**：所属阶段组（未配置时显示 `N/A`）

建议在进入编辑前先核对 **Code** 与 **对象**，避免在错误生命周期上修改状态和权限。
如需配置“阶段组”并在业务端展示阶段进度，可参考 [生命周期阶段组配置](04D_%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F%E9%98%B6%E6%AE%B5%E7%BB%84%E9%85%8D%E7%BD%AE.md)。

##### 编辑生命周期

在详情页点击右上角 **编辑** 后进入编辑页。编辑页用于维护生命周期基础信息，不用于直接维护状态流转和角色矩阵。

###### 顶部操作

| 按钮 | 作用 | 结果 |
|------|------|------|
| **取消** | 放弃本次编辑并返回查看态 | 未保存内容不生效 |
| **保存** | 保存当前编辑内容 | 保存成功后按新配置生效 |

###### 字段编辑规则

| 字段 | 页面表现 | 是否可编辑 | 说明 |
|------|------------|---------------|------|
| **名称** | 文本 | 否 | 生命周期显示名称，编辑页仅展示 |
| **Code** | 文本 | 否 | 系统标识，建议保持稳定，不在此页修改 |
| **对象** | 链接文本 | 否 | 当前绑定对象，仅用于核对范围 |
| **状态** | 下拉框 | 是 | 可切换生命周期启用状态（如启用） |
| **来源** | 文本 | 否 | 来源类型（如自定义），用于识别配置来源 |
| **描述** | 多行文本框 | 是 | 填写生命周期用途、适用范围、维护备注 |
| **阶段组** | 文本（如 `N/A`） | 否 | 生命周期阶段分组信息，未配置时显示 `N/A` |

###### 编辑步骤
1. 在详情页点击 **编辑**。
2. 先核对 **名称 / Code / 对象**，确认当前编辑目标正确。
3. 按需调整 **状态**（启用/停用）与 **描述**。
4. 点击 **保存** 完成提交；如需放弃修改，点击 **取消**。

###### 使用建议
1. 仅在需要上下线生命周期时修改 **状态**，避免频繁切换影响业务操作。
2. **描述** 建议记录“适用对象 \+ 主流程 \+ 维护责任人”，便于后续接手和排障。
3. 保存前确认该生命周期下无进行中的关键业务流转，降低变更风险。

状态表常见字段：

| 字段 | 说明 |
|------|------|
| **名称** | 状态显示名（如“开启”“关闭”） |
| **Code** | 状态系统标识 |
| **状态** | 该状态配置是否启用 |
| **描述** | 状态用途说明 |

##### 创建生命周期状态

在生命周期详情页的 **状态** 部分点击 **创建** 后，进入“创建状态”页面。该页面用于新增生命周期状态，并设置状态的基础属性。

###### 页面定位与顶部操作

| 控件 | 说明 | 使用时机 |
|------|------|------------|
| **面包屑：所有的生命周期 \> \{生命周期名称\} \> 创建状态** | 显示当前处于“创建状态”流程，可返回上级定位 | 需要确认当前创建对象时 |
| **返回** | 返回生命周期详情页状态列表 | 放弃创建或需要先查看现有状态时 |
| **批量设置** | 进入批量配置入口，对状态相关配置做集中处理 | 需要统一设置时 |
| **保存** | 保存当前状态配置并创建状态 | 字段填写完成后提交 |

###### 字段说明

| 字段 | 是否必填 | 页面表现 | 说明 |
|------|------------|------------|------|
| **名称** | 是 | 文本框 | 状态显示名称，建议使用业务可读名称（如“开启”“关闭”“待审核”） |
| **Code** | 是 | 文本框（后缀为系统格式） | 状态系统标识，建议使用语义化英文并保持唯一 |
| **状态** | 否（默认有值） | 下拉框 | 控制该状态配置是否启用，默认常见为“启用” |
| **来源** | 否（系统生成） | 文本 | 来源信息（如“自定义”），通常为只读展示 |
| **描述** | 否 | 多行文本框 | 补充状态用途、进入条件摘要、维护说明 |
| **工作流取消状态** | 否（默认有值） | 下拉框 | 定义记录在当前状态下取消工作流后的自动回退状态；默认值为“工作流发起时状态” |
| **处于此状态的记录置为停用** | 否 | 勾选框 | 勾选后，记录进入该状态时 `State` 自动变为“停用” |

###### 创建步骤
1. 在生命周期详情页进入 **状态** 部分，点击 **创建**。
2. 填写 **名称** 和 **Code**。
3. 按业务规则设置 **状态**、**描述**、**工作流取消状态**，并决定是否勾选“处于此状态的记录置为停用”。
4. 点击 **保存** 完成创建。

###### 工作流取消状态规则

每个生命周期状态都应有一个“工作流取消状态”选项。系统默认选择 **工作流发起时状态**（State in which workflow started）。

含义如下：
- 当用户在该状态下取消工作流时，记录会自动迁移到这里定义的状态
- 若保持默认值 **工作流发起时状态**，记录会回到该工作流启动时所在状态
- 若改为指定状态（如“评审未完成”），取消后会进入该指定状态

示例：
1. `Review` 工作流把记录从 `Draft` 推进到 `In Review`
2. 如果在 `In Review` 取消工作流：
3. 默认配置下，记录回到 `Draft`
4. 如果“工作流取消状态”设置为 `Review Incomplete`，记录回到 `Review Incomplete`

###### 校验与命名建议
1. `Code` 建议与状态语义保持一致，例如 `draft_status__c`、`complete_status__c`。
2. 避免名称重复或语义过近（如“结束”“已结束”），减少用户动作配置时选错状态。
3. 若该状态用于流程终止，建议同步核对：
状态转换是否可达、角色权限是否收敛、进入动作是否会触发不必要联动。

##### 状态详情

在生命周期详情页的状态列表中点击某个状态名称（如“开启”）后，进入“状态详情页”。该页面用于维护单个状态的规则、动作和权限。

###### 页面定位与顶部操作

| 控件 | 说明 | 使用时机 |
|------|------|------------|
| **面包屑：所有的生命周期 \> \{生命周期名称\} \> \{状态名称\}** | 显示当前状态定位，可快速确认是否进入正确状态 | 同名状态较多时 |
| **返回** | 返回生命周期详情页 | 仅查看不修改时 |
| **批量设置** | 对状态相关配置执行批量处理 | 多项权限或规则需统一调整时 |
| **编辑** | 进入当前状态编辑模式 | 需要修改状态属性、规则或权限时 |

###### 详情

详情部分展示该状态的基础属性，常见字段包括：
- **名称**
- **Code**
- **状态**（启用/停用）
- **来源**（如自定义）
- **描述**
- **工作流取消状态**（未调整时默认“工作流发起时状态”）
- **处于此状态的记录置为停用**（勾选项）

建议先核对 `Code` 与“工作流取消状态”，再维护后续条件和动作。

###### 进入条件

进入条件用于控制“记录能否进入当前状态”。该部分提供：

| 操作 | 作用 |
|------|------|
| **创建** | 新增进入条件 |
| **排序** | 调整条件执行顺序 |
| **行操作** | 编辑或删除已建条件 |

列表常见列：**执行方式**、**执行条件**、**操作**。
当页面显示“暂无数据”时，表示当前状态尚未配置进入条件。

###### 进入动作

进入动作用于在记录进入当前状态时自动执行系统动作。该部分提供：

| 操作 | 作用 |
|------|------|
| **创建** | 新增进入动作规则 |
| **排序** | 调整动作执行顺序 |
| **行操作** | 维护已有动作 |

列表常见列：**描述**、**规则**、**状态**、**操作**。
若动作较多，建议按“业务主流程优先、补偿动作靠后”的顺序排序。

###### 用户动作

用户动作用于在当前状态下提供可手动触发的操作按钮。该部分提供：

| 操作 | 作用 |
|------|------|
| **创建** | 新增用户动作 |
| **排序** | 调整动作展示顺序 |
| **行操作** | 编辑或停用动作 |

列表常见列：**描述**、**规则**、**动作**、**操作**。
当该部分无数据时，用户在该状态下可能无法手动推进流程。

###### 状态权限

状态权限用于定义“该状态下谁能看、谁能做什么”，可按能力域分组配置。页面中常见的分组包括：
状态权限的评估顺序、默认行为与角色覆盖规则可参考 [状态权限配置](04E_%E7%8A%B6%E6%80%81%E6%9D%83%E9%99%90%E9%85%8D%E7%BD%AE.md)。
- **状态权限：字段**
- **状态权限：对象动作**
- **状态权限：附件**
- **状态权限：用户动作**
- **状态权限：工作流**
- **状态权限：关系**
- **状态权限：审批矩阵**

###### 字段权限

字段权限分组支持通过**基础类型**筛选，并查看每个字段的默认状态行为（如“查看/编辑”）。
适合用于控制状态切换后哪些字段只读、哪些字段可编辑。

###### 对象动作 / 附件 / 用户动作权限

这些分组用于控制在当前状态下可执行的对象动作、附件相关操作和用户动作能力。
页面右上角 **编辑** 用于进入分组级权限编辑模式。

###### 工作流权限

工作流分组按“工作流组”展示默认行为（示例默认行为均为“执行”），常见项包括：
- 添加参与者
- 通知参与者
- 取消任务
- 取消工作流
- 重新分配
- 更新任务截止时间
- 替换工作流所有者

该分组用于确保流程协作动作在目标状态可按预期执行。

###### 关系 / 审批矩阵权限

用于控制关系和审批矩阵相关能力在当前状态的可用性。
若显示“暂无数据”，表示尚未配置该分组权限，可按业务需要补充。

###### 配置顺序建议
1. 先确定 **详情** 的状态属性（尤其工作流取消状态）。
2. 再配置 **进入条件** 与 **进入动作**，保证流转逻辑完整。
3. 补充 **用户动作**，确保用户可按流程推进。
4. 最后收敛 **状态权限**，验证“能看见/能执行”的边界。

#### 状态类型

状态类型部分用于把“状态类型”映射到具体生命周期状态，常见映射如：
- **初始状态 → 开启**
- **完成状态 → 关闭**

该映射会影响工作流按状态类型执行时的匹配结果，建议每个生命周期至少维护“初始状态”和“完成状态”的有效映射。
状态类型的创建策略、范围选择与治理方法可参考 [生命周期状态类型配置](04C_%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F%E7%8A%B6%E6%80%81%E7%B1%BB%E5%9E%8B%E9%85%8D%E7%BD%AE.md)。

| 操作 | 作用 |
|------|------|
| **创建** | 新增状态类型与生命周期状态映射 |
| **行操作（齿轮）** | 编辑或调整现有映射 |

#### 角色

角色部分用于配置生命周期角色在当前对象上的基础权限。常见列包括：
- **权限-查看**
- **权限-编辑**
- **权限-删除**

页面通常包含 `查看者`、`编辑者`、`拥有者` 等标准角色。
从页面配置示例可见：
- `查看者` 仅勾选查看
- `编辑者` 勾选查看与编辑
- `拥有者` 勾选查看与编辑（删除权限按业务策略单独控制）

| 操作 | 作用 |
|------|------|
| **编辑** | 切换到权限矩阵编辑模式并保存变更 |
| **角色前“\+”展开图标** | 展开角色下的细分配置（如状态粒度权限） |

##### 生命周期角色

生命周期角色用于在启用生命周期的对象上设置基于角色的权限控制。在计算权限时，除了权限集，还需要计算生命周期上设置的角色权限。

###### 标准角色

生命周期自动创建时，系统自动关联三个标准角色：
- **拥有者**：默认拥有查看、编辑、删除权限
- **编辑者**：默认拥有查看、编辑权限
- **查看者**：默认拥有查看权限

本章节仅说明生命周期角色的定位与入口，避免与专题手册重复。

###### 使用入口
1. 进入生命周期详情页，打开 **角色** 页签。
2. 在权限矩阵中查看各角色在不同状态下的查看/编辑/删除权限。
3. 通过【编辑】进入配置模式，按需调整权限。

###### 专题文档

生命周期角色的完整操作（新增角色、移除角色、角色级/状态级权限、用户组限制）请参见： [生命周期角色配置](04F_%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F%E8%A7%92%E8%89%B2%E9%85%8D%E7%BD%AE.md)

#### 事件动作

事件动作部分展示在特定事件触发时执行的系统动作，常见事件包括：
- 创建记录
- 修改记录
- 删除记录

该部分用于确认“记录创建/修改/删除”时是否有自动化动作被触发，建议在上线前与进入动作、用户动作一并核对，避免重复触发或遗漏触发。

## 配置完成后验证

建议至少完成以下验证，再推广到正式环境：
1. **路径验证**：分别测试主流程、驳回回退流程、异常分支流程是否可达。
2. **权限验证**：用作者/审批人/查看者等不同角色登录，确认按钮可见性与权限矩阵一致。
3. **条件验证**：构造“满足条件 / 不满足条件”两组样本，确认进入条件与条件校验提示正确。
4. **动作验证**：核对进入动作和用户动作对字段、相关对象、工作流的影响是否符合预期。
5. **审计验证**：检查状态变更、动作触发、权限拒绝是否留有完整审计记录。

## 最佳实践
1. **状态数量控制**：保持 5-7 个状态，过多会增加复杂度
2. **清晰的命名**：状态名称应准确反映业务含义
3. **单向流动**：主流程尽量单向，减少回退路径
4. **权限分离**：不同状态配置不同权限
5. **测试验证**：在沙箱环境充分测试后再部署

## 常见问题

**Q：如何修改已使用的生命周期？**

A：已有文档使用的生命周期可以修改，但需注意：
- 不能删除有文档停留的状态
- 修改状态名称不影响现有文档
- 添加新状态和转换是安全的

**Q：如何迁移文档到新生命周期？**

A：使用批量状态变更工具或 API 进行迁移。

**Q：为什么创建记录时没有执行初始状态的进入动作？**

A：这是系统默认行为。创建新记录进入初始状态时，不执行进入动作；仅当记录从其他状态回到初始状态时，才会触发该状态的进入动作。
