# 生命周期状态条件配置
> 本指南说明如何在 Gaia 平台的生命周期中配置状态相关条件，包括进入条件、用户动作显示条件、用户动作执行前校验、进入动作执行条件和事件动作执行条件。   

---

## 概述

生命周期中的“条件”用于决定一条状态规则是否生效。它不直接改变记录，而是控制以下事情是否允许发生：
- 记录能否进入目标状态
- 某个用户动作按钮是否显示
- 用户点击动作后是否允许继续执行
- 某个进入动作或事件动作是否真正触发

条件配置的核心目标，是把“什么时候可以流转”和“什么时候自动执行”拆开维护，避免把所有业务规则都堆到动作本身。

---

## 访问路径

### 状态详情页中的条件入口

`配置端 > 配置管理 > 业务逻辑 > 生命周期 > 选择目标生命周期 > 选择目标状态`

在状态详情页中，通常会维护以下条件入口：
- **进入条件**：控制记录是否能进入当前状态
- **用户动作**：控制按钮显示与点击后的校验
- **进入动作**：控制进入状态后哪些自动动作会执行

### 事件动作中的条件入口

`配置端 > 配置管理 > 业务逻辑 > 生命周期 > 选择目标生命周期 > 事件动作`

事件动作与具体状态不绑定，但它的执行条件与状态内动作条件使用同一套条件表达方式。

---

## 一、生命周期中有哪些条件

| 条件类型 | 配置位置 | 生效时机 | 不满足时的结果 | 常见用途 |
|------------|------------|------------|---------------------|------------|
| **进入条件** | 状态详情页 \> 进入条件 | 记录尝试进入目标状态时 | 不能进入该状态 | 审批完成后才允许进入“已批准” |
| **用户动作显示条件** | 状态详情页 \> 用户动作 | 打开记录详情页并加载动作按钮时 | 按钮不显示或不可用 | 只在满足业务前置条件时显示“提交审批” |
| **用户动作执行前校验** | 状态详情页 \> 用户动作 \> 条件校验 | 用户点击按钮后、动作正式执行前 | 弹出提示并终止执行 | 缺少必填信息时阻止“批准” |
| **进入动作执行条件** | 状态详情页 \> 进入动作 | 记录进入目标状态后 | 该条进入动作不执行 | 仅对重大记录发送通知 |
| **事件动作执行条件** | 生命周期详情页 \> 事件动作 | 创建、修改、复制等事件发生时 | 该条事件动作不执行 | 仅在字段被修改后同步相关记录 |

### 使用区别
- **进入条件**解决的是“能不能进入”。
- **用户动作显示条件**解决的是“用户能不能看到这个按钮”。
- **用户动作执行前校验**解决的是“按钮点了以后，是否允许真正执行”。
- **进入动作执行条件**和**事件动作执行条件**解决的是“自动动作要不要跑”。

如果一个规则既需要控制按钮显示，又需要控制执行结果，建议同时配置显示条件和执行前校验，而不是只保留其中一个。

---

## 二、单条条件由哪些部分组成

一条生命周期条件通常由以下部分组成：

| 组成项 | 说明 | 示例 |
|---------|------|------|
| **字段或判断对象** | 选择拿什么数据做判断 | 当前对象字段、父对象字段、引用对象状态 |
| **逻辑运算符** | 定义比较方式 | 等于、包含、大于、为空、已变更 |
| **逻辑值类型** | 定义右值来源 | 指定常量、指定字段、指定变量 |
| **逻辑值** | 具体比较值 | `已批准`、`当前时间`、某个字段 |

### 常见右值来源

| 逻辑值类型 | 说明 | 常见场景 |
|---------------|------|------------|
| **指定常量** | 手工输入或从选择器中直接选值 | 状态等于“已批准” |
| **指定字段** | 取主对象上的另一个字段作为比较值 | 当前对象截止日期大于父对象截止日期 |
| **指定变量** | 取系统运行时变量 | 当前用户、当前质量组织、当前日期、当前时间 |

---

## 三、生命周期条件可判断哪些对象

| 判断范围 | 说明 | 适用示例 |
|------------|------|------------|
| **当前对象状态** | 判断当前记录所处生命周期状态 | 当前对象已在“评审中” |
| **当前对象字段** | 判断当前记录字段值 | 负责人不为空 |
| **父对象状态 / 字段** | 判断父记录状态或字段 | 父偏差已关闭 |
| **子对象状态 / 字段** | 判断所有或部分子记录 | 所有 CAPA 子记录已完成 |
| **引用对象状态 / 字段** | 判断引用记录 | 关联 SOP 已生效 |

当条件依赖相关对象时，建议先确认：
- 相关对象是否已启用生命周期
- 相关关系是否能稳定取到记录
- 规则是否需要限制“全部满足”还是“任一满足”

---

## 四、常用字段类型与条件规则

不同字段类型支持的运算符和值输入方式不同。生命周期相关条件与字段配置条件使用同一套底层规则，但在生命周期场景中更常见的是以下几类。

### 文本、链接

| 项目 | 说明 |
|------|------|
| **常用运算符** | 等于、不等于、包含、不包含、开始于、结束于、为空、不为空 |
| **常用值类型** | 指定常量；部分场景支持指定字段 |
| **使用建议** | 文本比较适合编码、简称、标签类判断；避免把长文本内容当成核心流转条件 |

### 数字

| 项目 | 说明 |
|------|------|
| **常用运算符** | 等于、不等于、大于、大于等于、小于、小于等于、介于、为空、不为空 |
| **常用值类型** | 指定常量、指定字段 |
| **使用建议** | 用于计数、分值、版本序号或时限阈值控制；`介于` 适合做区间判断 |

### 选项、对象类型、生命周期状态、质量组织、用户、角色

| 项目 | 说明 |
|------|------|
| **常用运算符** | 等于、不等于、包含、包含于、不包含于、为空、不为空 |
| **常用值类型** | 指定常量、指定字段；部分字段支持指定变量 |
| **变量示例** | 当前质量组织、当前用户 |
| **使用建议** | 适合做角色判断、质量组织范围限制、状态值分流 |

#### 这一组字段的几个重点规则
- **质量组织**可使用变量 **当前质量组织**
- **用户**可使用变量 **当前用户**
- **角色**通常使用常量或字段，不直接使用运行时变量
- **生命周期状态字段**适合做“当前记录是否已到某状态”或“相关记录是否在目标状态集内”的判断

### 日期、日期时间

| 项目 | 说明 |
|------|------|
| **常用运算符** | 等于、不等于、大于、大于等于、小于、小于等于、介于、在过去、在未来、不在过去、为空、不为空 |
| **常用值类型** | 指定常量、指定字段、指定变量 |
| **变量示例** | 当前日期、当前时间 |
| **使用建议** | 适合做超期拦截、到期提醒、回顾窗口判断 |

#### 日期类条件的注意点
- 对比时间值时，按系统设置的时区计算
- `当前日期` 适用于日期字段，`当前时间` 适用于日期时间字段
- 使用固定常量日期时，后续维护成本高；长期规则优先考虑运行时变量

### 布尔、富文本、附件、对象

| 字段类型 | 常见规则 |
|------------|------------|
| **布尔** | 常用 `等于`、`为空`、`不为空` |
| **富文本 / 长文本** | 常用 `为空`、`不为空` |
| **附件** | 常用 `为空`、`不为空`，适合判断是否已上传文件 |
| **对象** | 常用 `为空`、`不为空`，也可在部分场景中与变量或字段联动 |

### 对象多选

对象多选在生命周期场景中常用于按人员、质量组织、角色集合判断是否命中。

| 项目 | 说明 |
|------|------|
| **常用运算符** | 包含、不包含、为空、不为空 |
| **常用值类型** | 指定常量、指定变量、指定字段 |
| **常量限制** | 常量通常只支持质量组织、用户组、角色 |
| **变量示例** | 当前质量组织、当前部门、当前用户 |

如果条件用于生命周期进入条件、进入动作、用户动作或事件动作，对象多选通常可以与对象、父对象、对象多选字段混用比较。

###  运算符

`已变更` 是生命周期条件中的特殊运算符，使用时要特别注意：
- 仅适用于**修改记录**类事件动作
- 仅适用于**当前对象字段**
- 适合判断“这次保存是否真的改动了某个字段”

如果是进入条件、进入动作条件或普通用户动作显示条件，不应使用 `已变更` 作为主要判断方式。

## 五、按入口配置生命周期条件

### 1\. 配置进入条件

进入条件用于限制记录是否允许进入当前状态。

操作步骤：
1. 进入目标生命周期的**状态详情页**
2. 打开 **进入条件**
3. 点击 **创建**
4. 选择条件类型，并配置字段、运算符、逻辑值类型和值
5. 如有例外场景，补充分支条件
6. 保存并按顺序检查条件列表

使用建议：
- 把“必须满足”的硬性要求放到进入条件
- 避免在进入条件中塞入过多补偿逻辑，复杂自动处理更适合放到进入动作
- 新建记录进入初始状态时，系统不会检查初始状态的进入条件；只有从其他状态回到初始状态时才会校验

### 2\. 配置用户动作显示条件与执行前校验

用户动作通常有两层控制：
- **显示条件**：决定按钮是否出现
- **执行前校验**：决定按钮点击后是否允许继续执行

操作步骤：
1. 进入目标状态的 **用户动作**
2. 创建或编辑目标动作
3. 在动作配置中填写**显示条件**
4. 在 **条件校验** 中补充执行前校验规则和失败提示
5. 保存后用不同角色、不同样本记录分别验证

使用建议：
- “按钮不该出现”用显示条件处理
- “按钮可以显示，但要拦截不合规操作”用执行前校验处理
- 提示文案要直接说明用户缺了什么，不要只写“条件不满足”

### 3\. 配置进入动作执行条件

进入动作条件用于控制自动动作何时执行，适合做“进入状态后按条件触发”的细分处理。

操作步骤：
1. 进入目标状态的 **进入动作**
2. 创建或编辑动作
3. 在动作规则中填写**执行条件**
4. 继续配置动作类型、参数和执行顺序
5. 保存后验证状态进入时的实际触发结果

使用建议：
- 多条进入动作按顺序执行，前后动作有依赖关系时应明确排序
- 如果动作会批量修改相关记录，建议先加上条件，避免无差别全量执行
- 对关键动作，建议同时准备“命中条件”和“未命中条件”两组样本做验证

### 4\. 配置事件动作执行条件

事件动作与状态无直接绑定，但判断表达方式与生命周期动作条件一致。

操作步骤：
1. 打开生命周期详情页中的 **事件动作**
2. 选择事件类型，如 **创建记录**、**修改记录**
3. 创建或编辑事件动作
4. 配置执行条件
5. 保存并通过真实事件触发验证

使用建议：
- 如果是 **修改记录** 事件，可优先考虑 `已变更` 运算符，减少无意义触发
- 事件动作常用于初始化、同步和补偿逻辑，应避免与进入动作重复执行同一件事

---

## 六、推荐配置顺序

建议按下面的顺序整理生命周期条件：
1. 先确定状态与流转路径
2. 再配置**进入条件**，收紧“能否进入”
3. 补充**用户动作显示条件**和**执行前校验**
4. 最后配置**进入动作条件**和**事件动作条件**

这样做的好处是：
- 先把主流程边界定清楚
- 再控制用户侧交互
- 最后再补自动化动作，减少相互打架

---

## 七、验证与排查建议

### 验证清单
1. 准备一组**满足条件**的数据和一组**不满足条件**的数据
2. 分别验证进入状态、显示按钮、点击按钮、自动动作触发是否符合预期
3. 检查条件命中后是否影响后续动作排序和状态流转
4. 对事件动作重点核对是否出现重复触发

### 常见排查方向

| 现象 | 优先检查 |
|------|------------|
| 记录进不了目标状态 | 进入条件、状态流转关系、用户动作目标状态 |
| 按钮显示了但执行失败 | 用户动作执行前校验、目标动作参数 |
| 进入状态后没触发自动动作 | 进入动作条件、动作排序、目标字段是否可更新 |
| 修改记录后没触发事件动作 | 事件类型是否选对、条件是否命中、是否误用了 `已变更` |
