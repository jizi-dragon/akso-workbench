# 权限体系概述
> 本文解释 Gaia 平台权限模型的核心概念和设计理念，帮助理解权限体系的架构思想。   

---

## 概述

Gaia 平台采用**多层次、细粒度**的权限体系，确保用户只能访问和操作其职责范围内的内容，同时满足 GxP 合规对权限控制的严格要求。

### 核心关系

| 关系 | 说明 |
|------|------|
| **用户 → 用户组** | 用户属于一个或多个用户组，便于批量管理 |
| **用户 → 角色** | 用户可以拥有多个角色 |
| **角色 → 权限集** | 角色拥有权限集，定义该角色可访问的功能和数据 |

---

## 功能权限 vs 数据权限

Gaia 平台采用**功能权限**与**数据权限**分离的设计模式：

| 权限类型 | 控制机制 | 解决问题 | 示例 |
|------------|------------|------------|------|
| **功能权限** | 权限集 | 用户能使用什么功能？ | 能否创建文档、运行报表、配置工作流 |
| **数据权限** | DAC | 用户能访问哪些数据？ | 能否看到这条质量事件记录 |

### 形象理解
```
功能权限（权限集）：你会开车吗？有驾照吗？
数据权限（DAC）：这辆车你能开吗？是你的车还是别人的车？
```

### 组合效果

| 功能权限 | 数据权限 | 结果 |
|------------|------------|------|
| ✓ 有 | ✓ 有 | 可以访问并操作该记录 |
| ✓ 有 | ✗ 无 | 能看到对象菜单，但看不到这条具体记录 |
| ✗ 无 | ✓ 有 | **完全无法访问**（对象菜单不可见，记录也不可见） |
| ✗ 无 | ✗ 无 | 完全无法访问 |
> ⚠️ **重要**：功能权限是前置条件。如果用户对某个对象没有任何功能权限，则该用户无法访问该对象的任何记录，即使通过 DAC 被分配了记录角色也无法访问。

## 权限层次

| 权限层次 | 控制机制 | 权限类型 | 静态/动态 | 作用范围 | 说明 |
|------------|------------|------------|-------------|------------|------|
| **功能权限** | 权限集 | 功能权限 | 静态 | 应用级别 | 全局定义用户可以访问哪些对象、字段、菜单 |
| **数据权限** | DAC | 数据权限 | 动态 | 记录级别 | 决定用户可以访问哪些具体记录 |
| **细粒度权限** | 状态权限 | 动态功能权限 | 动态 | 字段/操作级别 | 在记录级别动态调整功能权限 |

## 核心概念简介

### 用户（User）

每个用户代表一个独立的系统账户，具有唯一的登录凭证。用户的权限通过**角色**获得。

### 用户组（Group）

用户组用于将用户组织在一起，便于批量管理。可用于部门组织、职能分组、项目团队等场景。

### 角色（Role）

**角色**是权限管理的核心单元。角色定义了一组职责，并拥有相应的**权限集**来执行这些职责。

| 类型 | 说明 | 示例 |
|------|------|------|
| **应用角色** | 应用级别的角色，决定基础权限 | 系统管理员、业务管理员、普通用户 |
| **对象角色** | 用户与对象记录的关系，用于 DAC | 负责人、协作者 |

### 权限集（Permission Set）

**权限集**定义一组具体权限的集合，被分配给角色，决定该角色可以访问哪些功能和数据。

### 动态访问控制（DAC）

**DAC**是记录级访问控制模型，通过**共享规则**自动将用户分配到记录的角色，实现记录级别的精细化权限管理。

### 状态权限（State Security）

**状态权限**是细粒度权限控制机制，允许根据**生命周期状态**和**用户角色**精确控制字段、操作和关系的访问权限。

---

## GxP 合规要点

🔒 **职责分离**：系统支持配置职责分离规则，确保同一用户不能同时担任冲突角色（如起草和批准）。

🔒 **权限审计**：所有权限变更都被审计追踪记录，包括角色分配、共享设置变更等。

🔒 **定期审查**：建议定期审查用户权限，确保权限与职责匹配。

🔒 **最小权限原则**：只授予用户完成工作所需的最小权限。
