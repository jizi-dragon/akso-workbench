# 合规架构
> 本文解释 Gaia 平台如何满足 GxP 法规要求，包括 21 CFR Part 11、EU Annex 11 和中国 GMP 附录的合规支持。   

---

## 概述

Gaia 平台从架构设计层面内置合规能力，帮助生命科学企业满足全球主要法规的电子记录和电子签名要求。

### 支持的法规标准

| 法规 | 适用区域 | 主要内容 |
|------|------------|------------|
| **FDA 21 CFR Part 11** | 美国 | 电子记录和电子签名 |
| **EU Annex 11** | 欧盟 | 计算机化系统 |
| **中国 GMP 附录：计算机化系统** | 中国 | 计算机化系统验证 |
| **WHO 指南** | 全球 | 数据完整性指南 |
| **PIC/S 指南** | 全球 | 良好数据记录规范 |

## 审计追踪

### 什么是审计追踪？

\*\*审计追踪（Audit Trail）\*\*是系统自动记录的所有操作历史，包括谁、在什么时间、对什么内容、做了什么操作。

### 审计追踪内容

| 记录项 | 说明 |
|---------|------|
| **操作者** | 执行操作的用户 |
| **时间戳** | 操作的精确时间（UTC） |
| **操作类型** | 创建、修改、删除、查看等 |
| **操作对象** | 被操作的文档/记录 |
| **变更前值** | 修改前的字段值 |
| **变更后值** | 修改后的字段值 |
| **操作来源** | UI、API、自动化等 |
| **IP 地址** | 操作者的网络地址 |

### 审计追踪特性

| 特性 | 说明 |
|------|------|
| **不可篡改** | 审计记录无法被修改或删除 |
| **自动生成** | 系统自动记录，无需人工干预 |
| **完整性** | 记录所有 GxP 相关操作 |
| **可追溯** | 支持按时间、用户、对象查询 |
| **可导出** | 支持导出审计报告 |

### 查看审计追踪

用户可在以下位置查看审计追踪：

| 位置 | 范围 |
|------|------|
| **文档详情页** | 单个文档的操作历史 |
| **对象记录页** | 单条记录的操作历史 |
| **系统审计日志** | 全局操作日志（管理员） |
| **审计报表** | 自定义审计分析报表 |

## 电子签名

### 电子签名要素

Gaia 的电子签名符合 21 CFR Part 11 对电子签名的要求：

| 要素 | 实现 |
|------|------|
| **唯一性** | 签名与用户账户唯一绑定 |
| **认证性** | 签署时需重新验证密码 |
| **不可否认性** | 签名与记录不可分离 |
| **时间性** | 系统记录精确签署时间 |
| **含义性** | 显示签名含义（如"作者"、"审批人"） |

### 签名清单

每个电子签名记录以下信息：
```
┌─────────────────────────────────────────────────────────────┐
│                     电子签名记录                             │
├─────────────────────────────────────────────────────────────┤
│  签署者：张三 (zhangsan@company.com)                        │
│  签署时间：2026-02-02 14:30:25 UTC                          │
│  签名含义：质量审批人                                        │
│  操作：批准                                                  │
│  文档：SOP-QC-001 v2.0                                      │
│  IP 地址：10.0.1.100                                         │
└─────────────────────────────────────────────────────────────┘
```

### 签名配置

| 配置项 | 说明 |
|---------|------|
| **签名原因** | 可配置必填的签名理由 |
| **含义声明** | 配置签名代表的声明 |
| **双签名** | 要求两人独立签署 |
| **顺序签名** | 强制签署顺序 |

## 数据完整性

### ALCOA\+ 原则

Gaia 平台设计遵循 **ALCOA\+** 数据完整性原则：

| 原则 | 英文 | Gaia 实现 |
|------|------|-----------|
| **可归属** | Attributable | 所有操作关联用户身份 |
| **清晰可读** | Legible | 数据以标准格式存储显示 |
| **同步记录** | Contemporaneous | 操作时间由系统自动记录 |
| **原始记录** | Original | 原始数据永久保存 |
| **准确** | Accurate | 验证规则确保数据准确 |
| **完整** | Complete | 审计追踪记录完整历史 |
| **一致** | Consistent | 格式和规则保持一致 |
| **持久** | Enduring | 安全存储，长期可访问 |
| **可用** | Available | 需要时可快速检索 |

## 验证支持

### 验证文档包

Gaia 为客户提供验证支持文档：

| 文档 | 内容 |
|------|------|
| **功能规格说明书（FRS）** | 系统功能详细说明 |
| **安装确认（IQ）** | 安装验证方案和记录 |
| **运行确认（OQ）** | 功能验证方案和记录 |
| **性能确认（PQ）** | 性能验证指导 |
| **追溯矩阵** | 需求到测试的追溯 |
| **配置规范** | 安全配置建议 |

### 变更控制

Gaia 平台变更遵循严格的变更控制流程：
1. **变更评估**：影响分析和风险评估
2. **验证计划**：制定验证策略
3. **执行验证**：完成必要的测试
4. **发布说明**：提供版本更新说明
5. **通知客户**：提前通知重大变更
