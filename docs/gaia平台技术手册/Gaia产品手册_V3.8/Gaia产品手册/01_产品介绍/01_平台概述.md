# Gaia 平台概述

---

## 什么是 Gaia 平台

Gaia 是 Akso 自主研发的统一云平台，专为生命科学行业设计，是一个符合 GxP 规范的\*\*"内容\+数据"统一云操作系统\*\*。

### 一句话定义
> Gaia 平台是生命科学企业的数字化基础设施，统一管理文档、数据、流程和合规。   

### 平台特点

| 特点 | 说明 |
|------|------|
| **统一对象模型** | 文档是对象的一种，使用相同的管理机制 |
| **GxP 合规** | 满足生命科学行业的合规要求 |
| **本地化** | 针对中国市场优化 |
| **灵活部署** | 支持 SaaS 和私有化部署 |

## 为什么需要 Gaia

### 行业挑战

生命科学行业面临独特的数字化挑战：

| 挑战 | 传统方案的问题 |
|------|---------------------|
| **合规要求严格** | 通用软件无法满足 21 CFR Part 11 等法规 |
| **文档\+数据分离** | 传统 ECM 和数据库分离，难以关联 |
| **系统孤岛** | 多个独立系统，数据不互通 |
| **配置复杂** | 需要大量定制开发，实施周期长 |

## 五大核心能力

### 1\. 统一对象模型

Gaia 平台最核心的创新是**统一对象模型（Unified Object Model）**。
> **核心理念：在 Gaia 中，一切皆对象。文档也是一种标准对象，非结构化内容作为文档对象的一个字段来存储。**   

| 能力 | 说明 |
|------|------|
| **统一数据模型** | 文档和业务数据都是对象，使用相同的机制 |
| **文件字段** | 文档对象通过文件字段存储 Word/PDF 等非结构化内容 |
| **对象管理** | 基于对象的结构化数据，支持自定义字段和关系 |
| **文档渲染** | 文件字段内容自动渲染为可预览格式 |
| **版本控制** | 统一的版本管理机制 |

**为什么重要**：
- 文档和业务数据使用相同的生命周期、工作流、权限机制
- 简化配置和管理，一致的用户体验
- 更灵活的关联和查询能力
- SOP 文档可以直接关联培训任务、产品主数据、偏差记录等

### 2\. 流程与合规

| 能力 | 说明 |
|------|------|
| **生命周期管理** | 定义文档/数据从"草稿"到"归档"的状态流转 |
| **工作流引擎** | 可配置的审批流、任务分配、自动通知 |
| **审计追踪** | 自动记录所有操作，不可篡改 |
| **电子签名** | 符合 21 CFR Part 11 的电子签名 |

**为什么重要**：
- 满足 GMP、GLP、GCP 合规要求
- 确保数据完整性（ALCOA\+）
- 支持监管审计和检查

### 3\. 开发与集成

| 能力 | 说明 |
|------|------|
| **SDK** | 服务端自定义逻辑（触发器、动作） |
| **REST API** | 完整的 API 接口，支持外部集成 |
| **集成引擎** | 跨系统数据同步规则 |

**为什么重要**：
- 可以与 ERP、MES、LIMS 等系统集成
- 支持自定义业务逻辑
- 实现端到端的数字化流程

### 4\. 部署与运维

| 能力 | 说明 |
|------|------|
| **Sphere 管理** | Dev/QA/UAT 多级 Sphere，可承载开发、测试、验证和生产等不同用途 |
| **配置迁移** | 通过部署包在不同 Sphere 之间搬运配置 |

**为什么重要**：
- 支持规范的变更管理流程
- 降低生产环境风险
- 简化运维工作

### 5\. 智能化

| 能力 | 说明 |
|------|------|
| **AI Agents** | 嵌入工作流的智能助手 |
| **智能分类** | 自动识别文档类型 |
| **智能提取** | 自动提取元数据 |

**为什么重要**：
- 提高工作效率
- 减少人工错误
- 辅助合规审核

## 配置模型层次

Gaia 平台的配置能力分为三个层次，管理员和实施人员通过配置这三层来构建业务应用：
```
┌─────────────────────────────────────────────────────────────────┐
│                     Gaia 配置模型层次                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   ┌──────────────────────────────────────────────────────────┐  │
│   │                   界面呈现层                              │  │
│   │   菜单、列表布局、表单布局、视图、操作栏、仪表盘          │  │
│   │   → 定义"用户看到什么、如何交互"                         │  │
│   └──────────────────────────────────────────────────────────┘  │
│                              ▲                                   │
│   ┌──────────────────────────┴───────────────────────────────┐  │
│   │                   业务逻辑层                              │  │
│   │   生命周期、工作流、权限规则、验证规则、自动化动作        │  │
│   │   → 定义"业务如何流转、如何管控"                         │  │
│   └──────────────────────────────────────────────────────────┘  │
│                              ▲                                   │
│   ┌──────────────────────────┴───────────────────────────────┐  │
│   │                   数据模型层                              │  │
│   │   对象、字段、关系、子类型、文件字段                      │  │
│   │   → 定义"管理什么数据、数据结构是什么"                   │  │
│   └──────────────────────────────────────────────────────────┘  │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

| 层次 | 核心概念 | 作用 | 详细文档 |
|------|------------|------|------------|
| **数据模型层** | 对象、字段、关系 | 定义管理什么数据 | [数据模型](04_%E6%95%B0%E6%8D%AE%E6%A8%A1%E5%9E%8B.md) |
| **业务逻辑层** | 生命周期、工作流、权限 | 控制数据如何流转和访问 | [生命周期与工作流](06_%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F%E4%B8%8E%E5%B7%A5%E4%BD%9C%E6%B5%81.md)、[权限体系](05_%E6%9D%83%E9%99%90%E4%BD%93%E7%B3%BB%E6%A6%82%E8%BF%B0.md) |
| **界面呈现层** | 列表布局、表单布局、视图 | 决定用户如何查看和操作 | [界面与布局](../02_%E7%94%A8%E6%88%B7%E6%8C%87%E5%8D%97/01_%E5%BF%AB%E9%80%9F%E5%85%A5%E9%97%A8/02_%E7%95%8C%E9%9D%A2%E4%BB%8B%E7%BB%8D.md) |
> 💡 **配置顺序**：数据模型 → 业务逻辑 → 界面呈现（自下而上构建）

## 技术架构

### 云原生设计
- **多租户架构**：数据隔离，资源共享
- **弹性伸缩**：根据负载自动扩容
- **高可用性**：多区域部署，故障自动切换
- **安全防护**：端到端加密，定期安全审计

### 部署模式

| 模式 | 说明 | 适用场景 |
|------|------|------------|
| **SaaS 公有云** | Akso 托管运维 | 大多数客户 |
| **私有化部署** | 部署在客户环境 | 有特殊合规要求的客户 |
