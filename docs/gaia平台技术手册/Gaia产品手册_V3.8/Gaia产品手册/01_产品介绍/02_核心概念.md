# 核心概念

本文介绍 Gaia 平台的核心概念和术语，帮助您建立对平台的整体理解。

---

## 对象（Object）

### 定义

**对象**是 Gaia 平台中**唯一的数据实体类型**。无论是结构化的业务数据还是包含非结构化内容的文档，都通过对象来管理。
> 💡 **统一对象模型**：在 Gaia 中，**文档也是一种对象**，非结构化内容通过文件字段存储。这使得文档和业务数据使用相同的字段、生命周期、工作流和权限机制。   

### 核心特征

| 特征 | 说明 |
|------|------|
| **统一性** | 文档和业务数据都是对象 |
| **结构化** | 由预定义的字段组成 |
| **可配置** | 管理员可自定义对象和字段 |
| **可关联** | 对象之间可以建立引用关系 |
| **受控** | 可绑定生命周期和工作流 |

### 对象分类

| 类型 | 说明 | 示例 |
|------|------|------|
| **系统对象** | 平台核心，不可删除 | 用户(User)、组(Group)、角色(Role) |
| **文档对象** | 包含文件字段的标准对象 | 文档(Document) |
| **标准业务对象** | 应用预置，可配置 | 产品(Product)、供应商(Supplier) |
| **自定义对象** | 用户创建 | 培训课程、检验项目 |

### 示例

一个"产品"对象可能包含以下字段：
- 产品编码（文本）
- 产品名称（文本）
- 规格（文本）
- 生产企业（引用 → 供应商对象）
- 状态（选项列表）

## 字段（Field）

### 定义

**字段**是对象的属性，定义了数据的类型和约束。

### 字段类型

| 字段类型 | 说明 | 示例值 |
|------------|------|---------|
| **文本** | 单行文本 | "阿莫西林胶囊" |
| **长文本** | 多行文本 | 产品描述 |
| **数字** | 整数或小数 | 100, 3.14 |
| **日期** | 日期值 | 2026-02-01 |
| **日期/时间** | 日期和时间 | 2026-02-01 10:30:00 |
| **是/否** | 布尔值 | 是 / 否 |
| **选项** | 单选下拉 | 已激活 / 已停用 |
| **父对象** | 引用其他对象记录，建立父子关系 | \[业务单元-部门\] |
| **对象** | 引用其他对象记录；引用文档对象时支持版本绑定 | → SOP-001 v2.0 |
| **查找字段** | 从父对象或引用对象同步字段值（只读） | 自动带出：产品.持有人 |
| **统计字段** | 对关联记录进行聚合统计（计数、求和等） | CAPA 数量 = 12 |
| **附件** | 直接存储文件（无版本/生命周期） | 支持性文件、图片证据 |
| **公式** | 计算字段 | = 单价 × 数量 |
| **富文本** | 带格式的文本 | HTML 内容 |
| **组件** | 特有能力字段（可用能力以当前版本为准） | 状态 |
| **文件** | 非结构化内容存储（文档对象专用） | Word、PDF、图片等 |

### 字段属性

| 属性 | 说明 |
|------|------|
| **必填** | 保存时必须填写 |
| **只读** | 只能通过系统设置 |
| **默认值** | 新建时的初始值 |
> 📖 **参阅**：[字段类型参考](../04_%E9%85%8D%E7%BD%AE%E6%8C%87%E5%8D%97/01B_%E5%AF%B9%E8%B1%A1%E5%AD%97%E6%AE%B5.md)

## 文档（Document）

### 定义

**文档**是 Gaia 平台中的一种**标准对象**，其特殊之处在于包含一个**文件字段**，用于存储非结构化内容（如 PDF、Word、Excel 等文件）。
> 💡 **核心理念**：在 Gaia 中，文档不是独立于对象的实体，而是对象的一种。非结构化的文件内容作为文档对象的一个字段来管理。   

### 文档对象结构
```
┌─────────────────────────────────────────────────────────────────┐
│                    文档对象（Document Object）                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │  标准字段：名称、编号、状态、版本、创建者、部门...      │   │
│   └─────────────────────────────────────────────────────────┘   │
│                                                                  │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │  📄 文件字段 ← 存储 Word/PDF/Excel 等非结构化内容       │   │
│   └─────────────────────────────────────────────────────────┘   │
│                                                                  │
│   + 生命周期 + 工作流 + 权限（与其他对象使用相同机制）         │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 文档特性

| 特性 | 说明 |
|------|------|
| **统一对象模型** | 文档是对象，使用相同的字段、生命周期、工作流机制 |
| **版本控制** | 自动保留所有历史版本 |
| **在线预览** | 文件字段内容自动渲染为可预览格式 |
| **安全渲染** | 转换为安全格式，防止篡改 |
| **水印保护** | 下载时自动添加水印 |
| **批注协作** | 支持在渲染件上添加评论 |
| **全文搜索** | 文件内容可被索引和搜索 |

### 文档对象 vs 业务对象

| 维度 | 文档对象 | 业务对象 |
|------|------------|------------|
| **本质** | 标准对象 | 标准/自定义对象 |
| **特殊字段** | 包含文件字段 | 通常不含文件字段 |
| **内容** | 结构化字段 \+ 非结构化文件 | 结构化字段 |
| **渲染** | 文件可预览 | 表单展示 |
| **搜索** | 字段搜索 \+ 全文搜索 | 字段搜索 |
| **生命周期** | 相同机制 | 相同机制 |
| **工作流** | 相同机制 | 相同机制 |
| **权限** | 相同机制 | 相同机制 |

## 生命周期（Lifecycle）

### 定义

**生命周期**定义了对象或文档从创建到归档的状态流转规则。

### 生命周期组成

| 组成 | 说明 |
|------|------|
| **状态** | 对象/文档在某一时刻的情况（如：草稿、生效、废止） |
| **转换** | 从一个状态到另一个状态的路径 |
| **规则** | 转换时的条件和动作 |

### 示例：文档生命周期
```
                    ┌─────────┐
                    │  草稿   │
                    │  Draft  │
                    └────┬────┘
                         │ 提交审批
                         ▼
                    ┌─────────┐
            退回 ←──│ 审批中  │
             │      │ Pending │
             │      └────┬────┘
             │           │ 批准
             │           ▼
             │      ┌─────────┐
             └─────→│  生效   │
                    │Effective│
                    └────┬────┘
                         │ 作废
                         ▼
                    ┌─────────┐
                    │  废止   │
                    │Obsolete │
                    └─────────┘
```

### 生命周期控制

| 控制 | 说明 |
|------|------|
| **状态权限** | 不同状态下的可操作权限不同 |
| **自动锁定** | 某些状态下内容不可修改 |
| **转换条件** | 满足条件才能转换状态 |
| **触发动作** | 状态变更时自动执行动作 |
> 🔒 **合规要点**：生效后的文档自动锁定，不可直接修改。如需变更，必须创建新版本并重新走审批流程。

## 工作流（Workflow）

### 定义

**工作流**是自动化业务流程的机制，用于管理审批、任务分配和通知。

### 工作流类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **审批工作流** | 多人审批确认 | 文档发布审批 |
| **任务工作流** | 任务分配和跟踪 | CAPA 整改任务 |
| **通知工作流** | 自动发送通知 | 到期提醒 |

### 工作流组成

| 组成 | 说明 |
|------|------|
| **触发条件** | 何时启动工作流 |
| **节点** | 工作流中的步骤 |
| **参与者** | 每个节点的处理人 |
| **规则** | 流转条件和超时处理 |
> 📖 **参阅**：[工作流引擎](06_%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F%E4%B8%8E%E5%B7%A5%E4%BD%9C%E6%B5%81.md)

## 电子签名（E-Signature）

### 定义

**电子签名**是用户以电子方式确认操作的机制，等同于手写签名的法律效力。

### 签名场景

| 场景 | 说明 |
|------|------|
| **审批确认** | 批准或退回时签名 |
| **记录确认** | 确认数据的真实性 |
| **见证签名** | 多人共同确认 |

### 签名信息

每次电子签名记录以下信息：

| 信息 | 说明 |
|------|------|
| **签名人** | 执行签名的用户 |
| **签名时间** | 精确到秒的时间戳 |
| **签名含义** | 选择的签名原因 |
| **签名数据** | 加密的签名哈希 |
> 🔒 **合规要点**：根据 21 CFR Part 11，电子签名必须与唯一的个人绑定，签名操作需要身份验证（输入密码）。

## 审计追踪（Audit Trail）

### 定义

**审计追踪**是系统自动记录的操作日志，记录谁、在什么时间、做了什么操作。这是 GxP 合规的核心要求。

### 审计类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **数据审计** | 记录数据变更 | 字段值修改、状态变更 |
| **文件审计** | 记录文件操作 | 上传、下载、删除 |
| **签名审计** | 记录电子签名 | 审批签名、确认签名 |
| **访问审计** | 记录访问行为 | 登录、查看、导出 |
| **系统审计** | 记录配置变更 | 对象配置、权限变更 |

### 记录内容

| 内容 | 说明 |
|------|------|
| **操作人** | 执行操作的用户 |
| **操作时间** | 精确的时间戳（含时区） |
| **操作类型** | 创建、修改、删除、查看等 |
| **操作对象** | 被操作的对象/文档 |
| **变更详情** | 修改前后的值对比（新旧值） |

### ALCOA\+ 合规

审计追踪满足数据完整性的 ALCOA\+ 原则：

| 原则 | 实现 |
|------|------|
| **Attributable（可归属）** | 每条记录关联具体用户 |
| **Legible（可读）** | 清晰展示新旧值对比 |
| **Contemporaneous（同步）** | 操作时即时记录 |
| **Original（原始）** | 保留原始数据快照 |
| **Accurate（准确）** | 系统自动记录，无人工干预 |

### 查询审计日志
1. **按对象查询**：查看特定记录的操作历史
2. **按用户查询**：查看某用户的所有操作
3. **按时间范围**：筛选特定时间段的操作
4. **按操作类型**：筛选特定类型（如删除操作）

### 保留策略
- 审计日志**永久保留**，不可删除
- 支持归档到长期存储
- 满足法规要求的保留期限（通常 ≥10 年）

### 特性
- **不可篡改**：审计记录无法修改或删除
- **完整性**：所有操作都有记录
- **可追溯**：支持按时间、用户、对象查询
> 📖 **参阅**：[日志管理](../03_%E7%AE%A1%E7%90%86%E5%91%98%E6%8C%87%E5%8D%97/04_%E6%97%A5%E5%BF%97%E7%AE%A1%E7%90%86.md)
