# 作业管理
> 本文介绍如何在 Gaia 平台中创建、维护和监控后台作业。   

---

## 概述

作业用于按预定时间自动执行后台任务。管理员可以通过作业管理配置作业定义、安排执行计划，并在监控页面跟踪每次执行结果。

作业管理主要覆盖以下内容：
- 创建和维护作业定义
- 启用、停用、编辑和删除作业
- 查看计划作业、运行作业和历史作业
- 处理异常通知、取消实例和查看执行日志

### 访问入口

`配置环境 > 运维管理 > 作业管理`

作业实例监控入口位于：
- `配置环境 > 运维管理 > 计划作业`
- `配置环境 > 运维管理 > 运行作业`
- `配置环境 > 运维管理 > 历史作业`

---

## 1\. 作业的基本概念

作业管理中常见的几个概念如下：

| 术语 | 说明 |
|------|------|
| 作业定义 | 描述作业内容和执行计划的一组配置 |
| 作业实例 | 基于作业定义生成的一次具体执行记录 |
| 作业计划 | 定义作业的执行频率、执行时间和时区 |

按执行方式区分，作业可分为：
- 计划作业：按固定周期反复执行
- 临时作业：由系统事件触发，仅执行一次

按维护方式区分，作业可分为：
- 自定义作业：由管理员创建和维护
- 标准作业：由系统内置，管理员可查看、启停或调整部分属性

当前作业管理中常见的作业类型包括：
- 对象操作
- 文档操作
- URL 调用
- 计划导出
- 文档定期回顾
- 同步组织架构

其中，简报类作业由简报订阅功能自动创建。管理员不需要在作业管理中手工新增这类作业，通常只需要在列表中查看或配合排查执行情况。

---

## 2\. 作业定义列表

列表页集中展示当前环境中的全部作业定义。可以通过页面上方的查询框查找目标作业，通过右上角的 `新增` 创建新作业；需要一次处理多个作业时，可以先勾选记录，再执行 `批量启用` 或 `批量停用`。

点击作业名称可进入详情页。每条记录右侧的操作菜单可用于编辑、启用、停用或删除当前作业。

列表中会显示以下关键信息：

| 列 | 作用 |
|---|------|
| 勾选框 | 选择当前作业，用于批量启用或批量停用 |
| 名称 | 作业名称；点击名称可进入作业详情页 |
| 作业类型 | 标识当前作业属于对象操作、文档操作、URL 调用等哪一类 |
| 状态 | 标识作业当前是启用还是停用；只有启用状态的作业才会继续排期 |
| 启用延迟通知 | 标识该作业是否启用了延迟通知能力 |
| 作业 Cron 表达式 | 显示当前作业的执行计划表达式，便于管理员快速核对排期规则 |
| 连续执行错误次数 | 显示该作业连续执行错误的次数，便于管理员识别异常作业 |
| 操作 | 打开当前作业的操作菜单 |

页面中的常用操作如下：
- `新增`：进入作业创建页，新增一个作业定义
- `批量启用`：将已勾选的停用作业重新投入排期
- `批量停用`：停止已勾选作业后续的排期
- `编辑`：进入当前作业的编辑页，修改排期、动作或消息设置
- `启用`：将停用中的作业重新投入排期
- `停用`：停止后续排期，并取消该作业已经生成但未执行的实例
- `删除`：删除作业定义，并移除尚未执行的实例

操作菜单中的可见项会随作业当前状态变化：
- 启用中的作业可执行 `编辑`、`停用`、`删除`
- 停用中的作业可执行 `编辑`、`启用`、`删除`

## 3\. 执行计划

执行计划用于定义作业何时运行。当前支持以下周期：

| 周期 | 说明 |
|------|------|
| 每分执行 | 每分钟重复执行一次 |
| 每小时执行 | 每小时重复执行一次 |
| 每日执行 | 每天在指定时间执行 |
| 每周执行 | 每周在指定日期和时间执行 |
| 每月执行 | 每月在指定日期，或某周的某一天执行 |
| 每年执行 | 每年在指定日期和时间执行 |

配置执行计划时，需要同时确认执行时间和时区。作业实例监控页面中的计划执行时间、启动时间和完成时间也会显示时区信息。

## 4\. 创建作业

点击作业管理列表页右上角的 `新增` 后，可进入作业创建页。不同作业类型的字段有所差异，但以下信息通常会出现：

| 字段 | 作用 | 备注 |
|------|------|------|
| 名称 | 作业显示名称 | 必填，长度为 1-200 字符，需唯一 |
| Code | 作业唯一编码 | 必填，长度为 1-200 字符，需唯一 |
| 状态 | 控制作业是否启用 | 默认停用；启用后会立即生成下一条计划作业实例 |
| 作业类型 | 选择作业类别 | 不同类型会展开不同配置项 |
| 责任人 | 接收异常通知的角色或负责人 | 部分类型为非必填 |
| 执行计划 | 定义执行周期、执行时间和时区 | 必填 |

### 4.1 创建对象操作作业

对象操作作业用于按计划处理对象记录。进入创建页后，可先在 `详情` 中补齐基础信息，再设置执行周期、动作配置和消息提醒，最后通过右上角的 `保存` 完成创建。

#### 4.1.1 详情

`详情` 用于填写作业的基础信息，决定这条作业怎么标识、何时生效，以及由谁接收异常通知。

| 字段 | 作用 | 说明 |
|------|------|------|
| 名称 | 作业显示名称 | 必填，用于在列表页识别当前作业 |
| 状态 | 控制作业是否启用 | 创建页默认显示为 `禁用`，保存后可按需启用 |
| Code | 作业唯一编码 | 必填，作为作业的唯一标识 |
| 类型 | 选择作业类型 | 此处选择 `对象操作` |
| 启用延迟通知 | 控制是否对作业延迟执行发送通知 | 按需开启 |
| 责任人 | 接收异常通知的负责人或角色 | 可按业务需要选择 |
| 时区 | 定义作业执行所属时区 | 会直接影响计划时间和监控中的执行时间显示 |

#### 4.1.2 计划时间

`计划时间` 用于设置作业多久执行一次，以及具体在什么时间执行。周期支持 `每分 / 每小时 / 每日 / 每周 / 每月 / 每年`，时间可精确到分钟。设置时需要同时确认执行时间和时区，避免排期落在错误的业务时段。

#### 4.1.3 动作配置

`动作配置` 用于定义这条作业实际要做什么，以及处理哪些对象记录。

| 配置项 | 作用 |
|---------|------|
| 动作 | 选择作业要执行的动作 |
| 对象 | 指定受作业影响的对象 |
| 执行条件 | 限制哪些对象记录可以被本次作业处理 |
| 触发时间 | 指定以哪个日期字段作为触发依据 |

对象操作作业的常见动作如下：
- `修改状态`：将满足条件的对象记录变更到目标状态
- `发送消息`：在触发时间向对象生命周期角色发送消息
- `无操作`：不修改数据，通常只配合消息提醒使用
- `创建相关记录`：在满足执行条件和相关记录条件时自动创建相关记录

当动作选择为 `修改状态` 时，还可以决定是否在执行前取消活跃工作流。如果不取消，而记录上存在活跃工作流，作业会执行错误并记录异常日志。

执行条件区域支持继续新增条件，并通过逻辑关系组合多个条件，用来缩小实际参与作业的数据范围。

如果动作选择为 `修改状态`，需要继续确认目标状态、触发时间，以及是否在执行前取消活跃工作流。这个动作会把满足执行条件的对象记录推进到指定状态，适合处理到期自动流转、批量状态推进等场景。

如果动作选择为 `发送消息`，需要继续在 `消息设置` 中选择消息模板、收件人和发送日期。这个动作本身不修改对象数据，只在满足执行条件时按设定时间向相关角色或人员发送提醒。

如果动作选择为 `无操作`，系统不会修改对象记录，只会按照计划时间结合执行条件进行一次判断。这个动作通常用于只发提醒、不改状态的场景，因此一般需要配合 `消息设置` 一起使用。

如果动作选择为 `创建相关记录`，页面会继续要求选择相关记录配置，并结合执行条件决定哪些对象记录需要自动创建下游记录。这个动作适合在满足条件时自动补齐关联业务记录，减少手工创建。

#### 4.1.4 消息设置

`消息设置` 用于维护触发前提醒。需要提醒相关人员时，可以在这里选择消息模板、收件人，并设置在触发日期前多少小时发送。

| 字段 | 作用 |
|------|------|
| 消息模板 | 选择发送内容使用的模板 |
| 收件人 | 选择接收提醒的角色或人员 |
| 发送日期 | 设置在触发日期前多少小时发送 |

如果需要发送多条提醒，可点击 `添加动作` 继续新增消息设置。

### 4.2 创建文档操作作业

文档操作作业用于按计划处理文档。创建页面同样分为 `详情`、`计划时间`、`动作配置` 和 `消息设置`。前两部分与对象操作作业的填写方式基本一致，区别主要集中在 `动作配置`。

文档操作作业当前支持以下动作：
- `无操作`
- `修改状态`
- `发送通知`
- `创建相关记录`
- `计算培训完成率`

在当前配置场景中，作业类型为 `文档操作`，动作选择为 `修改状态`。这时需要继续补齐以下信息：

| 配置项 | 作用 |
|---------|------|
| 动作 | 选择当前作业要执行的文档动作；当前示例为 `修改状态` |
| 取消活跃的工作流以执行操作 | 控制执行前是否先取消文档上的活跃工作流 |
| 生命周期 | 选择当前作业作用于哪个文档生命周期 |
| 文档版本 | 选择处理哪个版本范围 |
| 执行条件 | 在选定生命周期后配置文档筛选条件，限制本次作业实际处理的文档范围 |
| 是否修改状态 | 控制系统在执行该动作时是否同步修改文档状态 |
| 目标状态 | 选择文档处理完成后要进入的状态 |
| 触发时间 | 选择作业以哪个日期字段作为触发依据 |

`文档版本` 当前支持以下选项：
- `最新版本`
- `最新稳定版本`
- `当前版本`

如果动作为 `修改状态`，就需要先确认生命周期。选定生命周期后，页面才可以继续配置执行条件，再依次确认文档版本、`是否修改状态`、目标状态和触发时间，最后决定是否勾选 `取消活跃的工作流以执行操作`。当文档上存在活跃工作流，而这里又没有勾选取消时，作业执行时可能无法直接修改状态。

需要发送提醒时，可以继续在 `消息设置` 中补充消息模板、收件人和发送时间；不需要提醒时，这一部分可以留空。

如果动作选择为 `创建相关记录`，页面会要求继续选择 `生命周期` 和 `相关记录配置`。选定生命周期后，同样可以继续配置 `执行条件`，用来限制哪些文档会参与本次作业。`执行条件` 下方的关系选项用于判断“满足以下条件的记录”或“不存在满足以下条件的记录”，系统会据此决定是否为当前文档自动创建相关记录。完成这些设置后，再选择 `触发时间`，就可以确定相关记录在什么时点被创建。

如果动作选择为 `发送通知`，页面会要求继续选择 `生命周期`，并填写 `消息模板` 和 `收件人`。选定生命周期后，同样可以继续配置 `执行条件`，用来限制哪些文档会触发本次通知。完成这些设置后，再通过 `触发时间` 确定通知发送的时点。这个动作不会修改文档状态，也不会创建相关记录，而是在满足条件时按设定内容向指定收件人发送通知。

如果动作选择为 `计算培训完成率`，页面会要求继续选择 `生命周期`。选定生命周期后，同样可以继续配置 `执行条件`，用来限制哪些文档会参与本次计算。这个动作额外提供 `是否修改状态` 开关，用于控制系统在计算培训完成率后是否同步修改文档状态。最后再通过 `触发时间` 确定培训完成率的计算时点。如果同时勾选了 `取消活跃的工作流以执行操作`，还需要提前确认当前文档上的活跃工作流是否允许被取消。

### 4.3 创建 URL 调用作业

URL 调用作业用于按计划调用外部 URL。

创建时，除基本信息和执行计划外，还需要在 `动作配置` 中继续填写 `接口类型`、`URL` 和 `接口超时时间`。

| 配置项 | 作用 |
|---------|------|
| 接口类型 | 选择本次调用使用的接口类型 |
| URL | 填写需要定时调用的接口地址 |
| 接口超时时间 | 设置接口调用的超时时间 |

配置 URL 调用作业时，先确认接口类型，再填写完整的 URL 地址，最后设置接口超时时间。保存后，系统会按照计划时间定时发起调用。

### 4.4 创建计划导出作业

计划导出作业用于按计划导出对象、审计日志或文档元数据。

如果导出场景属于简报订阅，对应的简报类作业会由简报订阅功能自动创建，不需要在这里手工创建。

创建时需要重点配置：

| 配置项 | 作用 |
|---------|------|
| 导出实体 | 选择希望导出的对象或日志类型 |
| 启用完整数据导出 | 控制是否每次都导出全量数据 |

计划导出作业的使用规则如下：
- 首次执行会导出全部历史数据
- 后续默认只导出上次成功作业与本次作业之间新增或未导出的数据
- 开启 `启用完整数据导出` 后，可再次导出全量数据
- 导出文件会保存在文件服务器上
- 作业执行成功或执行错误后，责任人都会收到通知

### 4.5 创建文档定期回顾作业

文档定期回顾作业用于按计划自动生成文档定期回顾记录。

创建时需要确认：
- 作业类型为 `文档定期回顾`
- 指定文档生命周期
- 设置条件
- 设置触发日期
- 设置作业状态

作业运行后，系统会为满足条件的文档自动创建定期回顾记录。

### 4.6 创建同步组织架构作业

同步组织架构作业用于按计划同步第三方系统中的组织架构数据，包括业务单元、部门、职位、用户及其引用关系。

创建时需要确认：
- 作业类型为 `同步组织架构`
- 责任人
- 执行计划
- 作业状态

作业运行后，系统会按执行计划调用同步服务，完成组织架构同步。

### 4.7 创建 SDK作业

SDK作业用于按计划执行指定的 SDK 逻辑。创建页同样分为 `详情`、`计划时间` 和 `动作配置`。

前两部分与其它作业类型一致，仍然需要先填写名称、状态、Code、责任人、时区等基础信息，再设置执行周期。当前页面中，`计划时间` 同样支持按分钟设置执行计划。

SDK作业和其它类型的主要区别在 `动作配置`。这里需要填写 `SDK编码`，用于指定本次作业实际执行哪一段 SDK 逻辑。保存后，系统会按计划时间定时执行该 SDK 作业。

## 5\. 编辑、启用、停用和删除

### 5.1 编辑作业

可以通过以下两种方式进入编辑页：
- 在作业列表页点击作业名称，进入详情页后再点击右上角 `编辑`
- 在作业列表页的操作菜单中直接点击 `编辑`

编辑时，管理员可以按需调整执行计划、动作、条件、消息提醒和状态等配置。

如果编辑的是启用中的作业，进入编辑页后其状态会自动变为 `停用`。保存前需要按需重新设置为 `启用`，保存后系统才会继续按新规则生成排期实例。

### 5.2 启用和停用
- `启用`：将停用中的作业重新投入排期，并按当前执行计划生成新的作业实例
- `停用`：停止后续排期，并取消该作业已经排期但尚未执行的实例

如果作业被重新启用，系统会按新的排期规则生成新的实例。

### 5.3 删除作业

删除作业前，系统会弹出确认框。

删除后会产生以下结果：
- 作业定义从列表中移除
- 尚未执行的作业实例会一起删除
- 已经执行完成的历史实例会保留，用于追溯

标准作业不允许删除。

## 6\. 作业实例的生成规则

### 6.1 临时作业

临时作业通常由事件触发，例如异步进入动作、导入导出等。执行完成后，实例会进入历史作业列表。

### 6.2 计划作业

计划作业会在以下场景生成新的作业实例：
1. 系统首次启动并加载作业计划
2. 配置迁移后重新生成排期
3. 新建作业并设置为 `启用`
4. 编辑作业后重新设置为 `启用`
5. 上一个实例执行完成后，自动生成下一周期实例

以下操作会取消已生成但未执行的实例：
- 删除作业
- 停用作业
- 取消作业计划

## 7\. 作业监控

### 7.1 计划作业

计划作业页面用于查看已经排期但尚未启动的实例。列表按计划时间分页展示当前环境中的计划作业，支持通过页面上方的查询框按名称等条件快速检索目标实例。

页面中会显示以下关键信息：
- `作业ID`：用于定位当前计划实例
- `名称`：显示该计划实例对应的作业名称
- `计划时间`：显示这条实例预计执行的时间
- `时区`：显示计划时间所属时区
- `状态`：当前页面常见状态为 `已排期`
- `操作`：打开当前计划实例的操作菜单

当前页面常用操作如下：
- `立即启动`：立刻执行当前实例，并取消下一个尚未运行的计划实例
- `停用作业`：停用该实例所属作业，并取消当前已排期实例
- `查看作业定义`：进入作业定义详情页
- `取消`：取消当前计划实例，并自动生成下一周期实例

执行 `立即启动` 和 `取消` 前，系统都会弹出确认提示。

### 7.2 运行作业

运行作业页面用于查看已经启动但尚未完成的实例。列表按启动时间分页展示当前环境中的运行作业，支持通过页面上方的查询框按名称等条件快速检索目标实例。

页面中会显示以下关键信息：
- `作业ID`：用于定位当前运行实例
- `名称`：显示该运行实例对应的作业名称
- `启动时间`：显示当前实例实际开始执行的时间
- `时区`：显示启动时间所属时区
- `状态`：显示当前实例的执行状态
- `操作`：打开当前运行实例的操作菜单

当前页面常见状态包括：

| 状态 | 说明 |
|------|------|
| 排队 | 已启动，正在等待执行 |
| 运行中 | 作业正在执行 |

当前页面常用操作如下：
- `查看作业定义`：进入该实例对应的作业定义详情页
- `取消`：取消当前运行实例

执行 `取消` 前，系统会弹出确认提示。

### 7.3 历史作业

历史作业页面用于查看已经执行完成的实例。列表按启动时间分页展示当前环境中的历史作业，支持通过页面上方的查询框按名称等条件快速检索目标实例。

页面中会显示以下关键信息：
- `作业ID`：用于定位当前历史实例
- `名称`：显示该历史实例对应的作业名称
- `启动时间`：显示该实例开始执行的时间
- `完成时间`：显示该实例执行完成的时间
- `时区`：显示时间所属时区
- `状态`：显示当前历史实例的执行结果
- `操作`：打开当前历史实例的操作菜单

常见完成状态包括：

| 状态 | 说明 |
|------|------|
| 成功 | 作业实例成功执行 |
| 已取消 | 作业实例被手动取消 |
| 执行错误 | 作业已运行，但部分数据处理失败 |
| 运行失败 | 作业启动或运行过程中发生内部错误 |
| 跳过 | 作业未在计划周期内正常启动，系统未执行该实例 |

当前页面常用操作如下：
- `查看作业定义`：进入该实例对应的作业定义详情页
- `查看日志`：查看当前历史实例的执行日志，用于排查执行结果和异常原因。日志中会记录这次执行的基础信息，例如作业ID、名称、时区、启动时间、结束时间和状态，便于核对这次执行是否成功

如果历史实例对应的作业定义已经删除，进入详情时会提示该作业已删除。

---

## 8\. 异常通知与异常处理

### 8.1 执行错误通知

当作业实例运行中出现错误时，系统会自动向作业责任人发送通知，便于及时排查。

### 8.2 常见异常处理规则
- 生成排期时如果因系统维护等原因失败，系统会在 5 小时后自动重试
- 重试仍失败时，该实例会被标记为 `跳过`
- 如果同一个作业的上一个实例尚未执行完成，而下一个周期已经到达，新实例会生成，但执行结果可能为失败
- 作业实例连续运行超过 24 小时，系统会强制取消该实例，并将作业状态置为停用，同时向责任人发送通知

---

## 9\. 系统内置作业

系统内置作业属于平台运行的一部分，会作为种子数据初始化到系统中。

管理员可以对这类作业执行的常见管理动作包括：
- 查看基本信息
- 调整状态
- 调整责任人
- 调整计划时间

系统内置作业不允许删除，也不能创建平台未开放的内置作业类型。

---

## 10\. 审计追踪

对象操作作业和文档操作作业执行后，会分别记录到对象审计追踪和文档审计追踪中。审计日志中的操作用户显示为 `系统`。

---

## 11\. 使用建议
- 关键作业启用前，先确认执行计划是否会与系统高峰或大批量任务冲突
- 修改启用中的作业后，保存前要确认是否需要重新启用
- 对 `修改状态` 类作业，提前确认是否允许取消活跃工作流
- 对导出类作业，提前确认责任人能否及时接收通知并下载结果文件
- 发现 `跳过` 或 `运行失败` 持续出现时，应优先检查系统维护、资源占用和前一实例是否长期未结束
