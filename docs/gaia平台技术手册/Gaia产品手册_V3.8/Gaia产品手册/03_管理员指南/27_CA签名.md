# CA签名
> 本文面向 Gaia 平台系统管理员、安全管理员和实施顾问，介绍如何配置 CA 电子签名策略、将策略分配给用户，并查看 CA 签名日志。CA 签名用于在电子签名场景中接入企业或第三方 CA 服务，使用户通过扫码或 UKey 完成签名验证。

## 概述

CA 签名用于替代传统的用户名和密码签名方式。启用后，用户在需要电子签名的业务操作中，可以通过 CA App 扫码或 UKey 完成签名。系统会记录签名方式、签名结果、签名时间、证书、签名原文和签名值，便于后续审计和问题追溯。

CA 签名按用户生效。管理员需要先创建并启用 CA 策略，再在用户安全策略中选择该 CA 策略，最后将用户关联到对应的安全策略。未配置电子签名策略时，电子签名验证方式通常与用户登录认证方式保持一致。

典型配置路径：

**管理端 \> 系统设置 \> 域设置 \> 安全设置 \> CA策略设置**

CA 签名日志路径：

**管理端 \> 日志管理 \> CA签名日志**
> \[!IMPORTANT\]
CA 签名属于 GxP 关键操作。生产环境启用前，应先在测试环境验证 CA 服务参数、用户证书、扫码签名、UKey 签名、异常提示、签名日志和回退方式，并保留至少一个可直接登录的管理员账号。

## 权限要求

管理员需要具备对应权限，才能查看或维护 CA 策略和 CA 签名日志。

| 权限 | 说明 |
|------|------|
| CA策略设置：查看 | 查看 CA 策略列表和详情 |
| CA策略设置：全部 | CA 策略全部操作权限 |

如果当前账号只有查看权限，页面可以展示策略或日志内容，但创建、编辑、删除、导出等入口不可用，或操作时被系统拒绝。

## 与安全策略的关系

CA 策略本身只保存 CA 服务对接参数。用户是否使用 CA 签名，取决于用户关联的安全策略。

| 配置对象 | 作用 |
|------------|------|
| CA 策略 | 维护 CA 供应商、Host、AppID、AppSecret、uniqueId、oid 等签名服务参数 |
| 用户安全策略 | 在电子签名策略中选择启用状态的 CA 策略，决定用户签名时是否使用 CA |
| 用户资料 | 通过安全策略字段关联具体策略，决定该用户实际使用的登录和签名规则 |
| 电子签名记录 | 保存签名方式，例如密码、CA-扫码、CA-UKey |
| CA 签名日志 | 记录 CA 签名请求、结果、失败原因和证书相关信息 |

用户安全策略中的电子签名策略可以不设置。不设置时，系统按用户认证方式处理电子签名；设置为 CA 策略后，用户在电子签名时会进入 CA 签名流程。

## CA策略设置页面

CA策略设置页面以列表形式展示当前系统中的 CA 策略，支持按名称关键字搜索和分页查看。

| 页面区域 | 说明 |
|------------|------|
| 关键字搜索 | 输入策略名称关键字后刷新列表，用于快速定位目标 CA 策略 |
| CA 策略列表 | 展示策略名称、Code、状态、来源和描述 |
| 名称 | 点击名称进入详情页，查看策略参数和状态 |
| 创建 | 新建 CA 策略。进入创建页后，需要填写基本信息和 CA 服务参数 |
| 编辑 | 修改策略名称、状态、描述和 CA 服务参数 |
| 启用/停用 | 控制策略是否可被用户安全策略用于电子签名 |
| 删除 | 删除允许删除的策略。删除前系统会进行二次确认和依赖检查 |

启用状态的 CA 策略才会作为有效电子签名策略使用。停用后，已关联用户在后续电子签名时不再使用该 CA 策略，系统会按当前可用的签名规则处理。

删除 CA 策略前，系统会检查是否仍有安全策略或用户配置正在引用该策略。如果存在依赖关系，系统不允许删除，并提示当前策略正在使用。

## 创建 CA 策略

### 操作步骤
1. 进入 **管理端 \> 系统设置 \> 域设置 \> 安全设置 \> CA策略设置**。
2. 点击 **创建**。
3. 填写名称、Code、状态和描述。
4. 在 CA 设置区域选择 CA 供应商，并填写 Host、AppID、AppSecret、uniqueId、oid 等参数。
5. 点击 **保存**。
6. 保存成功后，到用户安全策略中将电子签名策略设置为该 CA 策略。
7. 将目标用户关联到对应的用户安全策略。
8. 使用测试用户验证扫码签名和 UKey 签名。

保存成功后，新策略出现在 CA 策略列表中。只有处于 **启用** 状态，并被用户安全策略引用时，该策略才会影响用户的电子签名流程。

### 基本字段

| 字段 | 是否必填 | 说明 |
|------|------------|------|
| 名称 | 是 | CA 策略的显示名称。名称应能体现 CA 供应商、适用范围或客户环境 |
| Code | 是 | CA 策略的唯一标识，需满足通用 Code 校验规则 |
| 状态 | 否 | 可选启用或停用。启用后策略可用于电子签名；停用后不再作为有效签名策略使用 |
| 来源 | 否 | 只读字段。自定义创建的策略来源显示为自定义 |
| 描述 | 否 | 记录策略用途、适用用户范围、CA 供应商或维护说明 |
> \[!TIP\]
建议在名称或描述中写明供应商、环境和适用范围，例如“生产环境 CA 签名”“质量部 CA 扫码签名”。后续排查签名失败时，管理员可以更快判断用户是否关联了正确策略。   

### CA 设置字段

| 字段 | 是否必填 | 说明 |
|------|------------|------|
| CA供应商 | 是 | 选择当前策略对接的 CA 服务供应商 |
| Host | 是 | CA 服务地址，需满足 URL 地址格式校验 |
| AppID | 是 | CA 服务分配给 Gaia 的应用标识 |
| AppSecret | 是 | CA 服务分配给 Gaia 的应用密钥。应按客户安全要求限制可见范围和维护人员 |
| uniqueId | 否 | CA 服务要求的租户、应用或业务唯一标识。是否填写取决于 CA 供应商对接要求 |
| oid | 是 | CA 服务要求的组织、对象或证书相关标识，按供应商提供的参数填写 |
> \[!IMPORTANT\]
Host、AppID、AppSecret、uniqueId 和 oid 任一参数错误，都可能导致扫码二维码生成失败、UKey 签名失败或接口超时。生产环境变更这些参数后，应重新验证所有需要电子签名的关键业务操作。

## 在用户安全策略中启用 CA 签名

CA 策略创建后，还需要通过用户安全策略分配给用户。
1. 进入 **管理端 \> 系统设置 \> 域设置 \> 安全设置 \> 用户安全策略**。
2. 创建或编辑目标安全策略。
3. 在电子签名策略中选择已启用的 CA 策略。
4. 保存并启用安全策略。
5. 进入 **管理端 \> 用户管理**。
6. 打开目标用户详情或编辑页。
7. 将用户的安全策略设置为对应策略。
8. 保存用户资料。
9. 使用目标用户完成一次电子签名测试。

用户对象中的安全策略字段用于决定该用户实际采用的安全策略。历史用户未单独设置安全策略时，通常继续使用基础策略。批量导入、接口同步或迁移用户时，也应确认安全策略字段是否映射正确。
> \[!NOTE\]
CA 签名配置影响所有需要电子签名的场景，不只影响完成任务。凡是系统要求电子签名的操作，都应在上线前纳入验证范围。

## 用户签名流程

当用户进入需要电子签名的页面时，系统会根据用户关联的安全策略判断签名方式。

| 场景 | 用户看到的结果 | 管理员排查方向 |
|------|---------------------|---------------------|
| 用户未配置 CA 签名策略 | 系统按原有签名方式处理，通常要求输入密码或按认证方式完成验证 | 检查用户安全策略和电子签名策略 |
| 用户配置了 CA 签名策略且参数有效 | 密码输入区域变为可点击入口，点击后进入 CA 签名流程 | 验证扫码或 UKey 是否可成功签名 |
| 用户没有可用 CA 证书 | 系统提示用户缺少可用证书或无法完成 CA 签名 | 检查 CA 供应商侧用户证书绑定 |
| CA 接口超时 | 系统提示签名服务连接异常或超时 | 检查 Host、网络连通性和 CA 服务状态 |
| CA 参数错误 | 系统提示 CA 调用失败或参数异常 | 检查 AppID、AppSecret、uniqueId、oid 等配置 |

### 扫码签名

扫码签名适用于用户通过 CA App 完成电子签名的场景。系统调用 CA 服务成功后，会生成二维码。用户使用 CA App 扫码并确认签名后，系统接收 CA 返回结果，并写入电子签名记录和 CA 签名日志。

如果二维码无法生成，应先检查 CA 策略状态、Host、AppID、AppSecret、uniqueId、oid 和网络连通性，再检查 CA 供应商侧应用授权。

### UKey 签名

UKey 签名适用于需要通过本地证书介质完成签名的场景。用户点击 UKey 签名入口后，系统会检测证书介质，并要求用户输入 UKey 密码。

如果系统未检测到证书，用户可插入 UKey 后刷新页面再试。UKey 密码需要通过必填校验和正确性校验，校验失败时签名不会完成。

## CA签名日志

CA签名日志记录所有 CA 签名尝试，包括成功和失败记录。管理员可用于审计签名结果、排查签名失败原因，并导出日志留档。

典型路径：

**管理端 \> 日志管理 \> CA签名日志**

页面支持按条件查询、分页查看，并支持导出 PDF 和 CSV。查询字段的操作符与其他日志类型保持一致。

| 字段 | 说明 |
|------|------|
| 用户 | 执行签名的用户姓名 |
| 账号 | 执行签名的用户账号 |
| 签名对象 | 电子签名对应的主对象 |
| 签名对象实例 | 电子签名对应的主对象实例名称 |
| 签名方式 | 签名使用的方式，常见取值为 CA-扫码、CA-UKey |
| 签名时间 | 系统记录的签名时间 |
| 结果状态 | 签名结果，取值为成功或失败 |
| 失败原因 | 结果状态为失败时显示失败原因 |
| 证书 | 签名成功后由 CA 返回的证书信息 |
| 签名原文 | 签名成功后由 CA 返回的签名原文 |
| 签名值 | 签名成功后由 CA 返回的签名值 |
| 操作 | 查看详情或复制证书信息 |

点击 **详情** 后，系统打开详情抽屉，展示签名记录的完整信息。证书、签名原文和签名值可复制；复制成功后，系统显示复制成功提示。
> \[!TIP\]
排查签名争议时，应同时查看电子签名记录、CA 签名日志和对应业务对象的审计追踪。三类记录可以共同确认签名人、签名时间、签名动作、签名结果和业务上下文。

## 启用、停用和删除

| 操作 | 结果 | 注意事项 |
|------|------|------------|
| 启用 | CA 策略可被用户安全策略引用并用于电子签名 | 启用前应确认 CA 服务参数已验证通过 |
| 停用 | CA 策略不再作为有效签名策略使用 | 停用前应检查是否仍有用户安全策略引用该策略 |
| 编辑 | 修改策略基本信息或 CA 服务参数 | 修改 Host、AppID、AppSecret、uniqueId、oid 后，应重新验证签名流程 |
| 删除 | 删除允许删除的 CA 策略 | 删除前系统会检查依赖关系；存在引用时不允许删除 |

正式环境停用或删除策略前，建议先导出或记录当前配置，并准备可回退的用户安全策略。对生产用户批量切换签名方式时，应安排变更窗口并提前通知受影响用户。

---

## 变更前检查

在生产环境创建、启用或调整 CA 策略前，建议完成以下检查：

| 检查项 | 建议 |
|---------|------|
| CA 服务状态 | 确认供应商服务可用，测试环境可正常生成二维码或调用 UKey 签名 |
| CA 参数 | 确认 Host、AppID、AppSecret、uniqueId、oid 与供应商提供的信息一致 |
| 用户证书 | 确认目标用户在 CA 供应商侧已绑定有效证书 |
| 用户安全策略 | 确认目标用户已关联正确的安全策略，且电子签名策略指向启用状态的 CA 策略 |
| 业务覆盖范围 | 覆盖所有需要电子签名的关键场景，不只验证完成任务 |
| 日志与审计 | 验证成功和失败记录都能写入 CA 签名日志 |
| 移动端 | 如需移动端签名，应先确认 CA 供应商是否支持并完成端到端验证 |
| 回退方案 | 准备可恢复的用户安全策略和管理员登录入口 |

## 配置迁移与升级

CA 策略属于配置数据。进行环境迁移或版本升级时，应确认 CA 策略、用户安全策略和用户安全策略字段的迁移结果。

升级后，历史用户不应因为新增安全策略字段而改变原有登录或签名方式。电子签名对象新增的签名方式字段默认可不展示，是否展示由页面或对象配置决定。

## 常见问题

**Q：为什么用户签名时仍然要求输入密码？** A：请检查用户是否关联了正确的用户安全策略，并确认该策略中的电子签名策略已选择启用状态的 CA 策略。若未设置电子签名策略，系统通常按原有认证方式处理签名。

**Q：为什么扫码二维码无法生成？** A：常见原因包括 CA 策略未启用、Host 无法访问、AppID 或 AppSecret 错误、uniqueId 或 oid 不符合供应商要求，或 CA 服务接口超时。请先检查 CA 策略参数和网络连通性。

**Q：用户有 CA 策略，为什么提示没有证书？** A：CA 策略只定义 Gaia 与 CA 服务的对接参数。用户是否有证书，取决于 CA 供应商侧的用户证书绑定。请检查供应商侧账号、证书状态和证书有效期。

**Q：UKey 签名失败时先看哪里？** A：先确认用户已插入 UKey，浏览器或本地组件可识别证书，再检查 UKey 密码是否正确。仍失败时，查看 CA 签名日志中的失败原因。

**Q：停用 CA 策略会影响已完成的签名记录吗？** A：不会改变历史签名记录。停用只影响后续电子签名流程。历史电子签名记录和 CA 签名日志仍可用于审计追溯。
