\# 职位管理
> **所需权限**：系统管理员 或 用户管理员   

---

## 概述

职位管理用于维护组织内的岗位定义，并将岗位与用户、部门、业务单元等组织信息建立关联。合理维护职位信息后，可在人员管理、流程分配和数据权限场景中复用岗位关系，减少重复配置。

在该页面中，管理员通常会完成以下操作：
- 新建职位并设置基础属性。
- 在职位详情中维护任职人员。
- 调整职位与组织关系，确保流程与权限引用准确。

---

## 使用入口

进入 `【管理端】>【用户管理】>【职位管理】` 后，可查看职位列表并执行创建、查看、编辑等操作。

---

## 职位列表

职位列表用于集中查看当前租户下的职位，并作为进入详情维护的统一入口。

### 列表可执行操作
- **新建职位**：进入职位创建页，新增岗位定义。
- **查看详情**：进入职位详情页，查看职位基础信息和任职人员。
- **编辑职位**：修改职位名称、编码、组织归属等可编辑字段。

### 列表使用建议
- 新建前先确认命名规范，避免同义职位重复创建。
- 涉及流程或权限引用的职位，建议先确认变更影响范围再编辑。

---

## 创建职位

点击【新建职位】后进入创建页。

### 页面顶部操作
- **返回**：离开当前页面，不保存本次录入内容。
- **保存**：校验必填项后创建职位并写入职位列表。

### 职位信息字段说明

| 字段 | 必填 | 用途说明 | 配置建议 |
|------|------|------------|------------|
| 名称 | ✓ | 职位在列表、详情和人员归属中的显示名称 | 建议使用清晰且稳定的岗位名称，如“QA经理” |
| 编码 | ✓ | 职位唯一标识，用于系统识别、导入和集成引用 | 建议使用规则化编码，如 `QA&#95;MANAGER` |
| 部门 | ✓ | 定义职位所属部门，用于组织路由与人员归属判断 | 建议与组织架构保持一致，避免跨部门复用同一岗位编码 |
| 上级职位 |  | 定义职位上下级关系，用于审批链或组织层级表达 | 建议按真实汇报关系配置，避免循环或跳级关系 |
| 所属业务单元 | ✓ | 定义职位所属业务单元范围，用于质量体系相关流程和权限判断 | 建议与业务单元维护口径一致，避免与部门口径冲突 |
| 启用状态 | ✓ | 控制职位是否可被业务继续使用 | 正式停用前先评估该职位是否仍被用户、流程或规则引用 |
> 说明：不同租户可见字段和必填规则可能不同，请以当前页面实际配置为准。   

### 启用状态说明
- **启用**：职位可正常被用户、流程和规则引用。
- **停用**：职位通常不再作为新增或变更时的可选项；已存在的历史引用是否继续生效，取决于对应业务模块的规则。

### 操作步骤
1. 进入 `【管理端】>【用户管理】>【职位管理】`。
2. 点击【新建职位】。
3. 填写“名称”“编码”。
4. 选择“部门”，按需设置“上级职位”。
5. 选择“所属业务单元”。
6. 设置“启用状态”（默认建议选择“启用”）。
7. 点击【保存】。

### 保存后结果
- 新职位会出现在职位列表中。
- 可进入职位详情页继续维护任职用户。
- 后续可在流程分配、组织条件判断等场景引用该职位。

---

## 职位详情与人员维护

在职位详情页可查看职位完整信息，并维护“职位-人员”关系。

### 详情页常见操作
- **编辑**：修改职位基础信息并保存生效。
- **添加用户**：将用户关联到当前职位，用于岗位职责和流程分配。
- **移除用户**：解除用户与当前职位的关联关系。

### 维护影响说明

| 变更项 | 可能影响 |
|---------|------------|
| 修改名称/编码 | 影响列表展示、集成识别及引用该职位的配置可读性 |
| 修改部门/所属业务单元 | 可能影响组织路由、质量体系流程和权限判断结果 |
| 修改上级职位 | 可能影响按岗位层级计算的审批链或组织关系展示 |
| 切换启用状态 | 可能影响该职位在新增配置中的可选性及后续流程分配 |
| 添加或移除任职用户 | 影响该用户在岗位维度下的流程分配和组织识别 |
> 建议：执行“停用职位”或调整组织归属前，先确认是否存在审批流、任务分配或报表口径依赖该职位关系。   

---

## 业务单元取值逻辑

当用户未配置职位时，业务单元从用户档案中的“所属业务单元”取值；当用户已配置职位时，系统优先采用职位关联的业务单元。

这意味着：
- 职位关系可覆盖用户档案中的默认业务单元来源。
- 调整职位关联关系后，相关流程和数据范围判断结果可能同步变化。

---

## 常见问题

**Q: 用户已经有部门信息，为什么还要配置职位？** A: 部门用于组织层级归属，职位用于岗位职责表达与流程角色分配。两者配合使用，才能更准确地完成组织化路由与权限判断。

**Q: “上级职位”不填可以吗？** A: 可以。若当前场景不依赖岗位层级，可暂不配置；如审批链或组织展示需要上下级关系，建议补齐该字段。

**Q: 职位可以直接停用吗？** A: 可以停用，但建议先确认该职位是否仍被用户、流程或规则引用，避免产生分配异常或配置缺失。

**Q: 修改职位后，历史业务数据会自动改写吗？** A: 职位变更通常影响后续生效的组织识别与分配逻辑；已完成历史记录是否同步变化，取决于具体业务模块的数据冻结与追踪规则。
