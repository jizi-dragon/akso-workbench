# 权限配置
> **所需权限**：系统管理员，或具备用户、角色、权限集、对象权限及生命周期权限配置能力的管理员角色。   

---

## 概述

权限配置用于控制用户在 Gaia 平台中“能进入哪里、能看到什么、能执行哪些操作”。管理员通常需要同时配置角色、权限集、记录级共享规则、生命周期角色权限和状态权限，才能得到完整的权限效果。

建议按以下顺序理解 Gaia 权限：

| 层级 | 控制内容 | 常见配置位置 | 作用 |
|------|------------|------------------|------|
| **用户与组织** | 用户、用户组、部门、职位 | 管理端 \> 用户管理 | 决定权限分配对象 |
| **角色** | 岗位职责与权限承载关系 | 管理端 \> 用户管理 \> 角色 | 将权限集分配给用户或用户组 |
| **权限集** | 菜单、对象、字段、动作、API 等功能权限 | 管理端 \> 用户管理 \> 权限集 | 决定用户具备哪些基础能力 |
| **记录级权限** | 指定记录可由哪些用户访问 | 共享规则、DAC、手动共享 | 决定用户能访问哪些具体数据 |
| **生命周期角色权限** | 生命周期角色的查看、编辑、删除权限 | 生命周期 \> 角色 | 决定用户在生命周期内的默认操作边界 |
| **状态权限** | 不同生命周期状态下字段和动作是否可用 | 生命周期状态详情 | 决定记录处于某个状态时能做什么 |
> \[!NOTE\]
权限集是权限上限。DAC、共享规则和状态权限可以收紧权限，但不能授予超出权限集范围的能力。

## 配置前确认

配置权限前，建议先完成以下确认：
1. 明确用户职责边界，例如系统管理员、业务管理员、文档作者、审批人、只读用户。
2. 确认用户是否应通过用户组批量授权，避免按个人长期维护角色。
3. 梳理对象、字段、菜单、动作、报表、审批矩阵等权限点。
4. 判断是否需要记录级权限控制：如果同一对象中不同记录面向不同用户开放，通常需要 DAC 或共享规则。
5. 判断是否需要生命周期角色权限：如果同一生命周期中存在作者、审核人、批准人等不同职责，需要配置生命周期角色。
6. 判断是否需要状态级权限控制：如果记录在草稿、审核中、已批准等状态下权限不同，需要配置状态权限。
7. 对高权限角色、审批相关角色和审计权限建立复核机制。

## 用户与用户组

用户代表一个独立系统账户。用户本身不直接持有具体权限，通常通过角色获得权限。

用户组用于批量管理用户。管理员可以将角色分配给用户组，使组内成员自动获得对应角色能力。

| 管理对象 | 适用场景 | 配置建议 |
|------------|------------|------------|
| **用户** | 单个账号维护、账号启停、个人角色调整 | 仅对少量特殊账号直接维护角色 |
| **用户组** | 部门、项目组、职能组、外部系统同步组 | 优先用于批量授权，降低后续维护成本 |
| **部门 / 职位** | 需要按组织层级或岗位映射权限 | 与用户组、共享规则配合使用 |

常见做法：
- 新员工入职时，先确认所属部门和岗位，再加入对应用户组。
- 岗位调整时，优先调整用户组或角色关系，而不是临时追加零散权限。
- 用户离职或停用时，先停用账号，再复核其代理、待办任务和记录所有者关系。

更多账号维护说明参见 [用户管理](01_%E7%94%A8%E6%88%B7%E7%AE%A1%E7%90%86.md) 和 [用户组管理](01A_%E7%94%A8%E6%88%B7%E7%BB%84%E7%AE%A1%E7%90%86.md)。

## 角色配置

角色用于承载岗位职责。用户通过角色获得权限集中的功能权限。

权限关系：
```text
用户 -> 角色 -> 权限集 -> 具体权限点
```

### 角色设计原则

| 原则 | 说明 |
|------|------|
| **按职责命名** | 使用“质量文档作者”“系统管理员”等岗位职责名称，避免按个人命名 |
| **边界清晰** | 一个角色只承载一类职责，避免把审批、配置、审计权限混在同一角色中 |
| **可审计** | 角色名称、描述、权限集和适用人群应能解释为什么授予该权限 |
| **可复用** | 同一角色可分配给多个用户或用户组 |

### 角色分配方式

| 方式 | 说明 | 适用场景 |
|------|------|------------|
| **分配给用户** | 在用户详情或角色详情中直接关联用户 | 少量特殊授权 |
| **分配给用户组** | 将角色授予用户组，组内成员继承角色 | 部门、项目组、岗位批量授权 |
| **记录级角色** | 用户在某条记录上成为所有者、编辑者或查看者 | DAC、共享规则、手动共享 |
| **生命周期角色** | 用户在生命周期中承担作者、审核人、批准人等职责 | 状态权限和流程控制 |

同一用户拥有多个角色时，权限集能力按并集计算。最终能否访问记录或执行动作，还要继续满足 DAC、共享规则、状态权限和对象本身的配置。

### 导出角色权限报告

角色权限报告用于审计、权限复核和上线前检查。

| 导出方式 | 操作结果 |
|------------|------------|
| **表头动作导出** | 在角色列表页直接导出当前角色范围的权限明细 |
| **批量动作导出** | 勾选多个角色后导出权限报告，可按应用、对象、菜单、移动端菜单、菜单集等范围筛选 |

导出前需先在角色对象或角色视图中配置对应动作。执行导出后，系统生成报告并通过通知发送给操作人。

详细操作参见 [角色管理](01H_%E8%A7%92%E8%89%B2%E7%AE%A1%E7%90%86.md)。

## 权限集配置

权限集定义角色可使用的功能范围。创建或维护权限集时，进入 `管理端 > 用户管理 > 权限集`。

### 权限集配置范围

| 权限范围 | 控制内容 | 用户可见效果 |
|------------|------------|------------------|
| **应用权限** | 工作流管理、对象批量操作、审计追踪、导入导出等基础能力 | 用户是否能使用对应平台功能 |
| **管理端权限** | 业务管理、配置管理、用户与组、日志、运维、部署、集成、系统设置、域设置等菜单能力 | 用户是否能进入对应管理端页面并执行操作 |
| **对象权限** | 对象查看、创建、编辑、删除等基础操作 | 用户是否能访问对象菜单、打开记录、创建或修改记录 |
| **字段权限** | 字段查看和编辑权限 | 字段是否显示、是否可编辑、是否出现在列表筛选和显示列中 |
| **对象动作权限** | 对象动作、批量动作、表头动作等 | 按钮是否出现，是否可执行 |
| **附件权限** | 附件预览、上传、下载、删除等能力 | 附件区域和附件动作是否可用 |
| **审批矩阵权限** | 审批矩阵查看和编辑能力 | 业务记录中审批矩阵页签是否可见，参与人是否可维护 |
| **表单布局权限** | 不同表单布局下字段可见和可编辑范围 | 同一记录在不同布局下呈现不同字段权限 |
| **API 权限** | REST API 调用能力 | 集成账号或服务账号是否可调用指定接口 |

### 管理端权限

管理端权限控制管理员能进入哪些后台配置页面，以及能否创建、编辑、查看或删除配置。

管理端权限常见模块包括：

| 模块 | 说明 |
|------|------|
| **业务管理** | 文档、活页夹、页面模板、叠加层模板、运行报告模板、标签模板、全景图等 |
| **配置管理** | 对象、字段、选项集、生命周期、工作流、菜单、视图、规则等 |
| **用户与组** | 用户、用户组、角色、权限集、表单布局权限等 |
| **日志管理** | 系统审计日志、对象记录审计日志、登录审计日志、文件审计日志、操作日志等 |
| **运维管理** | 作业、计划作业、运行作业、消息作业监控等 |
| **部署管理** | 组件列表、出站配置包、入站配置包、配置报告等 |
| **集成管理** | 调用应用及集成相关配置 |
| **系统设置** | 常规设置、水印设置、安全设置、品牌设置等 |
| **域设置** | 安全策略、密码策略、LDAP、OAuth2.0 策略等 |
> \[!IMPORTANT\]
管理端权限受安全设置中的“管理端权限”开关影响。若环境仍处于宽松模式，管理端页面可能不会完全按权限集限制；切换为严格模式后，权限集中的管理端权限才会作为访问控制依据。   

### 对象与字段权限

对象权限决定用户是否能访问对象及其记录，字段权限决定用户在对象记录中能看到或编辑哪些字段。

在权限集的 **对象** 配置页中：

| 能力 | 说明 |
|------|------|
| 分页 | 对象列表默认每页 20 条，支持首页 / 上一页 / 页码 / 下一页 / 末页 |
| 搜索 | 支持按**对象名称**、**对象类型名称**模糊搜索；支持输入即搜与回车搜索 |
| 清除搜索 | 可一键清除搜索条件，恢复全部对象列表 |
| 组合使用 | 搜索结果仍分页展示，翻页时保留当前搜索条件 |

建议配置顺序：
1. 先授予对象级查看权限，否则用户无法访问该对象记录。
2. 再配置创建、编辑、删除等对象操作权限。
3. 进入对象字段权限，为关键字段设置查看或编辑权限。
4. 如存在多套表单布局，再配置表单布局权限。
5. 如页面按钮或动作不可用，再检查对象动作权限和状态权限。

字段权限的常见结果：

| 权限状态 | 业务端表现 |
|------------|---------------|
| **无查看权限** | 字段不显示，也不会出现在列表筛选条件和自定义显示列中 |
| **查看** | 字段可见但不可编辑 |
| **编辑** | 字段可见且可编辑 |

### 表单布局权限

表单布局权限用于在不同页面布局下继续收敛字段访问范围。它与对象字段权限共同生效。

配置时应注意：
- 对象字段权限是上限，表单布局权限不能突破对象字段权限。
- 同一对象存在多个表单布局时，应分别检查各布局的字段可见性。
- 如果用户能打开记录但某些字段缺失，优先检查对象字段权限和表单布局权限。

更多说明参见 [表单布局权限](01F_%E8%A1%A8%E5%8D%95%E5%B8%83%E5%B1%80%E6%9D%83%E9%99%90.md)。

### 对象动作与审批矩阵权限

对象动作权限控制按钮或动作是否对用户可见、可执行。审批矩阵权限控制用户是否能查看或编辑记录中的审批参与人。

常见排查顺序：
1. 权限集是否授予对象动作或审批矩阵权限。
2. 对象详情页是否启用了相关安全控制。
3. 当前生命周期状态下，状态权限是否允许该角色查看或执行。
4. 用户是否具备当前记录的访问权限。

审批矩阵的管理说明参见 [审批矩阵管理](09_%E5%AE%A1%E6%89%B9%E7%9F%A9%E9%98%B5%E7%AE%A1%E7%90%86.md)。

## 记录级权限配置

记录级权限用于控制“同一个对象中，用户能访问哪些具体记录”。如果某用户有对象查看权限，但仍看不到某条记录，通常需要检查记录级权限。

### 记录角色

启用 DAC 后，每条记录可拥有记录角色。

| 记录角色 | 常见权限 | 说明 |
|------------|------------|------|
| **所有者（Owner）** | 查看、编辑、删除、管理共享 | 通常由创建者或业务负责人承担 |
| **编辑者（Editor）** | 查看、编辑、必要时管理部分共享 | 适用于协作维护记录的用户 |
| **查看者（Viewer）** | 查看 | 适用于只读参与者 |

实际权限仍以对象权限、状态权限和共享规则计算结果为准。

### 记录级授权方式

当前记录级权限主要通过匹配共享规则和手动共享维护。

| 类型 | 使用场景 | 结果 |
|------|------------|------|
| **匹配共享规则** | 按国家、部门、产品线、站点等字段匹配用户责任范围 | 字段值匹配时，系统自动把用户加入记录角色 |
| **手动共享 / 人工分配** | 临时协作、少量例外授权 | 有权限的用户手动把其他用户加入记录角色 |

示例：
```text
规则：国家 = 中国，产品线 = Quality Suite
用户：张三
记录角色：编辑者
结果：符合条件的记录自动向张三开放编辑者权限
```

详细配置参见 [DAC权限规则详解](14_DAC%E6%9D%83%E9%99%90%E8%A7%84%E5%88%99%E8%AF%A6%E8%A7%A3.md) 和 [共享规则](../04_%E9%85%8D%E7%BD%AE%E6%8C%87%E5%8D%97/01F_%E5%85%B1%E4%BA%AB%E8%A7%84%E5%88%99.md)。

## 生命周期角色权限

生命周期角色权限用于控制用户在某个生命周期中的默认操作边界。它关注的是“用户以某个生命周期角色参与该记录时，默认可以查看、编辑还是删除”。

配置路径：`管理端 > 配置管理 > 业务逻辑 > 生命周期 > 目标生命周期 > 角色`

生命周期自动创建后，通常包含拥有者、编辑者、查看者等标准角色。管理员也可以把应用角色添加到生命周期中，例如作者、审核人、批准人、QA、合规负责人等。

### 权限层级

| 层级 | 控制内容 | 生效范围 |
|------|------------|------------|
| **角色级权限** | 为生命周期角色配置查看、编辑、删除 | 作为该角色在整个生命周期中的默认权限基线 |
| **生命周期角色的状态级权限** | 在角色展开视图中，为某个状态单独配置查看、编辑、删除 | 只影响该角色在指定状态下的权限结果 |

### 配置结果
- 在角色级授予权限后，该角色会在生命周期所有状态中获得对应默认权限。
- 在状态级调整权限后，仅目标状态的权限发生变化，不会改动其他状态。
- 勾选“编辑”时，系统同时授予“查看”；勾选“删除”时，系统同时授予“编辑”和“查看”。
- 移除生命周期角色只解除该角色与当前生命周期的关联，不会删除应用角色主数据。

生命周期角色权限适合配置记录在生命周期内的主体权限，例如作者在草稿状态可编辑、审核人在审核状态可查看、批准人在批准环节可处理。若需要进一步控制字段、对象动作、附件、工作流动作、关系或审批矩阵，应继续配置状态权限。

详细步骤参见 [生命周期角色配置](../04_%E9%85%8D%E7%BD%AE%E6%8C%87%E5%8D%97/04F_%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F%E8%A7%92%E8%89%B2%E9%85%8D%E7%BD%AE.md)。

## 状态权限配置

状态权限用于控制记录处于某个生命周期状态时，字段、动作、附件、工作流、关系和审批矩阵等能力是否可见或可执行。

配置路径：`管理端 > 配置管理 > 业务逻辑 > 生命周期 > 目标生命周期 > 目标状态 > 状态权限`

### 常见行为

| 权限对象 | 可配置行为 | 业务端效果 |
|------------|---------------|---------------|
| **字段** | 隐藏、查看、编辑 | 字段不显示、只读或可编辑 |
| **对象动作** | 隐藏、查看、执行 | 按钮不显示、显示但不可点击、可点击执行 |
| **附件** | 隐藏、查看、执行 | 附件动作不可见、只读或可执行 |
| **用户动作** | 隐藏、查看、执行 | 用户动作按钮按状态和角色开放 |
| **工作流动作** | 隐藏、查看、执行 | 添加参与者、取消任务、重新分配等动作受控 |
| **关系** | 查看、编辑 | 相关记录只读或允许创建、添加、移除 |
| **审批矩阵** | 隐藏、查看、编辑 | 审批矩阵页签隐藏、只读或可维护参与人 |

### 配置建议
1. 先配置默认状态行为，作为所有角色的基线。
2. 再为生命周期角色配置角色覆盖，例如作者可编辑、审核人只读、查看者隐藏。
3. 对批准、归档等状态收紧编辑和删除类权限。
4. 对取消工作流、重新分配、删除附件、修改审批参与人等高风险动作单独复核。
5. 配置后使用不同角色账号验证字段、按钮、关系和审批矩阵的实际表现。

状态权限不能突破权限集上限。例如权限集中没有对象编辑权限，即使状态权限为“编辑”，用户也不能编辑记录。

详细说明参见 [状态权限配置](../04_%E9%85%8D%E7%BD%AE%E6%8C%87%E5%8D%97/04E_%E7%8A%B6%E6%80%81%E6%9D%83%E9%99%90%E9%85%8D%E7%BD%AE.md)。

## 权限验证与排查顺序

当用户反馈“看不到菜单、打不开记录、不能编辑字段、按钮不可用”时，建议按以下顺序排查：
```text
1. 用户状态
   ↓ 用户是否启用，是否属于正确用户组？
2. 角色分配
   ↓ 用户或用户组是否拥有正确角色？
3. 权限集
   ↓ 角色绑定的权限集是否包含菜单、对象、字段、动作等基础权限？
4. 记录级权限
   ↓ 用户是否通过 DAC、共享规则或手动共享获得该记录访问权？
5. 生命周期角色权限
   ↓ 用户在该生命周期中是否命中正确角色，该角色是否具备查看、编辑或删除基线权限？
6. 生命周期状态权限
   ↓ 当前状态下，该角色是否允许查看、编辑或执行动作？
7. 页面与配置开关
   ↓ 管理端权限严格模式、动作安全、关系安全、表单布局权限等是否影响结果？
8. 审计与日志
   ↓ 查看权限变更、共享规则刷新、登录和操作日志，确认实际生效时间和操作人。
```

### 常见问题

**Q1：用户能看到对象菜单，但看不到记录？** A：对象查看权限已满足，但记录级权限可能不满足。检查 DAC、共享规则、手动共享和记录所有者。

**Q2：用户能打开记录，但某些字段不显示？** A：检查对象字段权限、表单布局权限和状态权限。隐藏字段不会出现在详情页，也通常不会出现在列表筛选和自定义显示列中。

**Q3：按钮没有显示或不可点击？** A：先检查权限集中的对象动作权限，再检查生命周期状态权限。若是对象动作，还需确认对象详情页是否启用了动作安全。

**Q4：状态权限配置为“编辑”，用户仍不能编辑？** A：状态权限不能超过权限集和生命周期角色权限上限。先确认权限集中是否授予对象编辑和字段编辑权限，再检查用户是否具备记录级权限，以及该用户命中的生命周期角色是否具备编辑基线权限。

**Q5：共享规则配置后没有立即生效？** A：检查规则条件、匹配字段、用户角色设置记录和权限刷新机制。批量规则或大量记录可能需要等待系统刷新完成。

**Q6：用户无法解除关系？** A：解除关系通常受关系字段编辑权限影响。需同时检查关系安全、状态权限和该关系字段的编辑权限。

## 管理建议
- 遵循最小权限原则，只授予完成工作所需的权限。
- 将系统配置、业务配置、审批、审计等高权限职责分离。
- 优先通过用户组分配角色，减少按个人长期维护权限。
- 对系统管理员、业务管理员、审批矩阵维护人、审计查看人等高权限角色定期复核。
- 上线前导出角色权限报告，确认新增角色、停用角色、权限集变更和用户组映射均已复核。
- 对 GxP 相关对象，重点检查审计追踪、电子签名、生命周期角色权限、状态权限和审批矩阵权限。
- 不建议在生产环境中为临时问题长期授予高权限角色；临时授权结束后应及时回收。
