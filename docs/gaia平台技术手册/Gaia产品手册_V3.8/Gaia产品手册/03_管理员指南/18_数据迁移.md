# 数据迁移
> 本文面向系统管理员、实施顾问和配置负责人，介绍如何通过数据迁移在不同 Sphere 之间迁出和迁入对象实例数据。数据迁移适用于业务数据、业务配置数据或需要按对象关系成组搬运的数据，不用于迁移对象、字段、页面、权限等组件配置。   

---

## 概述

数据迁移通过数据包完成。管理员先在源 Sphere 创建出站数据包，选择需要迁移的对象、对象关系、迁移模式、标识字段、筛选条件和字段范围；系统生成数据包后，再在目标 Sphere 导入为入站数据包，并按数据集执行导入。

在多业务单元场景下，**系统管理员**角色用户和 **admin** 用户导出、导入数据迁移包时可跨业务单元操作；普通用户仍仅限当前所属业务单元。跨业务单元规则详见下文「管理员跨业务单元导入导出」。

典型访问路径：

**管理端 \> 部署管理 \> 数据迁移 \> 出站数据包管理端 \> 部署管理 \> 数据迁移 \> 入站数据包**

数据迁移适用于以下场景：

| 场景 | 用法 |
|------|------|
| 业务配置迁移 | 将角色以外的业务配置、字典类数据、规则类对象实例从一个 Sphere 搬运到另一个 Sphere |
| 初始化数据准备 | 在新环境中导入基础业务数据，减少手工录入 |
| 多对象关联迁移 | 将一个主对象及其相关对象按关系一起打包，保留业务数据之间的引用关系 |
| 部署后补数 | 配置包部署完成后，将本次功能依赖的对象实例数据补充到目标 Sphere |
| 问题复现 | 将特定对象实例迁移到测试环境，用于复现和排查业务问题 |
> \[!IMPORTANT\]
数据迁移会在目标 Sphere 中创建、更新或删除对象实例数据。正式执行前，请确认目标环境已完成必要的对象、字段、生命周期、工作流和权限配置迁移，并保留迁移前的核对记录。   

---

## 与相关功能的区别

| 功能 | 处理对象 | 是否修改目标数据 | 典型用途 |
|------|------------|------------------------|------------|
| 配置迁移 | 对象、字段、页面、生命周期、工作流、权限等组件配置 | 是 | 将系统配置从源 Sphere 部署到目标 Sphere |
| 配置报告 | 当前 Sphere 的配置清单 | 否 | 部署前后核对、审计归档、问题排查 |
| 批量导入导出 | 单个对象或模板范围内的数据 | 是 | 日常批量维护、一次性导入或导出 |
| 数据迁移 | 一个或多个对象实例及其关系 | 是 | 跨 Sphere 搬运业务数据或业务配置数据 |

建议先完成配置迁移，再执行数据迁移。目标 Sphere 缺少对象、字段或引用关系时，数据包可能无法导入，或导入后数据无法在页面和业务流程中正常使用。

---

## 迁移流程

一次完整的数据迁移通常包括以下步骤：
1. 在源 Sphere 创建出站数据包。
2. 在出站数据包中添加一个或多个数据集。
3. 为每个数据集选择主对象，并按需要添加入站关系或出站关系中的相关对象。
4. 为每个对象设置迁移模式、标识字段、筛选器和字段范围。
5. 生成数据包并下载到本地。
6. 在目标 Sphere 导入数据包，形成入站数据包记录。
7. 在入站数据包详情中选择要导入的数据集，并执行导入。
8. 查看导入结果；如有失败记录，下载结果文件并处理后重新导入。

如果迁移内容涉及生产环境，建议先在测试或 UAT Sphere 完成一次演练，确认记录数量、关键字段、引用关系和页面显示都符合预期后，再在生产环境执行。

## 出站数据包

出站数据包用于在源 Sphere 中定义迁移范围并生成可下载的数据包文件。

### 列表页面

进入 **出站数据包** 后，列表显示已创建的出站数据包记录。管理员可以通过关键字搜索数据包，关键字通常匹配名称、概要或描述。

| 页面区域 | 说明 |
|------------|------|
| 创建 | 进入创建出站数据包页面。创建后，系统生成数据包名称 |
| 搜索 | 按关键字查找历史出站数据包，用于追溯某次迁移准备记录 |
| 行内操作 | 根据数据包状态显示查看、编辑、下载或移除等操作 |

### 创建出站数据包
1. 进入 **管理端 \> 部署管理 \> 数据迁移 \> 出站数据包**。
2. 点击 **创建**。
3. 填写 **概要** 和 **描述**，说明本次迁移目的、范围和目标环境。
4. 保存后进入出站数据包详情。

系统会按 `DAT-{YYYYMMDDhhmmss}` 规则生成出站数据包名称。建议在概要或描述中写明源 Sphere、目标 Sphere、迁移对象和业务背景，便于后续审计和问题追溯。

### 出站数据包详情

出站数据包详情用于管理数据集和生成数据包。

| 控件 / 区域 | 说明 |
|---------------|------|
| 添加 | 进入数据集添加页面。一个出站数据包可以包含多个数据集 |
| 搜索 | 在当前出站数据包内查找数据集 |
| 数据集列表 | 显示数据集名称、对象名称、对象 Code、迁移模式、标识字段等信息 |
| 生成数据包 | 按当前数据集配置生成可下载的数据包文件 |
| 数据包列表 | 显示已生成的数据包文件，管理员可下载或移除 |

数据包生成是异步任务。点击生成后，系统提示正在生成数据包；生成完成后，数据包列表新增记录，创建人通常会收到系统通知。生成尚未完成时重复点击生成，系统不会重复创建任务。

## 数据集

数据集用于描述一组需要一起迁移的对象数据。一个数据集最多包含 1 个主对象和 9 个相关对象；一个出站数据包最多包含 100 个对象。

### 添加数据集
1. 在出站数据包详情中点击 **添加**。
2. 在主对象区域选择对象。可选对象通常不包含系统对象、对象类型对象和已停用对象。
3. 如需迁移关联数据，点击 **添加相关对象**。
4. 选择入站关系或出站关系中的相关对象。
5. 点击 **保存** 返回出站数据包详情，或点击 **保存并新建** 继续添加下一个数据集。

保存时必须选择主对象。未选择对象时，系统会提示选择对象，并阻止保存。

系统会为数据集生成 `DateSet-{5位数字累加}` 格式的 ID。同一数据包内，数据集 ID 从 0 开始计数。

### 选择相关对象

相关对象用于把与主对象有关联的对象实例一起迁出。

| 关系类型 | 说明 | 迁移方向 |
|------------|------|------------|
| 入站关系 | 其他对象通过引用字段指向主对象 | 箭头从相关对象指向主对象 |
| 出站关系 | 主对象通过引用字段指向其他对象 | 箭头从主对象指向相关对象 |

未选择主对象前，**添加相关对象** 不可用。达到对象数量限制后，系统会禁用继续添加；如果当前数据包对象总数超过 100 个，系统不允许保存，并提示数据包对象数量已超过限制。

### 查看和编辑数据集

在数据集详情中，管理员可以查看主对象、相关对象和对象关系图。

| 操作 | 结果 |
|------|------|
| 编辑 | 进入数据集编辑页面，调整主对象或相关对象 |
| 删除 | 删除当前数据集。删除后，该数据集不会参与后续数据包生成 |
| 编辑迁移数据 | 打开迁移数据配置窗口，设置对象级迁移规则 |

删除数据集前，请确认该数据集没有被本次迁移范围依赖。删除只影响当前出站数据包，不会删除源 Sphere 中的业务数据。

## 迁移数据配置

迁移数据配置决定每个对象在目标 Sphere 中如何处理。需要重点确认迁移模式、标识字段、筛选器和字段范围。

### 迁移模式

| 迁移模式 | 目标 Sphere 中的处理方式 | 适用建议 |
|------------|--------------------------------|------------|
| 创建 | 创建新的对象实例数据 | 目标 Sphere 中确认不存在相同业务数据时使用 |
| 删除 | 删除与标识字段匹配的对象实例；没有匹配数据时不处理 | 清理测试数据或撤销已迁移数据时谨慎使用 |
| 更新 | 更新与标识字段匹配的对象实例；没有匹配数据时不处理 | 目标 Sphere 已有数据，只需要同步字段值时使用 |
| 插入/更新 | 匹配到数据时更新；没有匹配数据时创建 | 常用默认模式，适合初始化后持续补数 |

选择 **创建** 时，标识字段下拉列表不可用，因为系统不会在目标 Sphere 中查找已有记录。选择删除、更新或插入/更新时，请确认标识字段能稳定识别唯一业务记录。

### 标识字段

标识字段用于在目标 Sphere 中查找匹配数据。未选择标识字段时，系统默认使用 `name__ak` 字段进行匹配和查找。

建议优先选择业务上稳定且唯一的字段，例如编码、编号或外部系统标识。不要选择容易变化的名称、描述或状态类字段作为标识字段，否则可能出现重复创建、更新错误记录或无法匹配的情况。

### 筛选器

筛选器用于限定迁出的源数据范围，规则与导入导出工具中的导出条件一致。管理员可以通过筛选器只迁出本次需要的数据，例如指定状态、所属部门、创建时间或业务分类。

筛选条件越精确，数据包越容易核对。正式迁移前，建议记录筛选条件，并在源 Sphere 中确认筛选结果数量。

### 字段范围

字段范围决定哪些字段值会被迁出。只有已选择字段的值才会进入数据包。

选择字段时请同时考虑以下内容：

| 字段类型 | 建议 |
|------------|------|
| 业务必填字段 | 必须包含，否则目标 Sphere 可能导入失败 |
| 标识字段 | 建议包含，便于导入结果核对和后续追溯 |
| 引用字段 | 若目标数据依赖对象关系，应包含相关引用字段，并确认引用对象已迁移或已存在 |
| 状态字段 | 涉及生命周期或流程状态时谨慎选择，避免目标环境状态与业务流程不一致 |
| 大文本或文件字段 | 仅在业务需要时选择，避免数据包过大 |

## 生成和下载数据包

数据集配置完成后，管理员可以在出站数据包详情中生成数据包。
1. 确认所有数据集均已配置迁移模式、标识字段、筛选器和字段范围。
2. 点击 **生成数据包**。
3. 等待系统完成后台生成任务。
4. 在数据包列表中找到生成完成的记录。
5. 点击 **下载**，将数据包保存到本地受控目录。

系统生成的第一个数据包名称通常与出站数据包名称一致；后续生成的数据包会在名称基础上追加序号。下载后建议按项目、源 Sphere、目标 Sphere 和日期归档，例如 `Prod_数据迁移_供应商基础数据_20260514.zip`。
> \[!TIP\]
生成数据包前，建议导出源 Sphere 和目标 Sphere 的配置报告，并记录本次迁移涉及的数据集、对象、筛选条件和预计记录数。这样在导入后可以快速核对差异。

## 入站数据包

入站数据包用于在目标 Sphere 中接收并导入出站数据包文件。

### 导入数据包文件
1. 进入 **管理端 \> 部署管理 \> 数据迁移 \> 入站数据包**。
2. 点击 **导入**。
3. 在文件选择器中选择已下载的数据包文件。
4. 系统创建入站数据包记录，并进入导入处理流程。

入站数据包列表支持关键字搜索，关键字通常匹配名称、概要或描述。管理员可以通过列表查看历史导入记录和导入状态。

### 入站数据包详情

入站数据包详情显示数据包中的数据集和导入步骤。管理员可选择需要导入的数据集，然后点击右上角 **导入**。

| 页面区域 | 说明 |
|------------|------|
| 数据集列表 | 显示数据包中可导入的数据集 |
| 步骤 / 结果 | 显示导入进度、成功数量、失败数量和失败原因 |
| 导入 | 对选中的数据集执行导入 |
| 下载结果 | 导入失败时下载结果文件，查看失败数据明细 |

如果只需要导入部分数据集，请先勾选目标数据集再执行导入。导入失败时，系统支持下载失败数据明细，管理员应根据失败原因修复配置或数据后再重新导入。

## 管理员跨业务单元导入导出

数据迁移包的业务单元隔离对普通用户仍然生效；对具备平台级管理身份的用户，系统在数据迁移包导入导出时豁免业务单元限制。

### 适用身份

满足以下**任一**条件的用户，在数据迁移包导入导出时不受业务单元限制：

| 条件 | 说明 |
|------|------|
| 系统管理员角色 | 用户角色中包含「系统管理员」（System Administrator） |
| admin 用户 | 平台内置超级管理员账号 |

豁免仅作用于**数据迁移包**的导入导出，不影响其他模块的业务单元隔离。非上述身份的用户行为与原先一致：仅能导出、导入当前所属业务单元范围内的数据。

### 导出

管理员导出时：
- 业务单元选择范围扩展为当前环境全部业务单元，支持多选。
- 默认可选「全部业务单元」；也可只勾选部分业务单元。
- 选择全部时，导出包包含所选对象在各业务单元下的实例数据；选择部分时，仅包含所选业务单元的数据。
- 包内数据按业务单元组织，并保留所属业务单元标识，便于导入时正确归属。
- 包详情或列表可展示涵盖业务单元、业务单元数量和数据量等信息（以当前页面为准）。

非管理员导出时不提供跨业务单元选择，仍只导出当前业务单元数据。

### 导入

管理员导入时：
- 可查看数据包涵盖的业务单元，并选择导入目标。
- 默认推荐「按原业务单元归属导入」：将包内各业务单元数据分别导入到目标环境中同名（或对应）的业务单元。
- 也可自定义源业务单元到目标业务单元的一对一映射；多个源映射到同一目标时，系统会要求确认。不允许将同一源业务单元同时映射到多个目标。
- 跳过「数据必须属于当前用户业务单元」的归属校验，但仍校验目标业务单元是否存在，并执行对象结构、唯一性、字段类型等常规校验。
- 导入结果可按业务单元维度展示成功、失败、跳过等统计（以当前页面为准）。

非管理员导入时仍只能导入到当前所属业务单元。

### 权限与注意

| 项 | 说明 |
|---|------|
| 权限前提 | 除系统管理员 / admin 身份外，仍需具备数据迁移相关菜单、生成下载和导入权限，以及对象数据读写权限 |
| 审计 | 跨业务单元导入导出会记入审计日志，通常包含操作人、包名称、涵盖或映射的业务单元、数据量及是否跨业务单元等 |
| 误操作风险 | 管理员可将数据导入到错误业务单元。导入前请核对业务单元映射；正式环境建议先在测试 Sphere 演练 |
| 数据量 | 全平台导出可能数据量很大，请关注生成耗时与文件体积，必要时分批按业务单元导出 |

## 权限要求

| 操作 | 权限要求 |
|------|------------|
| 查看数据迁移菜单 | 需要具备部署管理或数据迁移相关查看权限 |
| 创建和编辑出站数据包 | 需要具备数据迁移配置维护权限，并能读取源对象数据 |
| 生成和下载数据包 | 需要具备数据包生成、下载权限，以及相关对象数据读取权限 |
| 导入入站数据包 | 需要具备数据迁移导入权限，并能在目标对象上创建、更新或删除数据 |
| 跨业务单元导入导出 | 还需具备系统管理员角色，或使用 admin 账号；普通用户不可跨业务单元操作 |
| 查看导入结果 | 需要具备入站数据包查看权限和作业结果查看权限 |

权限不足时，用户可能看不到菜单、无法选择对象、无法生成数据包，或在导入时出现对象数据写入失败。

## 迁移前检查

正式迁移前，建议完成以下检查：

| 检查项 | 说明 |
|---------|------|
| 目标配置已就绪 | 目标 Sphere 已具备对象、字段、页面、生命周期、工作流、权限和引用关系 |
| 对象范围已确认 | 主对象和相关对象能覆盖完整业务场景，且没有包含无关对象 |
| 筛选条件已复核 | 源 Sphere 中按筛选条件查询出的记录数量符合预期 |
| 标识字段已确认 | 标识字段在目标 Sphere 中可用于稳定匹配，且不存在明显重复 |
| 迁移模式已评审 | 删除、更新、插入/更新等模式已经过业务和实施负责人确认 |
| 字段范围已复核 | 必填字段、标识字段、引用字段和业务关键字段均已包含 |
| 回退方案已准备 | 已保留迁移前配置报告、数据导出或备份，必要时可定位和恢复 |
| 业务单元范围已确认 | 跨业务单元导出或导入时，已确认系统管理员 / admin 身份，并核对涵盖业务单元或映射关系 |

## 导入后核对

导入完成后，不要只查看导入任务是否成功，还应进行业务核对。

建议核对：
1. 入站数据包结果中成功、失败和跳过的记录数量。
2. 目标对象中的记录总数和关键筛选条件下的记录数量。
3. 标识字段、名称、状态、所属组织、引用关系等关键字段。
4. 主对象与相关对象之间的引用关系是否完整。
5. 页面、列表、报表和工作流中是否能正常读取迁移后的数据。
6. 审计日志或作业记录中是否能追溯本次导入操作。

如发现导入失败，请先下载结果文件查看失败明细。常见原因包括目标 Sphere 缺少字段或引用对象、标识字段无法匹配、字段值不符合目标对象校验规则、用户权限不足、数据格式不符合字段类型要求。

## 常见问题

**Q：数据迁移可以替代配置迁移吗？** A：不可以。数据迁移处理对象实例数据；对象、字段、页面、生命周期、工作流和权限等组件配置仍应通过配置迁移完成。

**Q：为什么导入时提示找不到字段或对象？** A：通常是目标 Sphere 尚未完成配置迁移，或目标环境中的对象、字段 Code 与源环境不一致。请先完成配置迁移并核对配置报告。

**Q：未选择标识字段会怎样？** A：系统默认使用 `name__ak` 字段查找匹配数据。若 `name__ak` 不能稳定唯一地代表业务记录，建议手工选择更合适的标识字段。

**Q：什么时候使用“插入/更新”？** A：目标 Sphere 中可能已有部分记录、也可能缺少部分记录时使用。系统会匹配到则更新，匹配不到则创建，适合初始化后补数和增量同步。

**Q：什么时候不建议使用“删除”？** A：生产环境、引用关系复杂或无法确认匹配范围时不建议直接使用删除。删除前请先确认筛选条件和标识字段，必要时先在测试环境演练。

**Q：为什么数据包生成完成后下载的是 ZIP 文件？** A：数据包需要包含结构化数据和相关元信息，系统通常会打包为 ZIP 文件，便于在目标 Sphere 中完整导入。

**Q：导入失败后可以重新导入吗？** A：可以。请先下载结果文件，处理失败原因后再重新导入。重新导入前应确认迁移模式和标识字段，避免重复创建或覆盖错误记录。

**Q：谁可以跨业务单元导出或导入数据迁移包？** A：具备系统管理员角色的用户，以及 admin 用户，可在数据迁移包导入导出时选择全部或部分业务单元，并可做业务单元映射导入。业务单元管理员和普通用户仍只能在当前所属业务单元范围内操作。

**Q：管理员导入时可以改数据归属到别的业务单元吗？** A：可以。默认按原业务单元归属导入；也可自定义源到目标的业务单元映射。目标业务单元必须在当前环境中已存在。一对多映射不被允许；多对一映射需确认后执行。
