# 配置报告
> 本文面向系统管理员、实施顾问和配置负责人，介绍如何创建、查看、下载和使用配置报告。配置报告用于导出当前 Sphere 的配置清单，常用于配置迁移前后核对、配置审阅、问题排查和审计归档。   

---

## 概述

配置报告会将当前 Sphere 中的配置类信息导出为报告文件。报告主体通常为 Excel 文件；当报告包含文档模板、页面模板或其他附件类内容时，系统会将 Excel 报告和相关文件一起打包为 ZIP 文件。

配置报告用于核对和留档，不用于执行迁移。组件配置通过配置包迁移；业务配置应使用数据迁移完成迁移。报告可以帮助管理员在迁移前确认基线，在迁移后核对对象、字段、生命周期、工作流、权限等配置是否符合预期。

典型访问路径：

**管理端 \> 部署管理 \> 配置报告**

配置报告适用于以下场景：

| 场景 | 用法 |
|------|------|
| 部署前留档 | 在配置包导入或生产部署前导出当前 Sphere 配置，作为变更前基线 |
| 部署后核对 | 部署完成后再次导出，用于确认配置变化是否符合预期 |
| 配置审阅 | 将对象、字段、生命周期、工作流、权限等配置导出给业务或 QA 审阅 |
| 问题排查 | 对比不同时间或不同 Sphere 的配置，定位异常来源 |
| 审计归档 | 保存配置报告、配置包和部署日志，作为变更记录的一部分 |
> \[!IMPORTANT\]
配置报告只导出配置清单，不会修改系统配置，也不会代替配置包部署或数据迁移。需要迁移组件配置时，请使用出站配置包和入站配置包；需要迁移业务配置时，请使用数据迁移。   

---

## 报告内容

配置报告按配置类型输出。管理员可在创建报告时选择导出范围，减少不必要的内容。

| 内容类型 | 说明 | 常见用途 |
|------------|------|------------|
| 配置迁移数据包组件 | 对象、字段、生命周期、工作流、页面、权限集等组件配置 | 配置包部署前后核对、配置评审 |
| 非组件类型 | 不直接归属于组件的数据或系统配置 | 排查 Sphere 差异、记录系统基线 |
| 组件引用数据 | 组件依赖的角色、权限、引用项、基础配置等 | 检查配置包依赖是否完整 |
| 文档模板 | 与文档模板相关的配置和附件 | 文档对象、模板套用、合规审阅 |
| 已停用组件 | 已停用但仍存在于系统中的组件实例 | 清理历史配置、确认是否仍被引用 |

报告中每类组件通常会输出到独立工作表。子组件会通过工作表名称或字段内容与父组件保持关联，便于管理员追踪配置层级。

## 列表页面

进入 **配置报告** 后，列表页面显示已经创建的报告任务。记录通常按创建时间倒序排列。

### 列表字段

| 字段 | 说明 |
|------|------|
| 编号 | 报告任务的唯一标识，可用于搜索和追溯 |
| 配置版本 | 创建报告时当前 Sphere 的配置版本，用于和配置包版本、部署记录一起核对 |
| 状态 | 当前任务进度，例如待执行、生成中、完成或失败 |
| 创建时间 | 报告任务创建时间 |
| 拥有人 / 创建人 | 创建报告任务的用户 |
| 操作 | 根据状态显示下载、取消、重试等动作 |

### 页面操作

| 操作 | 结果 |
|------|------|
| 创建 | 进入创建页面，选择报告范围并提交后台生成任务 |
| 搜索 | 按编号或关键词查找历史报告任务，用于追溯某次部署或核对记录 |
| 下载 | 在任务完成后下载 Excel 或 ZIP 文件 |
| 取消 | 在任务尚未完成前停止生成，已生成的文件不会被下载 |
| 重试 | 在任务失败后重新执行生成，通常用于临时任务异常或后台作业恢复后 |

已创建的报告任务不建议编辑。如果导出范围选择错误，请重新创建一条报告任务。

## 创建配置报告

### 操作步骤
1. 进入 **管理端 \> 部署管理 \> 配置报告**。
2. 点击 **创建**。
3. 在创建页面选择组件类型和导出选项。
4. 点击 **生成**。
5. 系统创建导出任务，并异步生成报告。
6. 任务完成后，在列表页或系统通知中下载报告文件。

点击 **生成** 后，系统不会立即下载文件。报告会进入后台任务队列，管理员可以离开当前页面，稍后回到列表查看状态。

### 创建页字段

| 字段 / 选项 | 说明 | 建议 |
|---------------|------|------|
| 组件类型 | 选择需要导出的组件类型。默认可包含全部父级组件类型 | 日常核对可按模块选择；生产部署前建议覆盖本次变更涉及的全部组件 |
| 对象数据 | 用于选择是否导出对象数据。当前通常不作为配置报告的主要范围 | 如需迁移业务配置或业务数据，请使用数据迁移；配置报告仅用于核对 |
| 系统设置 | 控制报告中是否包含系统级设置 | 涉及系统参数、安全策略、Sphere 配置时建议勾选 |
| 文档模板 | 控制是否包含文档模板相关配置和文件 | 本次变更涉及文档模板、页面模板或运行报告时建议勾选 |
| 已停用组件 | 勾选后，报告会包含状态为停用的组件实例 | 排查历史配置或清理组件时建议勾选 |
| 空结果 | 控制无数据的组件是否生成对应工作表 | 需要精简报告时可启用；需要完整审计结构时可保留空工作表 |
| 仅包含指定时间之后修改过的组件 | 输入日期后，仅导出该日期当天或之后修改的组件和子组件 | 用于缩小变更核对范围 |
> \[!TIP\]
如果报告用于生产部署前后对比，请记录导出时间、源 Sphere、目标 Sphere 和配置包版本。这样后续审计或排查时能快速还原变更上下文。

## 任务状态

配置报告通过后台任务生成。列表中的状态用于判断当前任务是否可下载、是否需要等待或是否需要处理失败。

| 状态 | 含义 | 可执行操作 |
|------|------|---------------|
| 待执行 | 任务已创建，尚未开始生成 | 可取消 |
| 生成中 | 系统正在提取配置数据 | 可等待，必要时取消 |
| 打包中 | 数据已提取，系统正在整理 Excel 或 ZIP 文件 | 可等待 |
| 完成 | 报告已生成 | 可下载 |
| 失败 | 生成过程中出现错误 | 可查看失败信息并重试 |
| 取消 | 任务已被取消 | 不再生成报告 |

如果任务长时间停留在生成中或打包中，请先刷新列表查看最新状态。仍无变化时，可联系管理员检查后台作业是否拥堵。

## 下载与通知

报告生成完成后，系统通常会向任务拥有人发送通知。管理员也可以在配置报告列表中找到状态为 **完成** 的记录，并点击 **下载**。

下载结果可能有两种：

| 文件类型 | 说明 |
|------------|------|
| Excel 文件 | 仅包含结构化配置清单时，通常直接下载 `.xlsx` 文件 |
| ZIP 文件 | 包含 Excel 报告以及模板、附件或其他文件时，系统会打包为 `.zip` |

下载后建议按项目、Sphere 和时间归档，例如：`Prod_配置报告_部署前_20260514.zip`。文件名不影响系统记录，但清晰命名可以降低后续核对成本。

## 报告结构

配置报告通常包含以下内容。实际内容取决于创建报告时选择的组件类型和导出选项。

| 部分 | 说明 |
|------|------|
| 封面页 | 显示报告概要，例如 Sphere、生成时间、组件范围等信息 |
| 目录页 | 列出报告中包含的组件类型或工作表 |
| 组件内容页 | 按组件类型输出配置明细 |
| 子组件内容页 | 输出字段、状态、规则、步骤等子级配置 |
| 附件文件 | 当报告包含模板或相关文件时，随 ZIP 一起下载 |

### 内容显示规则

| 规则 | 说明 |
|------|------|
| 字段标题 | 优先使用便于阅读的配置名称 |
| 布尔值 | 通常显示为“是 / 否” |
| 空值 | 保持为空白单元格 |
| 子组件 | 通过父组件名称、组件编码或工作表命名体现关联 |
| 引用项 | 显示被引用配置的名称、编码或标识 |

报告用于核对配置。不要把报告内容当作可导入模板修改后回传系统；需要迁移组件配置时，应重新生成配置包；需要迁移业务配置时，应使用数据迁移。

## 使用建议

### 部署前后对比

配置迁移前后分别导出配置报告，可以帮助管理员确认全量迁移后的配置状态是否符合预期。

推荐做法：
1. 在目标 Sphere 部署前导出配置报告，作为基线。
2. 部署配置包或完成数据迁移后再次导出配置报告。
3. 对比对象、字段、生命周期、工作流、权限和页面模板等关键配置。
4. 对业务配置类内容，结合数据迁移结果和业务核对清单确认记录数量、关键字段和引用关系。
5. 将两份报告、配置包、数据迁移记录和部署日志一起归档。

### 缩小导出范围

当系统配置较多时，完整报告可能生成较慢。可以通过以下方式缩小范围：
- 只选择本次变更涉及的组件类型。
- 使用“仅包含指定时间之后修改过的组件”筛选变更。
- 不勾选与本次核对无关的文档模板或已停用组件。
- 对于正式审计归档，再导出完整范围报告。

### 排查 Sphere 差异

如果验证 Sphere 和生产 Sphere 表现不同，可分别导出两边配置报告，重点检查：
- 对象、字段、字段类型和默认值是否一致。
- 生命周期状态、转换条件和入口动作是否一致。
- 工作流步骤、参与人、条件和操作是否一致。
- 权限集、角色、对象权限和字段权限是否一致。
- 页面模板包、视图和布局是否一致。

配置报告适合做静态核对。若需要迁移组件配置，请结合 [配置迁移](07_%E9%85%8D%E7%BD%AE%E8%BF%81%E7%A7%BB.md) 中的配置包说明使用；若需要迁移业务配置，请使用数据迁移并保留迁移记录。

## 常见问题

**Q：配置报告会修改系统配置吗？** A：不会。配置报告只读取并导出配置内容，不会创建、更新或删除系统配置。

**Q：为什么报告完成后下载的是 ZIP 文件？** A：当报告包含模板、附件或多个输出文件时，系统会将 Excel 报告和相关文件一起打包为 ZIP。

**Q：报告生成失败后怎么办？** A：先查看任务状态和失败信息。如果是临时任务异常，可以点击重试；如果多次失败，请缩小导出范围或联系技术支持。

**Q：能否用配置报告迁移配置？** A：不能。配置报告用于查看和核对配置。组件配置迁移应通过出站配置包和入站配置包完成；业务配置应使用数据迁移完成迁移。

**Q：为什么报告里没有某些配置？** A：可能是创建报告时未选择对应组件类型，也可能是当前用户缺少组件读取权限。请检查导出范围和权限配置。

**Q：配置报告能否替代部署前后的业务验证？** A：不能。配置报告只能反映配置清单，不能证明业务流程已经可用。部署后仍需验证关键对象、页面、权限、工作流和业务数据。
