# 审批矩阵管理
> 本文面向管理员，说明如何在业务端维护审批矩阵数据、矩阵角色、默认参与人、默认职位、权限和变更规则。审批矩阵的配置建模、匹配字段和工作流节点设置，请参见 [审批矩阵配置](../04_%E9%85%8D%E7%BD%AE%E6%8C%87%E5%8D%97/20_%E5%AE%A1%E6%89%B9%E7%9F%A9%E9%98%B5%E9%85%8D%E7%BD%AE.md)。   

---

## 概述

审批矩阵用于在同一类流程中，根据业务记录的字段值自动匹配不同的审批角色、参与人范围和任务分配顺序。配置人员启用审批矩阵配置后，系统会生成对应的审批矩阵管理对象；管理员在该对象中维护具体矩阵数据，例如某类文件、某个业务单元或某个对象分类应由哪些角色或用户组参与审批。

审批矩阵通常用于以下场景：
- 同一流程在不同文件类型、部门、业务单元或对象分类下，需要不同审批人。
- 发起工作流时，希望系统先带出默认参与人，减少人工选错。
- 审批角色有串行、并行、最少人数、最多人数、候选范围等约束。
- 文档升版后，需要复用上一版本审批矩阵成员。

管理员主要负责：
- 创建、启用、停用和维护审批矩阵管理记录。
- 维护矩阵角色、用户组、默认用户、成员数量约束和排序。
- 配置默认职位记录，支持签批时自动带出职位。
- 控制审批矩阵的查看、编辑和管理权限。
- 在变更矩阵前评估对新记录、历史记录和工作流的影响。

---

## 访问路径与前提

审批矩阵管理对象部署在业务端，入口菜单由配置人员决定。常见路径为：

`系统管理 > 审批矩阵管理`

如果业务端没有看到入口，通常需要先检查以下前提：

| 前提 | 说明 |
|------|------|
| 审批矩阵配置已启用 | 只有启用的审批矩阵配置才会生成并展示对应的管理对象。 |
| 菜单已配置 | 配置人员需要把审批矩阵管理对象加入菜单。 |
| 管理对象权限已授予 | 管理员需要具备该对象的查看、创建、编辑、删除等对象权限。 |
| 表单和列表布局已配置 | 若某些字段未显示，需要检查审批矩阵管理对象及其子对象布局。 |
| 业务侧权限已配置 | 业务用户能否查看或管理记录上的审批矩阵，还受权限集和状态权限控制。 |

审批矩阵管理页维护的是“具体规则数据”。匹配字段、角色规则、任务类型、锁定状态等基础模型由配置人员在管理端配置。

## 1\. 审批矩阵数据模型

审批矩阵涉及多类数据。管理员日常最常接触的是审批矩阵管理记录和审批矩阵角色记录。

| 数据 | 作用 | 管理位置 |
|------|------|------------|
| 审批矩阵配置 | 定义适用对象、匹配字段、角色规则和系统生成结构。 | 管理端配置页面 |
| 审批矩阵管理记录 | 维护某一套可命中的审批矩阵数据，例如适用部门、业务单元、默认规则和权重。 | 业务端审批矩阵管理对象 |
| 审批矩阵角色记录 | 维护该矩阵下的角色、用户组、默认用户、人数限制和顺序。 | 审批矩阵管理记录详情页的子列表 |
| 审批矩阵成员记录 | 保存某条业务记录实际匹配和选择后的参与人快照。 | 由系统在业务记录上生成和维护 |
| 默认职位记录 | 维护用户在指定审批矩阵角色下的默认签批职位。 | 启用默认职位管理后显示 |

审批矩阵的运行结果可以理解为两步：
1. 系统先根据业务记录字段值命中一条审批矩阵管理记录。
2. 系统再读取该管理记录下的角色、用户组、默认用户和人数限制，生成业务侧的参与人选择区。

## 2\. 审批矩阵列表

进入审批矩阵管理页面后，系统以列表展示已创建的矩阵记录。列表字段由布局决定，常见字段如下。

| 字段 | 说明 |
|------|------|
| 名称 | 审批矩阵名称。点击名称进入详情页。 |
| 记录状态 | `启用` 的记录才参与匹配；`停用` 后不再被新记录命中。 |
| 是否默认规则 | 当其他规则均未命中时，是否作为兜底矩阵。 |
| 权重 | 多条矩阵同时命中时，权重越大优先级越高。 |
| 参与人类型 | 业务侧按角色选人，或按用户组选人。 |
| 允许用户添加角色 | 发起流程时是否允许业务用户额外添加角色行。 |
| 提示说明 | 命中该矩阵时显示给发起人的矩阵级提示。 |
| 所属业务单元 | 用于区分不同业务单元下的矩阵数据。是否显示取决于对象布局。 |
| 描述 | 记录矩阵用途、适用范围或维护备注。 |

常用操作：

| 操作 | 结果 |
|------|------|
| 创建 | 新建一条审批矩阵管理记录。保存后可继续维护矩阵角色。 |
| 编辑 | 修改当前矩阵的基础信息、匹配字段值、权重或提示说明。 |
| 删除 | 删除当前矩阵记录。已匹配到业务记录上的历史矩阵不随之删除。 |
| 筛选/视图 | 按状态、业务单元等字段筛选，并按需保存个人视图。 |
> \[!CAUTION\]
删除或停用审批矩阵前，先确认后续新流程是否仍需要这套规则。已保存到业务记录上的历史矩阵快照不会被改写，但新记录将无法再命中已删除或停用的矩阵。

## 3\. 创建和维护审批矩阵

### 3.1 创建步骤
1. 打开审批矩阵列表页。
2. 点击 `创建`。
3. 填写名称、状态、匹配字段值、权重、默认规则等信息。
4. 按需填写 `提示说明`，用于提醒发起人当前矩阵的适用范围或选人要求。
5. 点击 `保存`。
6. 进入详情页后，继续创建矩阵角色。

### 3.2 基础字段

| 字段 | 说明 |
|------|------|
| 名称 | 建议包含业务场景，例如 `SOP 文件审批矩阵`、`偏差调查审批矩阵`。 |
| 记录状态 | `启用` 后参与新记录匹配；`停用` 后不再被新记录命中。 |
| 权重 | 当多条矩阵同时满足条件时，系统优先使用权重较大的矩阵。 |
| 是否默认规则 | 作为兜底矩阵使用。建议同一审批矩阵配置下只保留一条默认规则。 |
| 参与人类型 | 选择业务侧按 `角色` 还是按 `用户组` 控制候选人范围。 |
| 允许用户添加角色 | 开启后，发起流程时用户可在审批矩阵参与人区域新增额外角色行。 |
| 提示说明 | 命中该矩阵后，在表单创建/编辑模式和发起工作流弹窗中展示。 |
| 描述 | 记录维护背景、变更说明或适用边界。 |
| 匹配字段值 | 根据配置端定义的匹配字段生成。管理员在这里维护具体命中条件。 |

### 3.3 匹配与优先级

系统根据配置端定义的匹配字段，将业务记录与审批矩阵管理记录进行比对。匹配字段可能来自对象字段、父对象字段、选项字段，也可以按配置使用部分公式字段。

匹配时通常遵循以下规则：
1. 只有启用状态的审批矩阵管理记录参与匹配。
2. 业务记录字段值与矩阵管理记录中的匹配字段值一致时，才可能命中。
3. 树形对象字段可按配置使用“相等且包含下级”或“相等且包含子级”。
4. 多条记录同时命中时，优先使用权重更高的矩阵。
5. 没有普通规则命中且存在默认规则时，使用默认规则。

匹配字段、空值匹配方式和公式字段限制由配置人员维护。管理员发现矩阵没有按预期命中时，应先核对当前记录字段值、矩阵记录状态、权重和默认规则，再联系配置人员检查匹配字段配置。

### 3.4 提示说明

`提示说明` 是矩阵级说明，适合说明当前命中的整套矩阵为什么适用，或提醒发起人如何选择参与人。例如：
- “适用于研发类 SOP 文件，QA 审核人需选择文件所属业务单元的质量负责人。”
- “若本次变更涉及生产工艺，请补充生产负责人参与审批。”

显示规则：

| 场景 | 是否显示 |
|------|------------|
| 业务表单创建模式 | 显示 |
| 业务表单编辑模式 | 显示 |
| 业务表单详情模式 | 不显示 |
| 发起工作流弹窗 | 显示 |
| 移动端查看 | 不显示 |

`提示说明` 与角色规则上的帮助内容不同。`提示说明` 说明整套矩阵的适用范围；角色帮助内容说明某个角色应该如何选人。管理员维护矩阵数据时，通常只填写矩阵级 `提示说明`；如果需要调整角色级帮助内容，请由配置人员在审批矩阵配置中维护。

## 4\. 管理矩阵角色

矩阵角色记录定义业务侧展示的参与人行。每条角色记录会影响发起流程时出现的角色、候选人范围、默认参与人、是否允许修改以及任务分配顺序。

### 4.1 查看角色列表
1. 在审批矩阵列表中点击矩阵名称。
2. 在详情页进入 `矩阵角色` 子列表。
3. 查看角色名称、规则、用户组、默认用户、人数限制和排序。

常见字段如下。

| 字段 | 说明 |
|------|------|
| 名称 | 角色记录名称。建议使用业务用户能识别的名称。 |
| 规则 | 选择配置端生成的矩阵角色规则。该规则决定角色口径和任务类型。 |
| 用户组 | 参与人类型为 `用户组` 时，用于限定候选用户范围。 |
| 默认用户 | 发起流程时自动带出的用户，可多选。 |
| 是否允许修改参与人 | 为 `否` 时，发起人只能查看系统带出的参与人，不能手工调整。 |
| 是否以用户组的用户作为默认值 | 为 `是` 时，系统将当前用户组成员整体带出作为默认参与人。 |
| 是否专属成员 | 限定该角色只能使用明确指定的专属成员。 |
| 最小成员数 | 发起流程时该角色至少需要的参与人数。 |
| 最大成员数 | 该角色允许选择的最多参与人数。 |
| 排序 | 决定角色在业务侧审批矩阵中的显示顺序。 |

### 4.2 创建角色
1. 在矩阵角色子列表点击 `创建`。
2. 选择 `规则`，并填写角色名称。
3. 根据参与人类型维护用户组、默认用户和人数限制。
4. 设置排序。
5. 点击 `保存`。

保存后，新角色会影响后续新匹配的业务记录。已保存过审批矩阵成员的历史记录不会被自动改写。

### 4.3 参与人类型

审批矩阵管理记录上的 `参与人类型` 决定角色记录的维护重点。

| 参与人类型 | 管理方式 | 业务侧结果 |
|---------------|------------|---------------|
| 角色 | 通过规则、应用角色和角色约束确定候选人范围。 | 发起流程时按角色规则选择用户。 |
| 用户组 | 在角色记录上维护用户组。 | 发起流程时只能从对应用户组成员中选择用户。 |

使用用户组时，建议逐条检查角色记录是否已维护用户组。未维护用户组的角色无法正确收窄候选范围。

### 4.4 默认用户与只读控制

默认用户用于减少发起流程时的手工选择。管理员可以在角色记录上维护一组默认用户，也可以在使用用户组时让系统自动带出用户组成员。

| 配置 | 业务侧结果 |
|------|---------------|
| 默认用户 | 发起流程时自动带出这些用户。 |
| 是否以用户组的用户作为默认值 = 是 | 自动带出当前用户组成员。 |
| 是否允许修改参与人 = 是 | 发起人可以调整系统带出的参与人。 |
| 是否允许修改参与人 = 否 | 当前角色参与人控件只读，发起人不能修改。 |

如果同时维护了默认用户，并开启“以用户组的用户作为默认值”，建议先在测试记录中确认最终带出的名单。对于强合规场景，如默认名单必须固定，可将 `是否允许修改参与人` 设为 `否`，同时建立定期复核机制。

### 4.5 专属成员

`是否专属成员` 用于限制当前角色只能由指定成员承担。开启后，即使其他用户也符合角色或用户组候选范围，业务侧仍只允许选择专属成员范围内的用户。

该设置适合固定审批人场景，例如首席质量官、指定法规负责人或特定业务单元负责人。启用前应确认专属成员仍处于有效账号和在岗状态，否则发起流程时可能出现无可选审批人的情况。

### 4.6 人数限制和排序

| 配置 | 行为 |
|------|------|
| 最小成员数 = N | 发起流程时少于 N 人会阻止提交，并提示补充参与人。 |
| 最大成员数 = M | 达到 M 人后不能继续添加参与人。 |
| 排序 | 角色按排序值展示；串行任务通常按角色顺序和成员顺序依次分配。 |

最小成员数适合强制必须有审批人的角色。最大成员数适合限制会签范围，避免参与人过多导致流程膨胀。

### 4.7 删除或停用角色

删除或停用角色后，系统不会改写已保存到业务记录上的历史矩阵成员。后续新记录重新匹配时，才会使用调整后的角色列表。

变更前建议检查：
- 是否仍有活动工作流依赖该角色。
- 是否有业务表单或工作流开始节点正在使用该审批矩阵。
- 是否需要先创建替代角色，再停用旧角色。

## 5\. 默认职位管理

如果配置人员在审批矩阵配置中启用了默认职位管理，审批矩阵管理详情页会出现默认职位相关区域。管理员可为某个用户在某个审批矩阵角色下维护默认职位。

默认职位常用于电子签名要求选择职位的场景。用户完成审批任务时，如果存在匹配的默认职位，系统优先带出该职位；如果没有匹配默认职位且用户有多个职位，则由用户手动选择。

默认职位记录通常包含以下字段。

| 字段 | 说明 |
|------|------|
| 用户 | 需要设置默认职位的用户。 |
| 职位 | 该用户可选职位范围内的职位。 |
| 审批矩阵角色 | 默认职位适用的矩阵角色。 |
| 记录状态 | 启用状态的默认职位记录才生效。 |

使用建议：
- 同一用户在不同角色下可能需要不同默认职位，应分别维护。
- 用户岗位变更后，及时复核默认职位记录。
- 批量工作流也可能使用默认职位，正式启用前建议用测试流程验证签批职位带出结果。
- 工作流参与人控件若设置为当前业务单元，任务责任人的可选职位会限定在对应业务单元下。

## 6\. 复制上一版本成员

文档对象可按配置复用上一版本审批矩阵成员。该能力适合文件升版后审批人基本不变的场景。

### 6.1 表单中的复制成员

当文档布局中的审批矩阵部分开启“允许复制之前版本的审批矩阵成员”后，业务端审批矩阵编辑模式会显示 `复制成员` 按钮。

点击后系统会：
1. 查找最近一个有审批矩阵成员的历史版本。
2. 检查当前版本命中的矩阵规则是否与历史版本一致。
3. 规则一致时，将历史版本成员复制到当前版本，并覆盖当前已选成员。
4. 规则不一致时，提示用户手动重新选择成员。

`复制成员` 按钮受审批矩阵管理权限控制。管理员应提醒业务用户：复制会覆盖当前版本已选成员，点击前先确认是否需要保留当前选择。

### 6.2 工作流发起时复制

工作流开始节点也可配置为默认选择或允许复制上一版本审批矩阵成员。该能力仅在单文档工作流中生效。

| 配置 | 发起流程时的结果 |
|------|------------------------|
| 默认选择上一版本成员 | 规则一致且历史版本有成员时，系统自动带出上一版本成员。 |
| 允许复制上一版本成员 | 发起弹窗显示 `复制成员` 按钮，用户点击后再带出历史成员。 |

如果用户已经在表单中维护了审批矩阵成员，系统优先使用表单中的成员，不再自动覆盖。

## 7\. 权限管理

审批矩阵权限分为管理对象权限和业务记录上的审批矩阵权限。

### 7.1 管理对象权限

管理对象权限决定管理员能否进入审批矩阵管理对象并维护矩阵数据。

| 权限 | 说明 |
|------|------|
| 查看 | 可以打开审批矩阵管理列表和详情。 |
| 创建 | 可以新建审批矩阵管理记录或角色记录。 |
| 编辑 | 可以修改矩阵基础信息、角色、默认用户等内容。 |
| 删除 | 可以删除矩阵记录或角色记录。 |

若管理员只能看到列表但不能创建或编辑，请检查权限集中的对象权限，以及菜单是否指向正确的审批矩阵管理对象。

### 7.2 业务侧审批矩阵权限

业务用户在对象记录上能否查看或管理审批矩阵，由两层权限共同决定。

| 权限层 | 作用 |
|---------|------|
| 权限集 | 决定用户是否具备审批矩阵查看或编辑的基础权限。 |
| 状态权限 | 决定记录处于某个生命周期状态时，哪些角色可以查看、编辑或隐藏审批矩阵。 |

状态权限不能突破权限集上限。即使状态权限设置为编辑，如果权限集中没有审批矩阵编辑权限，用户仍不能管理矩阵成员。

常见配置示例：

| 角色 | 草稿 | 审批中 | 已生效 |
|------|------|---------|---------|
| 文件创建者 | 编辑 | 查看 | 查看 |
| 文件管理员 | 编辑 | 编辑 | 查看 |
| 普通用户 | 隐藏 | 查看 | 隐藏 |

### 7.3 锁定状态

审批矩阵配置或角色规则中可设置锁定状态。业务记录进入锁定状态后，即使用户具备编辑权限，也不能编辑对应审批矩阵成员。

锁定状态适合用于已审批、已生效、已归档等不应再调整参与人的阶段。

## 8\. 历史矩阵与重新匹配

### 8.1 历史矩阵保持规则

审批矩阵一旦保存到业务记录上，就形成该记录的矩阵快照。后续管理员修改审批矩阵管理记录、删除角色或调整角色顺序，不会自动改写已保存的历史矩阵。

| 场景 | 行为 |
|------|------|
| 已保存审批矩阵成员的记录 | 保持原角色、原参与人和原顺序。 |
| 新创建或重新匹配的记录 | 使用最新启用的矩阵规则。 |
| 文档升版 | 通常沿用已保存的历史矩阵内容；若配置了复制能力，可按规则复制上一版本成员。 |

例如，文件 v1.0 命中某矩阵并保存了 5 个角色。管理员后来将该矩阵改为 4 个角色，v1.0 的审批矩阵仍保留原来的 5 个角色；只有后续新记录或按配置重新匹配的记录，才会使用新的 4 个角色。

### 8.2 启动工作流时重新匹配

默认情况下，记录首次匹配审批矩阵后，后续启动工作流会沿用已保存的矩阵。若工作流开始节点启用了“启动工作流时重新匹配”，系统会在每次发起时重新检查当前记录字段值，并可能带出新的矩阵。

| 设置 | 行为 |
|------|------|
| 不启用重新匹配 | 沿用记录上已保存的审批矩阵。 |
| 启用重新匹配 | 每次发起工作流时重新按当前字段值匹配矩阵。 |

如果业务字段可能在流程间发生变化，例如部门、文件类型、业务单元发生调整，配置人员可评估是否启用重新匹配。管理员在启用前应和流程负责人确认历史一致性要求。

## 9\. 并行审批与自定义角色

### 9.1 并行参与人去重

当审批矩阵存在并行任务时，同一用户可能因多个角色或用户组同时被选中。启用并行参与人去重后，同一用户在并行审核中只收到一条待办任务。

| 设置 | 结果 |
|------|------|
| 启用去重 | 同一用户在并行审核中只生成一条待办。 |
| 不启用去重 | 同一用户在不同角色下可能收到多条待办。 |

如果界面上没有去重字段，需要检查审批矩阵管理对象的表单布局是否已加入该字段。

### 9.2 并行提前结束

审批矩阵并行审核可按配置在当前角色或当前用户组的所有用户完成任务后判断是否提前结束。该能力用于减少无效等待，但会改变并行任务的完成条件。启用前应由流程负责人确认审批策略。

### 9.3 自定义角色

当 `允许用户添加角色` 为 `是` 时，业务用户发起流程时可在审批矩阵参与人区域新增角色行。

| 场景 | 行为 |
|------|------|
| 首次发起流程 | 用户可点击添加按钮，新增额外角色并选择参与人。 |
| 重新发起流程 | 用户新增的自定义角色可按首次发起时的规则移除或调整。 |
| 必填校验 | 新增角色选择参与人后，相关选人项会参与提交校验。 |

如果流程必须严格按预设审批链执行，建议关闭 `允许用户添加角色`。

## 10\. 日常维护建议

### 10.1 命名建议

| 对象 | 建议 |
|------|------|
| 审批矩阵名称 | 包含业务对象、适用范围或流程场景，例如 `质量文件-生产基地审批矩阵`。 |
| 矩阵角色名称 | 包含角色职责和审批方式，例如 `QA 审核-串行`、`部门负责人-并行`。 |
| 默认规则 | 名称中标明 `默认` 或 `兜底`，便于排查命中结果。 |

### 10.2 变更建议

变更矩阵前，建议按以下顺序检查：
1. 确认当前是否有活动工作流依赖该矩阵。
2. 确认变更是否只影响新记录，还是需要通过重新匹配影响后续发起。
3. 在测试记录中验证匹配结果、默认用户、用户组候选范围和人数校验。
4. 对删除角色、关闭默认规则、调整权重等高影响变更提前通知业务用户。
5. 在描述字段或变更记录中写明调整原因和时间。

### 10.3 定期复核

| 复核项 | 建议频率 | 重点检查 |
|---------|------------|------------|
| 默认用户 | 每季度 | 是否存在离职、休假、禁用或调岗用户。 |
| 用户组 | 每季度 | 用户组成员是否仍符合审批职责。 |
| 默认职位 | 每季度 | 用户职位是否发生变化，签批职位是否仍正确。 |
| 权重和默认规则 | 业务规则调整时 | 是否存在多条规则同时命中或兜底规则误命中。 |
| 权限 | 每半年 | 是否只有必要管理员和业务角色具备编辑权限。 |

## 11\. 常见问题

**Q：创建的审批矩阵为什么没有在业务记录上显示？** A：检查审批矩阵配置和管理记录是否启用、表单布局是否放入审批矩阵部分、当前用户是否有查看权限、当前记录字段值是否满足匹配条件，以及矩阵管理记录是否为启用状态。

**Q：多个审批矩阵同时命中怎么办？** A：系统按权重选择优先级更高的矩阵。建议为可能同时命中的矩阵设置不同权重，并保留一条清晰的默认规则。

**Q：删除矩阵角色会影响已发起或已保存的流程吗？** A：不会改写已保存的历史矩阵。删除或停用角色只影响后续新匹配或重新匹配的记录。

**Q：默认用户已经维护，为什么发起人仍然能修改？** A：检查该角色记录的 `是否允许修改参与人`。如果设为 `是`，发起人可以调整默认名单；设为 `否` 后控件只读。

**Q：使用用户组后，为什么候选人没有按用户组收窄？** A：检查审批矩阵管理记录的 `参与人类型` 是否为 `用户组`，并确认对应角色记录已维护用户组。

**Q：业务用户看得到审批矩阵，但不能点击管理？** A：通常是缺少审批矩阵编辑权限、状态权限只给了查看权限，或当前记录处于锁定状态。

**Q：提示说明为什么在详情页不显示？** A：提示说明只在表单创建/编辑模式和发起工作流弹窗中展示，详情模式不显示。
