# 接口应用管理
> 本文介绍如何在 Gaia 平台中维护接口应用和接口路由，用于支持 Gaia 主动调用 ERP、MES、LIMS、企业门户等外部系统 API。   

---

## 1\. 适用范围

接口应用表示一个被 Gaia 调用的外部系统。管理员先创建接口应用，登记外部系统的基础访问地址；再在该应用下创建接口路由，定义具体 API 的请求路径、请求方式和编码。

常见使用场景包括：
- Gaia 调用外部系统查询主数据、批次、供应商或物料信息。
- Gaia 将流程状态、审批结果或业务记录回写到外部系统。
- 表单字段通过外部 API 实时获取数据并带回页面。
- 后台作业按固定规则调用外部系统接口。

---

## 2\. 访问入口

访问路径：`管理端 > 集成管理 > 接口应用管理`

如果当前账号看不到入口，请先确认是否已具备集成管理相关的管理员权限。接口应用会影响系统与外部服务的连接关系，建议仅开放给系统管理员、实施顾问或集成维护人员。

---

## 3\. 查看接口应用列表

接口应用列表以分页方式展示当前环境中已经注册的外部系统。管理员可以通过页面上方的查询条件按名称查找目标应用。

列表中的主要信息如下：

| 列 | 说明 |
|---|------|
| 名称 | 接口应用的显示名称。点击名称可进入详情页。 |
| HOST 地址 | 外部系统 API 的基础地址。接口路由中的请求路径会基于该地址发起调用。 |
| 创建人 | 创建该接口应用的用户。 |
| 创建时间 | 接口应用首次保存的时间。 |
| 描述 | 接口应用的用途说明，建议写明对接系统和业务场景。 |

列表页常用操作如下：
- `创建`：新增一个接口应用。
- `搜索`：按关键字定位已有接口应用。
- `查看详情`：点击名称进入详情页，查看基础信息并维护接口路由。

---

## 4\. 创建接口应用
1. 进入 `管理端 > 集成管理 > 接口应用管理`。
2. 点击 `创建`。
3. 填写接口应用信息。
4. 点击 `保存`。

创建接口应用时，需要重点填写以下字段：

| 字段 | 是否必填 | 说明 | 示例 |
|------|------------|------|------|
| 名称 | 是 | 接口应用在页面中的显示名称。建议使用“系统名称 \+ 接口用途”的格式，便于后续识别。 | ERP 系统接口集成应用 |
| 编码 | 是 | 接口应用的唯一编码，用于系统内部引用。保存后不建议随意修改。 | erp\_interface\_app |
| HOST 地址 | 是 | 外部系统 API 的基础访问地址。建议生产环境使用 HTTPS。 | `https://api.example.com` |
| 描述 | 否 | 说明该接口应用对接的外部系统、业务范围和维护责任人。 | 用于对接 ERP 主数据同步接口 |

保存成功后，系统会生成接口应用记录。此时仅完成了外部系统注册，还需要继续创建接口路由，Gaia 才能按具体路径和请求方式发起调用。

---

## 5\. 查看和编辑接口应用

在接口应用列表中点击名称，可进入接口应用详情页。详情页用于查看该应用的基础信息，并集中管理该应用下的接口路由。

常用操作如下：
- `编辑`：修改接口应用的名称、HOST 地址或描述。修改 HOST 地址会影响该应用下所有接口路由的实际请求地址，生产环境调整前应先确认外部系统地址是否已经切换完成。
- `创建接口路由`：在当前接口应用下新增一个具体 API 端点。
- `查看接口路由`：进入某条接口路由详情页，核对请求路径、请求方式和编码。

---

## 6\. 接口路由管理

接口路由用于定义 Gaia 调用外部系统时的具体 API 端点。一个接口应用可以包含多条接口路由，例如“查询供应商”“同步批次”“回写审批结果”等。

### 6.1 创建接口路由
1. 进入接口应用详情页。
2. 在 `接口路由` 区域点击 `创建`。
3. 填写接口路由信息。
4. 点击 `保存`。

接口路由的主要字段如下：

| 字段 | 是否必填 | 说明 |
|------|------------|------|
| 接口路由名称 | 是 | 路由在页面中的显示名称。建议写清业务动作，例如“查询物料主数据”。 |
| 路由请求 | 是 | API 请求路径，通常填写相对 HOST 地址的路径。保存后，系统会将 HOST 地址与该路径组合为实际请求地址。 |
| 请求方式 | 是 | HTTP 请求方式，例如 `GET`、`POST`、`PUT`。应与外部系统接口定义保持一致。 |
| 编码 | 是 | 路由的唯一编码，用于系统内部引用。建议使用稳定、可读的英文编码。 |

### 6.2 查看接口路由

接口路由列表显示在接口应用详情页的 `接口路由` 区域。点击路由名称可以进入详情页，核对该路由的请求路径、请求方式和编码。

如果外部系统接口发生变更，应先在测试环境更新路由配置并完成联调，再同步到生产环境。尤其是请求方式和请求路径变更，可能直接影响正在运行的业务流程或后台作业。

### 6.3 编辑接口路由

在接口路由详情页点击 `编辑`，可以修改路由配置。保存后，后续使用该路由的调用会按新的配置执行。

编辑时建议重点确认：
- 路由请求是否仍然与外部系统接口路径一致。
- 请求方式是否与外部接口定义一致。
- 编码是否已经被工作流、作业、SDK 或其他配置引用。
- 是否已在测试环境完成联调验证。

### 6.4 维护入参和出参

接口路由详情页支持维护 `入参` 和 `出参`。这些参数用于描述外部 API 的请求字段和响应字段，方便后续在表单外部数据填充、后台作业或其他集成场景中选择字段并完成映射。

路由详情页左侧会显示 `基础`、`入参`、`出参` 导航项；页面主体中也会显示对应的 `入参` 和 `出参` 区域。管理员可以在对应区域点击 `创建` 新增参数。

#### 创建入参

入参表示 Gaia 调用外部接口时传递给外部系统的请求字段。例如在表单中引用外部数据时，可以把当前表单字段、固定值或其他上下文值映射到接口入参中。

创建入参时，需要填写以下字段：

| 字段 | 是否必填 | 说明 |
|------|------------|------|
| 名称 | 是 | 入参在页面中的显示名称，建议使用业务人员容易识别的名称。 |
| 字段编码 | 是 | 入参的字段编码，应与外部接口定义或映射规则保持一致。 |

保存后，入参会出现在接口路由详情页的 `入参` 列表中。列表通常展示序号、名称、字段编码、创建时间、创建人和操作列，便于后续查询、编辑或维护。

#### 创建出参

出参表示外部接口返回给 Gaia 的响应字段。例如在表单中填充外部数据时，可以把接口返回的出参映射到当前表单字段上。

创建出参时，需要填写以下字段：

| 字段 | 是否必填 | 说明 |
|------|------------|------|
| 名称 | 是 | 出参在页面中的显示名称，建议与返回数据的业务含义一致。 |
| 字段编码 | 是 | 出参的字段编码，应与外部接口返回字段或解析规则保持一致。 |
| 是否显示 | 是 | 控制该出参是否在后续选择或展示场景中显示。选择 `是` 时，该字段可作为可见返回字段使用；选择 `否` 时，该字段通常不展示给配置人员选择。 |
| 显示排序 | 是 | 控制多个出参在页面或选择列表中的显示顺序。数字越小通常越靠前。 |

保存后，出参会出现在接口路由详情页的 `出参` 列表中。列表通常展示序号、名称、字段编码、是否显示、显示排序、创建信息和操作列。

#### 使用建议
- 入参和出参的字段编码应保持稳定。字段编码一旦被表单外部数据填充、作业或 SDK 引用，修改后可能导致映射失效。
- 创建参数前，建议先与外部接口提供方确认请求字段、返回字段和字段含义。
- 用于表单外部数据填充时，应只维护业务配置需要使用的出参，避免把无关返回字段全部暴露给配置人员。
- 出参的 `是否显示` 和 `显示排序` 会影响后续配置人员选择字段时的可读性，建议按业务常用顺序维护。

---

## 7\. 安全与排查

配置外部接口时，建议遵循以下规则：
- 生产环境的 HOST 地址优先使用 HTTPS。
- 不在名称、描述等普通字段中填写密码、密钥或令牌。
- 为每个外部系统单独创建接口应用，不建议把多个系统的路由混在同一个应用下维护。
- HOST 地址、路由请求和请求方式变更前，应先确认引用范围，并在测试环境完成联调。
- 接口应用、接口路由、入参和出参的编码一经被流程、作业、表单配置或 SDK 引用，应保持稳定，避免因修改编码导致引用失效。

当 Gaia 调用外部接口失败时，可按以下顺序排查：
1. 确认接口应用的 HOST 地址是否正确。
2. 确认接口路由的请求路径和请求方式是否与外部系统一致。
3. 确认外部系统网络是否允许 Gaia 访问。
4. 查看审计日志或接口调用日志，定位失败时间、调用配置和错误信息。
