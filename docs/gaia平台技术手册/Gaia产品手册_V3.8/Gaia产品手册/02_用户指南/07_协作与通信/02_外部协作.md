# 外部协作
> 本文介绍如何与外部合作伙伴协作，包括与第三方应用集成、文件推送至外部签署平台、外部协作者管理等能力。   

---

## 前提条件
- 组织已启用外部协作相关功能
- 管理员已完成外部协作者、邮件通道或签署平台配置
- 当前用户具备对应流程或文档的操作权限

---

## 功能简介

外部协作适用于需要**外部用户参与流程**的业务场景，例如：

| 场景 | 说明 |
|------|------|
| **外部审批** | 供应商、合作伙伴等非内部人员参与文档审批 |
| **跨组织协作** | 与外部单位共同完成质量放行、变更评审等流程 |
| **邮件快速响应** | 外部人员无需登录系统，通过回复邮件即可完成审批 |

### 协作方式

| 方式 | 说明 |
|------|------|
| **临时账号** | 系统为外部人员创建受限账号，任务完成后可禁用 |
| **邮件回复** | 外部人员通过回复邮件中的关键词（如同意/拒绝）完成任务 |
| **免登录访问** | 从第三方办公应用访问时，绑定账号后可自动登录 |

## 与第三方应用集成

### SSO 单点登录

系统支持与第三方身份提供商集成，实现**单点登录（SSO）**，用户一次登录即可访问多个应用。

### 免登录访问

当用户已绑定第三方应用账号时，可直接从该应用访问 Gaia，减少重复登录操作。

**前置条件**：管理员需在系统设置中开启「账号绑定第三方应用后自动登录」选项，该选项支持密码策略、LDAP 策略、OAuth2.0 策略等多种认证方式。

**说明**：免登录访问仍会记录登录日志，并执行用户状态、锁定状态和认证策略校验。

## 文件推送至外部签署平台

系统支持将文件推送至**第三方电子签署平台**进行签署和盖章，适用于批签发报告、合同等需要正式签章的文档。

### 使用流程
1. **配置签署平台**：管理员在「数字签名策略设置」中指定签署平台及流程
2. **推送文件**：文件进入「签署中」状态时，系统自动或通过用户动作将文件发送至签署平台
3. **获取签署结果**：签署完成后，通过「获取签署结果」动作同步签署状态和签署后的文件
4. **更新格式副本**：签署成功时，系统将文件的格式副本替换为签署后的版本

### 状态说明

| 状态 | 说明 |
|------|------|
| **签署中** | 文件已推送至签署平台，等待签署 |
| **签署完成** | 签署成功，格式副本已更新 |
| **签署失败** | 签署终止或失败，需根据业务规则处理 |

## 外部协作管理

### 外部协作者
- 外部人员通过\*\*人员（Person）\*\*对象管理，参与流程时系统为其创建临时用户
- 临时用户具有**外部协作者**角色，权限受控，不占用正式 License
- 完成协作后，系统可自动禁用其访问权限

### 通过邮件完成任务

当启用「回复邮件完成任务」时：
1. 系统向外部人员发送包含任务说明和审批选项的邮件
2. 外部人员直接回复邮件，输入配置的审批关键词（如「同意」「拒绝」）
3. 系统定时扫描收件箱，解析回复内容并自动完成任务
4. 邮件主题需包含任务业务编号，以便系统正确识别
> 邮件回复需与任务接收人邮箱一致，否则视为无效回复。   

### 任务跟踪

系统记录外部用户的任务分配与完成情况。当外部协作者所有任务完成后，可执行禁用动作关闭其账号，并发送协作结束通知。

---

## 结果验证
- 外部协作者已收到任务通知或邮件通知。
- 通过临时账号或邮件回复完成后，任务状态在系统内同步更新。
- 推送签署后可看到“签署中/签署完成/签署失败”等状态变化。
- 协作完成后，外部账号按策略被禁用或回收。

## 常见问题

**Q：外部人员如何参与审批？**

A：有两种方式：一是通过临时账号登录系统完成任务；二是通过回复邮件中的审批关键词完成任务（需管理员预先配置）。

**Q：从第三方办公应用访问时如何免登录？**

A：需先在系统中完成账号与第三方应用的绑定，且管理员已开启「账号绑定第三方应用后自动登录」。绑定后，从该应用内访问系统时将自动登录。

**Q：文件推送至签署平台后如何更新？**

A：签署完成后，管理员需配置「获取签署结果」用户动作，系统会根据签署状态更新文件状态和格式副本。

**Q：外部协作者的任务能否移交或代理？**

A：外部任务不允许责任人自行移交或重新指派，其他操作与内部用户任务一致。
