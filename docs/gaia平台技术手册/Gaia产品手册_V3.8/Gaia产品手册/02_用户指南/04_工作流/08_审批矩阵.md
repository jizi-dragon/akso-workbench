# 审批矩阵
> 本指南用于帮助业务用户在 Gaia 平台中查看和使用审批矩阵，并在发起/进行中的工作流中正确维护参与人。   

---

## 功能简介

审批矩阵用于按业务条件自动匹配审批参与人，避免每次发起流程都手工逐个选人。 
系统可基于对象字段（如文件类型、组织、业务单元等）匹配不同规则，自动带出不同的审批链。

典型价值：
- 同一流程可按不同场景自动匹配不同审批人
- 发起流程时可以先校验再提交，减少选错人
- 串行/并行规则可同时存在，满足复杂审批策略

---

## 前提条件
- 当前对象已由管理员配置审批矩阵
- 您具备审批矩阵查看权限；如需维护成员，还需具备管理权限
- 当前记录处于允许编辑审批矩阵的生命周期状态（若配置了锁定状态，锁定时不可改）

---

## 入口与可见范围

在记录详情页中，审批矩阵以独立区域或标签页展示。是否可见取决于以下条件是否同时满足：
1. 审批矩阵配置为启用状态
2. 页面布局已放入审批矩阵区域且未隐藏
3. 当前用户有查看权限（权限集 \+ 状态权限）
4. 当前记录数据满足矩阵匹配条件
5. 匹配到的审批矩阵管理记录为启用状态

---

## 查看审批矩阵

### 操作步骤
1. 打开目标记录详情页
2. 进入 **审批矩阵** 区域
3. 查看规则与成员信息

### 页面中常见信息

| 区域 | 说明 |
|------|------|
| 审批角色 | 该角色在流程中的职责分组 |
| 参与人 | 当前角色下的用户，可多选 |
| 顺序角标 | 串行场景下用于表示分配顺序 |

---

## 管理审批矩阵成员（详情页）

当您有管理权限时，可直接在详情页维护审批矩阵成员。

### 进入管理模式
1. 进入审批矩阵区域
2. 点击 **管理**
3. 页面进入编辑态，显示 **保存 / 重置 / 取消**

### 可执行操作

| 操作 | 结果 |
|------|------|
| 添加成员 | 在对应角色下新增参与人 |
| 删除成员 | 从该角色移除参与人 |
| 调整顺序 | 调整串行分配顺序 |
| 保存 | 提交当前变更并更新成员 |
| 重置 | 回到本次编辑前状态 |
| 取消 | 退出管理模式且不保存 |
> \[!NOTE\]
点击记录页面的通用“编辑”不会自动进入审批矩阵管理态。审批矩阵是否可编辑仅由其“管理”按钮和权限控制。

## 发起工作流时使用审批矩阵

当流程节点配置了“使用审批矩阵作为参与人”后，发起弹窗会自动加载匹配结果。

### 发起时的行为
1. 点击 **发起工作流 / 提交审批**
2. 在弹窗中查看审批矩阵参与人区
3. 系统自动带出匹配角色与成员
4. 按需要调整后提交

### 发起时可调整内容

| 场景 | 行为 |
|------|------|
| 删除某成员 | 仅影响本次流程发起 |
| 补充某角色成员 | 新增后参与本次任务分配 |
| 添加自定义角色 | 仅在矩阵开启“允许用户添加角色”时可用 |
> \[!TIP\]
新增的自定义角色一旦选定成员，相关选人项会转为必填；未完成必填项将无法提交流程。   

### 提交校验
- 必填角色无人时，界面会高亮并提示需补全
- 通过校验后才可提交
- 未通过时，先修正对应角色再提交

---

## 串行与并行规则

审批矩阵角色规则可配置为串行或并行，两者对任务分配影响不同：

| 规则类型 | 分配方式 | 适用场景 |
|------------|------------|------------|
| 串行 | 按参与人顺序依次派发 | 强制逐级审批 |
| 并行 | 同时派发给该角色下成员 | 并行会审或共同确认 |

在串行规则下，参与人的显示顺序就是系统分配顺序。

---

## 进行中工作流的参与人管理

在“管理活动工作流”中，审批矩阵流程支持“添加参与人”，并遵循以下原则：
1. 仅对当前活跃任务节点生效
2. 已完成或未开始节点不展示可编辑选人
3. 新增参与人后，系统按规则判断是否生成新待办

任务生成规则（新增参与人后）：
- 若该用户在活跃任务中已完成过或已有计划任务，不重复生成
- 若该用户在活跃任务中被取消/移交/重指派导致当前无任务，可补生成新待办
> \[!NOTE\]
“重新指派”“移交任务”后的新任务所有者，不会反向写回审批矩阵成员。   

---

## 时间线查看说明

在工作流时间线中，审批矩阵相关节点会展示参与人信息：
- 进行中/已完成节点：显示实际参与人
- 尚未生成节点：显示计划参与人

这有助于区分“设计上的参与人”和“实际执行过的人”。

---

## 默认职位管理（启用时）

若管理员在审批矩阵中启用了“默认职位管理”，且电子签名启用了“需要选择职位”，签批时职位会按规则预选：
1. 条件匹配且用户有多个职位时，优先带出矩阵预设职位
2. 条件不匹配且用户有多个职位时，用户手动选择
3. 用户仅有一个职位时，自动带出唯一职位

该能力仅在“默认职位管理”实例为启用状态时生效，并可用于批量工作流。

## 常见问题

**Q1：为什么我看不到审批矩阵区域？**   A：通常是未配置、被布局隐藏、无查看权限、条件未匹配或匹配记录未启用。可联系管理员排查。

**Q2：为什么“管理”按钮不可用？**   A：通常是无管理权限，或当前记录状态已被设置为锁定不可编辑。

**Q3：我修改了矩阵成员，会影响已发起的流程吗？**   A：不会。已发起流程按发起时快照执行，后续修改仅影响新发起流程。

**Q4：发起流程时提示某项未完成配置怎么办？**   A：对应角色是必填但未选人。补齐后再提交。
