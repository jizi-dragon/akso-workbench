## 2. 表单布局这一层：已学的六条

1. **建壳 ≠ 保存**：新建一个表单布局 = **不带 `id`** 的 `SaveLayoutDetail`（**11 键**、`source: 3`、
   四个空数组），**响应 `data` 直接就是新布局 id**；此后一律带 `id` 保存（17 键）。
   `[真机]` n=2（`新建表单布局` / `新建布局`，**名字变了、形状没变**）。
2. **形状是「逐元素」的，不是「逐请求」的** ★ ——同一条请求里可以两种形状并存：

   | 元素 | 本次新增 | 已存在 |
   |---|---|---|
   | 部分（`sections[]`） | **5 键** `{id, code, name, type, columnsNum}` | **62 键**（完整物化） |
   | 控件（`controls[]`） | **8 键** `{id, sectionId, code, name, fieldId, type, gridSpan, attrs}` | **23 键** |

   `[真机]` 3 条独立样本：同一请求内『ceshi』5 键 + 已有部分 62 键；
   新控件 `demo_parent__c` 8 键 + 老控件 23 键；新控件 `demo_number__c` 8 键 + 老控件 23 键。
   ⇒ **纠正**：早期报告里"精简形状 vs 完整形状两种请求体"是**错口径**——"整份看着精简"其实是
   "当次新增元素占满了整份体"，"整份看着完整"是"所有元素都已存在"。
3. **控件 = 字段的投影**：`code` / `name` / `fieldId` 逐字来自所选字段，`type` = **`AK<组件名>`**
   （实测 `AKInput`/`AKInputNumber`/`AKSelectorYesNo`/`AKSelectorSingle`/`AKDateTime`/`AKAttachment`/`AKSelectorObject`
   共 7 个值，对应 9 种 `dataType`，**多对一、非双射**）。`[手册]` `01D §4.1`：**「控件即对象字段，
   新增控件本质是在该部分中引入字段」**。
4. **换 id 是独立一步、且是增量的**：保存"含新组件"之前先调 `GetStableComponentIds`，
   **只报本次新增的组件**（实测 8 / 5 / 1 / 2 个 = 新增部分 + 控件个数）。
5. **弹窗不落盘**：`[真机]` n=1（零写入）——「添加部分」「添加控件」的弹窗只改前端状态，
   **只有布局顶层的「保存」才发起提交**（段 6 受控实验二次确证：只点弹窗「确定」全程不碰顶层保存 ⇒
   `SaveLayoutDetail` **0 条**，写请求只有 1 条只读查询）。
   ⇒ 任何"在界面上加部分/控件"的取证，要复现的是**那一次保存提交**，不是"逐步提交"。
6. **一次「保存」点击 = 1 条写入，且就是完整形状**（部分 62 键 / 控件 23 键）：
   `[真机]` n=3（段 6 §3c 受控实验：空保存×2 → 2 条；+1 控件 → 1 条；+1 部分+1 控件 → 1 条）。
   ⚠️ 仍有一处对不上：段 6 早先出现过"一次改动 2 条写入"，更可能是**当时点了两次保存**
   （用户在段 6 §3b 自述"点了两次保存"，对应正好录到 2 条逐字段相同的写入）；
   要彻底定需记录**请求发送时刻**（现有时间戳被"事件分发时刻"压平，见 #74 与 §4 的 F44）。

## 3. 跨五层的通用规律

### 3.1 四条规律

| 规律 | 证据 |
|---|---|
| **键数 = 客户端把模型物化到什么程度**，不是平台的硬要求（同一端点见过 4 / 6 / 8 / 11 / 14 / 15 / 16 / 17 / 23 / 62 键，平台**全部 `200/code=0`**） | `[真机]` 全语料；F48 是最硬的一条（同一控件同批发过 14/15/16/23 键） |
| **写入侧与读取侧词表不同**：读侧控件 33 键（`dataType`/`required`/`visible`/`readOnly`/`width`），写侧只 8/23 键；字段读侧 93 键有 `isRequired`，写侧从不发 | `[真机]` 读侧回读 + `SaveField` n=11（F58/F62） |
| **全量替换语义**：`SaveLayoutDetail` 与 `AddColumns` 都是整份提交（空保存也整份重写）⇒ **"读旧 → 合并 → 提交"是平台侧的硬约束**，不是风格问题 | `[真机]` 空保存 ×2 条都带完整内容；`AddColumns` 连页面渲染都整份重发 |
| **平台自己的客户端不做幂等**：重复点击就重复写（不去重） | `[真机]` 空保存 2 条逐字段相同；`ObjectPicklist/save` 才按 `code` upsert（F3） |

### 3.2 五条派生的工程口径（比事实本身更重要）

1. **判"成功"必须看平台回读，不能看接口返回** —— F1/F2/F8 合起来意味着"接口回 `data:true`"与
   "东西真的建对了"是两件事。
2. **键名的事实源是平台的读侧 schema + 界面的真实请求体**，不是任何一侧的字段名。
   本次先靠读侧 schema（字段 93 键）正确预测了 `minValue`/`maxValue`，又正确推出了 `scale`。
3. **先拿到界面请求体，再动写侧** —— #62/#63/#67/#69 四条的成因完全一样：**照着猜的信封/键名写**，
   而症状一律是"接口回成功、回读才发现空"（F2/F7/F8/F62 是这一族的正面事实）。
4. **分清"一串人工操作"与"一次页面事件"，唯一依据是 Δt**：`acct-891a4f9d-20260921-210820` 那 8 条
   **全在 165 ms 内**，是**一次页面渲染**，却被读成了"用户依次配了 10 列"；对照另一场 20 条写请求跨
   **221 秒**、`SaveField` 每 15–33 秒一次——**那才是人的节奏**（报告：`2026-09-21-L3列表布局取证与监听失败复盘.md` §11）。
5. **Δt 只在"同一批被分发的事件之间"可用**：09-22 三个布局会话里"动作缓冲里最后一次点击"与"请求时间戳"
   差 **38–61 秒**，而同一批请求的观测跨度只有 **14 毫秒**（09-21 六个会话是 0.1–3.1 秒）。
   **可用**：同批事件之间的相对间隔、这批请求的先后顺序（顺序另有内容语义背书：3× 下拉查询 →
   `GetStableComponentIds` → `SaveLayoutDetail`）；**不可用**：跨"动作缓冲 ↔ 请求"的时间差（F44，#74）。

### 3.3 外部参照（他山之石，**不是本平台事实**）

| 参照对象 | 它的做法 | 与本平台的关系 |
|---|---|---|
| Terraform（`terraform plan` / `import`） | plan 只**声明**将要发生什么；对"已存在的资源"要么报错要么要求显式 `import`，不会因为"看起来像"就改别的资源 | 参照：**"不存在"要出声** |
| `kubectl apply` | 按名字**创建或更新**（upsert），打错名字就**创建出一个新对象** | **本平台的旧行为与它一模一样**；差别是 K8s 里多出来的 Deployment 能 `kubectl get` 看见，而本平台里"多出来的空对象"**没有任何提示**，删除要走界面（F78） |
| Google Cloud CLI（`gcloud`） | 资源不存在时**明确报错**并给出候选（有的命令给相似资源建议） | 参照：行业共识 —— "不存在"要出声，不要静默创建 |
| 上游 AkSx（`akso-auto` 的 `name-resolver.js`） | 只做"名称/编码冲突"提示，**没有**"不存在 + 候选"这一半 | 上游只防"重名"，不防"打错" |

## 7. 复算方式

**证据在 `factory-tuning/reports/**`（人工可读报告）；采集工具链已随功能一并移除**，
因此本文没有"跑一条命令重算形状"的路 —— 能重算的只有"某条事实在存活报告里出现过几次 / 长什么样"：

```powershell
# 0. 存活的报告清单（人工可读；gaia-v38-study/ 下是手册逐簇笔记）
Get-ChildItem factory-tuning\reports -Recurse -File -Filter *.md | Select-Object -ExpandProperty Name

# 1. 某条键名/端点/数值在存活报告里出现在哪
Select-String -Path factory-tuning\reports\*.md -Pattern 'listlayoutColumns|GetStableComponentIds|minValue' -CaseSensitive

# 2. 某条事实的原始逐键对照（例：控件层 vs 字段层的词表）
Select-String -Path factory-tuning\reports\2026-09-22-控件与字段的词汇对照.md -Pattern 'required|visible|readOnly' -CaseSensitive
```

> ⚠️ **判据纪律（#78）**：`Select-String` **默认大小写不敏感**（与 `grep`/`rg` 相反）。
> 用形状正则（如 `AK[A-Z][A-Za-z]+`）会**被无关文本蹭中**——实测被 `Akso`（厂商名）蹭出 228 条假命中，
> 让"手册里没有 `AK*`"这条结论当场自相矛盾。写判据要 **`-CaseSensitive` + 点名具体值**。
